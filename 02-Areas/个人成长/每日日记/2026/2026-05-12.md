# 2026-05-12 每日日记

## 每日三块 AI 思考总结

### 1. SaaS 的 AI 能力释放 / 商品基础能力
上午研究了商品条码和货号在有赞、微盟两家的处理方案。两家的处理方式不一样，细节还需要进一步确认。

**判断：** 商品条码/货号不是单纯字段问题，而是商品主数据、AI 取数、经营分析稳定性的底层口径问题。后续如果要让 Agent 帮客户做商品分析，必须先保证商品识别逻辑可靠。

### 2. 组织的 AI 转型 / 内部 AI 提效
针对内部 AI 提效，已经将玄武中的需求数据分析和 BUG 数据开放出来，后续可以给公司内部人员用于需求管理和 PRD 评审。

**判断：** 这是内部 AI 提效的关键数据底座。需求管理和 PRD 评审可以从“靠经验补漏”升级为“用历史需求、BUG、问题链路辅助评审”，有机会形成公司内部统一的 AI 评审能力。

### 3. 产品能力强化 / 外部 AI 赋能
针对外部 AI 赋能，今天发现森马和 bebe 两个客户分别提出 Agent 取数和分析需求。已找 CSM 沟通，准备和客户一起聊，看是否可以共创。

**判断：** 客户需求已经开始从“系统里查数据”升级为“让 Agent 帮我取数、分析、给判断”。这验证了 EZR 从 SaaS 功能提供方升级为 Agent Skill / 数据上下文提供方的方向。

## 风险提醒
- 商品条码/货号口径如果不统一，后续 AI 分析会出现“同物不同码 / 同码不同物”的质量风险。
- 内部需求/BUG数据开放后，要控制权限、解释口径和使用边界，避免数据被误读。
- 客户共创不能直接滑向定制报表，应抽象成可复用的 Agent 取数与分析 Skill。
