### 3. WorkBuddy Buddy 应用建设评估（下午，主线）
- 输入：老板给的 URL + 两个包（连接器包 `ezr-crm 3`、技能包 `aggregated-skills-collection`）。
- 盘点结论：**已有资产基本齐备**。连接器含 connector-meta + mcp.json + icon + 覆盖 64 个 MCP 工具的 skill；技能包含 1 个路由主技能 + 14 个子技能，无硬编码密钥。
- **关键实测**：MCP 端点无 Token → 401 并指向 `/.well-known/oauth-protected-resource`；受保护资源与授权服务器元数据均 200，支持 PKCE S256；`POST /oauth/register`（RFC 7591）返回 201，`token_endpoint_auth_method` 支持 `none`。

## 反思

1. **基础设施工具有"静默失效"属性**。23 个任务同时坏，但没有任何一条通知——是我去问才发现。基础设施不该依赖人肉巡检：**关键任务的失败告警必须默认开启**，而不是等出事再补。
2. **升级动作要有"事后核对清单"**。这次的坑完全可预防。教训写进记忆了：网关升级后必须主动核对 `cron list --json` 的 agentId 分布。
3. **补跑长任务走主会话，不要走 subagent**。今天两次试错（cron 阻塞等待、subagent 超时）都浪费了时间。这条已经确定，不再是待验证假设。
4. **WorkBuddy 这题的意外收获**：原本以为要开发对接，实测发现标准 MCP OAuth 已经通了。**能实测的就要动手实测，不要照着文档猜**——文档里 `auth_mode: "server-side"` 的写法反而可能把我们带偏（这也是最可能被审核打回的点）。
5. **今天没有推进重点项目本身**（指标库、知识库、App极速版）。修复 + 评估是必要的，但要警惕"应急事务吃掉主线时间"。
