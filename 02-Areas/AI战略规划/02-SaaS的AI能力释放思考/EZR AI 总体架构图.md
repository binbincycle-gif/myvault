# EZR AI 总体架构图

## 目标：把 EZR 从 CRM 系统升级为 Agent 可调用的经营能力底座

## 一、先说结论

**结论**  
EZR 的 AI 路线，不应该理解成“在现有 CRM 上加几个 AI 功能”，而应该理解成三层升级：

1. **底层把业务能力重构成可被 AI 调用的能力底座**
2. **中间补一层安全治理与权限控制**
3. **上层让 Copilot / Agent / Skills 形成可闭环的执行体系**

所以 EZR AI 总体架构的本质是：

> **业务能力底座 + 安全治理层 + 智能协同入口 + 执行反馈闭环**

## 二、总体架构图（建议分 6 层）

我建议你把 EZR AI 总图拆成 **6 层**：

1. **智能入口层**
2. **Agent / Copilot 协同层**
3. **安全治理层**
4. **AI 可调用能力层**
5. **EZR 业务基础层**
6. **反馈学习闭环层**

这六层对应的是：

- 从哪里发起
- 谁来理解和协同
- 谁来兜安全
- 调什么能力
- 能力来自哪里
- 结果怎么回流

## 三、六层总图

## 1）智能入口层
### 作用
承接 AI 的实际使用入口。

### 典型入口
- 管理后台内嵌 AI 助手
- 导购工作台 Copilot
- OpenClaw / 自有 Agent 工作台
- 飞书 / 钉钉 / 企业微信入口
- API / 第三方 Agent 入口

### 这一层的目标
让 AI 不只是独立 demo，而是真正嵌进组织日常工作流。

### 这一层的定位
> **入口层解决的是“人在哪里发需求，AI 从哪里接单”。**

## 2）Agent / Copilot 协同层
### 作用
这一层决定 EZR AI 到底以什么形态服务业务。

我建议明确区分三类形态：

### A. Copilot
#### 特征
- 辅助人完成任务
- 人主导，AI建议
- 偏工作台型
- 强交互，弱自治

#### 适用场景
- 导购助手
- 运营助手
- 报表解读
- 经营建议
- 话术生成

#### 本质
> **Copilot = 帮人做判断与准备动作，但不轻易替人自主执行。**

### B. Agent
#### 特征
- 能跨步骤完成任务
- 能调用多个能力
- 能发起部分动作
- 有一定自治性

#### 适用场景
- 活动策划与执行助手
- 会员召回任务流
- 门店经营诊断与跟进
- 管理层经营协同助手

#### 本质
> **Agent = 围绕目标自主拆解、调用、执行、回写。**

### C. Skills
#### 特征
- 原子能力单元
- 可被 Copilot / Agent 调用
- 封装业务规则与接口能力

#### 适用内容
- 查询会员画像
- 查交易数据
- 识别流失风险
- 生成营销建议
- 创建待办任务
- 写回执行结果

#### 本质
> **Skills = AI 可调用的经营能力颗粒。**

### 这一层的最终关系
> **Copilot 是交互形态，Agent 是执行形态，Skills 是能力底座。**

这句话你可以拿去讲，非常清楚。

## 3）安全治理层
### 作用
确保 AI 不是“能调系统”，而是“被放心地调系统”。

### 这一层包括
#### 入口治理
- 渠道鉴权
- 身份映射
- 会话可信校验

#### 权限治理
- 数据权限判断
- 动作权限判断
- 组织/品牌边界控制

#### 安全代理
- Prompt Injection 防护
- 敏感数据识别
- 数据污点追踪
- 输出净化
- 动作分级放行

#### 执行控制
- 工具白名单
- 接口放行控制
- 沙箱执行
- 高风险动作审批
- 密钥不暴露

#### 审计回溯
- 调用链留痕
- 风险判定留痕
- 审批记录
- 输出日志
- 责任归属

### 这一层的定位
> **安全治理层不是“附加限制”，而是 AI 真正进入生产系统的准入门槛。**

## 4）AI 可调用能力层
### 作用
这一层是整套架构里最核心的“AI 调用面”。

建议按六类能力提供：

### 4.1 身份与权限能力
- 身份识别
- 组织识别
- 数据范围判断
- 动作权限判断

### 4.2 上下文数据能力
#### 会员
- 会员画像
- 生命周期
- 标签
- 行为轨迹
- 流失风险

#### 商品
- 商品信息
- 库存
- 热销滞销
- 客群匹配

#### 交易
- 订单
- 客单价
- 连带率
- 复购率
- 渠道来源

#### 营销
- 活动数据
- 发券核销
- 触达效果
- 活动反馈

#### 导购 / 组织
- 导购会员池
- 跟进记录
- 转化表现
- 组织归属

### 4.3 诊断分析能力
- 门店问题识别
- 会员流失识别
- 商品结构分析
- 活动效果诊断
- 导购经营质量分析

### 4.4 策略生成能力
- 会员召回策略
- 商品经营建议
- 导购跟进建议
- 活动方案建议
- 管理层问题优先级建议

### 4.5 执行动作能力
- 创建待办
- 生成话术
- 生成客群包
- 创建活动草案
- 调起触达
- 触发审批
- 写回执行记录

### 4.6 反馈学习能力
- 动作结果回写
- 推荐采纳率
- 活动效果回写
- 策略效果评估
- 案例沉淀
- 模板优化

### 这一层的定位
> **AI 可调用能力层 = EZR 未来真正的 Agent API / Skill 底座。**

## 5）EZR 业务基础层
### 作用
承接 AI 调用背后的真实业务系统。

### 现有业务基础
- 会员中心
- 商品中心
- 订单/交易中心
- 营销中心
- 导购体系
- 组织权限体系
- 报表与分析基础
- 消息触达链路
- 审批流（如已有）

### 这一层的定位
> **这层不是要被替代，而是要被重新封装。**

也就是说，EZR 不是推倒重来，而是：
- 把原来“给页面调用”的能力
- 升级成“给 Agent / Copilot / Skills 调用”的能力

## 6）反馈学习闭环层
### 作用
把 AI 从一次性能力，变成越来越懂业务的持续系统。

### 这一层包括
- 执行结果回写
- 推荐采纳记录
- 活动结果归因
- 导购执行反馈
- 风险事件记录
- 人工修正记录
- 模板沉淀
- Skill 优化
- 策略优化

### 这一层的定位
> **没有反馈闭环，AI 只能反复输出；有了闭环，AI 才能持续贴近经营结果。**

## 四、把这张总图翻译成人话

如果你在会上不想讲太技术，可以直接这么讲：

> **EZR AI 总体架构，分成三件事：**
> 1. 上面要有 Agent / Copilot 入口，真正进工作流  
> 2. 中间要有安全治理层，确保 AI 可控可追溯  
> 3. 下面要把 CRM、交易、导购、营销能力重构成可调用能力底座，并形成结果闭环

## 六、建议你怎么讲 Agent / Copilot / Skills 的关系

这个是你这周很关键的讨论点，我帮你压成一版非常适合沟通的话术：

## 1. Skills 是能力颗粒
它回答：
- AI 能调什么能力？

## 2. Copilot 是辅助形态
它回答：
- 人和 AI 怎么协作？

## 3. Agent 是执行形态
它回答：
- AI 能不能围绕目标自己推进任务？

所以不是三选一，而是三层关系：

> **Skills 是底座，Copilot 是人机交互层，Agent 是自治执行层。**

这个比单纯讲“我们做 Agent 还是做 Copilot”要成熟得多。

更准确应该是：

> **短期以 Copilot 落地价值，中期以 Skills 做能力沉淀，长期以 Agent 做目标闭环。**

## 七、建议的落地路径

## 第一阶段：Copilot 先落地
### 目标
先证明 AI 对业务有帮助

### 场景
- 导购跟进助手
- 门店诊断助手
- 报表解读助手
- 管理层周报助手

### 原则
- 以建议为主
- 低风险动作先跑
- 人工把关为主

## 第二阶段：Skills 体系成型
### 目标
把业务能力结构化、接口化

### 建设重点
- 统一能力网关
- Skill 颗粒定义
- 场景能力封装
- 权限与规则注入

## 第三阶段：Agent 闭环试点
### 目标
让 AI 开始围绕目标执行任务

### 试点方向
- 会员召回任务流
- 营销活动策划与执行助手
- 门店问题跟进协同
- 管理层经营问题派发

### 原则
- 中低风险先做
- 高风险动作必须审批
- 全程留痕
