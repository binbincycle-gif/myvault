# EZR Agent 能力层建设方案 V0.1

> 生成时间：2026-08-06  
> 主题：EZR 从 SaaS CRM 升级为品牌经营 Agent 能力供给方  
> 关联主线：Agent 入口平台化 / MCP / Skill / 智能导购 / 导购小龙虾 / CRM 能力 Agent 化

## 一句话结论

这 10 个能力不是 10 个功能，而是 EZR 从 SaaS 页面系统升级为 **品牌经营 Agent 能力供给方** 的第一批能力资产。

建设原则：

> 先不做大而全 Agent，先把高频经营动作封装成可调用、可解释、可执行、可回写的 MCP / Skill 能力。

---

# 一、能力总览

| 序号 | 能力名称 | 核心价值 | 优先级 |
|---|---|---|---|
| 1 | 会员经营诊断 | 找出会员经营问题 | P0 |
| 2 | 沉默会员唤醒 | 把沉默会员转成导购任务 | P0 |
| 3 | 复购机会识别 | 找出近期可能复购客户 | P0 |
| 4 | 导购任务生成 | 把策略变成每日动作 | P0 |
| 5 | 导购话术生成 | 降低导购沟通门槛 | P1 |
| 6 | 活动效果诊断 | 判断活动是否有效 | P1 |
| 7 | 门店经营诊断 | 帮店长发现经营问题 | P1 |
| 8 | 客户分层策略 | 统一会员分群逻辑 | P1 |
| 9 | 权益推荐策略 | 给出优惠券/权益使用建议 | P2 |
| 10 | 经营复盘生成 | 自动沉淀品牌/门店复盘 | P2 |

建议第一阶段不要 10 个全做，先打穿这条闭环：

> **会员经营诊断 → 沉默会员唤醒 → 复购机会识别 → 导购任务生成 → 结果回写**

# 二、每个能力要准备什么

## 1）会员经营诊断能力

### 要解决的问题

品牌现在不知道会员经营到底卡在哪里：

- 新客留存差？
- 老客复购低？
- 高价值会员流失？
- 导购跟进弱？
- 活动转化低？
- 权益使用差？

### 使用角色

- 品牌运营
- 店长
- 区域经理
- 客户成功
- 未来外部 Agent

### 需要准备的数据

- 会员总量、新增会员、活跃会员
- 最近消费时间
- 消费频次
- 客单价
- 复购周期
- 会员等级
- 门店归属
- 导购归属
- 最近互动记录
- 活动参与记录
- 权益领取/核销记录

### 输出结果

```text
诊断结论：
- 当前会员经营最大问题是什么

问题分层：
- 高价值流失风险
- 沉默会员占比高
- 新客二购不足
- 权益领取后未核销
- 导购触达不足

建议动作：
- 优先唤醒哪类人
- 哪些门店/导购要重点跟进
- 应该配什么权益或话术
```

### MCP / Skill 输入输出

**输入：**

```json
{
  "brandId": "",
  "storeIds": [],
  "timeRange": "",
  "memberScope": "",
  "diagnosisType": "overall/member_retention/repurchase/silent"
}
```

**输出：**

```json
{
  "summary": "会员经营核心问题",
  "riskSegments": [],
  "opportunitySegments": [],
  "recommendedActions": [],
  "priority": "high/medium/low",
  "evidence": []
}
```

### 风险边界

- 不能输出未经授权的会员明细。
- 诊断结果要带数据依据，不能只给 AI 判断。
- 涉及个人隐私字段必须脱敏。
- 不自动执行营销动作，只给建议。

---

## 2）沉默会员唤醒能力

### 要解决的问题

导购不知道今天该唤醒谁、为什么唤醒、怎么说。

### 使用角色

- 导购
- 店长
- 品牌运营

### 需要准备的数据

- 沉默天数
- 最近消费品类
- 最近消费金额
- 偏好风格/尺码/品类
- 会员等级
- 导购归属
- 最近触达记录
- 是否近期被其他导购触达
- 当前活动/权益
- 是否存在投诉/反感记录

### 输出结果

```text
今日推荐唤醒会员名单
每个会员推荐理由
建议触达话术
适配权益/商品/活动
风险提醒
触达后回写字段
```

### MCP / Skill 输入输出

**输入：**

```json
{
  "brandId": "",
  "storeId": "",
  "guideId": "",
  "silentDays": 90,
  "limit": 10,
  "excludeRecentlyContacted": true
}
```

**输出：**

```json
{
  "members": [
    {
      "memberId": "",
      "reason": "",
      "suggestedMessage": "",
      "suggestedBenefit": "",
      "riskWarning": "",
      "nextAction": ""
    }
  ]
}
```

### 风险边界

- 必须校验导购是否有该会员权限。
- 近期已触达会员默认排除。
- 投诉/反感会员必须提示风险。
- 话术必须允许导购确认后再发送。
- 不能直接自动群发。

## 3）复购机会识别能力

### 要解决的问题

品牌和导购不知道哪些会员近期最可能复购。

### 使用角色

- 导购
- 店长
- 品牌运营
- 客户成功

### 需要准备的数据

- 历史购买周期
- 品类复购周期
- 最近购买商品
- 常购品类
- 会员等级
- 最近浏览/互动
- 活动匹配度
- 库存/新品信息
- 优惠券状态

### 输出结果

```text
近期高复购机会会员
复购理由
推荐商品/品类
推荐触达时机
建议导购动作
```

### MCP / Skill 输入输出

**输入：**

```json
{
  "brandId": "",
  "storeId": "",
  "guideId": "",
  "timeWindow": "7d/14d/30d",
  "category": ""
}
```

**输出：**

```json
{
  "opportunities": [
    {
      "memberId": "",
      "repurchaseProbability": "",
      "reason": "",
      "suggestedCategory": "",
      "suggestedAction": "",
      "bestContactTime": ""
    }
  ]
}
```

### 风险边界

- 复购概率要解释，不要黑盒。
- 商品推荐不能脱离库存和品牌规则。
- 不应过度打扰同一会员。
- 不能把低置信判断包装成确定结论。

## 4）导购任务生成能力

### 要解决的问题

品牌运营策略不能落到导购每天的动作上。

### 使用角色

- 品牌运营
- 店长
- 导购

### 需要准备的数据

- 品牌经营目标
- 门店目标
- 导购归属会员
- 会员机会名单
- 活动规则
- 权益规则
- 导购历史任务完成情况
- 导购工作负载

### 输出结果

```text
今日导购任务清单
任务优先级
每个任务的客户/原因/动作
完成标准
回写要求
```

### MCP / Skill 输入输出

**输入：**

```json
{
  "brandId": "",
  "storeId": "",
  "guideId": "",
  "businessGoal": "silent_wakeup/repurchase/activity_conversion",
  "maxTasks": 20
}
```

**输出：**

```json
{
  "tasks": [
    {
      "taskType": "",
      "memberId": "",
      "priority": "",
      "reason": "",
      "suggestedAction": "",
      "deadline": "",
      "successCriteria": ""
    }
  ]
}
```

### 风险边界

- 任务数量不能超出导购可执行负载。
- 必须避免重复派单。
- 任务来源要可追溯。
- 店长/运营要能调整优先级。
- 执行结果必须回写。

## 5）导购话术生成能力

### 要解决的问题

导购知道要联系客户，但不知道怎么说，或者话术不符合品牌调性。

### 使用角色

- 导购
- 店长
- 品牌运营

### 需要准备的数据

- 会员画像
- 最近消费
- 偏好品类
- 推荐商品/权益
- 品牌语气规范
- 触达渠道：微信/企微/短信/电话
- 禁用表达
- 客户敏感标签

### 输出结果

```text
适合当前客户状态的话术
不同语气版本
风险提醒
可编辑建议
```

### MCP / Skill 输入输出

**输入：**

```json
{
  "brandId": "",
  "memberId": "",
  "guideId": "",
  "scenario": "silent_wakeup/repurchase/activity_invite",
  "channel": "wechat/wecom/sms",
  "tone": "warm/professional/concise"
}
```

**输出：**

```json
{
  "message": "",
  "alternativeMessages": [],
  "reason": "",
  "riskWarning": ""
}
```

### 风险边界

- 不自动发送。
- 不承诺未经确认的权益。
- 不生成夸大、诱导、违规话术。
- 敏感会员要提示谨慎触达。
- 所有话术要保留生成记录。

## 6）活动效果诊断能力

### 要解决的问题

品牌不知道活动效果差在哪里：

- 是人群不准？
- 权益不吸引？
- 导购没触达？
- 门店执行弱？
- 商品不匹配？
- 还是活动本身设计有问题？

### 使用角色

- 品牌运营
- 区域经理
- 店长
- 客户成功

### 需要准备的数据

- 活动目标
- 目标人群
- 触达人群
- 参与人数
- 核销人数
- 成交金额
- 客单价
- 门店维度表现
- 导购维度表现
- 权益领取/核销
- 活动前后对比

### 输出结果

```text
活动整体诊断
人群/门店/导购/权益分层表现
异常点
改进建议
下一轮活动建议
```

### MCP / Skill 输入输出

**输入：**

```json
{
  "brandId": "",
  "campaignId": "",
  "timeRange": "",
  "compareWithBaseline": true
}
```

**输出：**

```json
{
  "summary": "",
  "keyProblems": [],
  "storePerformance": [],
  "guidePerformance": [],
  "segmentPerformance": [],
  "recommendations": []
}
```

### 风险边界

- 活动归因不能简单等同成交归因。
- 要区分自然成交和活动影响。
- 低样本数据不能过度判断。
- 对门店/导购排名要谨慎使用，避免误伤团队。

### 使用角色

- 品牌运营
- 数据运营
- 客户成功
- Agent 工作流

### 需要准备的数据

- RFM 指标
- 会员等级
- 消费频次
- 最近购买时间
- 品类偏好
- 客单价
- 活动响应
- 权益使用
- 导购互动
- 生命周期阶段

### 输出结果

```text
会员分层结果
每类人群定义
经营目标
建议动作

触达频率
```

**输入：**

## 9）权益推荐策略能力

### 要解决的问题

品牌不知道给谁发什么权益，导购也不知道怎么配合权益做转化。

### 使用角色

- 品牌运营
- 店长
- 导购

### 需要准备的数据

- 会员等级
- 历史消费
- 价格敏感度
- 品类偏好
- 当前活动
- 可用优惠券
- 权益成本
- 库存
- 毛利限制
- 历史权益核销表现

### 输出结果

```text
推荐权益类型
适用人群
推荐理由
预期目标
风险提醒
成本影响
```

### MCP / Skill 输入输出

**输入：**

```json
{
  "brandId": "",
  "memberId": "",
  "scenario": "wakeup/repurchase/vip_retention/activity_conversion",
  "availableBenefits": []
}
```

**输出：**

```json
{
  "recommendedBenefit": "",
  "reason": "",
  "expectedOutcome": "",
  "costRisk": "",
  "usageCondition": ""

```

### 风险边界

- 不得突破品牌价格/毛利规则。
- 权益有效期必须准确。
- 高成本权益需要审批。
- 不自动发券，除非有明确授权。

```json
  "timeRange": "",
  "reviewType": "weekly/monthly/campaign"
}
```

**输出：**

```json
{

  "goalAchievement": "",
  "keyFindings": [],
  "effectiveActions": [],
  "problems": [],
```

# 三、建议建设顺序

## 第一阶段：打穿导购经营闭环

目标：证明 EZR 能力可以被 Agent 调用，并产生业务动作。

建议先做 5 个：

1. 会员经营诊断
2. 沉默会员唤醒
3. 复购机会识别
4. 导购任务生成
5. 导购话术生成

形成闭环：

```text
发现问题
  → 识别机会会员
  → 生成导购任务
  → 生成话术
  → 导购执行
  → 结果回写
```

### 第一阶段交付物

- 一张能力地图
- 一个沉默会员唤醒样板
- 一套 MCP / Skill 输入输出定义
- 一个导购任务工作流 Demo
- 一份结果回写字段表

---

## 第二阶段：扩展到品牌经营诊断

目标：从导购个人动作，升级到品牌/门店经营视角。

加入 3 个：

6. 活动效果诊断  
7. 门店经营诊断  
8. 客户分层策略  

形成闭环：

```text
品牌经营诊断
  → 找到门店/会员/活动问题
  → 生成运营策略
  → 下发导购/店长任务
  → 复盘结果
```

### 第二阶段交付物

- 品牌经营诊断模型
- 门店经营健康度指标
- 活动效果归因模板
- 客户分层统一口径
- 店长 / 品牌运营看板 Demo

---

## 第三阶段：形成能力商品化

目标：从内部能力变成可售卖、可开放、可运营的 Agent 能力包。

加入 2 个：

9. 权益推荐策略  
10. 经营复盘生成  

形成产品包：

```text
品牌经营 Agent 能力包
导购增长 Agent 能力包
活动诊断 Agent 能力包
会员复购 Agent 能力包
```

### 第三阶段交付物

- 能力目录
- 调用权限体系
- 计费/套餐包装
- 客户试点方案
- 运营看板
- 效果评估报告

---

# 四、明天可以直接推进的会议方案

## 会议名称

**EZR Agent 能力层第一批 MCP 能力定义会**

## 会议目标

不是讨论“要不要做 Agent”，而是确定：

# 六、风险提醒

## 1. 不要做成“AI 查询助手”

如果只是让 Agent 查会员数据、查销售数据，价值不够。  
真正有价值的是：

```text
查数据 → 做诊断 → 给策略 → 派任务 → 回写结果
```

## 2. 不要让 MCP 变成裸接口

MCP 要封装业务语义，而不是暴露一堆底层 API。

错误方向：

```text
getMemberList()
getOrderList()
getCouponList()
```

正确方向：

```text
diagnoseMemberOperation()
recommendSilentMemberWakeup()
generateGuideTasks()
reviewCampaignPerformance()
```

## 3. 不要绕过权限体系

Agent 调用能力时，必须继承 SaaS 原有权限：

- 品牌权限
- 门店权限
- 导购归属权限
- 会员数据权限
- 导出权限
- 操作权限
- 审计日志

## 4. 不要只做输出，不做回写

没有回写，就没有复利。  
每个能力都要问：

> Agent 执行后，结果回到哪里？下次推荐会不会变得更准？

# 七、建议明天拍板的 3 件事

## 1. 定义方向

**EZR 不做通用 Agent 平台，先做品牌经营 Agent 能力供给方。**

## 2. 定义样板

**第一个样板场景：沉默会员唤醒。**

因为它天然覆盖：

```text
会员诊断 → 人群识别 → 导购任务 → 话术 → 触达 → 回写
```


# 八、最终对外 / 对内表达口径

你可以这么讲：

> 我们判断未来 Agent 的入口会被大平台掌握，但品牌经营能力不会天然存在。EZR 的机会不是再做一个 AI 入口，而是把 CRM 数据、会员经营经验、导购动作、活动诊断和结果回流，封装成 Agent 可以调用的能力。第一阶段我们先围绕沉默会员唤醒，把诊断、任务、话术、触达、回写这条链路跑通，形成 EZR 的第一批 MCP / Skill 能力资产。
