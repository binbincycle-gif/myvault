## A. 今日结论（3条）

1. **海外主线从“模型发布”转向“企业级 Agent 部署控制”。** OpenAI 今日重点不是单纯发新模型，而是 Codex 被 Gartner 评为企业 AI Coding Agent Leader，并与 Dell 推进混合云/本地化部署；Google 则把 Gemini 3.5、Antigravity 2.0、Gemini for Home、AI Edge Gallery/MCP 串成“端云协同 + Agent 工作流”路线。
2. **国内主线是“性价比 + 长上下文 + API 兼容 + 私域可控”。** DeepSeek V4 系列给出 1M 上下文、工具调用、OpenAI/Anthropic 兼容 API 与极低价格；Kimi K2.6 明确 256k、多模态、Agent/长程代码、上下文缓存与即将下线旧 K2；火山方舟、百度千帆、智谱继续强化企业模型服务与 Agent 平台。
3. **安全合规成为企业落地的前置门槛。** OpenAI 推 C2PA + Google SynthID + 公共验证工具；Anthropic、阿里 Qwen、智谱、百度等均在安全/内容治理/平台审计方向补能力。对 ToB SaaS/CRM 来说，模型能力不是唯一瓶颈，**权限审计、私域数据不外流、模型路由成本可控**会决定能否规模化上线。

## C. 对中国 ToB SaaS / CRM 的影响判断

### 增长
- **AI 导购与营销内容生成进入可商用窗口**：多模态、长上下文、工具调用成熟后，可围绕“会员画像 → 商品/活动推荐 → 导购话术 → 海报/短视频 → 跟进任务”做闭环。
- **企业客户会更愿意采购“可控 Agent”，而不是单点 AI 功能**：OpenAI/Dell 的方向证明，客户真正关心的是能否接入私域数据、被审计、可回滚、可控权限。
- **CRM 的差异化机会在业务上下文，不在模型本身**：EZR 的会员、交易、导购、营销、门店动作数据，是大模型输出可执行建议的关键护城河。

### 效率
- **研发效率**：Codex/Claude/Kimi/DeepSeek 可分层用于代码审查、测试生成、改动影响分析、需求到测试用例。
- **运营效率**：DeepSeek V4 / Kimi K2.6 适合长文档总结、工单归因、客户成功材料生成、活动复盘。
- **客服/导购效率**：低成本模型承接常规问答，高阶模型处理复杂投诉、会员经营建议和跨系统任务编排。

### 风险
- **数据合规**：会员数据、订单数据、营销效果数据不可直接外发给海外模型；需脱敏、授权和地域路由。
- **模型路由成本**：长上下文和工具调用会隐藏成本，必须按场景设置模型、上下文、缓存、最大输出、调用预算。
- **私域数据外流**：Agent 接入知识库、CRM、BI、工单系统后，权限模型要继承业务系统权限，不能只用一个“超级 API Key”。
- **权限审计**：Agent 执行修改类动作（发券、改会员标签、发消息、改订单）必须有审批、日志、回滚和异常告警。

## D. 今日可执行动作（3条）

1. **建立 EZR 多模型路由小表（本周可完成）**：
   - 低成本长上下文：DeepSeek V4 Flash/Pro
   - 中文复杂文档/前端/Agent：Kimi K2.6
   - 高价值推理/代码审查：Claude Opus/Sonnet 或 OpenAI GPT-5.5/Codex

   - 所有 Agent 工具按 read/write/external-send/destructive 四类分级。
   - write/external-send 必须 human approval。
   - 所有工具调用保留：用户、时间、模型、输入摘要、工具名、参数摘要、结果、回滚方式。

3. **选一个 CRM 场景做端到端 PoC**：
   - 推荐场景：导购任务助手（会员画像摘要 + 推荐话术 + 后续跟进任务）。

   - 验收指标：导购采纳率、单条建议成本、生成时延、误触发率、审计完整率。
