## A. 今日结论（3条）

1. **海外头部模型进入“Agent 性能/成本/安全”三线竞争。** OpenAI GPT-5.6 强调多 Agent 并行、Programmatic Tool Calling 与编码/长程任务效率；Anthropic Sonnet 5 把接近 Opus 的 Agent 能力下放到更低价模型；Google Gemini 3 API 则把思考控制、多模态 token 控制、Thought Signatures、Grounding 结构化输出做成工程接口。
2. **国内主线是“低成本多模态 + Agent 长链路 + 本土安全护栏”。** 豆包 2.0 系列强化视频/空间/运动理解、复杂指令与 Agent 工作流；Qwen 博客继续突出 Qwen3Guard、Qwen-Image-Edit、Qwen-MT 等工具层能力；DeepSeek 官网首页未披露新增发布，第三方 DeepSeek-V4 软文未入库。
3. **ToB SaaS/CRM 的关键不再是选一个最强模型，而是搭建“模型路由 + 工具权限 + 成本看板 + 审计护栏”。** 低价长上下文模型适合批量知识处理；高阶海外模型适合复杂推理/代码/多 Agent；所有触达客户、发券、改权益、导出数据的动作必须先纳入权限与审计。

- 建议动作：内部 PoC 不直接上生产写动作，先用 GPT-5.6 类模型跑“复杂需求分析/技术方案复核/CRM 活动复盘”。

## D. 对中国 ToB SaaS / CRM 的影响判断

### 1. 增长机会

- **经营动作 Agent 化：** 将“会员分群 → 策略建议 → 话术生成 → 导购任务 → 效果复盘”变成可控 Agent 流程，是 CRM 从工具升级为经营能力的关键。
- **多模态服饰场景可变现：** 豆包 2.0 的视频/空间/运动理解、Qwen-Image-Edit 的图文编辑，适合门店巡检、陈列评估、导购培训、商品素材生产。
- **低成本工具层扩大 AI 覆盖面：** Qwen-MT、豆包 Lite/Mini/Code 等让翻译、文案、代码、资料整理可以规模化嵌入日常流程。

### 2. 效率机会

- **研发效率：** Sonnet 5 / GPT-5.6 适合复杂代码改造和验证；豆包 Code、国内低价模型适合批量代码理解、测试用例、前端页面生成。
- **运营效率：** Gemini/GPT/豆包可用于活动复盘、会员洞察、竞品资料整理；Qwen 工具层负责图文和翻译。
- **交付效率：** 会议纪要、需求文档、配置清单、验收标准可自动整理为任务与风险清单。

### 3. 风险判断

- **数据合规：** 会员、订单、导购、企业微信聊天、私域标签属于高敏业务数据；跨境模型必须脱敏或禁用敏感字段。
- **模型路由成本：** 多 Agent/ultra/高分辨率多模态会快速放大成本；需要按任务设预算阈值。
- **私域数据外流：** Agent 连接 CRM、企微、订单、优惠券系统后，提示注入可能诱导越权读取或外发。
- **权限审计：** 发券、改积分、改标签、群发、导出客户数据必须留痕、可回滚、可追责。

### 对 EZR 的影响（明确落地部分）

1. **先做 CRM Agent 权限模型，再接强模型。** 按导购/店长/运营/总部/客服角色定义可读数据、可执行动作、审批层级。
2. **建立模型路由底座。** 国内模型处理长文本、批量、低风险；海外高阶模型处理复杂推理、代码、方案复核；Qwen3Guard/内容安全做前后置护栏。
3. **优先试点三个增长场景：** AI 导购任务建议、会员流失挽回、活动复盘与二次触达建议；指标看触达率、转化率、复购率、人工节省时间。
