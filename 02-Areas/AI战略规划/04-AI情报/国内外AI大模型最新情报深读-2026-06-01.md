## A. 今日结论（3条）

1. **近24小时没有看到 OpenAI / Anthropic / Google DeepMind / Meta / xAI / Mistral / 国内头部厂商的全新旗舰模型发布；但企业 Agent、安全治理、价格/缓存策略发生实质变化。** 重点不是“又发了一个模型”，而是模型平台开始把身份、缓存、私网连接、工具权限、AWS/云平台部署做成企业级能力。
2. **海外主线：Agent 平台化 + 私有系统连接 + 合规前置。** OpenAI 的 24h prompt cache retention、workload identity federation、Secure MCP Tunnel；Anthropic 的 Claude Platform on AWS、Managed Agents；Google 的 Gemini 3.5 / Antigravity；Mistral Vibe 都指向同一个方向：Agent 要进入企业内部系统，必须先解决身份、沙箱、审计、数据边界。
3. **国内主线：低成本长上下文 + OpenAI/Anthropic 兼容 + 平台聚合。** DeepSeek V4 Pro 75% 折扣窗口在 2026-05-31 15:59 UTC 结束并转为 1/4 常规定价；Kimi K2.6、Qwen3.7/Qwen3.6、GLM-5.1 继续围绕长上下文、工具调用、Agentic Coding 和中文多模态形成可选矩阵。对 ToB SaaS/CRM 来说，下一步要做模型路由与工具网关，而不是单模型押注。

## B. 重点情报（10条，含来源链接与时间）

### 1. 【国外】OpenAI：prompt_cache_retention 默认 24h，降低长上下文/重复 Agent 任务成本

- **厂商 / 模型 / 产品**：OpenAI API / Responses、Chat Completions、Batch / prompt caching
- **发布时间**：2026-05-29
- **证据链接**：https://developers.openai.com/api/docs/changelog
- **能力变化**：对未开启 ZDR 的组织，`prompt_cache_retention` 默认从 `in_memory` 调整为 24h，延长提示词缓存保留时间。
- **上下文 / 工具 / 多模态 / Agent / 价格 / 部署方式**：与 GPT-5.5 1M 上下文、Responses API、工具调用/Computer Use/Hosted Shell/MCP 等能力组合后，长程 Agent 的重复上下文成本和延迟可下降；但 ZDR 组织不适用该默认策略。
- **企业部署影响**：企业做长程 Agent、知识库问答、代码库分析时，缓存命中会成为成本治理核心指标。
- **对 ToB SaaS / CRM / EZR 的机会**：CRM Agent 可把组织级制度、品牌知识、会员经营规则做稳定前缀，提高缓存命中；活动复盘、客户经营周报、工单归因可复用上下文。
- **风险**：缓存保留与数据治理存在张力；涉及会员/交易/企微聊天等高敏数据时，要确认缓存、保留、删除、ZDR 条款。
- **建议动作**：模型路由矩阵增加字段：缓存命中价、缓存保留策略、是否支持 ZDR/数据不保留。

### 2. 【国外】OpenAI：企业身份与私网 MCP 连接持续增强，Agent 进入内网系统门槛降低

- **厂商 / 模型 / 产品**：OpenAI / Workload Identity Federation、Admin API、Secure MCP Tunnel
- **发布时间**：2026-05-26（身份与 Admin API），2026-05-19（Secure MCP Tunnel）
- **证据链接**：https://developers.openai.com/api/docs/changelog
- **能力变化**：可信工作负载可用外部身份令牌换取短期 OpenAI access token，减少长期 API Key；Admin API 增加 spend alerts、model allowlists、data retention、hosted tool permissions、billing line items；Secure MCP Tunnel 让 ChatGPT、Codex、Responses API、AgentKit 连接客户私有或本地 MCP Server。
- **企业部署影响**：模型平台正在补齐企业 IAM、预算、权限、私有工具连接能力，Agent 可以更安全地触达内网系统。
- **对 ToB SaaS / CRM / EZR 的机会**：EZR 若做 CRM Agent，应该把会员、商品、订单、营销、工单能力封装为“受控工具/MCP”，通过身份、租户、权限、审计统一管理。
- **风险**：私网连接能力增强后，越权调用和数据外流风险同步上升；MCP Server 必须有租户隔离、字段脱敏、审批、操作回滚。
- **建议动作**：启动“CRM Agent 工具网关”设计：只读工具先行，写操作默认审批。

### 3. 【国外】Anthropic：Claude Platform on AWS 获得 Managed Agents、多 Agent 编排、自托管沙箱

- **厂商 / 模型 / 产品**：Anthropic / Claude Platform on AWS / Claude Managed Agents
- **发布时间**：2026-05-29
- **证据链接**：https://platform.claude.com/docs/en/release-notes/overview
- **能力变化**：Claude Managed Agents 的 webhooks、multiagent orchestration、self-hosted sandboxes 已在 Claude Platform on AWS 可用，并提供新的 IAM actions 与托管策略。
- **上下文 / 工具 / 多模态 / Agent / 价格 / 部署方式**：Claude 当前模型均支持文本和图像输入；NextOpus/Opus 4.7/Sonnet 4.6 进入 1M 上下文体系；AWS 路径强化企业 IAM、云账单、区域和沙箱治理。
- **企业部署影响**：Claude 不只是模型 API，而是变成“企业云上的 Agent 执行平台”。大客户会更容易接受云账号/IAM 下的模型调用，而非散落 API Key。
- **对 ToB SaaS / CRM / EZR 的机会**：可以参考其 IAM + sandbox + webhook 模式，为内部 AI Coding 与业务 Agent 设计“任务状态、回调、审批、沙箱执行”机制。
- **风险**：云平台集成会带来供应商锁定；跨境数据、区域路由、日志留存要逐项核对。
- **建议动作**：AI Coding 试点记录“模型 + 工具权限 + 沙箱 + 回调 + 成本 + 人工修正率”，沉淀内部 Agent 评估口径。

## D. 对中国 ToB SaaS / CRM / EZR 的影响判断（增长 / 效率 / 风险）

### 增长

- **AI CRM 的产品机会不是“聊天助手”，而是“可控 Agent 工作流”。** 海外平台都在向 Managed Agents、Workflows、Connectors、MCP、远程沙箱演进；EZR 应把会员经营、活动复盘、导购任务、客户成功周报做成流程型能力。
- **差异化来自行业上下文。** 服饰零售的会员、商品、门店、导购、企微、交易链路是 EZR 的优势；模型只是执行引擎，关键是把行业经验变成工具、规则、评测集。

### 效率

- **模型路由可以直接降本。** 高频文本用 DeepSeek/Qwen Flash 类低成本模型；多模态/长文档用 Kimi/Qwen Omni；复杂推理/架构/代码评审用 Claude/OpenAI；公开情报可尝试 xAI/Gemini/Mistral。
- **研发提效要从“让 AI 写代码”升级为“Agentic Coding 闭环”。** 需求拆解、改动点识别、测试生成、PR 审核、风险提示、上线复盘都要纳入 eval harness。

### 风险

- **数据合规**：会员画像、交易记录、导购聊天、企微内容均属高敏私域数据；必须做租户隔离、字段脱敏、用途限制、日志留痕、可删除。
- **模型路由成本**：1M 上下文和多模态会让 token 成本失控；必须记录模型、输入/输出 token、缓存命中、工具调用、失败重试成本。
- **私域数据外流**：Agent 连上 CRM/企微/订单系统后，越权读写风险高于模型回答错误。
- **权限审计**：读操作要按角色限制字段；写操作必须审批、回滚、告警。
