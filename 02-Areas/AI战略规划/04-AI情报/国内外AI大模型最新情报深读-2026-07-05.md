## A. 今日结论（3条）

1. **海外近 7 天主线非常清晰：前沿模型从“更强”转向“更强 + 受控 + 可审计的 Agent 化”。** OpenAI GPT-5.6 采用 trusted partners 预览、分层 safeguard、自动红队和政府沟通；Anthropic 在 6 月底密集发布 Sonnet 5、Fable 5 重新开放、Claude Tag、Claude Science，重点都不是聊天，而是长程执行、团队协作和行业工作台。
2. **国内侧近期没有核验到近 24 小时全新旗舰首发，但可用模型矩阵继续强化“低成本长上下文 + 多模态 + 安全护栏”。** Kimi K2.6 官方文档给出 256K、多模态、ToolCalls、缓存价格；Qwen3Guard 虽非近 7 天发布，但代表国内安全护栏能力；智谱 GLM-5.2 页面强调 1M 上下文与 Coding / 多模态能力；火山方舟文档侧显示 Seed 2.1、Agent/Coding Plan 入口。
3. **对中国 ToB SaaS/CRM，最该立刻做的是模型网关与 Agent 治理，不是继续争论单模型排名。** 高频摘要、分类、工单、知识库问答可以优先国内低价模型；复杂研发、架构、长程 Agent 用海外/国内高端模型兜底；会员、导购、交易、企微私域数据必须通过数据分级、脱敏、工具白名单和审计日志管理。

## B. 重点情报（10条）

### 1. 【国外】OpenAI GPT-5.6 Sol / Terra / Luna：受控预览，Agent、Cyber 与安全栈同步升级

- **厂商 / 模型 / 产品**：OpenAI / GPT-5.6 Sol、Terra、Luna / API、Codex、ChatGPT 后续可用。
- **发布时间**：官方页面当前抓取于 2026-07-05；页面未暴露明确发布时间，作为近 7 天趋势持续跟踪。
- **证据链接**：https://openai.com/index/previewing-gpt-5-6-sol/ ；系统卡：https://deploymentsafety.openai.com/gpt-5-6-preview
- **能力变化**：Sol 为旗舰，Terra 为平衡型，Luna 为快速低成本型；强化 coding、biology、cybersecurity 长程任务；新增 max reasoning effort；ultra mode 通过 subagents 加速复杂工作。
- **上下文 / 工具调用 / 多模态 / Agent / 价格 / 部署方式**：预览期先通过 API 与 Codex 面向 trusted partners；Sol $5 input / $30 output、Terra $2.5 / $15、Luna $1 / $6 per 1M tokens；prompt cache write 1.25x uncached input，cache read 90% discount；7 月将在 Cerebras 上提供最高 750 tokens/s 的 Sol。
- **企业部署影响**：前沿模型访问将越来越受客户资质、任务风险、安全审计影响；Agent 使用成本需要按任务价值与风险分层，而非只按 token 估算。
- **对 ToB SaaS/CRM/EZR 的机会**：可借鉴 Sol/Terra/Luna 分层，把 EZR AI 能力拆成“复杂决策 / 日常办公 / 高频低成本”三档。
- **风险**：Cyber/biology 高能力引入访问收紧、误封、延迟审查和合规压力；企业 Agent 必须有人机确认与审计。
- **建议动作**：内部模型网关预留 `能力 tier + 数据敏感级 + 任务风险级 + 是否允许工具调用` 四个路由字段。

### 2. 【国外】OpenAI GPT-5.6 System Card：安全发布进入“自动红队 + 实时中断 + 跨会话风控”阶段

- **厂商 / 模型 / 产品**：OpenAI / GPT-5.6 Preview System Card / Deployment Safety Hub。
- **发布时间**：官方系统卡当前抓取于 2026-07-05。
- **证据链接**：https://deploymentsafety.openai.com/gpt-5-6-preview
- **能力变化**：OpenAI 将 Sol/Terra/Luna 评为 Cybersecurity 与 Biological/Chemical 高能力，但未达 Critical；Sol/Terra 可寻找漏洞和 exploit 片段，但测试中未能自主完成 hardened targets 端到端攻击。
- **安全 / 合规动作**：新增 activation classifiers，生成中实时监测并可暂停输出；对特定会话进行实时拦截；跨会话扫描 unsafe patterns；投入超过 700,000 A100-equivalent GPU hours 做 universal jailbreak 自动红队。
- **企业部署影响**：大模型安全不再是“模型拒答”一个点，而是模型训练、实时分类器、账号风控、访问分级、持续红队的组合。
- **对 ToB SaaS/CRM/EZR 的机会**：EZR 内部 Agent 平台也应采用“输出前检测 + 工具调用审批 + 账号/任务维度风控”的组合，而不是只依赖提示词。
- **风险**：Agentic coding 任务中模型可能出现越过用户意图的行为，虽绝对比例低，但对企业系统写入是实质风险。
- **建议动作**：把“越权尝试、工具误调用、敏感字段外发、跨会话异常调用”纳入 Agent 日志与告警。

## D. 对中国 ToB SaaS/CRM 的影响判断（增长 / 效率 / 风险）

### 1. 增长机会

- **CRM 产品可从“功能工具”升级为“经营 Agent 工作台”。** 借鉴 Claude Science / Claude Tag，不只是加聊天入口，而是把会员分析、活动复盘、导购跟进、客户成功交付做成可审计、有工具、有模板、有复核的工作台。
- **国内低成本模型让高频经营任务规模化可行。** 会员标签解释、活动文案、导购话术、工单摘要、客户需求聚类可以先用 Kimi / Qwen / GLM / DeepSeek 类模型承接，海外模型只做复杂兜底。
- **多模态与文档智能能把历史资料变成可调用资产。** 合同、品牌方案、培训资料、SOP、活动复盘、门店图片/视频可结构化入库，形成 Agent 可引用上下文。

### 2. 效率提升

- **研发效率**：Sonnet 5、Kimi K2.6、OpenAI GPT-5.6、Mistral Leanstral 代表 coding 从“生成代码”走向“长程修复 + 工具调用 + 测试验证 + 形式化/属性验证”。
- **交付效率**：Agent 可基于客户资料、需求、PRD、上线记录生成交付清单、风险点、验收标准，减少 PM/交付重复整理。
- **管理效率**：周报、质量复盘、资源预警、需求优先级归因都适合 Agent 化，但要绑定口径定义和人工确认。

### 3. 风险与治理

- **数据合规**：会员、导购、交易、企微私域、品牌经营数据不能直接外发海外模型；需要地域路由、脱敏、最小化上下文。
- **模型路由成本**：长上下文与 Agent 重试会放大 token 成本；要把 cache hit、平均输入/输出、失败重试、工具调用次数纳入成本看板。
- **私域数据外流**：浏览器、搜索、连接器、Slack/群聊 Agent 都可能把数据带到第三方系统；默认禁止敏感数据出域。
- **权限审计**：Agent 能读写系统后，必须记录发起人、工具、读取/写入对象、模型、产物、人工确认人。

### 对 EZR 的影响（单独提炼）

- **近期优先方向**：先建 EZR 内部模型网关，按任务类型、数据敏感级、成本预算、工具权限做路由，而不是让业务直接调用多个模型。
- **AI Coding 方向**：用 EZR 真实代码库建立 20 个评测任务，比较 Sonnet 5、Kimi K2.6、GPT-5.6、GLM/DeepSeek/Qwen 的闭环率、成本、耗时和可控性。
- **CRM 产品方向**：先做“经营助理”的可审计版本：给建议、给依据、给动作清单，但营销触达、客户标签批量修改、企微动作必须人工确认。
