## A. 今日结论（3条）

1. **海外主线从“模型能力”转向“企业级治理 + Agent 基建”。** OpenAI 在 7 月 29 日发布 Terraform Provider，把项目、用户、角色、服务账号、证书、项目级限流纳入 IaC；Anthropic 在 7 月 24 日发布 Claude Opus 5，并继续强化 Managed Agents、Webhook、Memory Store、Tool 变更等企业 Agent 生命周期能力。对 ToB SaaS 来说，下一阶段竞争点不是“接一个模型”，而是“模型权限、成本、审计、Agent 编排是否产品化”。

2. **1M 上下文、长程任务、工具调用正在成为头部模型标配，但国内更强调成本与 OpenAI/Anthropic 兼容。** Anthropic Claude Opus 5、Kimi K3、智谱 GLM-5.2、豆包 Seed-Evolving 等都在 1M 上下文/长程任务上加速；阿里百炼、Kimi、DeepSeek 等普遍强化 OpenAI-compatible / Anthropic-compatible 接入。对企业落地最有价值的是：用低成本国内模型承接“长文档/代码仓/知识库处理”，海外模型用于高复杂推理与关键 Agent 决策。

3. **安全风险开始从“内容安全”升级为“Agent 执行安全”。** Hugging Face 7 月披露了 Frontier Lab Agent Intrusion 技术时间线与安全事件；Google ADK 2.0 明确强调确定性 Workflow 与 Agent 混合；Mistral、OpenAI、Anthropic、xAI 均在不同方向增加成本、权限、审计、语音/文件/上下文治理能力。EZR 如果做 CRM Agent，必须先建立“权限边界、数据出域、工具调用审计、成本上限、人工兜底”五件套。

## C. 对中国 ToB SaaS / CRM 的影响判断

### 1. 增长：AI 能力应从“卖功能”变成“卖经营结果”

- **机会**：长上下文 + Grounding + Agent 可把 CRM 从“客户资料/营销工具”升级为“客户经营助手”：自动读客户历史、识别机会、生成跟进策略、补全公开资料、形成复购/续费建议。
- **可包装产品**：
  - 客户经营诊断 Agent
  - 导购话术/回访总结 Agent
  - 会员分层与营销活动生成 Agent
  - 竞品/行业情报 Grounding Agent
- **管理判断**：优先选择能帮助客户提升增长、续费、客单价的场景，而不是只做内部提效 Demo。

### 2. 效率：AI Coding 与长文档处理会先产生内部 ROI

- **机会**：Claude Opus 5、Kimi K3、GLM-5.2、豆包/DeepSeek 等都适合做需求理解、代码仓分析、测试用例生成、历史工单复盘。
- **落地路径**：
  - 研发：需求 → 改动点 → 测试用例 → 回归范围建议
  - 产品：客户原始需求 → PRD 初稿 → 版本影响分析
  - 交付：项目文档/会议纪要 → 风险清单 → 待办拆解
- **管理判断**：内部效率提升应以“减少返工、减少漏测、缩短需求澄清周期”为核心指标，而非只统计调用次数。

### 3. 风险：CRM Agent 最大风险不是回答错，而是“越权执行 + 私域数据外流”

- **高风险点**：
  - 私域会员数据、交易数据、导购聊天记录进入外部模型；
  - Agent 直接调用营销、发券、群发、客户标签修改等工具；
  - 长上下文混入不同客户数据，产生上下文污染；
  - 多模型路由下成本不可控、审计链断裂。
- **底线要求**：
  - 数据分级：公开数据、企业内部数据、客户敏感数据、个人信息分层；
  - 工具分级：只读、建议、需审批写入、禁止自动执行；
  - 审计闭环：每一次模型输入、工具调用、权限、成本、结果留痕。
