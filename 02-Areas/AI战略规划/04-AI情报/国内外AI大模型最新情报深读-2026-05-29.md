## A. 今日结论（管理层版）

1. **海外主线从“模型参数竞争”转为“Agent 生产系统竞争”。** OpenAI、Mistral、Google、Anthropic 的最新信号都指向：长上下文 + 工具调用 + 企业连接器 + 人工审批 + 可观测/评测闭环，正在成为企业级 Agent 的标配。
2. **国内模型侧重点更偏“低成本长上下文 + 多模态 + 本地/私域可控接入”。** DeepSeek V4、Kimi K2.6、Qwen/百炼、GLM-5.1、豆包/火山方舟的公开文档显示：国内厂商在 200K-1M 上下文、缓存定价、工具调用、MCP/Agent 能力上快速补齐，对 ToB SaaS 做“模型路由 + 成本分层”很有价值。
3. **安全合规从“附加项”变成采购前置条件。** OpenAI 发布 Frontier Governance Framework，Anthropic 文档强调云平台区域/全球端点差异，国内平台持续更新价格与模型清单。对 CRM 场景，权限审计、客户私域数据隔离、模型调用留痕、跨境/跨云路由成本将直接影响能否规模化落地。

## D. 对中国 ToB SaaS / CRM 的影响判断

### 1. 增长影响

- **AI 能力会从“产品卖点”变成“成交门槛”。** 大客户会问：能不能接企业微信/CRM/订单/会员？能不能按权限执行？能不能私有化？能不能审计？
- **CRM 的新增长点是“经营动作 Agent 化”。** 不是再卖一个 AI 问答，而是卖“会员分群 → 导购任务 → 内容生成 → 触达 → 复盘”的闭环。
- **多模态会打开商品与导购场景。** 商品图、短视频、门店陈列、聊天截图能被模型理解后，CRM 可以做素材合规、导购话术、会员偏好提炼。

### 2. 效率影响

- **研发效率：Agentic Coding 已进入企业生产形态。** OpenAI Tax AI、Mistral Vibe、GLM-5.1 都在指向长程编码与生产闭环，可推动内部研发从“AI 辅助写代码”升级到“任务级 Agent + eval + PR 审核”。
- **运营效率：长上下文 + 缓存定价适合 CRM 批处理。** DeepSeek / Kimi / Gemini Flash 等适合做客户摘要、标签解释、导购任务草稿、复盘报告。
- **知识库效率：连接器 / MCP 会成为企业 AI 中台基础设施。** CRM 能力应逐步工具化，避免每个 Agent 重复接 API。

### 3. 风险影响

- **数据合规风险**：客户私域数据、会员画像、交易记录不能默认外发到境外/不可控模型；要有模型路由白名单。
- **模型路由成本风险**：多模型接入后，Search、File Search、Code Interpreter、Grounding、缓存存储都可能单独计费，需按业务场景测算毛利。
- **私域数据外流风险**：联网搜索、第三方 MCP、连接器若默认开放，容易把客户上下文带出域。
- **权限审计风险**：Agent 一旦能创建营销任务、发送消息、改会员标签，就必须有操作级审批、回滚、日志、责任人。

## E. 今日可执行动作（3条）

1. **建立“CRM AI 模型路由矩阵 v0.1”。**
   - 任务分层：高价值复杂推理 / 高频文本生成 / 长上下文摘要 / 多模态理解 / Coding Agent。
   - 每层指定候选模型：OpenAI/Claude/Gemini/Mistral + DeepSeek/Kimi/Qwen/GLM/豆包。
   - 输出字段：成本、上下文、工具调用、部署方式、数据合规等级、失败回退模型。

2. **把 EZR CRM 核心能力做 MCP / Tool 清单。**
   - 第一批：会员查询、标签洞察、营销活动草稿、导购任务生成、订单摘要、知识库检索。
   - 每个工具必须标注：读/写权限、敏感等级、是否需要人工确认、审计字段、回滚方式。

3. **启动一个“生产 trace + eval”小闭环 POC。**
   - 推荐场景：导购话术生成或会员分群解释。
   - 每次 Agent 输出记录：输入上下文、调用工具、模型、成本、人工修改、最终采用结果。
   - 每周沉淀 20-50 条失败样本，形成 eval，用于 prompt / 工具 / 模型路由迭代。
