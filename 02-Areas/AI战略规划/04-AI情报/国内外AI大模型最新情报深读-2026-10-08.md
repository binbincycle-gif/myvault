## C. 对中国 ToB SaaS / CRM 的影响判断

### 增长机会
- **Agent 化功能的定价空间被打开。** Haiku 5.5（$0.10/M 输入）与 GPT-6 Luna（$0.10/M 输入）把高频小任务成本压到"几乎可忽略"，此前因成本不敢做的功能（全量会话质检、每条线索 AI 评分、导购实时话术、订单异常自动核查）现在具备规模化商业化的条件。
- **"混合智能"给私有化叙事加了新弹药。** 桌面级万亿参数设备 + OS 级本地/云分级调度，让"敏感数据不出内网"从卖点变成可落地的架构默认值，对金融、医药、国企类客户的 AI 采购具备直接说服力。
- **国产模型出海通道成型。** GLM-5.3 与 Kimi K3 通过 AWS Bedrock 分成接入，为中国 SaaS 出海提供了"合规可解释、数据不搬迁"的模型底座选择。

### 效率提升
- **大小模型分层路由可立刻做。** 把会话摘要/意图分类/字段抽取下沉到 Haiku 5.5 或 GPT-6 Luna，复杂推理与 Agent 编排留给旗舰（GPT-6 Sol / Opus 5.5 级）。按官方口径，缓存命中成本可低至未命中的 5%–10%，配合 prompt caching 收益显著。
- **Agent 执行链的权限设计有了行业范本。** Anthropic CVP"实名 + 留存 + 审计"、微软 Windows Agent 的权限边界，可直接映射为 CRM Agent 的权限模型（谁授权、能碰哪些字段、操作留痕），避免像 Meta Muse 那样被平台以"身份不可识别"为由风控拦截。

### 风险
- **数据合规**：国内《标识办法》+《拟人化互动服务管理暂行办法》+网信办备案，与 EU AI Act 第 50 条透明度义务同时生效。CRM 中的 AI 生成本身就是"对外内容"，标识与备案需前置；面向 EU 客户时文本水印策略必须显式设计。
- **模型路由成本失控**：多模型并存下，若缺少统一的用量/路由/缓存治理，"降价 50%"可能被无序调用吃掉。必须建立模型级成本看板与调用配额，锁精确 model id（本次已出现"同名系列多版本并存"）。
- **私域数据外流**：本地/云分级看似解决了问题，但端侧 Agent 获得系统级文件访问权后，**权限边界与审计日志才是真正的防线**；一旦缺审计，"本地处理"反而扩大了数据可见面。
- **平台依赖与可达性**：旗舰模型"先安全圈、后大众"的顺序正在固化（Gemini 4 Argon allowlist、OpenAI Astra 搁置）；单一模型绑定等于把业务连续性押在他人发布节奏上。

### 对 EZR 的具体影响（仅落地点）
1. **成本结构可重估**：把 CRM 内高频 AI 调用（会话摘要、线索打分、工单分类、导购助手）按"小模型优先"重构，预期单位成本下降一个数量级，可作为下一轮 AI 功能定价的输入。
2. **集成层是护城河，不是界面**：Workday 的案例说明"客户绕过原生界面直接取数"正在发生。EZR 的应对不是收紧界面，而是**做厚"可被外部 Agent 安全调用"的能力层**（MCP/A2A 兼容 + 数据语义层 + 身份与权限 + 可审计执行链）。
3. **行业规则结构化 = 议价资产**：与模型厂商共建"什么叫成功完成任务"的行业规则（审批链、报价规则、会员权益、退换货政策），是 EZR 相对通用模型厂商的稀缺资产，应纳入指标库/知识库建设范围。
4. **合规前置**：面向有出海或强合规需求的服饰零售品牌客户，把"内容标识 + 备案 + 留存审计"做成产品内建能力，而非交付期补丁。
