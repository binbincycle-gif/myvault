## A. 今日结论（3条）

1. **近24小时未确认“足以改变格局”的头部基础模型新发布，主线仍是海外 Agent 平台化、国内长上下文与低成本兼容 API 的快速补齐。** OpenAI、Anthropic、Mistral、xAI 的重点已经不是单个模型参数，而是把模型、工具、权限、数据驻留、审计、开发者工作流打包成企业可采购的系统。

2. **国内模型的可用性正在进入企业试点区间：DeepSeek V4、Kimi K3、Qwen3.8-Max、智谱、百度千帆、腾讯混元都在围绕 1M 上下文、OpenAI/Anthropic 兼容、工具调用、Agent 平台与多模态补能力。** 中国 ToB SaaS 不能再停留在“等海外模型成熟”，应同步建设模型路由、数据分级、国内模型压测与客户私有化交付方案。

3. **安全与成本会成为 AI CRM 落地的第一约束。** 长上下文、工具调用、MCP、浏览器/终端执行、实时搜索会显著放大数据外流、越权操作、提示注入和 token 成本失控；CRM 场景必须先做“只读 Agent + 审计 + 人审确认”，再逐步开放写操作。

## 国外 vs 国内对照：API / 价格 / 上下文 / 多模态 / Agent

| 维度 | 国外头部 | 国内头部 | 管理判断 |
|---|---|---|---|
| API 兼容 | OpenAI / Anthropic 成为事实标准；Mistral、xAI、Google 各有生态 | DeepSeek、阿里百炼、Kimi、MiniMax、智谱等强化 OpenAI/Anthropic 兼容 | Model Gateway 必须优先兼容 OpenAI/Anthropic 协议，再做厂商差异适配 |
| 价格 | OpenAI / Claude 高能力高价格，长上下文、数据驻留、工具调用会显著加价；Mistral/xAI中档 | DeepSeek、Kimi 等中文场景成本优势明显，但 DeepSeek 已提示涨价；云厂商价格需动态复核 | 不看单 token 价格，要看“单任务成功成本 = token + 工具 + 人审 + 失败重试” |

## C. 对中国 ToB SaaS / CRM 的影响判断（增长 / 效率 / 风险）

### 1. 增长判断

- **从“AI 功能”转向“Agent 可调用的经营能力”。** CRM 的竞争点不是内置聊天框，而是把会员分群、导购任务、优惠券、企微触达、活动复盘、门店巡检、指标分析封装成可授权、可审计、可组合的 Tool。
- **客户更愿意为“结果闭环”付费。** 活动复盘 Agent、导购任务 Agent、会员流失预警 Agent、素材生成与审核 Agent，比单纯知识库问答更容易形成增购点。
- **国内模型降低试点门槛。** DeepSeek/Kimi/Qwen/智谱/百度/腾讯可作为低成本、中文友好、合规更可控的底座，适合先在国内品牌客户做 PoC。

### 2. 效率判断

- **研发效率进入项目级上下文阶段。** 1M 上下文可承接 PRD、代码仓库、历史缺陷、测试用例、接口文档的一体化分析；技术中心可从个人 Copilot 升级到团队 AI Coding 流程。
- **运营知识处理可降本。** 字段抽取、工单摘要、FAQ 聚类、客户反馈分类、活动复盘初稿，可由国内低价模型/本地模型批量处理，强模型只做复杂决策。
- **兼容 API 有利于统一网关。** 越多国内厂商兼容 OpenAI/Anthropic，越应该尽快建设统一 Model Gateway、成本统计、缓存、脱敏、路由与降级机制。

### 3. 风险判断

- **数据合规**：会员手机号、消费记录、企微聊天、导购任务、客户经营数据属于敏感数据，不应默认进入海外模型；需数据分级、脱敏、客户授权、日志留存与出境评估。
- **模型路由成本**：1M 上下文、长输出、工具调用、搜索、代码执行会让账单不可见；必须记录模型、token、缓存命中率、工具调用、重试次数、单任务成本。
- **私域数据外流**：Agent 一旦接入企微、CRM、营销系统，提示注入或插件越权可能导出客户资产；必须做租户隔离、字段级权限、最小化工具权限。
- **权限审计**：发券、打标签、群发、改会员等级、导出报表都是业务写操作，不能由模型直接执行；高风险动作必须人审确认、留痕、可回滚。
