# 国内外AI大模型最新情报深读｜2026-11-13

> 定位：前沿 AI 学习与感知。核验时间：2026-11-13 08:10（Asia/Shanghai）。仅收录有明确时间戳、可回溯的一手公告、官方文档或政策页面；已过滤营销软文、榜单、无日期“爆料”与无法独立核验的参数。

## A. 今日结论

1. **海外竞争进一步从“模型能力”转为“可执行 Agent + 安全护栏”。** Google 在 11 月 12 日将 Gemini 4 Hydrogen 面向开发者推出，重点是 Agentic 开发；此前 Gemini 4 Carbon 已强调网络安全、科学推理与长程工作流。Mistral 则把企业 Agent、工作流、应用构建进一步产品化。
2. **国内今天没有确认的旗舰文本模型大版本，但生产侧的 API 生命周期风险很实际。** Kimi 已标明 `kimi-k2.6` 不再向新注册用户提供、预计 12 月底下线；火山方舟持续公告模型退役/自动迁移。模型路由、版本锁定和回归测试比追逐型号更紧急。
3. **中国 ToB SaaS/CRM 的可落地路径不应是“接一个大模型”，而是“国内可控推理 + 权限化业务工具 + 人审闭环”。** 海外模型更值得用于代码、深度研究和复杂多模态的脱敏评测；会员、订单、企微会话与客户联系人等私域数据默认走国内、最小化、可审计路径。

   - **时间：2026-11-12。**

   - **能力变化：** 重点是快速、可执行的开发任务与 Agent 工作流，不宜直接把发布口径等同于 CRM 业务准确率；需要以 EZR 的真实代码修复、工具选择、结构化输出任务复测。
   - **证据：** [Google Blog](https://blog.google/innovation-and-ai/technology/developers-tools/build-with-gemini-4-hydrogen/)｜2026-11-12；[产品介绍](https://blog.google/innovation-and-ai/models-and-research/gemini-models/introducing-gemini-4-hydrogen/)｜2026-11-12。

## 国外 vs 国内：能力、成本与部署对照

| 维度 | 国外头部：OpenAI / Anthropic / Google / Meta / xAI / Mistral | 国内头部/开源：Qwen / DeepSeek / 豆包 / Kimi / GLM / 文心等 | 企业决策含义 |
|---|---|---|---|
| 产品重心 | 复杂推理、编码、Agent 执行、多 Agent、企业连接和全球云市场 | 本地生态、低成本推理、长上下文、OpenAI 兼容、国产云与私有化选择 | 选“可完成任务 + 可审计 + 可恢复”，不选单一跑分 |
| API / 版本 | SKU、SDK、区域与工具服务组合更深，迁移频繁 | 价格更灵活、兼容层更多，但 SKU 下线/滚动更新同样常见 | 建立统一网关，业务不得硬编码模型 ID |
| 上下文 / 多模态 | Google 的 1M 统一上下文与前沿多模态/Agent 能力突出 | DeepSeek 多模态、文心长文档解析、Qwen 长上下文等更便于中国本地部署 | 长上下文不是权限治理；仍需 RAG、分租户检索和字段级策略 |
| 价格 / 成本 | 前沿模型 token 单价和工具/云资源成本较高 | 通常具备低价、Batch、缓存及套餐优势 | 用“每成功任务成本”核算：token + 工具 + 重试 + 人审 + 运维 |
| 部署 / 合规 | 跨境、区域可用性、云采购与 EU 规则影响更大；Mistral 可提供主权部署路线 | 国内处理、备案/安全评估、本地支持与私有化更符合中国客户预期 | 中国私域数据默认国内闭环；跨境模型仅用于低敏、脱敏或离线评测 |

## C. 对中国 ToB SaaS / CRM 的影响判断

### 增长
- **机会：把“客户/商品/活动/权益/库存/导购知识”变成权限化的业务工具。** Agent 的价值来自能调用 CRM 中的真实上下文，并把建议接回销售、导购、客服和运营动作，而不是一个孤立聊天框。
- **建议先做三类可衡量场景：** 商机风险解释、导购下一步建议、沉睡会员召回策略；先输出“建议卡 + 依据 + 人审”，再逐步开放受控执行与归因。

### 效率
- **采用模型路由。** 高频、低风险的摘要/分类/字段抽取/离线标签优先国内模型与 Batch；代码、复杂研究、跨模态理解可用海外模型做脱敏评测，以任务成功率和可控性决定是否升级。
- **把成本工程纳入产品底座。** 上下文缓存、检索切片、短上下文重写、会话/工具预算、超时和中止策略都应可配置、可观测。

### 风险
- **数据合规：** 会员、订单、企微聊天、工单、联系人需分级；敏感字段脱敏、最小必要传输、默认国内处理，跨境模型不得默认接收原始数据。
- **权限审计：** Agent 使用独立服务身份和最小权限；触达、写 CRM、导出、改价、删除须审批、留痕、可撤回并按租户隔离。
- **供应商漂移：** 自动迁移、别名滚动升级和 SKU 退役会造成质量、成本及审计变化。版本台账、回归集、灰度、fallback、熔断缺一不可。

## 对 EZR 的影响

1. **产品：** 目标不是“CRM 内置聊天”，而是“按角色、权限和流程运行的业务 Agent 工作台”——销售、导购、运营、客服各有可调用工具、数据范围和审批门。
2. **技术：** 优先建设统一模型网关、知识/数据权限中台、Agent 工具目录、策略引擎、审计链和评测集；模型供应商应可替换。
3. **商业化：** 以每次被采纳的有效建议、有效触达或可归因转化衡量价值；避免把 token 包或无限问答做成核心卖点。

## D. 今日可执行动作（3条）

1. **建立“模型 API 生命周期台账”并接入发布流程。** 本周盘点 Kimi、DeepSeek、方舟及现有供应商的模型 ID、实际版本、区域、上下文、价格、退役日、数据路径和 fallback；禁止业务代码直接硬编码模型名称。
2. **完成 CRM Agent 安全基线 v1。** 明确数据分级、字段脱敏、服务身份、工具白名单、审批门、审计字段、租户隔离与回滚；首期仅开放“只读分析 + 待审建议”。
3. **用 5 个真实任务做路由评测。** 客户周报、商机风险归因、活动/商品内容、知识问答、代码修复；比较国内模型与一款海外前沿模型的成功率、时延、引用真实性、越权率和每成功任务成本。
