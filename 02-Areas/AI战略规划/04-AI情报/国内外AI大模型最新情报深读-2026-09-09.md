## A. 今日结论（3条）

1. **海外模型的焦点已从“旗舰能力”转到“可规模化 Agent”。** Google 在 9 月 2 日发布 Gemini 3.8 Flash 模型卡：以 1M 上下文、文本/图像/音频/视频输入、64K 输出和可调 effort，直接瞄准生产级 Agent；OpenAI GPT-5.6 则用程序化工具调用与多 Agent 编排降低复杂任务的模型回合数。
2. **国内平台正在形成“低成本长上下文 + 标准兼容 + 多模型聚合”的部署优势。** DeepSeek V4 提供 1M 上下文、Tool Calls、Responses API、Anthropic API 兼容；Kimi K3 为视觉原生 1M 上下文；百炼已把 Qwen、DeepSeek、Kimi、GLM 等聚合为一个模型市场。
3. **企业采购的核心门槛变为数据控制和 Agent 治理。** Anthropic 推出 Enterprise Frontier Safeguards，尝试同时满足零数据保留、异常行为检测、客户自持密钥/日志；这对 CRM Agent 的启示明确：模型能力必须与工具白名单、数据分级、人工确认、审计闭环一起交付。

## B. 重点情报（10条）

### 1. [国外] Google 发布 Gemini 3.8 Flash 模型卡：1M 上下文，定位生产级 Agent
- **时间：2026-09-02（近7天）**
- **来源：** https://deepmind.google/models/model-cards/gemini-3-8-flash/
- **厂商/模型：** Google DeepMind / Gemini 3.8 Flash。
- **能力变化：** 文本、图像、音频、视频输入；文本输出；上下文 1M token、最大输出 64K token；支持可调 effort，在软件工程、Agent 知识工作、长上下文、计算机使用等场景评测。
- **价格：** 模型卡列示缓存条件下 $0.75/百万输入、$3.75/百万输出；常规价 $1.50/$7.50。
- **企业部署影响：** “Flash”级模型也进入长任务和 Agent 生产场景，企业可将常规知识处理、文档/视频理解和工程任务放到较低单价层，再把最高难任务升级给旗舰模型。
- **风险：** 模型卡披露其多语种安全评测相对上一代出现回退（+5.4pp，低为好），跨语言生产评测不可省略。

### 2. [国外] OpenAI GPT-5.6：以程序化工具调用和多 Agent 编排压缩复杂工作流成本
- **时间：** 产品页当前有效；页面更新含 2026-08-21 降价信息（近7天外，作为当前有效规格）。
- **来源：**
  - https://openai.com/index/gpt-5-6/
  - https://developers.openai.com/api/docs/models
  - https://developers.openai.com/api/docs/pricing
- **厂商/模型：** OpenAI / GPT-5.6 Sol、Terra、Luna（当前文档同时将 GPT-6 Astra 列为复杂推理与编码的旗舰起点）。
- **能力变化：** GPT-5.6 可通过 Responses API 的 Programmatic Tool Calling 编写和运行轻量程序，协调工具、筛选中间数据、动态决定下一步；`ultra` 模式默认并行协调四个 Agent，API 侧可通过 multi-agent beta 实现类似模式。全系支持文本/图像输入和视觉。
- **API/价格：** GPT-5.6 Sol/Terra/Luna 标准短上下文输入/输出分别为 $4/$20、$2/$12、$0.2/$1.2 每百万 token；Batch 约为标准价一半。GPT-6 Astra 为 $10/$50；区域数据驻留端点对符合条件的新模型加价 10%。
- **企业部署影响：** 复杂任务的成本不再只取决于单次 token 单价，还取决于工具回合、缓存、并行 Agent、长上下文与区域处理。应把工具执行日志、超时、重试、预算统一纳入网关。

### 3. [国外] Anthropic Claude Sonnet 5 把 Agent 能力下放到更低成本档位
- **时间：** 官方新闻页当前有效；本轮页面未稳定呈现结构化发布日期，因此不将其表述为“今日发布”。
- **来源：**
  - https://www.anthropic.com/news/claude-sonnet-5
  - https://platform.claude.com/docs/en/models/overview
- **厂商/模型：** Anthropic / Claude Sonnet 5。
- **能力变化：** 强化规划、浏览器/终端工具使用、长任务自主执行、代码与知识工作；官方称其 Agent 性能接近 Opus 4.8，同时较 Sonnet 4.6 更安全。当前 Claude Fable 5.1、Opus 5、Sonnet 5 的上下文均为 1M、最大输出 128K；均支持文本/图像输入、视觉和工具调用。
- **价格：** Sonnet 5 为 $2/百万输入、$10/百万输出；Opus 5 $5/$25；Fable 5.1 $10/$50。
- **企业部署影响：** 企业可以用中档模型承接多数代码和 Agent 工作，再以 Fable/Opus 处理真正高难的长程任务；上线前仍需以自身任务集验证“自主执行”而非只看 benchmark。

### 4. [国外] Anthropic EFS：安全监控与客户自持数据/密钥开始合并为企业产品能力
- **时间：** 官方新闻页当前有效；文中说明将于今年秋季分阶段向客户推出。
- **来源：** https://www.anthropic.com/news/enterprise-frontier-safeguards
- **产品/部署方式：** Enterprise Frontier Safeguards（EFS），目标是结合零数据保留（ZDR）与滥用检测；活动数据可放在客户自己的 AWS S3、Azure Blob Storage 或 Google Cloud Storage，客户控制加密密钥、访问策略与审计日志，告警交由客户人员复核。
- **企业部署影响：** 高敏感数据场景的采购边界从“是否不训练”推进到“日志在哪、谁持密钥、谁能人工查看、如何跨会话监控”。
- **对 CRM 的启示：** 客户画像、私域会话、订单、导购触达动作应支持客户域内留存、可审计和角色隔离；不要将模型厂商的默认日志策略当成合规方案。

### 5. [国外] OpenAI 的旗舰模型与区域处理、缓存、Fast/Batch 服务层绑定更紧
- **时间：** 官方价格文档当前有效；Fast mode 于 2026-07-30 更名说明仍有效。
- **来源：** https://developers.openai.com/api/docs/pricing
- **变化：** 同一模型按短/长上下文、缓存读写、标准/Fast/Batch、区域数据驻留产生不同成本；GPT-6 Astra 的短上下文输入/缓存输入/输出为 $10/$1/$50，长上下文为 $20/$2/$75。
- **企业部署影响：** 预算治理需要从“按模型定价”升级到“按工作流定价”：上下文裁剪、缓存命中、异步批处理和服务等级是可量化的成本杠杆。

### 6. [国内] DeepSeek V4：1M 上下文、双接口兼容与低价缓存，适合生产主路由候选
- **时间：** 官方价格/模型文档当前有效；版本为 `DeepSeek-V4-Flash-0731`、`DeepSeek-V4-Pro-0813`。
- **来源：** https://api-docs.deepseek.com/quick_start/pricing/
- **厂商/模型：** DeepSeek / V4 Flash、V4 Pro、V4 Flash Vision Exp。
- **能力变化：** 1M context、最大输出 384K；支持思考/非思考模式、JSON Output、Tool Calls、Responses API、Anthropic API 兼容；Vision Exp 支持图像输入计费。
- **API/价格：** Flash 峰/谷时段每百万 token：缓存命中 $0.014/$0.007，缓存未命中 $0.44/$0.22，输出 $1.32/$0.66；Pro 约为 Flash 的 3 倍。并发上限 Flash 2500、Pro 500。官方明确价格可调整。
- **企业部署影响：** 对已有 OpenAI/Anthropic SDK 的迁移阻力低，适合承担摘要、分类、结构化提取、标准问答、部分工具调用；但必须通过 CRM 自有评测验证结构化输出、工具选择和长任务稳定性。

### 7. [国内] Kimi K3 成为迁移目标：视觉原生、1M 上下文，同时出现明确版本下线窗口
- **时间：** `kimi-k2.5` 与 `moonshot-v1` 于 **2026-08-31** 下线（近7天外但已进入当前生产影响期）。
- **来源：**
  - https://platform.kimi.com/docs/models.md
  - https://platform.kimi.com/docs/pricing/chat
- **厂商/模型：** 月之暗面 / Kimi K3。
- **能力变化：** Kimi K3 标注 2.8 万亿参数、原生视觉理解、1M token 上下文，面向软件工程、知识工作、深度推理；K2.7 Code 为 256K 上下文，并有高速度版本。平台对 K3 单列定价入口。
- **企业部署影响：** 对接方不能把 `-latest` 或老版本当作稳定契约：版本下线会直接返回 404。模型网关必须具备版本白名单、迁移预演、双跑对照和降级策略。

### 8. [国内] 阿里云百炼：多模型市场已覆盖文本、视觉、图像/视频、语音、向量与重排
- **时间：** 官方模型大全当前有效。
- **来源：** https://help.aliyun.com/zh/model-studio/models
- **生态/平台动作：** 同时列示 Qwen 3.8、DeepSeek V4、Kimi K3、GLM 5.2/5.3、MiniMax M3、MiMo 等文本模型；并覆盖图像/视频理解生成、语音、全模态、向量和 rerank。
- **企业部署影响：** 企业的模型采购正在从“选一款模型”变成“选统一平台 + 路由编排 + 计费与审计”。对 SaaS 而言，应在自身架构中保留模型能力抽象，不要把业务逻辑直接绑定任一供应商控制台。

### 9. [国内] 智谱：模型即服务能力向专属部署、微调、评测、搜索与知识库一体化延展
- **时间：** 官方开发文档当前有效。
- **来源：** https://docs.bigmodel.cn/cn/guide/start/introduction.md
- **生态/部署方式：** 提供文本、视觉、图像、视频、音频 API；支持专属资源部署、模型微调、评测、联网搜索、知识库检索，提供 OpenAI SDK 兼容与 LangChain 集成。
- **企业部署影响：** 国内客户会越来越要求“模型能力 + 数据隔离 + 评测/运营工具 + 服务支持”一并交付，单纯 API 接入难形成长期壁垒。
- **对 EZR 的机会：** 可将行业知识检索、模型评测和权限审计封装为 CRM AI 的标准交付件，而不是各项目临时搭建。

### 10. [国内外] Agent 时代的共同风险：提示注入、越权工具调用、版本漂移与数据流向
- **时间：** 近7天持续趋势；本轮基于上述官方模型卡、Agent 产品和企业安全材料综合判断。
- **证据：** Gemini 3.8 Flash 模型卡披露安全/多语种限制；Anthropic EFS提出跨会话滥用监控和客户自持日志；OpenAI提供多 Agent/程序化工具调用；国内平台强化 Tool Calls、MCP/Agent 和接口兼容。
- **风险判断：** 模型能力越能自主执行，越不能只做 prompt 防护。私域数据外流、越权读写客户/订单、错误触达、长上下文成本膨胀、供应商静默更新均会成为生产事故源。
- **建议：** 必须在模型外实现敏感字段脱敏、工具白名单、最小权限、事务确认、人审阈值、版本锁定、灰度发布、全链路日志和回归评测。

## C. 对中国 ToB SaaS/CRM 的影响判断

### 增长
- **产品卖点从“AI 问答”升级为“可控的经营 Agent”。** 将会员、客户、导购、订单、活动、项目知识接入受控工具，输出可执行建议与证据，而不是独立聊天框。
- **形成能力分层。** 低成本国内模型承担标签、摘要、质检、结构化提取和标准回复；高阶模型仅承担复杂分析、方案编排、代码与关键决策辅助，形成可售卖的效果/成本梯度。
- **知识库升级机会。** 面向活动规则、导购 SOP、交付文档和客户政策，采用“检索—定位—验证—引用”的可追溯知识 Agent，比传统一次性 RAG 更适合交付型场景。

### 效率
- 统一模型网关把路由、缓存、上下文裁剪、限流、预算、版本、评测和降级收口，避免各团队重复集成。
- OpenAI/Anthropic 兼容接口与国产模型成熟，利于复用 AI Coding、MCP/Tool 和 Agent 编排资产。
- 将 Prompt、Tool schema、评测集和业务 Skill 视为版本化资产，沉淀服饰零售经营方法，而不是重复写提示词。

### 风险
- **数据合规：** 私域会话、会员画像、订单、门店经营与项目文档不能默认发往海外模型；需明确数据分级、脱敏规则、区域处理与日志留存策略。
- **权限审计：** Agent 对 CRM 的读写必须拆分“看什么、能做什么、何时需确认”；涉及触达、改价、发券、导出客户信息的动作默认人审/审批。
- **模型路由成本：** 1M 上下文与多 Agent 容易带来 token 放大；要设置任务预算、缓存命中指标、上下文裁剪、异步批处理和模型降级。
- **版本与供应商风险：** Kimi 的明确下线案例说明，必须有版本锁定、双跑、回归评测、替换预案；不可让业务代码直连单一模型。

### 对 EZR 的影响
1. 建设 **CRM Agent 中台**：统一模型路由、客户数据权限、工具白名单、知识检索、操作确认、调用审计与效果评测。
2. 优先试点三类低风险高价值任务：导购跟进建议、活动/会员运营复盘、项目交付知识问答（要求返回证据定位）。
3. 对外方案默认采用 **“国内模型生产主路由 + 海外高阶模型授权灰度”**：按客户的数据边界、专属资源和审计要求提供分层交付。

## D. 今日可执行动作（3条）

1. **本周确定模型网关最小规范：** 模型/版本白名单、数据分级、默认国内路由、海外调用审批、缓存与预算字段、统一调用日志；禁止业务服务直接绑定模型厂商。
2. **启动“可验证知识 Agent”两周试点：** 选 CRM SOP 或项目交付库，规定每个答案必须附原文证据位置；跟踪准确率、人工复核率、平均延迟、每任务 token 成本。
3. **完成一次 Agent 权限演练：** 为“读取客户资料—生成建议—执行触达”拆分三段权限；对发券、群发、导出、改价等高风险工具强制二次确认，并模拟提示注入/越权调用。
