## A. 今日结论（3条）

1. **海外主线从“单模型更强”转向“Agent 工作流 + 成本可控 + 企业治理”。** OpenAI GPT-5.6 已进入 GA，Sol/Terra/Luna 形成旗舰/均衡/低成本分层，配套 Programmatic Tool Calling、多 Agent beta、Spend Controls、ZDR/区域处理等企业治理能力；Mistral 则把 Prompts/Skills 版本化、OCR 4、Robostral Navigate 作为企业 Agent 基础设施来打。
2. **国内主线仍是“低成本、长上下文、OpenAI/Anthropic 兼容、可本地化护栏”。** Kimi K2.7 Code 给出 256k 上下文、图片/视频输入、ToolCalls/JSON/Partial Mode 和缓存价格；DeepSeek V4 提供 OpenAI/Anthropic 兼容入口并明确旧模型名废弃时间；Qwen3Guard/Qwen-MT 代表国内开源社区在安全护栏和垂直任务模型上的补齐。
3. **企业落地的竞争点已经不是“选哪个模型”，而是“模型路由 + 权限审计 + 成本归因 + 安全护栏”能否产品化。** 对中国 ToB SaaS/CRM 来说，最优策略是：国内模型承接高频中文与敏感数据任务，海外模型处理复杂推理/研发兜底，所有 Agent 必须纳入权限、日志、人审、数据分级和成本看板。

### 1. 【国外】OpenAI GPT-5.6 GA：Sol/Terra/Luna 三档模型进入通用可用，Agent 与 Coding 能力继续前推

- **厂商 / 模型 / 产品**：OpenAI / GPT-5.6 Sol、Terra、Luna / API、ChatGPT Work、Codex 等。
- **发布时间**：官方页面当前抓取于 2026-07-15；页面为 GPT-5.6 GA 发布文。
- **证据链接**：https://openai.com/index/gpt-5-6/
- **能力变化**：Sol 为旗舰；Terra 面向日常均衡；Luna 面向成本效率。官方强调在 coding、知识工作、网络浏览、computer use、网络安全、科学任务上提升；ultra 模式可并行协调多个 agent；Responses API 支持 multi-agent beta。
- **上下文 / 工具调用 / 多模态 / Agent / 价格 / 部署方式**：官方发布文强调 Programmatic Tool Calling、multi-agent、computer use、文档/表格/演示生成。价格页显示短上下文 GPT-5.6 Sol $5 input / $30 output per 1M tokens，Terra $2.5 / $15，Luna $1 / $6；长上下文价格翻倍或更高。
- **企业部署影响**：可把任务拆成旗舰复杂任务、日常办公任务、低成本批量任务三层，按结果价值而非单 token 价格选型。
- **对 ToB SaaS/CRM/EZR 的机会**：复杂需求分析、PRD/测试用例/SQL 风险审查可用 Sol；客服摘要、导购话术、标签解释可用 Terra/Luna 或国产模型；沉淀内部“任务-模型-成本”路由表。
- **风险**：海外模型处理客户私域数据需脱敏；多 Agent 任务更易形成不可见成本和权限扩散。
- **建议动作**：将 GPT-5.6 Sol 纳入“复杂研发/安全/架构评审兜底模型”，同时强制记录每次调用的任务类型、成本、是否命中缓存、是否涉及敏感数据。

### 4. 【国外】OpenAI Programmatic Tool Calling：模型可生成受限 JavaScript 编排工具，降低长链路工具调用成本

- **厂商 / 模型 / 产品**：OpenAI / Responses API / Programmatic Tool Calling。
- **发布时间**：开发者文档当前抓取于 2026-07-15。
- **证据链接**：https://developers.openai.com/api/docs/guides/tools-programmatic-tool-calling
- **能力变化**：模型可在隔离 V8 runtime 中写/运行 JavaScript，支持并行工具调用、循环、条件、保留中间结果并返回更小结构化结果。
- **限制与合规**：无 Node.js、无包安装、无直接网络、无通用文件系统、无子进程；仅通过请求中授权工具访问外部系统；支持 ZDR 工作流但需组织/项目启用。
- **企业部署影响**：适合把“多次查表、过滤、聚合、去重、校验”交给受控程序执行，减少模型反复读大工具输出。

- **风险**：一旦工具权限边界不清，程序化调用会放大越权访问；写操作和审批敏感动作不应默认交给程序化阶段。
- **建议动作**：内部 Agent 设计中区分三类工具：只读可程序化、写入必须直连审批、高风险工具必须人审。

## C. 对中国 ToB SaaS/CRM 的影响判断（增长 / 效率 / 风险）

### 增长

1. **AI 导购从“推荐话术”升级为“可审计增长工作流”。** 海外 Agent 平台化和 Mistral Prompt/Skill 版本化说明，增长类 AI 能力要把“为什么推荐、用了哪些数据、谁批准、效果如何”串起来，才能进入客户预算。
2. **语音和多模态会打开门店/导购新入口。** GPT-Live 代表自然语音交互成熟度提升；结合门店培训、导购晨会、电话质检、客户跟进复盘，CRM 有机会把 AI 从后台工具推进到一线工作流。
3. **文档智能是 ToB SaaS 的低阻力入口。** Mistral OCR 4、Kimi 长上下文、Qwen-MT 都指向一个机会：把客户历史方案、商品资料、活动 SOP、会员制度结构化，形成品牌专属经营知识库。

### 效率

1. **AI Coding 应从“人选模型”改成“任务路由”。** 复杂架构/安全审查用海外强模型兜底；常规代码解释、测试用例、需求变更分析可用 Kimi/DeepSeek；安全检测接 Qwen3Guard 类护栏。
2. **Prompt/Skill 版本化会明显降低运营事故。** 导购回复、营销策略、会员标签解释如果不版本化，难以追责和复盘；应该像代码一样有 owner、版本、审批、回滚。
3. **成本治理必须前置。** OpenAI 明确提出 cost per accepted outcome，说明 AI 成本会成为管理层关注项。EZR 内部也要从第一天记录 tokens、工具调用、缓存、结果质量。

### 风险

1. **数据合规风险**：客户私域数据、会员画像、交易记录、导购聊天记录不能默认流向海外模型；必须脱敏、分级、记录用途。
2. **模型路由成本风险**：Agent 多轮工具调用和 ultra/多 Agent 模式会快速放大成本；没有预算阈值和任务归因，ROI 会失真。
3. **权限审计风险**：Programmatic Tool Calling / MCP / connectors 让模型能调用更多系统，必须明确只读/写入/审批边界，避免越权访问和自动化误操作。
