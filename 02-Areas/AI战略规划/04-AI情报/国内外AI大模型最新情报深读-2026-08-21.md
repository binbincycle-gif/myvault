## A. 今日结论（3条）

1. **海外方向：模型竞争从“单模型聪明”转向“可控推理 + 企业级 Agent 基建”。** OpenAI 将 GPT-5.6 Sol/Luna 做成不同用户层级的默认体验，并引入推理强度滑杆；Google 加入 Agent Plugins 1.0.0 核心维护；Mistral 新闻流重点转向 Agentic Search、Prompt/Skill system of record、Studio/Workflows 等企业 Agent 工程化。
2. **国内方向：1M 上下文、OpenAI/Anthropic 兼容、工具调用、缓存、长程 Coding Agent 正在快速成为标配。** DeepSeek V4、Kimi K3、智谱 GLM-5.3、通义 Qwen 3.8 系列均体现出“替换接入成本低、长上下文强、Agent 场景优先”的趋势。
3. **对中国 ToB SaaS/CRM：短期机会不是做聊天框，而是把业务流程封装成可审计 Agent。** CRM 的会员分析、导购任务、营销编排、客诉处理、数据取数最适合先落地；同时必须建立模型路由、权限审计、私域数据脱敏、成本看板，否则越智能越容易失控。

## C. 对中国 ToB SaaS/CRM 的影响判断

### 增长

1. **产品卖点会从“功能模块”升级为“岗位 Agent”。** 例如：会员运营 Agent、导购督导 Agent、营销活动复盘 Agent、客户成功续费 Agent，比单点 AI 文案更容易形成付费理由。
2. **长上下文让 CRM 的历史数据价值释放。** 客户档案、消费记录、导购跟进、活动记录、工单反馈可以被统一读取，形成“客户经营建议”。
3. **国产模型的价格与兼容性降低落地门槛。** DeepSeek/Kimi/GLM/通义均兼容 OpenAI 或 Anthropic 协议，有利于 SaaS 做多模型路由，避免绑定单厂商。

### 效率

1. **研发提效进入 Agent 阶段。** GLM-5.3、Claude Opus 5、Kimi K3 都在复杂代码库、长程任务上发力，可用于需求拆解、代码审查、测试用例生成、缺陷定位。
2. **交付/客户成功可先自动化。** 用 Agent 自动生成客户经营月报、活动复盘、导购跟进建议，能直接减少 CSM/运营顾问重复劳动。
3. **知识库治理成为效率前置条件。** 如果业务术语、指标口径、权限边界不清，模型越强越容易输出“看似正确但不可执行”的建议。

### 风险

1. **数据合规风险：** CRM 私域数据、会员手机号、消费行为、导购聊天记录不能直接进入外部模型；必须做脱敏、客户授权、数据驻留策略。
2. **模型路由成本风险：** 1M 上下文与高推理档会快速放大 token 成本；需要任务分层：低价值批处理走便宜模型，高价值决策走强模型。
3. **私域数据外流风险：** 长上下文缓存、工具调用、日志留存都可能导致数据外泄；需要供应商审查与本地日志脱敏。
4. **权限审计风险：** Agent 一旦能调用营销、会员、优惠券、企微触达等工具，必须有审批流、幂等控制、回滚机制和操作日志。

### 对 EZR 的影响

- **短期建议做“AI 能力中台 + 业务 Agent 样板间”。** 不急着全量产品化，先选 3 个高频岗位：会员运营、导购督导、客户成功。
- **优先沉淀技能包资产。** 参考 Agent Plugins 思路，把 EZR 的行业经验封装成 Skills：指标解释、活动复盘、会员分层、导购任务推荐、企微触达建议。
- **建立模型网关。** 支持 OpenAI/Anthropic 兼容协议、国产模型优先路由、客户级隔离、成本统计、敏感字段脱敏、工具权限审计。

## D. 今日可执行动作（3条）

1. **技术动作：搭一个“多模型路由 + 成本看板”最小闭环。** 先接 DeepSeek V4、Kimi K3、GLM-5.3、OpenAI GPT-5.6 Luna/Sol 四类模型，统一记录任务类型、输入输出 token、成本、成功率、人工评分。
2. **产品动作：选 3 个 CRM Agent 样板场景。** 建议优先：会员运营分析、活动复盘、导购任务推荐。每个场景定义输入数据、可调用工具、输出模板、审批点、失败兜底。
3. **治理动作：发布一版 AI Agent 权限清单。** 按“只读分析 / 生成建议 / 草稿创建 / 自动执行”四级授权，所有触达客户、发券、改会员标签、外发消息动作默认需要人工确认。
