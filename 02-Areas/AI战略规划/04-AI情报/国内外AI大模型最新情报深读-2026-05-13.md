## A. 今日结论（3条）

1. 海外大厂主线从“模型发布”转向“企业部署 + Agent工作流”：OpenAI 成立 Deployment Company，Google 围绕 I/O 预热 “agentic era”，Mistral / xAI 也在强化编码 Agent 与长上下文。

2. 国内模型进入“低价长上下文 + 多模型聚合 + 安全护栏”阶段：DeepSeek、Kimi、通义百炼都在把 1M / 256K 上下文、Tool Calls、视觉 / 语音 / 安全模型做成企业可用组件。

3. ToB SaaS / CRM 的机会不是换模型，而是把 CRM 数据、权限、流程、导购动作封装成 Agent 可调用的 Skill / API；风险重点在数据合规、模型路由成本、客户私域数据外流。

## B. 重点情报（可见部分）

### 1. [国外] OpenAI 推出企业部署公司，FDE 模式加速进入企业核心流程

- **时间**：2026-05-11
- **来源**：https://openai.com/index/openai-launches-the-deployment-company/
- **要点**：OpenAI 成立 OpenAI Deployment Company，并收购 Tomoro，带入约 150 名 FDE / 部署专家；目标是把模型接入企业数据、工具、控制和业务流程。
- **判断**：OpenAI 正在复制 Palantir / FDE 路线，未来企业 AI 项目竞争不只拼 API，而拼“工作流改造能力”。

### 2. [国外] OpenAI Realtime-2 发布，语音 Agent 从问答走向“实时执行”

- **时间**：2026-05-07
- **来源**：https://openai.com/index/advancing-voice-intelligence-with-new-models-in-the-api/
- **要点**：GPT-Realtime-2 支持 GPT-5 级推理、并行工具调用、128K 上下文、可调 reasoning effort；另有实时翻译、实时语音转写模型。
- **对 CRM 影响**：客服、导购、门店督导、客户成功的“语音 Agent”会更快落地。

### 3. [国外] OpenAI GPT-5.5-Cyber 进入有限预览，安全能力开始分级授权

- **时间**：2026-05-07
- **来源**：https://openai.com/index/gpt-5-5-with-trusted-access-for-cyber/
- **要点**：GPT-5.5-Cyber 面向经过验证的防御方；通过 Trusted Access 控制高风险安全能力。
- **判断**：大模型能力释放将越来越多采用“身份 + 权限 + 审计”模式，企业侧也应按角色开放 Agent 能力。

### 4. [国外] OpenAI Codex 安全实践披露，Agent 治理标准开始成型

- **时间**：2026-05-08
- **来源**：https://openai.com/index/running-codex-safely/
- **要点**：Codex 通过沙箱、审批、网络策略、OpenTelemetry 日志、企业合规日志来控制 Agent 行为。
- **判断**：这套机制可直接借鉴到企业内部 AI Coding / CRM Agent：低风险自动执行，高风险必须审批。

### 5. [国外] Anthropic 当前模型侧重长上下文与 Agent Coding

## C. 对 EZR / ToB SaaS CRM 的判断

### 1. 竞争重点从模型选择转向企业部署能力

OpenAI Deployment Company 和 FDE 路线说明，大模型厂商正在向企业核心流程下钻。EZR 的机会不是做通用模型代理，而是把零售 CRM 的客户数据、导购流程、会员运营、营销触达、权限审计变成可部署、可运营、可持续优化的 Agent 工作流。

### 2. 语音 Agent 值得重点观察导购与客户成功场景

Realtime-2 类能力如果成熟，门店导购、客服、客户成功、督导巡检都会从“文本问答”升级到“实时语音理解 + 工具调用 + 行动建议”。EZR 可以提前设计语音导购 / 语音督导的数据闭环：通话/对话 → 意图识别 → 会员画像补全 → 跟进动作 → 转化复盘。

### 3. Agent 治理会成为 CRM AI 的底线能力

OpenAI Codex 与 GPT-5.5-Cyber 的安全实践显示，未来高能力 Agent 必然需要身份、权限、审计、沙箱、审批、日志。EZR 如果要把 AI 接入客户私域数据，必须先把“低风险自动执行、高风险人工确认”的规则做成平台能力。
