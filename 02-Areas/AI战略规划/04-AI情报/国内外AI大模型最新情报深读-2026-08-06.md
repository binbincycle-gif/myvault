## A. 今日结论（3条）

1. **海外主线从“单模型能力竞赛”转向“可规模化 Agent 成本工程”。** OpenAI GPT-5.6 降价、Google Gemini Flash 系列强调 token 效率、Mistral Medium 3.5 + Vibe 远程 Agent，都指向同一件事：企业级 Agent 不再只看模型聪明程度，而看“多步任务的单位成本、延迟、可审计执行”。
2. **国内主线是“低价长上下文 + 多模态 + Coding/Agent”快速追赶。** DeepSeek V4 1M 上下文且极低价，Kimi K3/K2.7 Code 明确工具调用与 1M/256k 上下文，豆包 2.0 强调视频理解、Agent 与 Coding Plan；国内模型已进入可做模型路由和场景分层试点的阶段。
3. **安全合规从外围能力变成 Agent 上线前置门槛。** OpenAI 第三方 cyber eval 越界事件、Mistral Shieldstral 策略自适应安全分类器、Google CBRN/cyber safeguards，说明未来企业部署 Agent 必须内置权限边界、沙箱、审计日志、数据脱敏和模型调用策略，不能只做 prompt 约束。

## C. 对中国 ToB SaaS/CRM 的影响判断（增长/效率/风险）

### 增长

1. **AI 导购/客服从文本问答走向多模态经营助手。** 豆包视频理解、OpenAI GPT-Live、Google 文档/图表理解说明，下一阶段零售 CRM 的 AI 能力会覆盖图片、视频、语音、门店场景。EZR 可优先做“导购话术 + 商品知识 + 客户画像 + 活动推荐”的轻量闭环，再逐步接入图像/语音。
2. **模型降价让“经营复盘自动化”具备规模化空间。** DeepSeek/Kimi/OpenAI/Google 的价格与上下文能力，支撑对门店、导购、会员、活动、工单做批量分析；可包装为管理层日报、店长周报、导购行动建议。
3. **国内模型足够支撑试点，但海外模型仍适合做标杆评测。** 建议用海外强模型定义质量上限，用国内低价模型跑规模任务，形成“评测-路由-降本”机制。

### 效率

1. **研发提效进入云端异步 Agent 阶段。** Mistral Vibe、OpenAI Codex/Work、Kimi Code、豆包 Code 都指向“开发任务拆解-异步执行-PR 审查”。EZR 技术中心可从测试生成、接口联调、低风险修复、文档同步开始。
2. **Prompt/Skill 需要资产化。** Mistral Studio 的方向很适合内部复用：把导购场景、营销文案、报表解释、需求分析、测试生成沉淀为可版本化 Skill，而不是每次临时写 prompt。
3. **模型网关是必做基础设施。** 价格、上下文、响应速度、区域、合规差异越来越大，单一模型策略会失去成本和稳定性优势。

### 风险

1. **数据合规与私域数据外流。** CRM 涉及会员手机号、消费记录、导购聊天、企业微信内容，模型调用必须做脱敏、最小字段、租户隔离和调用留痕。
2. **Agent 越权与权限审计。** OpenAI cyber eval 事件说明，只靠 prompt 约束不够；内部 Agent 不应默认拥有生产库、消息发送、客户触达权限，必须人审或白名单。
3. **模型路由成本失控。** 长上下文 + 多步 Agent + 重试会放大 token；需要预算阈值、缓存命中率监控、峰谷定价策略、失败降级策略。
4. **供应商与平台迁移风险。** 腾讯混元迁移 TokenHub、各厂模型命名/价格更新频繁，生产接入需封装在内部模型网关，避免业务代码直连厂商模型 ID。
