## A. 今日结论（3条）

1. **推理层开源，私有化部署的"隐性溢价"被打掉了。** DeepSeek 10-20 把内部生产推理框架 **DeepInfer** 全面开源（Apache 2.0），并同步开源 token 编解码组件 `deepseek-recipe`，与官方 API 处理逻辑完全对齐。此前"官方 API 比自建便宜"的根本原因是推理框架不开源；现在这条路被抹平——**云厂商/企业自建的 DeepSeek 调用成本可以接近甚至低于官方**（官方说法是负载调度合理时可更低）。叠加 MiniMax M3.1 Flash（$0.15/$0.60，1M 上下文）和 Inception Mercury 3（$0.20/$0.70，100 万上下文，1068 tok/s，扩散架构），**Agent 的边际成本已经进入"每任务几厘钱"的区间**。竞争焦点正式从"谁的模型强"转到"谁的单位任务更便宜 + 谁能私有化"。

2. **Agent 治理从"最佳实践"变成"可售卖产品"，这是今年 ToB 软件最重要的产品信号。** 微软 10-19 发文把 Agent 定义为"最新的内部威胁（insider）"，主张"把智能的供给与对它的授权分离"，配套 Entra Agent ID（每个 Agent 一个一等身份 + 人类 sponsor）+ Agent 365 统一注册表 + Project Perception 扩展；Notion 10-20 直接把 **AI Command Center**（用量看板、消费上限、Agent 治理）做进 Business/Enterprise 席位，同时用 Auto 路由器把成本打到旗舰模型的约 10%。**含义：企业买 SaaS 的评估项，正在从"你有没有 AI 功能"变成"你能不能管住这些 AI、能不能出账、能不能审计"。**

3. **模型选型第一次变成"合规架构"问题，双轨/多路由从优化项变成必需项。** 美国 DHS 10-19 下令联邦文职机构停止采购并移除 DeepSeek 相关产品及第三方服务（可申请例外）；同期中国拟将 23 项 AI 技术纳入出口管制目录，覆盖**参数超 2 万亿的模型**与高敏感场景 Agent（开源模型豁免）。**含义：任何面向跨国客户或多云交付的 SaaS，都必须假设"同一功能在不同司法辖区要跑不同模型"，路由层、模型可替换性、以及"数据不出境"的证据链，要写进架构而不是写在 PPT 里。**

### 1. [国内｜2026-10-20] DeepSeek 全面开源生产推理框架 DeepInfer，私有化部署成本直逼官方 API
- **厂商/产品**：DeepSeek / DeepInfer（Apache 2.0）+ deepseek-recipe（生产级 token 编解码组件）。
- **能力变化**：集成高性能算子与深度优化推理引擎，支持**分布式推理、推测解码、SWA Bounded Replay、结构化输出**；兼容**英伟达 SM100 与华为昇腾 950**；`deepseek-recipe` 与官方 API 的 token 处理逻辑完整对齐，社区部署可获得与官方一致的编解码体验。首个版本仅支持 DeepSeek-V4.1-Flash。仓库已 4.7k stars。
- **为什么重要**：官方推理框架与编解码组件，是"原生部署 vs 社区部署"成本差异最大的系统层原因；MaaS 厂商开放权重但不开推理框架，本质上是在保护自家 token 收入。DeepSeek 是**全球头部大模型中第一个开放生产级推理框架的**。
- **企业部署影响**：私有化/专属云交付的 TCO 模型要重算。此前"客户自建不如买 API"的结论在很多场景下不再成立，尤其是有数据不出域硬约束的客户。对我们意味着：**专属化交付可以从"卖 license + 每年重谈 API 预算"变成"一次性算力投入 + 可控边际成本"**，商业模型更干净。
- **证据**：[IT之家（2026-10-20 17:05）](https://www.ithome.com/1/015/429.htm)｜[21世纪经济报道（2026-10-20）](https://www.21jingji.com/article/20261020/herald/5330df27d9317a4d21cf51ae14472b44.html)｜[澎湃新闻（2026-10-20 19:01）](https://www.thepaper.cn/newsDetail_forward_34290209)

### 2. [国外｜2026-10-20] 美国 DHS 下令联邦文职机构移除 DeepSeek，可申请例外

### 3. [国外｜2026-10-19] 微软：把 Agent 当"内部威胁"建模，治理栈产品化
- **主体/产品**：Microsoft / Entra Agent ID + Agent 365 + Project Perception（Guardian Agents）。
- **核心主张**：每个 Agent 应有**独立于使用者的一等身份**；"控制 Agent 能访问什么、能做什么、是否应继续运行的机制，必须放在模型之外，模型不能绕过或篡改"；"最可信的 Agent 系统不是模型最可信的那个，而是设计上允许我们最不信任模型的那个"（Nadella）。
- **四类持续职责**：知道有哪些 Agent/谁拥有/为什么存在/在做什么；行动前限制其权限边界；保护其路径上的数据、工具、运行时；随行为与风险变化持续调整策略。
- **企业部署影响**：这是给我们产品设计的直接模板。**Agent 的权限必须与人的权限解耦，且要有"sponsor（人类负责人）+ 有效期 + 最小权限 + 全量动作日志"四件套**。我们做 CRM Agent 时，导购 Agent 不该继承店长的全部数据权限，而应有"按客户归属 + 按字段 + 按时间段"的可撤销授权。
- **证据**：[Microsoft Security Blog（2026-10-19）](https://www.microsoft.com/en-us/security/blog/2026/10/19/agents-are-your-newest-insiders-security-must-move-at-their-speed/)

## C. 对中国 ToB SaaS / CRM 的影响判断

### 增长（机会）
1. **"专属化 + 私有化"第一次具备健康毛利。** DeepInfer 开源 + 昇腾双栈支持，让"给大客户做专属部署"从"赔本赚吆喝"变成"可计价的产品"。对服饰零售里那些数据敏感、又想要 AI 的头部品牌（正是我们的核心客群），这是最有说服力的一张牌：**数据不出域、成本可预算、能力可迭代**。
2. **"老系统迁移"可以做成入场服务。** COBOL/Fortran/VB 迁移能力跃升 + 国内模型成本极低，意味着我们可以承接客户的历史 ERP/POS/自研报表迁移，用它换 CRM 的替换窗口。这是一条**用 AI 能力换客户关系**的进攻路径，而不是防守。
3. **"一句话下指令"进 CRM 的成本归零。** Xing4.0-29B-Intent（Apache 2.0、可私有化）+ Mercury 3（$0.10 起、1068 tok/s）组合，足以支撑导购/店长用自然语言查数、改单、发起任务。这是**移动端体验的一次结构性升级**，也是 App 极速版最该抓的点。

### 效率（内部）
1. **把 80% 的调用从旗舰挪走。** 参照 Notion Auto 的做法做三级路由：实时/简单任务→小模型或端侧（Glimmer 30B / Mercury 3 / GLM-5.3-Flash），常规任务→M3.1 Flash / V4.1-Flash，复杂推理→旗舰。目标：**同等效果下推理成本降 70%+**。
2. **Agent 长任务的工程底座要补。** Notion 把单任务从 5 分钟做到 24 小时，靠的是"独立服务 + 队列 + 检查点"。我们现在的 Agent 大多是"请求-响应"，一旦断线就前功尽弃。**这是纯工程投入、不需要等模型**，应该立刻排期。
3. **verifier 模式做可靠性。** 用一个小模型专门审核主 Agent 的动作（改价、发券、改客户归属），成本极低但能挡住大部分灾难性误操作。

### 风险
1. **模型来源成为采购门槛（合规）。** 美国禁 DeepSeek 到联邦系统、中国拟管制 2T 以上模型，意味着**"用了哪个模型"要能说清、能切换、能证明数据流向**。建议建立"模型成分清单"（每个功能用了哪个模型、部署在哪、数据是否出境），作为标书附件。
2. **私域数据外流的认定风险上升。** 用客户数据微调的产物，在出口管制语境下可能被认定为受限技术。**合同里必须明确：微调产物的所有权、存放地、可否迁移、服务终止后如何销毁。**
3. **模型路由成本失控。** 路由做不好会两头亏：该用便宜的用了贵的（成本高），该用贵的用了便宜的（效果差、返工更贵）。必须有**按任务类型的成本/质量看板**，而不是靠感觉调。
4. **权限审计缺失。** Agent 继承人的权限是最常见的设计错误。导购 Agent 拿到全店客户数据，一次越权查询就是事故。**Agent 必须有独立身份、最小权限、可撤销、全量留痕。**

### 对 EZR 的具体机会（仅此处涉及落地）
- **近期（2–4 周）**：用 Xing4.0-29B-Intent 做一次"自然语言查数/改单"的 PoC，用真实导购语句测槽位抽取；用 Mercury 3 或 M3.1 Flash 替换现有的会话摘要/打标调用，先拿到降本数字。
- **中期（1–2 月）**：把 Agent 执行框架升级为"队列 + 检查点 + verifier"，让长任务（如"帮我复盘这 30 家门店的本月陈列执行"）可以真跑完。
- **中期（1–2 月）**：推出"专属化部署"选项（DeepInfer + 昇腾/英伟达），面向数据敏感头部品牌，按"算力 + 年度服务"计价，摆脱纯 API 转售的低毛利。
- **持续**：把"模型成分清单 + 数据流向图 + Agent 权限矩阵"做成标准交付物，这是当下最便宜、最有效的差异化。
