## A. 今日结论（3条）

1. **海外大模型竞争正在从“单点模型能力”转向“企业级服务层能力”：速度、长上下文、Agent、成本治理、安全审批成为新战场。**  
   OpenAI 推 Ultrafast / Fast mode，Google Gemini 3.7 Flash 强调 1M 上下文与企业流程自动化，Anthropic 强化 Opus/Sonnet 的 agentic coding、computer use 与诚实性，说明企业选型不能只看榜单，要看“可稳定跑业务流程”的综合能力。

2. **国内模型进入“长上下文 + 多模态 + 开源/私有化 + 安全护栏”并行阶段，适合中国企业做模型路由与合规落地。**  
   Kimi K3、DeepSeek V4、GLM-5.x、Qwen3Guard/Qwen-Image-Edit 等信号显示，国内厂商正在补齐长上下文、代码/Agent、多模态内容生产、安全治理能力；对 ToB SaaS 来说，国内模型更适合处理中文业务、私域数据、合规部署和成本敏感场景。

3. **对中国 ToB SaaS/CRM 的关键启发：AI 能力要从“功能插件”升级为“可审计的业务执行系统”。**  
   未来 CRM 的差异化不只是接入一个聊天模型，而是把会员、导购、营销、交易闭环沉淀成 Agent 可调用的工具、权限、数据上下文与审计链路；增长机会很大，但模型路由成本、客户私域数据外流、权限越权和内容安全要同步建设。

## C. 对中国 ToB SaaS/CRM 的影响判断

### 1. 增长：从“营销工具”升级到“实时经营 Agent”

- **机会判断**：OpenAI Ultrafast、Gemini/Claude/Kimi/GLM 的长上下文和 Agent 能力，会让 CRM 从“人点功能”变成“Agent 主动执行经营动作”。
- **可落地方向**：
  - 导购实时话术推荐：结合会员画像、历史购买、活动策略，实时生成下一句话。
  - 会员运营 Agent：自动识别沉睡会员、生成触达策略、产出企微/短信/小程序内容。
  - 经营问数 Agent：用自然语言查询会员、交易、活动转化、导购绩效。
- **对 EZR 的重点机会**：把服饰零售行业经验沉淀为 Agent Playbook，例如“新品上市私域转化 SOP”“大促前会员分层唤醒 SOP”。

### 2. 效率：AI Coding 和业务文档理解进入可规模化阶段

- **机会判断**：Claude Opus/Sonnet、DeepSeek、Kimi、GLM 都在强化编程 Agent、长程任务、工具集成，研发提效进入“单点辅助 → 任务闭环”阶段。
- **可落地方向**：
  - 需求 → 改动点 → 测试用例 → 回归范围自动生成。
  - 代码审查 Agent：功能风险、安全风险、兼容风险分层输出。
  - 项目知识库 Agent：读取 PRD、会议纪要、代码结构、历史缺陷，给出交付风险。
- **对 EZR 的重点机会**：在 OpenClaw + AI Coding 流程里建立内部 benchmark，用真实 EZR 需求验证模型，不迷信公开榜单。

### 3. 风险：模型路由、数据合规、权限审计会成为 AI CRM 的基础设施

- **风险判断**：模型越强，越容易直接接触客户私域数据、交易数据、导购行为数据和企业内部系统权限。
- **主要风险**：
  - **数据合规**：海外模型处理客户私域数据可能涉及跨境和合同约束。
  - **模型路由成本**：长上下文和高阶模型容易导致 token 成本失控。
  - **私域数据外流**：提示词、日志、向量库、Agent 工具调用都可能泄露客户数据。
  - **权限审计**：computer use / browser agent 可能越权点击、导出、修改业务数据。
- **建议原则**：
  - 海外模型优先用于公开资料、技术研发、非敏感知识工作。
  - 国内模型优先用于中文业务、客户私域、需要合规约束的场景。
  - 所有 Agent 上线前必须具备：权限最小化、操作日志、人工确认点、成本阈值、安全护栏。
