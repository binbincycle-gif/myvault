# 国内外AI大模型最新情报深读（管理层版）

> 口径：优先收录厂商官方公告、官方文档和可追溯价格页。近24小时明确的海外基础模型发布不多，本期重点是开源权重、Agent运行时、国内模型生命周期与价格变化。营销软文、榜单和无明确时间戳材料已过滤。

## A. 今日结论

1. **海外的差异化正在从“更强模型”转向“可部署的 Agent 运行时”。** OpenAI 将 Codex 同源的长程 Agent harness、沙箱、工具搜索与上下文压缩开放为 Agents API；Google 维持百万级上下文的 Gemini 4 Argon；Mistral 则把 Large 4 进一步转为开放权重，企业可在主权部署与前沿能力之间获得新选项。
2. **国内进入“模型快迭代 + 可替换 + 按任务计费”的运营阶段。** Kimi K3.1 Pro 已将视觉、100万上下文与高速版作为主供给，同时集中下线 K2.x/旧 moonshot-v1；阿里百炼持续接入 1M 长上下文、多模态/实时音频和 Agent 模型；腾讯价格页在11月4日更新，峰谷、缓存和模型梯度使单价比较必须升级为任务总成本比较。
3. **EZR 的核心不是选定单一冠军模型，而是建设可审计 AI Gateway。** 客户/私域数据默认国内路由；海外模型用于经脱敏的复杂规划、代码与质量复核；所有写 CRM、外发、检索外部数据的动作都要经过最小权限、人工审批、版本锁定、成本限额与审计。

## B. 重点情报

1. **[国外｜2026-11-05] Mistral 宣布 Mistral Large 4（Le Chonk）开放权重。**
   - **变化：** 从10月发布的旗舰模型进一步转向可控部署，官方将企业“模型主权、知识与工作流控制权”作为核心定位。
   - **企业影响：** 对有私有化/区域部署要求的客户，开放权重可降低供应商锁定，但仍需验证许可证、推理成本、中文能力、工具调用稳定性与安全补丁责任。
   - 来源：[Mistral — Mistral Large 4 is now open weight](https://mistral.ai/news/mistral-large-4-oss/)

2. **[国外｜2026-10-13，近7天持续有效] Google Gemini 4 Argon 面向开发者和企业全球可用，主打百万 Token 上下文、复杂多步骤推理、编程与金融研究。**
   - **能力：** 1M 上下文使其适合跨文档研究与复杂任务编排；不能因此跳过 RAG 过滤、租户隔离与权限裁剪。
   - 来源：[Google — Gemini 4 Argon](https://blog.google/innovation-and-ai/models-and-research/gemini-models/introducing-gemini-4-argon/)

3. **[国外｜2026-09-10，近7天策略基线] OpenAI Agents API 以 Codex 的 Agent harness 为底座，提供长会话上下文压缩、工具搜索、子任务协调及托管/自托管/合作方沙箱。**
   - **能力/部署：** 可在 OpenAI 托管沙箱、企业自有基础设施或合作方环境运行；关键是把“上下文、文件、代码、工具和长程状态”变成可运营的服务。
   - **对比：** 海外领先点不只是模型能力，而是长程执行环境和 Agent 基础设施；跨境数据与执行环境选址须单独评审。
   - 来源：[OpenAI — Introducing the Agents API](https://openai.com/index/introducing-the-agents-api/)

4. **[国外｜2026-10-21，近7天趋势] Mistral 与 NVIDIA 推进 AI-native 工程工作流和推理基础设施合作。**
   - **判断：** 海外企业级竞争正在从聊天入口转入“模型 + 算力 + 工程工作流”。本窗口未检索到可核验的 OpenAI、Anthropic、Meta、xAI 新旗舰模型/API 调价公告，不以二手传闻影响选型。
   - 来源：[Mistral News](https://mistral.ai/news/)

5. **[国内｜2026-11-05 核验] Kimi 开放平台当前主力为 K3.1 Pro、K3.1 Pro HighSpeed 与 K3。**
   - **能力：** K3.1 Pro 标注为3万亿级参数、原生视觉、100万 Token 上下文，覆盖代码、3D创作与金融研究；HighSpeed 约为标准版2–3倍速度。
   - **部署影响：** 高价值深度任务可用标准版，交互/批量任务需以延迟和单任务成本评估高速版，不应只看每百万 token 单价。
   - 来源：[Kimi — 模型列表](https://platform.kimi.com/docs/models)

6. **[国内｜2026-11-05 核验] Kimi 正在系统性收敛旧模型：K2.7 Code、K2.6 已停止向新用户提供，预计2026年12月底全面下线；K2.5、moonshot-v1及多个 preview 已下线。**
   - **风险：** 生产调用若依赖 `latest`、preview 或旧模型，会面临不改业务代码但输出漂移/服务中断的风险。
   - **建议：** 建立“模型ID—版本—替代模型—回归集—下线日期”的配置台账；禁止生产环境使用无固定版本别名。

## API / 能力对照（国外 vs 国内）

| 维度 | 国外头部供给 | 国内头部供给 | 企业部署结论 |
|---|---|---|---|
| Agent | OpenAI 正在产品化 harness、长会话压缩、工具搜索、沙箱与环境选择 | 百炼/国内云将 Agentic、工具调用、实时多模态和模型聚合快速商品化 | 不绑定单一 Agent SDK；抽象任务状态、工具协议、审批和审计 |
| 上下文 | Gemini 4 Argon 以1M面向复杂研究/编程 | Kimi K3.1、Ling 3.1、MiniMax M3.1等均提供1M级供给 | 长窗口不替代RAG、字段脱敏和租户隔离 |
| 多模态 | 海外强项偏向跨应用执行、云端运行时 | 国内已覆盖视觉、视频、音频与实时双工，云接入更接近中国企业 | 录音/图片/视频需单独授权、最短留存和访问审计 |
| API/版本 | Agent API 与模型能力共同演化，平台更新快 | 模型上/下线、协议兼容、聚合平台替换更频繁 | 统一兼容层、契约测试、版本锁定、灰度和回退 |
| 价格 | 需叠加模型、执行环境、工具与网络能力成本 | 峰谷、缓存、标准/高速版、聚合平台价差更明显 | 指标从“每百万Token”切到“单任务总成本/成功率” |
| 部署与合规 | 高阶 Agent 工程能力领先，但跨境/数据主权约束高 | 国内区域云与国产模型更适合默认数据路径 | 客户和私域数据默认国内闭环；海外模型仅进脱敏增强层 |

## C. 对中国 ToB SaaS / CRM 的影响判断

### 增长
- 把模型能力封装为经营闭环而非聊天入口：销售拜访纪要转待办、商机阶段诊断、客户分层、活动复盘、导购回访建议、带证据的知识问答。
- 语音实时化为一线销售/导购场景提供新入口，但必须先做录音授权、转写校验和人工确认。

### 效率
- 建议采用“国内模型做默认批处理、长文档和涉及客户数据的任务；海外强模型做脱敏后的复杂规划/代码与质检复核”的路由策略。
- 把模型版本/替代模型/下线日期、上下文与输出上限、工具费、缓存费、SLA和数据条款接入统一配置中心，防止静默升级伤害生产流程。

### 风险
- **数据合规：** 客户画像、交易、私域对话、员工绩效和录音，默认不得未经审批出境；实现字段级脱敏、地域路由、租户隔离与处理台账。
- **成本与可用性：** 峰谷、缓存失效、搜索/工具、长上下文和失败重试可显著抬升成本；必须按任务总成本设预算阈值。
- **权限与责任：** CRM读取、创建、修改、发送必须分层授权；写回/外发/连接外部系统均需人工确认、撤回能力和完整执行审计。

## 对 EZR 的影响（单独提炼）

1. **AI Gateway 最小可用版：** 租户级模型白名单、字段级脱敏、国内/海外路由、模型版本锁定、调用审计、预算阈值、降级和回退。
2. **首批业务闭环：** 销售录音/拜访纪要 → 结构化机会与待办建议 → 销售确认 → 写回 CRM；默认禁止无确认的写回和外发。
3. **评测卡：** 以50条脱敏真实任务，比较 Kimi/DeepSeek/Qwen（或百炼聚合模型）与一款海外强模型的事实准确率、工具成功率、P95延迟、单任务总成本、人工采纳率和越权拦截率。

## D. 今日可执行动作

1. **今天完成模型生命周期盘点。** 识别生产/候选调用中所有 Kimi K2.x、`latest`、preview 与无版本别名；录入替代模型、下线日期、回归任务和回退开关。
2. **本周建设任务级成本看板。** 将输入/输出、缓存、峰谷、检索/工具、重试和人工复核都归集至“单任务成本”；先覆盖“销售纪要→CRM建议”链路。
3. **启动 AI Gateway 治理 MVP。** 先落地租户白名单、字段脱敏、地域路由、写操作审批、版本固定、执行日志与预算熔断；海外模型只允许接收脱敏后的必要上下文。
