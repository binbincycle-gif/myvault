## C. 对中国 ToB SaaS / CRM 的影响判断（增长 / 效率 / 风险）

### 增长

- **AI 导购与会员运营可以从“内容生成”升级为“任务闭环”。** 模型已具备长上下文、多模态、工具调用能力，可让 Agent 读取会员标签、交易记录、活动目标，自动生成触达策略、导购任务和复盘报告。
- **CRM 产品可以卖“经营结果”而非“AI 功能”。** 海外 Claude Science / Mistral OCR 的信号很清楚：客户买的是专业工作台和可审计产物，不是一个聊天框。
- **国产模型可支撑中小客户低成本规模化。** 高频场景如话术、总结、标签解释、商品推荐理由，可优先走国内低成本模型，把海外高端模型留给复杂策略和高价值客户。

### 效率

- **研发效率：Coding Agent 已进入可生产阶段。** GPT-5.6、Kimi K2.7 Code、GLM-5.2、多平台 coding 能力都适合纳入 AI Coding 流程，但必须有 PR 验收、测试生成、回滚方案。
- **知识库效率：文档 OCR + RAG 输入层会成为基础设施。** 合同、PRD、客户需求、Bug 复盘、培训材料需要先结构化、带置信度和来源引用，再交给 Agent。
- **运营效率：Agent 可处理跨系统任务。** 但前提是 EZR 自身系统 API、权限和日志要 Agent-ready，减少脆弱的浏览器模拟操作。

### 风险

- **数据合规**：会员手机号、交易明细、导购聊天、私域标签属于敏感经营数据，不能直接发往不明区域或无审计模型。
- **模型路由成本**：长上下文 + 多模态 + Agent 工具调用会快速放大 token 成本，需要模型网关记录每次任务的模型、输入输出 token、缓存命中、业务收益。
- **私域数据外流**：第三方模型、浏览器 Agent、MCP 工具都可能成为外流路径，必须做字段级脱敏和最小权限。
- **权限审计**：Agent 一旦能调用 CRM API，就必须保留“谁发起、读了什么、改了什么、谁审批、如何回滚”。
