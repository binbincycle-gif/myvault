## A. 今日结论（3条）

1. **海外主线不是单点模型发布，而是“Agent 工作流进入企业治理层”。** OpenAI 围绕 GPT-5.6、Microsoft 365 Copilot、ChatGPT Work、Spend Controls、Deployment Company 反复强调“Useful Intelligence per Dollar / 成功任务成本”，Mistral 则把 Prompts & Skills 做成可版本化、可审计、可回滚的生产资产。对企业来说，AI 成本管理正在从“token 单价”切换到“可验收任务产出”。

2. **国内头部模型继续在“长上下文 + 工程/Agent + 低成本专用模型 + 安全护栏”上追赶，并出现可企业部署的组合。** 智谱 GLM-5.2 与 Kimi K3 都给出 1M 上下文；Kimi K3 明确定价与工具调用能力；Qwen-MT 给出低价高并发翻译 API；Qwen3Guard 补齐实时安全检测。国内可落地优势在成本、中文、多语言、本地化与开源/私有化组合。

3. **安全与合规正在成为 Agent 规模化的第一门槛。** OpenAI GPT-Red 指向 prompt injection / 数据外流 / 工具误操作风险；Anthropic 继续强调 jailbreak 严重度框架；Qwen3Guard 提供流式安全检测；Google DeepMind 近期聚焦多 Agent 安全与 bioresilience。对 ToB SaaS/CRM，下一步不是“接一个更强模型”，而是先补齐模型路由、权限审计、私域数据边界与可回滚的 Prompt/Skill 治理。

### 1. [国外] OpenAI：GPT-5.6 成为 Microsoft 365 Copilot preferred model，进入 Office 工作流

- 厂商 / 产品：OpenAI GPT-5.6 / Microsoft 365 Copilot
- 发布时间：官方页面称 Today；本次核验时间 2026-07-18 08:14
- 证据链接：https://openai.com/index/gpt-5-6-preferred-model-microsoft-365-copilot/
- 能力变化：GPT-5.6 被用于 Word、Excel、PowerPoint、Chat、Cowork；强调更高质量输出、更少提示轮次、Excel 深度分析、跨职能 Cowork 协作；Microsoft 将通过 OpenAI API 原生接入。
- 企业部署影响：AI 不再停留在聊天入口，而进入文档、表格、PPT、协同工作流；企业采购更看重“工作产出”而不是模型名字。
- 对 ToB SaaS/CRM/EZR 的机会：CRM 内的经营分析、会员洞察、活动复盘、导购话术、客户成功报告，都应嵌入业务界面和工作流，不应只做一个独立聊天框。
- 风险：Office 生态会占据企业 AI 入口，垂直 SaaS 若不把行业数据和流程做成 Agent 能力，容易被通用办公入口截流。
- 建议动作：设计“CRM Copilot 嵌入式场景清单”：会员经营分析、活动复盘、客户分层、导购任务生成、周报自动成稿。

### 2. [国外] OpenAI：从 token 成本转向 Useful Intelligence per Dollar / 成功任务成本

- 厂商 / 产品：OpenAI / ChatGPT Work / GPT-5.6 family
- 发布时间：官方页近期发布；本次核验时间 2026-07-18 08:14
- 证据链接：https://openai.com/index/a-scorecard-for-the-ai-age/
- 能力变化：提出 AI 价值衡量应看“useful work / cost per successful task / dependability / value at scale”；GPT-5.6 分 Sol / Terra / Luna 三档，Sol 旗舰，Terra 平衡性能成本，Luna 快速低价。
- API / 价格 / Agent：强调模型族分层路由；OpenAI 文中称 GPT-5.6 Sol 在 coding agent 指标上减少输出 token，并降低估算 API 成本。
- 企业部署影响：企业 AI 成本核算会从“每百万 token 单价”升级到“每个被验收任务成本”。
- 对 ToB SaaS/CRM/EZR 的机会：EZR 的 AI 功能应建立任务级指标：每次活动方案生成成本、每次会员分析成本、每次导购任务自动分配成本、人工复核率。
- 风险：只追低价模型会导致重试、人工修正、幻觉成本变高；需要模型路由与质量评测。
- 建议动作：建立 `AI任务成本看板`，字段包括模型、token、工具调用次数、成功率、人工修正率、单任务成本。

## C. 对中国 ToB SaaS / CRM 的影响判断

### 增长机会

1. **从“AI 功能”转为“AI 工作流产品包”。** 海外已经把 AI 放进 Office 工作流，国内也具备长上下文与工具调用能力。CRM 可以包装为：活动策划 Agent、会员经营 Agent、导购任务 Agent、客户成功复盘 Agent。
2. **垂直行业数据是防御通用大模型入口的关键。** Microsoft 365 抢办公入口，但不懂服饰零售会员、导购、私域、活动转化。EZR 应把行业经验、指标口径、客户上下文做成 Agent 可调用能力。
3. **多语言与跨境品牌是低成本新增场景。** Qwen-MT 这类专用低价模型使商品文案、导购话术、活动内容的多语言批量生成更可控，可服务跨境/多地区品牌。

### 效率机会

1. **AI Coding 进入“项目级上下文”阶段。** GLM-5.2 / Kimi K3 的 1M 上下文适合研发流程改造：PRD 理解、影响面分析、测试用例、回归清单、代码评审。
2. **Prompt/Skill 应进入资产化管理。** Mistral 的版本控制方向值得直接借鉴：业务专家维护规则，技术侧负责评测、审批、灰度、回滚。
3. **成本优化要从模型路由开始。** 旗舰模型做复杂推理，轻量/专用模型做分类、翻译、摘要、质检，安全模型做护栏，才能让 AI 成本可控。

### 风险判断

1. **数据合规：** CRM 私域数据、会员手机号、消费记录、导购跟进内容必须做脱敏、权限继承、供应商边界管理。
2. **模型路由成本：** 长上下文模型输出价格高，若没有缓存、摘要层和任务验收指标，会出现“看似便宜、实际反复重试更贵”。
3. **私域数据外流：** Agent 读取网页、邮件、文件、工具响应时，prompt injection 可能诱导泄露客户资料或业务数据。
4. **权限审计：** Agent 能操作营销券、标签、群发、订单时，必须区分建议、草稿、需审批执行、禁止执行四类动作。

## D. 今日可执行动作（3条）

1. **增长动作：输出《CRM AI Agent 场景优先级清单》第一版。**
   - 先选 5 个高价值低风险场景：活动复盘、会员分层解释、导购任务建议、客户成功周报、商品/活动文案生成。
   - 每个场景定义：输入数据、输出结果、人工确认点、价值指标。

2. **效率动作：启动“长上下文模型 PoC”。**
   - 候选：GLM-5.2、Kimi K3、现有主力海外模型。
   - 测试任务：读取一个真实 PRD + 相关代码/接口文档，输出改动点、影响范围、测试用例、风险清单。
   - 验收指标：准确率、遗漏率、人工修正时间、单任务成本。

3. **风险控制动作：建立 AI Agent 上线前安全门禁。**
   - 建立 Prompt Injection 红队用例库。
   - 建立动作分级：只读建议 / 生成草稿 / 需审批执行 / 禁止执行。
   - 建立 Prompt/Skill 版本记录：Owner、上线时间、评测集、回滚点、审计日志。
