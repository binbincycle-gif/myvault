## 一句话结论

今天这组三份材料把方向基本拉清楚了：**短期用 SaaS+AI 在现有 PC/App 场景里先出结果；中长期要把 EZR SaaS 的数据、权限、业务动作和知识资产 MCP 化 / Skill 化，变成 Agent 可调用的零售经营能力底座。**

这不是“CRM 加 AI 入口”，而是从页面软件升级为：

```text
SaaS 数据 + 权限 + 知识 + 业务动作
→ MCP / Skill 能力开放
→ 内部 CSM Agent + 外部导购/门店/品牌 Agent
→ 结果回写与持续复盘
```

---

## 1）内部提效 AI：先打 CSM 场景

### 方向判断
内部 AI 第一阶段不要泛化覆盖所有流程，应该优先服务 CSM。因为 CSM 是客户问题、需求、工单、产品解释、内部协同的关键枢纽，也是当前经验最分散、重复查询最多、信息最容易断链的位置。

### 三个内部智能体
1. **需求助手**
   - 客户诉求识别
   - 需求完整性检查
   - 相似需求检索
   - 历史技术方案匹配
   - 需求初稿 / 评审摘要 / 进度跟进 / 对客反馈生成

2. **工单助手**
   - 问题分类
   - 信息补全
   - 相似工单检索
   - 处理进度汇总
   - 对客阶段性反馈
   - 工单结果沉淀

3. **知识问答助手**
   - 基于帮助中心、产品规则、指标口径、已验证技术方案回答 CSM 高频问题
   - 必须显示来源、版本、更新时间
   - 不确定时不能编答案，要转产品/研发/工单流程

### 需要开放的能力
- 玄武：需求查询、阶段、负责人、评审排期、阻塞风险、相似需求、沟通记录
- SPIDER：工单查询、分类、优先级、处理状态、历史方案、跟进记录
- 帮助中心：标准产品知识、操作方法、权限要求、指标口径、功能限制
- 技术方案：复杂定制经验、系统边界、历史案例、可复用组件、不建议方案

### 关键边界
技术方案不能直接对客承诺。涉及工作量、排期、费用、最终实现方式，必须产品或研发确认。

## 2）外部赋能 AI：围绕导购、门店、品牌三个角色

### 方向判断
外部 AI 不做泛化问答，要围绕客户组织里的真实角色做场景化智能体：

- **导购**：经营会员、发现销售机会、生成跟进策略
- **门店 / 店长**：分析经营结果、复盘门店动作、安排下一步
- **品牌总部**：快速问数、分析经营问题、形成管理判断

这与 EZR 的垂直优势一致：服饰、鞋、快消等行业不能只靠通用 Agent，需要结合行业场景、会员经营、门店动作和品牌知识做专属体验。

### 最优先外部闭环
建议先打导购会员经营助手：

```text
发现线索
→ 分析会员
→ 生成跟进理由和话术
→ 导购确认执行
→ 记录跟进结果
→ 生成下一步建议
```

因为这个闭环最贴近 EZR 的会员经营优势，也最容易证明 AI 带来一线经营价值。

### 品牌侧能力
品牌总部可以先做：
- 品牌问数
- 指标解释
- 趋势分析
- 门店 / 区域对比
- 异常发现
- 品牌分析报告
- 月度经营复盘

但品牌问数不能停在“查数据”，必须继续往“发现问题 → 下钻原因 → 生成策略 → 跟踪结果”走。

## 3）元工智能 × EZR SaaS：AI+SaaS 的长期底座

### 核心定位
元工智能和 EZR SaaS 的结合，不是加一个 AI 入口，而是两层能力分工：

- **元工智能**：Agent 创建、运行、编排、管理平台
- **EZR SaaS**：通过 MCP 提供租户权限、业务数据、业务操作能力

核心主张：

> 让每一个 EZR SaaS 品牌，都能快速拥有基于自身数据、知识和业务能力运行的品牌 Agent。

### SaaS MCP 第一阶段优先开放
1. **数据查询 MCP**
   - 品牌经营指标
   - 门店业绩
   - 会员数据
   - 会员标签和画像
   - 导购及会员经营数据
   - 活动数据
   - 交易及商品数据
   - MA 任务和触达结果

2. **人群圈选 MCP**
   - 自然语言理解经营目标
   - 转换圈选条件
   - 试算人群规模
   - 解释人群特征
   - 保存人群草稿
   - 复用历史人群规则

3. **MA 智能营销 MCP**
   - 查询可用活动和触达方式
   - 生成营销策略
   - 生成内容和话术
   - 创建 MA 任务草稿
   - 查询执行状态
   - 生成效果复盘

### 必须坚持的权限原则
Agent 默认继承当前登录用户在 EZR SaaS 中已有权限，而不是获得整个品牌租户权限。

必须映射：
- 品牌租户
- 用户身份
- 组织 / 区域 / 门店范围
- 角色权限
- 数据字段权限
- 业务操作权限

## 4）我对这组三份材料的管理判断

### 判断一：方向已经从“AI功能”升级到“AI能力平台”
今天材料里最有价值的，不是列了多少 Agent，而是把能力来源说清楚了：玄武、SPIDER、帮助中心、技术方案、SaaS 数据、品牌知识库、MCP、权限、回写。

这意味着后续不能只按产品功能推进，而要按能力底座推进。

### 判断二：内部和外部其实是一套能力的两种使用方式
内部 CSM 用的是：需求、工单、知识、技术方案。
外部客户用的是：会员、导购、门店、品牌经营、营销。

底层都需要：
- 统一身份权限
- 统一知识来源
- 统一业务对象
- 统一审计
- 统一结果回写

所以技术上不应该做成三套孤立系统，而要沉淀成可复用 MCP / Skill。

### 判断三：第一阶段必须“AI 生成，人工确认后执行”
无论内部还是外部，第一阶段都不能直接自动执行高风险动作。

尤其这些动作必须人工确认：
- 创建需求 / 工单
- 对客承诺
- 保存人群
- 创建 MA 任务
- 批量触达
- 发放权益
- 调整目标 / 考核 / 预算

## 5）建议明天推进的三个动作

### 动作 1：拉一张 AI 项目分层表
把所有 AI 项目按三层归类：

| 层级 | 项目 | 目标 |
|---|---|---|
| SaaS+AI 快速落地 | PC 数据解读、App 导购助手、CSM 问答助手 | 先出样板，验证使用价值 |
| AI+SaaS 能力开放 | 数据查询 MCP、人群圈选 MCP、MA 草稿 MCP、玄武/SPIDER 查询 | 沉淀 Agent 可调用能力 |
| Agent 平台化 | 品牌 Agent、导购 Agent、门店 Agent、CSM Agent | 形成可复制产品形态 |

### 动作 2：先定 3 个 P1 样板
建议优先：
1. **CSM 知识问答助手**：低风险、高频、内部先验证。
2. **导购会员经营助手**：最贴近 EZR 会员经营护城河。
3. **品牌问数 / 数据解读 Agent**：符合公司当前 PC 后台先添加数据解读的方向。

### 动作 3：同步启动 MCP 能力清单
不要等前端页面做完才想接口。明天就应该开始梳理：
- 数据查询 MCP v1
- 人群圈选 MCP v1
- MA 任务草稿 MCP v1
- 玄武需求查询 MCP v1
- SPIDER 工单查询 MCP v1
- 帮助中心知识检索 MCP v1

每个 MCP 都要写清：输入、输出、权限、审计、是否允许写操作、异常处理。

## 6）风险提醒

1. **项目过散风险**
   - 内部、外部、平台同时推进，容易每条线都做一点，但没有样板。
   - 建议用 3 个 P1 样板收敛。

2. **AI 入口化风险**
   - 如果只是给 PC/App 加聊天入口，会很快变成演示功能。
   - 必须接真实数据、真实权限、真实业务动作、真实回写。

3. **权限与承诺风险**
   - Agent 不能越权查数据，也不能基于历史技术方案直接对客承诺。
   - 所有高风险写操作必须人工确认。

4. **只有报告没有动作风险**
   - 品牌问数和数据解读如果不能导向人群、任务、营销、导购动作，就只是增强版报表。
   - 经营结果必须能回流 SaaS。

## 一句话沉淀

EZR 的 AI 方向不能做成一堆分散助手，而要形成一条主线：**用 SaaS+AI 先在 PC、App、CSM 场景出结果；用 AI+SaaS 把数据、权限、业务动作和知识资产封装为 MCP / Skill；最终让每个品牌拥有基于自身经营上下文运行的专属 Agent。**
