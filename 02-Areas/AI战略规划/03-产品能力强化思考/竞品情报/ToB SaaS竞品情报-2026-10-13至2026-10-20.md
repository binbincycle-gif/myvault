# ToB SaaS竞品情报（近7天，产品情报版）

## 管理摘要

本期确认 **3 条高置信新增信号**，且刚好分布在三个不同层次：

1. **政策层（品类被正式命名）**：商务部等 9 部门 10-13 印发《关于加快推进科技兴商的意见》，首次在国家级文件中把「**智能导购 / 智能运营 / 智能物流**」列为要培育的**商业智能体**业态，同时给商业智能体设了**分级治理 + 数据负面清单**的边界。
2. **产品层（AI 能力的收费方式定型）**：天猫「AI 店小蜜」双11 推出**高阶版八大权益包**，把 AI 能力做成"版本分层 + 大促限时权益"的续费抓手，而不是按调用量单独卖。
3. **风险层（SaaS 事故传导到品牌）**：中国台湾零售 SaaS 91APP 的 Commerce Cloud 数据库遭自动化攻击、部分数据被非法获取，诈骗集团随即**冒名品牌**向消费者发"定期购/自动扣款"诈骗信——品牌方承担客诉。这是多租户零售 SaaS 的典型风险传导链。

**一句话判断**：AI 在零售的竞争，已经从"谁有功能"进入"**谁的能力能被写进采购文件、被装进版本包、被审计**"的阶段。前两条给 EZR 送来了**品类词和定价结构**，第三条给 EZR 送来了**必须提前补的风险动作**。

> 与上期（2026-10-12 至 2026-10-19）重叠项（天猫超级旗舰、唯品会 AI小唯、微信小店双11补贴、有赞 POS 会员码一码收款、企微×WorkBuddy 互通、微盟参编 GEO 团标）本期**不重复入库**。

## 高置信新增信号

### 1. 商务部等 9 部门印发《关于加快推进科技兴商的意见》：首次把「智能导购」写进国家级商业智能体业态

- **厂商/主体**：商务部、中央网信办、国家发改委、教育部、科技部、工信部、文旅部、中国人民银行、市场监管总局（9 部门联合）
- **产品/能力**（官方原文，商建函〔2026〕551 号）：
  - **（十）培育商业智能体新业态**：明确"开发**智能导购、智能运营、智能物流**等专业智能体"，并推动具身智能在家庭服务、商贸物流落地；支持"云逛街、云展示"等智能消费场景。
  - **（八）推动批发零售数智化升级**：实施零售业创新提升工程，鼓励企业用数字技术优化**门店布局、进销存管理、物流配送、防伪溯源、售后管理**。
  - **（十四）夯实数智基础设施**：建设一批商贸领域**高质量数据集和可信数据空间**，推动普惠算力赋能商贸 AI 创业企业。
  - **（十五）完善安全监管治理**：对**商业智能体实行分级治理**；明确商业数据收集、使用、共享的边界与规范；**探索发布数据应用负面清单**；建立数据安全风险监测预警体系；允许在可控范围内做压力测试与沙盒试点。
  - **（十三）标准体系**：推广《人工智能终端智能化分级》系列国家标准。
  - **（十六）（十八）**：培育商业技术应用创新中心；支持智能仓储、数智供应链企业申报**专精特新**；加大财政金融支持。
- **时间**：**发文 2026-10-13**；10-19 起媒体集中解读（新华/新京报/证券之星等）

  - **无直接定价或成交信号**（政策文件）；
  - **可用的商业化信号**：文件明确"支持智能仓储、数智供应链企业申报专精特新"+"加大财政金融支持"+"普惠算力"→ 对 SaaS 厂商意味着**补贴/专项/融资通道**，对客户意味着**立项有政策依据、预算科目更容易过**；
  - **采购口径变化（最值得关注）**：`智能导购` 从厂商自造词变成**政策术语**，品牌方 IT 立项书、招标文件、集团数字化预算里大概率会开始直接引用。谁先把方案对齐这套词，谁在标书里占位。

- **对 EZR 的产品动作建议**：**决策（对外话术与方案对齐，本周可做）**
  - **立刻统一对外品类词**：把"AI导购/导购助手/智能推荐"统一表述为「**零售智能导购体**」，并在方案首页引用政策原文（第十条）——这是最低成本、最高杠杆的"权威背书"。
  - **把三个场景做成可验收清单**：智能导购（导购工作台内的推荐+话术+跟进任务）、智能运营（门店/商品/会员的异常诊断与动作下发）、智能售后（退换货与客诉归因）——每个场景给出"输入数据、AI 动作、人工兜底、验收指标"四段式。
  - **提前做"分级"预案**：把 AI 能力按 L1（仅建议，不改数据）/L2（可改数据，需确认）/L3（自动执行）分级，产品与合同里明确客户可选上限。等细则出来时，EZR 是"已支持"而不是"整改中"。

### 2. 天猫「AI 店小蜜」双11 高阶版八大权益包：AI 能力被打包成"版本分层 + 限时权益"

- **厂商/主体**：阿里巴巴 / 淘天集团（AI 店小蜜，基于千问大模型）
- **产品/能力**：面向**已签约 AI 店小蜜高阶版**的商家，双11 期间开放 **8 项限时权益**，按"风险 / 转化 / 售后 / 值守"四维组织：
  - **转化类（4 项）**：① 大促直播间导流（实时更新店铺直播状态，智能引导进直播间下单）；② 大促优惠攻略卡（活动日历+优惠+玩法聚合，支持自定义玩法与 FAQ 配置）；③ **大促跨店流失洞察**（对询单流失做归因：流向竞对 / 痛点未解 / 本店回复问题）；④ **长周期智能跟单**（客户咨询后长时间未下单，算法识别高流失风险并自动触发跟单流程）。
  - **风险类（2 项）**：⑤ 大促舆情风险预警（实时质检，识别服务升级/媒体曝光类高风险会话，推送到群）；⑥ 大促智能风险防控（主动识别恶意买家账号、**AI 生成假图**、黄牛账号，提前预警）。
  - **售后类（1 项）**：⑦ 一站式售后智能处理（退定金、退差价、查物流等高频场景交给售后 Agent，支持打通第三方工单系统）。
  - **值守类（1 项）**：⑧ 大促高峰联合值班。
- **时间**：2026-10-16 前后官宣并开放（双11 预售期 10-15 起）
- **证据链接**：
  - [投资界/清科：天猫双11正式开启，淘天金融惠商政策火力全开（2026-10-16）](https://news.pedaily.cn/20261016/140885.shtml)
  - [电商导航网：天猫双11，AI店小蜜助商家转化提升、风险防控一站式搞定（2026-10-16）](https://dsdhw.com/a/1579)
  - [派财经：同题（2026-10-16）](https://www.pai.com.cn/p/01m51myren6116ywjgzd515r8m)
- **核验时间**：2026-10-20 08:00 Asia/Shanghai
- **是否真实上线**：**是（已在大促期对高阶版商家开放，权益可在店小蜜后台"大促权益包"页查看/开通）**。但**部分能力为限时权益**（双11 后是否保留未明），且"高阶版"准入与价格未公开 → **能力真实，商务条件不透明**。
- **客户案例/定价/成交或效率信号**：
  - **效率（官方口径，未经第三方审计）**：一站式售后智能处理可使**转人工概率降低 5–10 个百分点**；
  - **关键运营数据**：部分商家**高达 20.8% 的询单流失最终流向竞争对手**——这是"跨店流失洞察"的产品立论基础，也是**导购/客服环节可量化损失的公开锚点**；
  - **定价**：**不单独收费，绑定"高阶版"订阅**。这是本期最重要的商业化信号：**AI 能力不做独立 SKU、不按 token 计价，而是作为版本升迁与续费的抓手**；大促再叠加"限时权益包"制造升级紧迫感。
- **合规风险**：**中**。①"AI 生成假图识别"涉及对消费者上传内容的判定，误判会引发客诉与平台责任争议；②"舆情风险预警"对会话做实时质检，需在商家侧明确告知与授权边界（尤其涉及消费者个人信息）；③"跨店流失归因"若对外表述为"客户流向某竞对"，存在比较性表述与数据准确性风险；④自动跟单涉及营销触达频次，需符合《网络反不正当竞争暂行规定》与平台规则。
- **对 EZR 的产品动作建议**：**决策（定价结构 + 一个能力点，本月内定）**
  - **照抄它的"收费结构"，不要照抄功能**：把 EZR 的 AI 能力收进**版本分层**（如 专业版含 N 次导购 Agent 任务/月，旗舰版含全量 Agent + 归因洞察），**不做按 token 单独售卖**。理由：客户无法预估 token 成本，按量计费会直接杀死续费率；而"版本 + 额度"能锁定 ARPU。
  - **优先抄"长周期智能跟单"这一个点**，而不是八个都抄。线下零售的对应场景更值钱：**导购加了企微、发了商品、客户没回**——EZR 完全有能力识别"高意向但沉默"的客户并自动派任务给导购。这是把 AI 直接挂到"成交"上，而不是挂在"内容生成"上。
  - **"跨店流失"在线下要换个说法**：不是流向竞对，而是"**离店未成交 / 加购未支付 / 试穿未购买**"的归因。这个口径 EZR 有独家数据（门店行为 + 导购过程），平台拿不到。
  - **不要做"恶意买家识别"**：这是平台级风控，SaaS 没有全局黑名单，做了也识别不准。线下对应风险是"导购刷单/虚假退货/薅券"，那个才该做。

### 3. 91APP Commerce Cloud 数据库遭自动化攻击：零售 SaaS 事故直接传导为品牌方客诉

- **厂商/主体**：91APP（九易宇轩，中国台湾上柜 6741）——零售云端商务 SaaS，服务大量品牌电商与门店
- **产品/能力（事件）**：Commerce Cloud 核心数据库于 **10-14 遭"自动化攻击"**，**部分资讯遭非法撷取**；公司 **10-16 在公开资讯观测站发布重大讯息**，称事件已获控制、已向警方报案，并依个资事故通报与处理程序处置。随后**多家品牌的消费者收到冒充品牌的"定期购 / 自动扣款"诈骗信**，要求操作 ATM 或提供验证码。官方**未公开实际外泄笔数与字段范围**。
- **时间**：攻击 2026-10-14；重大讯息与媒体曝光 2026-10-16；诈骗信扩散 10-17 至 10-19
- **证据链接**：
  - [数位时代：91APP电商平台遭骇！多家品牌顾客收「定期购」诈骗信（2026-10-19）](https://www.bnext.com.tw/article/92706/91app-database-attack-scam-emails)
  - [Yahoo新闻：91APP爆资安事件，Commerce Cloud资料库遭攻击、部分资讯遭非法撷取（2026-10-16）](https://tw.news.yahoo.com/91app%E7%88%86%E8%B3%87%E5%AE%89%E4%BA%8B%E4%BB%B6-commerce-cloud%E8%B3%87%E6%96%99%E5%BA%AB%E9%81%AD%E6%94%BB%E6%93%8A-%E9%83%A8%E5%88%86%E8%B3%87%E8%A8%8A%E9%81%AD%E9%9D%9E%E6%B3%95%E6%93%B7%E5%8F%96-044648493.html)
  - [东森新闻：91APP遭骇发重讯，吁防诈骗团冒名品牌行骗（2026-10-16）](https://news.ebc.net.tw/news/business/576073)
- **核验时间**：2026-10-20 08:00 Asia/Shanghai
- **是否真实上线**：**是（已发生并被公司重讯确认）**。但**外泄字段、笔数、攻击手法均未公开** → 影响面只能定性，不能定量。地域为中国台湾，**不构成大陆竞品动态，但对零售 SaaS 的产品风险设计有直接参照价值**，故按"风险信号"入库。
- **客户案例/定价/成交或效率信号**：
  - **无定价/成交信号**；
  - **可确认的传导链（这才是核心情报）**：`SaaS 多租户数据库被拖` → `会员/订单字段外流` → `诈骗集团冒名品牌` → `消费者投诉品牌` → **品牌方承担客诉与信任损失**，而事故方只承担通报与整改；
  - **品牌侧反应**：多家电商老板公开表达"他们被骇，要我们去扛"——说明**合同里的数据安全责任条款与事故赔付机制，是客户当前最不满的空洞**。
- **合规风险**：**高**。①多租户架构下"单租户数据被批量拉取"难以及时发现；②会员手机号+购买记录足以支撑精准诈骗，属《个人信息保护法》敏感组合；③事故通报时效与内容若不足，会同时触发监管与客户合同违约；④第三方（短信/物流/代运营）接口是常见侧门。
- **对 EZR 的产品动作建议**：**决策（风险控制，本周必须启动）**
  - **四个出口先堵住**：会员手机号/地址/身份证在 **① 列表导出 ② 自定义报表 ③ 测试/沙箱环境 ④ 开放 API** 四个出口做**默认脱敏 + 按角色申请 + 全量审计留痕**。这四项做完，等于把 80% 的"拖库可获利性"打掉。
  - **加"异常拉取"检测**：单账号单位时间内的**批量查询/导出次数、跨门店跨品牌查询、非工作时间大批量读取**三类行为触发告警并自动降速。成本极低，效果直接。
  - **补一份对客承诺**：在合同/服务等级里明确"数据泄露通知时限（建议 ≤24h）+ 联合处置义务 + 品牌侧公告模板"。91APP 事件里客户最愤怒的不是被攻击，是"没人告诉我该怎么办"。**这份模板本身就是销售武器**。
  - **反向做卖点**：面向服饰品牌提案时，把"多租户隔离 + 导出审计 + 泄露应急"作为独立章节——在对手刚出事的窗口期，这是最容易打动 CIO/信息安全负责人的一页。
