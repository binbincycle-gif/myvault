# ToB SaaS竞品情报（近7天，产品情报版）

## 管理摘要

本周确认 **3 条高置信新增信号**，均有明确官方版本号/上线时间与可核验证据，且都指向同一趋势：**AI/平台能力正从"独立入口"下沉进商家天天在用的工作台**（企业微信、收银台、经营后台）。

1. **企业微信 × WorkBuddy 双向深度互通**（2026-10-14）：WorkBuddy 以可对话机器人身份进入企业微信通讯录，共用企微账号体系，管理员可统一配置机器人、分配账号、管用量、采购 AI 算力并限制高敏感信息访问。这是国内最大企业连接平台正式把"企业级 Agent 运行时"接入私有域经营主链路的标志性动作，对依赖企微做会员/导购经营的 SaaS 是**架构级冲击**。
2. **千问办公电商版 Agent**（2026-10-14）：阿里系推出独立第三方电商 Agent，首批四项能力（跨平台经营看板、趋势洞察与卖点分析、爆款素材批量生成、跨平台 ROI 智能优化），并已接入生意参谋、**有赞**、千牛、阿里妈妈万相台等主流经营工具。它把"经营决策 + 内容生产 + 投放优化"打包成跨平台订阅，直接切商家经营预算。
3. **有赞门店经营闭环持续加密**（2026-10-09 / 10-13）：合伙人分账下放到微商城单店与零售单店；Android HD 支持"扫会员码自动余额卡收款"（4 步 → 1 次扫码）；本地生活约名额支持单场次活动预约。属于**收银/分账/交易履约层的真实能力交付**，不是营销话术。

未核验到近7天同时具备明确时间戳、官方上线范围、客户验收或定价证据的零售SaaS重大融资并购或财报经营信号。微盟近7天多为星启GEO的奖项/案例传播（智擎奖、金贝家政），属营销材料，已过滤。

## 高置信新增信号

### 1. 企业微信 × WorkBuddy 联合发布新版本，实现双向深度互通

- **厂商/主体**：腾讯（企业微信 5.0.12 + WorkBuddy 5.8.0）。
- **时间**：2026-10-14 发布（核验：2026-10-16 08:00 Asia/Shanghai）。
- **一句话摘要**：WorkBuddy 以可对话机器人身份进入企业微信通讯录并共用企微账号体系，企业可在企微内统一配置机器人、分配账号、管理用量与采购 AI 算力，并按组织身份限制高敏感信息访问。
- **产品/能力与影响点**：
  - **用户价值**：员工在企微侧边栏即可领取/调用智能体处理任务；企业无需另建账号体系与入口，AI 从"办公提效"走向"经营组织生产力"。
  - **功能差异**：WorkBuddy 获授消息、文档、会议、网盘等十大能力权限；支持多模型、多 Agent 按岗位/场景组合；管理员统一做账号分配与算力采购，并可按组织身份设访问权限。
  - **商业化路径**：已认证企业开放，提供限免体验名额，可"领取 / 申请开通 / 统一采购"——把 AI 算力采购变成企微内的管理项，形成新的企业级结算入口。
- **是否真实上线**：**是**（明确版本号 5.0.12 / 5.8.0 已发布，面向企微已认证企业开放）。
- **客户案例/定价/成交或效率信号**：公开报道称欧莱雅、麦当劳、比亚迪正探索落地"企业微信+WorkBuddy"方案；企微已覆盖超 1400 万家真实企业与组织、每日服务微信用户 7.5 亿。**未披露具体定价与成交金额**。
- **合规风险**：AI 获得跨消息/文档/会议/网盘权限后，数据流转路径与责任边界成为企业审计重点；企微强调"按组织身份限制 AI 访问高敏感信息"，说明权限继承与最小化访问将成为招采硬门槛。
- **对 EZR 的产品动作建议**：**决策**——把 EZR 的会员/导购经营能力做成"可被企微内 Agent 调用"的受控能力接口（客户画像查询、任务下发、结果回写），并同步设计角色授权、敏感字段屏蔽、操作审计与一键停用；优先保住"零售经营语义层 + 执行闭环"的所有权，避免只做被调用的数据源。来源链接：

  - [财新：腾讯AI办公智能体WorkBuddy打通企业微信](https://companies.caixin.com/m/2026-10-14/102493271.html)

### 2. 千问办公发布"电商版 Agent"，跨平台经营工具开放邀测

- **厂商/主体**：千问办公（阿里系）。
- **时间**：2026-10-14 发布并开启邀测（核验：2026-10-16 08:00 Asia/Shanghai）。
- **一句话摘要**：推出面向电商的独立第三方 AI 生产力工具，首批四项核心能力为跨平台经营看板、趋势洞察及卖点分析、爆款素材批量生成、跨平台 ROI 智能优化，并已接入生意参谋、有赞、千牛、阿里妈妈万相台等主流经营工具。
- **产品/能力与影响点**：
  - **用户价值**：中小商家在同一个 Agent 里完成"看经营 → 找趋势 → 出素材 → 调投放"，降低多平台切换与外包成本（厂商口径称可从数万元开店准备成本压到几百元级别）。
  - **功能差异**：定位"独立第三方、面向所有电商平台开放"，跨平台聚合数据与操作，而非绑定单一平台后台；另附潜力新品挖掘、素材裂变/诊断、预算监控、客服等能力。
  - **商业化路径**：以订阅/邀测方式向商家直接收费，跨平台属性使其可绕开单一平台生态分成；厂商称目前 20% 付费用户为电商用户。
- **是否真实上线**：**是**（已发布并开启邀测）；**尚未全量**，需以邀测开放范围为准。
- **客户案例/定价/成交或效率信号**：厂商披露 20% 付费用户为电商用户、商家覆盖店铺巡检/经营分析/订单库存/素材设计/行情监测等场景；**具体定价、客户成效数据未公开披露，不作为成交或 ROI 证据**。
- **合规风险**：跨平台抓取/汇聚经营数据涉及平台数据授权边界与"第三方代操作"责任；商家账号授权范围、投放资金自动操作权限需明确审批与留痕。

## 一线需补采的3条竞品产品信号

1. **企微内 Agent 的零售落地真实进度**：查清欧莱雅/麦当劳/比亚迪等"企业微信 + WorkBuddy"是否已进入生产环境，采集：接入的岗位与场景、权限/敏感字段控制方式、是否涉及会员数据 → 判断企微 Agent 是否会直接承接零售会员经营。
2. **第三方 Agent 与零售 SaaS 的合作条款**：向有赞等被接入方了解"千问办公电商版"合作形式（数据接口范围、是否有分成/流量互换、是否触达商家会员数据），以及它在服饰类目商家的实测效果与续费情况。
3. **门店级能力对标数据**：采集有赞"扫码即收款/合伙人分账"在服饰连锁客户的实际使用率与客诉率，以及是否带动门店 HD / 连锁版增购；同步对比 EZR 同场景的操作步数与失败回滚率。

## 今日3个产品动作

1. **增长｜把"企微内可调用的 EZR 经营能力"定义为一个可售能力包**：本周输出接口清单（会员画像查询 / 导购任务下发 / 触达结果回写）与合作模式草案（开放接口换入口/换增量），找 1–2 个已用企微经营的服饰客户做联合验证。
2. **效率｜门店端对齐"一次扫码完成关键动作"的体验基线**：梳理 EZR 收银/导购高频动作（识别会员 → 权益/储值 → 结算 → 关系绑定）的当前步数，选定 1 个最长路径本周出优化方案，验收标准减步数 ≥50% 且异常可回滚。
3. **风险控制｜给"外接 Agent 调用 EZR 数据/动作"立四道闸**：能力接口须具备角色授权、敏感字段最小化、调用审计日志与一键停用；批量触达与跨系统写回必须走审批。此清单作为所有 Agent 对接的前置准入条件。

## 结论

- **真实上线**：本周确认 3 条（企业微信×WorkBuddy 双向互通、千问办公电商版 Agent、有赞三项门店经营能力），均有官方版本/上线时间。
- **客户案例/定价/成交或效率信号**：本周未取得可公开复核的新增定价或成交数据；仅获"4 步→1 步"等产品口径的效率差异。
- **对 EZR 优先级**：最大风险来自**企微把 Agent 运行时收进企业侧**（入口与数据权属之争），最大机会来自**第三方跨平台 Agent 需要零售经营能力供给**。策略上先守"零售经营语义层 + 执行闭环"的所有权，再考虑以受控接口换外部入口。
