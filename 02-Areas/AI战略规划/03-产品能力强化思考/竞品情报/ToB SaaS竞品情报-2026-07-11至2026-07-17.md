- **CRM 侧：纷享销客正在把 AI Agent 从“演示能力”推进到“版本发布 + 开通/购买条件 + 全网状态”**，尤其是邮件线索提取、线索获取、智能报价/下单、服务 Agent、连接器动作开放，已具备真实上线追踪价值。

- **对 EZR：一边要补“AI 导购/AI CRM 的可交付闭环”，一边要重视交易后链路的自动结算、对账和售后账务固化**，这些正在成为竞品从营销工具走向经营系统的关键差异。

### 1. 纷享销客发布 20.26.0711 版本：多类 CRM Agent 与连接器能力进入版本说明

- 厂商：纷享销客
- 产品/能力：20.26.0711 版本更新；营销归因 2.0、邮件线索提取 Agent、线索获取 Agent、智能报价 Agent、智能下单 Agent、服务管理 AI Agent、集成平台连接器等
- 时间：2026-07-11（版本号 20.26.0711；核验于 2026-07-17）
- 证据链接：https://help.fxiaoke.com/f4ad/9c20
- 1句话摘要：纷享销客在 20.26.0711 版本中把营销、销售、服务、渠道、集成、PaaS、BI 多模块升级打包发布，其中多项 Agent 标注“全网”发布或明确购买/开通条件。
- 是否真实上线：是；页面明确出现“发布状态：全网/计划发布”，其中邮件线索提取 Agent、线索获取 Agent、智能报价 Agent、智能下单 Agent 等标注全网。
- 客户案例/定价/成交或效率信号：
  - 邮件线索提取 Agent：有任一纷享销客 AI 产品订单即可开启；支持高置信邮件自动存入 CRM 线索、低置信进入人工工作台。
  - 线索获取 Agent：接入 Apollo 海外数据源，具备“营销通-AI营销插件”即可开通。
  - 智能报价 Agent：标注购买“智能下单Agent”，算粒另行购买；宣称报价出单效率提升 75%。
  - 智能下单 Agent：宣称替代 90% 以上手工录入核对重复性工作。
- 产品影响点：
  - 用户价值：把线索获取、邮件询盘识别、报价、下单、服务接待、归因分析等高频流程从“人填表”推进到“Agent 辅助执行 + 人工复核”。
  - 功能差异：Agent 不只是聊天入口，而嵌入 CRM 对象、字段映射、线索写入、CPQ、连接器、服务 SLA、渠道财务等业务对象。
  - 商业化路径：AI 插件 / AI 产品订单 / 智能下单 Agent / 算粒另购，显示其 AI 能力开始走模块化售卖与用量计费组合。
- 合规风险：
  - 邮件 Agent 涉及读取企业邮箱与自动提取个人信息，需关注授权、留痕、误识别处理与敏感字段脱敏。
  - Apollo 海外线索数据源涉及跨境数据、联系人邮箱采集、营销触达合规。
  - 多连接器开放给 ShareCRM 调用后，权限边界、外部系统数据同步与审计风险上升。
- 对 EZR 的产品动作建议：
  - **决策**：把“AI 导购/AI CRM”拆成 3 个可上线 Agent 场景：会员意图识别、导购跟进建议、活动/私域线索沉淀；每个场景必须有对象写入、人工复核、结果回流。
  - **试点**：选择 1 个服饰客户，用企微聊天/导购跟进记录做“会员需求摘要 + 标签建议 + 下次触达话术”，先不要做全自动发送。
  - **观察**：持续追踪纷享销客 AI 插件、算粒、Agent 单独售卖方式，判断客户是否愿意为“业务动作自动化”单独付费。

### 2. 有赞供应链分账能力上线：连锁/直播/联营商品按 SKU 自动分账结算

- 厂商：有赞
- 产品/能力：有赞分账 - 供应链分账能力
- 时间：2026-07-07（有赞产品更新页与文章均显示 2026-07-07；核验于 2026-07-17）
- 证据链接：
  - https://www.youzan.com/whats-new
  - https://www.youzan.com/blog/articles/77764
- 1句话摘要：有赞上线供应链分账能力，支持按商品绑定供应商、成本价/比例自动拆分货款，并提供供应商自助开户、自动提现、退款逆向处理与对账能力。
- 是否真实上线：是；文章明确“有赞分账上线「供应链分账」功能”，适用“有赞连锁零售全系列版本”，并给出后台路径与开通步骤。
- 客户案例/定价/成交或效率信号：
  - 应用案例覆盖私域直播、社交电商、连锁便利门店联营商品。
  - 效率信号：替代人工导出订单、逐单匹配、线下转账和月底拆分收银流水；供应商可自助查账、提现。
  - 定价：未披露公开价格；需联系服务经理开通。
- 产品影响点：
  - 用户价值：解决多供应商、多门店、多商品联营场景下的结算效率、对账清晰度和售后退款账务一致性。
  - 功能差异：从前端商城/营销工具延伸到资金清分、供应商协同和财务凭证，增强连锁零售“经营系统”属性。
  - 商业化路径：作为分账/财务增值能力，由服务经理开通，适合绑定连锁版本做增购。
- 合规风险：
  - 涉及分账服务协议、实名认证、自动提现、银行电子回单；需要关注支付合规、账户实名、退款逆向与历史账单不可变更留痕。
  - 现金支付、标记支付等不经有赞资金的订单不参与分账，业务边界需要明确，避免客户预期错配。
- 对 EZR 的产品动作建议：
  - **观察/试点**：盘点 EZR 当前客户是否存在“联营商品、寄售、直播多供应商、门店代销”结算痛点；先用客户访谈确认是否高频。
  - **决策**：若服饰品牌中多品牌集合店/联营模式占比高，建议将“供应商结算规则 + 门店销售分账 + 退款反向冲销 + 对账单导出”纳入交易中台能力池。
  - **风险控制**：不要贸然做资金清分闭环；优先做“应结算金额计算 + 对账单 + 审批/导出”，支付划拨需单独合规评估。

## 一线需补采的 3 条竞品产品信号

1. **AI 能力是否真实可购买**：竞品 Agent 是包含在标准版本、AI 插件、算粒包，还是项目制交付？是否有最小起售价格与续费口径？
2. **是否写回业务对象**：AI 导购/AI CRM 是否能真实写回会员标签、线索、商机、跟进记录、任务、订单，还是只生成建议文案？
3. **客户真实效果**：竞品是否能提供成交率、导购跟进效率、线索转化率、人工录入减少、对账周期缩短等可量化案例，而非只讲“AI 原生/智能化”。

## 今日 3 个产品动作

1. **增长动作**：设计 EZR“会员邀请/老带新”产品清单，补齐邀请关系绑定、任务达成、奖励发放、退款回收、活动复盘字段，先服务服饰品牌的私域裂变场景。
2. **效率动作**：启动“AI 导购跟进助手”最小闭环：输入企微/会员互动记录 → 输出会员摘要、标签建议、下一步话术 → 人工确认后写回 CRM，不做全自动触达。
3. **风险控制动作**：建立 AI 与资金类能力的产品红线：AI 涉及邮箱/企微/会员数据必须有授权与审计；分账/结算类能力先做对账和审批，不直接做资金划拨。
