# 2026-09-18 业务Skill学习记录（Day35）

## 学习内容
阅读《业务Skill学习手册》Day29《Skill安全边界：权限、审批、回滚与人工确认》。

核心判断：**业务 Skill 一旦从“生成建议”进入真实经营动作，权限、审批、审计、回滚不是技术附属，而是产品能否规模交付的前置能力。**

Skill 权限不能只按账号判断，必须同时校验：

```text
身份：谁在调用（总部运营 / 店长 / 导购）
场景：在查询、生成建议、提交审批，还是执行动作
动作：准备读取什么数据、修改什么状态、触达谁
```

动作分级：

- **L0 只读查询**：查看数据、读取知识库、生成摘要。
- **L1 建议生成**：生成话术、清单、诊断结论。
- **L2 半自动执行**：人确认后提交执行。
- **L3 自动执行**：系统直接发券、触达、改价、改配置；默认不放开，必须具备明确权限、额度、审计与回滚。

## 与当前主线的连接

智能导购 MVP 应坚持“先建议、后确认、再灰度半自动”的路径，而不是追求一次到位的自动触达。

以“沉默会员唤醒”为例：

```text
允许：导购读取本人会员池、生成重点客户排序与一对一话术建议
人工确认：实际发送、触达渠道选择、是否使用权益
审批：批量发券、高面额权益、跨门店触达
禁止默认自动：群发、越权查看其他导购会员、修改会员等级或核心标签
```

同时，CRM 的实时判权必须是 Skill 调用的底座；记忆与策略沉淀只保留脱敏经验模式，不能替代 SaaS 对会员数据和操作范围的实时授权。

## 今日练习：智能导购 Skill 安全边界表 v0.1

| 项目 | 一期定义 |
|---|---|
| Skill 名称 | 导购沉默会员唤醒 Skill |
| 调用角色 | 导购、店长、总部运营；管理员仅配置规则 |
| 可读数据 | 导购本人会员池；店长本店汇总与授权范围；总部仅汇总和规则配置 |
| 可生成内容 | 唤醒优先级、原因解释、单客话术、权益建议 |
| 可执行动作 | 仅生成待发送任务；不直接对客户发出 |
| 人工确认点 | 每一条触达、渠道、权益使用均由导购确认 |
| 审批条件 | 批量触达、高面额权益、跨门店客户、策略版本发布 |
| 回滚方式 | 撤销待发送任务、停用策略版本、修正标签并留纠偏记录 |
| 审计记录 | 调用人、数据范围、输入、建议、确认/拒绝、执行结果、规则版本 |

## 今天的一个动作

在智能导购 MVP 评审里新增“安全边界”作为准入项。责任人需按上表明确 L0-L3 动作等级；任何涉及客户触达、权益、标签变更的能力，未明确实时判权、人工确认、审计和回滚，不进入开发承诺。

## 晚间复盘问题

1. 今天讨论的智能导购动作，是否明确了“AI 能建议什么”和“AI 能替人执行什么”的边界？
2. 真实执行时，权限是否仍由 SaaS 按调用当下的角色、组织和数据范围校验？
3. 如果规则或触达发生错误，是否能在分钟级停用、追溯并纠偏？

## 一句话总结

> 没有实时判权、人工确认、审计与回滚的业务自动化，不是产品能力，而是把经营风险放大。
