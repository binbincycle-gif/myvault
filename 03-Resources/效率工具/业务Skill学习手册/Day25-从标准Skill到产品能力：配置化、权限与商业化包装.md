# Day25｜从标准 Skill 到产品能力：配置化、权限与商业化包装

## 今日主题

Day24 解决的是：一个 Skill 通过 MVP 后，如何整理交付包并逐层复制。

Day25 往前走一步：**当一个 Skill 已经能跨团队、跨客户复制时，如何判断它是否应该产品化，以及产品化前必须补齐哪些能力。**

> Skill 产品化，不是把一个内部工具加到菜单里，而是把稳定业务能力变成可配置、可授权、可审计、可计费、可运营的产品能力。

---

## 技术原理（技术视角）

### 1. 标准 Skill 与产品能力的差别

| 维度 | 标准 Skill | 产品能力 |
|---|---|---|
| 使用范围 | 试点团队 / 指定客户 | 多客户、多角色、可持续交付 |
| 配置方式 | 依赖实施或研发调整 | 后台可配置、可模板化 |
| 权限控制 | 基础身份校验 | 角色、组织、数据范围、敏感动作分层控制 |
| 结果反馈 | 人工复盘为主 | 结构化回写、可统计、可优化 |
| 风险治理 | 靠使用说明约束 | 审计、审批、回滚、异常告警 |
| 商业表达 | 能用 | 能卖、能续、能证明价值 |

判断标准很简单：

> 如果一个 Skill 每次落地都需要研发重新改逻辑，它还只是交付工具；如果客户可以通过配置适配自己的业务口径，它才开始接近产品能力。

### 2. 产品化前必须补齐 5 件事

1. **配置化**：客户差异不能都写死在代码里。
2. **权限化**：不同角色看到的数据、能执行的动作必须不同。
3. **可观测**：调用次数、采纳率、成功率、异常率必须能看见。
4. **可回滚**：错误建议、错误触达、错误配置必须能停、能查、能恢复。
5. **可定价**：要能说明这个能力到底替客户节省了什么、提升了什么。

### 3. 产品化不是一步到位，而是三层演进

```text
内部 Skill
  ↓
交付型 Skill 模板
  ↓
产品化 AI 能力
```

- 内部 Skill：先服务团队自己，把能力跑通。
- 交付型 Skill 模板：能给指定客户交付，但仍需要实施配置。
- 产品化 AI 能力：客户可配置、可授权、可持续运营，并能纳入产品定价或续费价值。

---

## 业务翻译（业务视角）

业务上可以这样理解：

> 一个 Skill 如果只能“帮我们干活”，是效率工具；如果能“帮客户稳定产生经营结果”，才是产品能力。

管理者今天要盯三句话：

1. 不要把内部提效工具误包装成客户产品。
2. 不要把一次成功交付误认为标准能力。
3. 只有能配置、能控权、能复盘、能证明价值，才值得进入产品路线图。

## 典型场景（EZR 业务版）

### 场景：导购会员跟进建议 Skill 产品化

试点阶段，这个 Skill 可能只是：
- 输入会员数据；
- 输出重点跟进名单；
- 给导购一段推荐话术。

但产品化以后，至少要补齐：

| 能力 | 要解决的问题 |
|---|---|
| 品牌策略配置 | 不同品牌的会员分层、活动目标、权益策略不同 |
| 门店 / 导购权限 | 导购只能看自己权限内会员，店长看门店，区域看区域 |
| 话术模板管理 | 不同品牌语气、活动政策、禁用词不同 |
| 触达审批边界 | 发券、承诺折扣、敏感关怀不能自动执行 |
| 结果回写 | 是否采纳、是否触达、是否成交、客户反馈必须回流 CRM |
| 效果看板 | 采纳率、成交率、复购率、沉睡唤醒率要可追踪 |

### 管理判断

如果导购用了以后只是觉得“建议挺像回事”，还不够。

产品化判断要看：
- 是否减少导购筛选客户时间；
- 是否提升触达质量；
- 是否带来复购、转化或沉睡唤醒；
- 是否让店长/运营更容易管理过程；
- 是否能成为续费或增购理由。

## 管理者关注点（增长 / 效率 / 风险）

### 1. 增长

优先产品化那些能直接支撑客户经营结果的 Skill，例如会员唤醒、导购跟进、活动复盘、客户风险识别。

### 2. 效率

产品化不是多做页面，而是减少每次交付的重复解释、重复配置、重复研发。

### 3. 风险

涉及会员数据、营销触达、权益发放、客户承诺的 Skill，必须先有权限、审批、审计和回滚机制，再扩大客户范围。

---

## 今日练习

选一个已经跑通过 MVP 的 Skill，用下面 4 个问题判断它是否具备产品化条件：

1. 客户差异能不能靠配置解决？
2. 权限边界是否清楚？
3. 结果能不能结构化回写？
4. 客户是否能感知到明确经营价值？

如果 4 个问题答不清楚，今天不要急着产品化，先补交付包和运营看板。

---

## 今日一句话

> Skill 产品化的关键，不是“能不能做出来”，而是“换客户、换角色、换场景后，是否还能安全地产生可证明的经营结果”。
