# Day23｜MVP 试点复盘：判断是否值得放大

## 今日主题

Day22 讲的是：如何把 Skill 蓝图压缩成 1-2 周可以验证的 MVP。

Day23 继续往前走一步：**MVP 跑完后，如何判断这个 Skill 值不值得继续投入、放大或下线。**

> 业务 Skill 的复盘，不是看“AI 回答得像不像人”，而是看它有没有推动真实业务动作，并且这些动作是否值得被组织复制。

---

## 技术原理（技术视角）

### 1. Skill MVP 复盘要看四层证据

| 层级 | 要回答的问题 | 典型证据 |
|---|---|---|
| 调用证据 | 目标角色有没有真的用 | 调用次数、连续使用天数、使用人数 |
| 动作证据 | 使用后有没有产生业务动作 | 触达、建单、回访、补充记录、发起审批 |
| 结果证据 | 动作有没有带来结果变化 | 转化、成交、响应、节省时间、减少返工 |
| 沉淀证据 | 是否产生可复用经验 | 有效判断规则、话术模板、反馈字段、风险边界 |

如果只有调用，没有动作，说明 Skill 可能只是“看起来有用”。

如果有动作但无结果，说明需要调整判断逻辑或适用场景。

如果有结果但无沉淀，说明它还是个人工具，没有变成组织资产。

### 2. 复盘要区分三类结论

Skill MVP 跑完后，不要只给“成功/失败”两个判断。建议分成三类：

1. **值得放大**：使用稳定、动作真实、结果有改善、风险可控。
2. **继续小范围迭代**：场景成立，但输入、输出或反馈字段还不稳定。
3. **暂停/下线**：用户不用、动作不发生、结果不可证明，或风险成本高于收益。

这能避免两种常见问题：
- 因为一次演示效果好就盲目扩张。
- 因为早期数据不完美就过早否定。

### 3. 复盘数据要提前埋，不要事后补

Skill MVP 试点前就要确定最少 5 个字段：

```text
调用人：谁用了
调用时间：什么时候用
推荐对象/任务：AI 建议处理什么
人工采纳状态：用了 / 改了 / 没用
结果反馈：客户反应、成交、未成交原因、异常说明
```

没有这些字段，复盘就会退化成“大家感觉怎么样”。

## 业务翻译（业务视角）

业务上可以这样理解：

> Skill MVP 复盘，就是判断这条 AI 行动链是否值得从“一个试点”变成“一个组织标准动作”。

管理者今天要盯住三句话：

1. 不看演示，看真实使用。
2. 不看生成内容，看业务动作。
3. 不看单次亮点，看是否能被复制。

---

## 典型场景（EZR 业务版）

### 场景：导购会员跟进建议 Skill 复盘

**试点目标**：AI 是否能帮助导购更快找到值得跟进的会员，并推动有效触达。

### 复盘口径

| 复盘项 | 判断问题 | 示例标准 |
|---|---|---|
| 使用 | 导购是否连续使用 | 3-5 名导购连续 5 天使用 |
| 采纳 | AI 建议是否被采用 | 推荐名单/话术采纳率 ≥50% |
| 动作 | 是否产生真实触达 | 触达反馈记录率 ≥70% |
| 结果 | 是否带来经营改善 | 客户响应率、复购线索、成交转化有提升趋势 |
| 风险 | 是否出现越权或误导 | 无自动触达、无越权查看、无高风险话术 |
| 沉淀 | 是否形成可复用资产 | 留下有效推荐规则、话术模板、反馈字段 |

### 三种决策

```text
A. 放大：增加门店 / 导购范围，进入灰度发布。
B. 迭代：继续优化推荐逻辑、话术结构、反馈字段。
C. 暂停：场景先不扩大，回到蓝图阶段重新定义问题。
```

## 管理者关注点（成本 / 效率 / 风险）

### 1. 成本

不要让一个不确定的 Skill 无限试点。每轮 MVP 必须有复盘时间和继续投入条件。

### 2. 效率

复盘会议不要变成功能评审会，只回答三个问题：有没有人用、有没有动作、值不值得放大。

### 3. 风险

凡是涉及客户触达、权益、订单、敏感数据的 Skill，放大前必须补齐权限、审计、人工确认和异常回滚机制。

### 4. 组织沉淀

复盘后至少沉淀一份资产：规则、模板、字段、边界或下线原因。否则试点结束后组织没有变强。

## 本日自检

1. 这个 Skill MVP 的调用数据是否真实？
2. 用户用了之后是否产生了业务动作？
3. 动作结果是否有反馈字段支撑复盘？
4. 继续放大的风险是否可控？
5. 本轮试点沉淀了什么可复用资产？

---

## 一句话总结

**MVP 复盘不是证明 AI 很聪明，而是证明一条业务动作链值得被复制：有人用、有动作、有结果、有沉淀，才值得放大。**
