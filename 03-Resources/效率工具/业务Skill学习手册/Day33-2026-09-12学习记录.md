# 2026-09-12 业务Skill学习记录（Day33）

## 学习内容
阅读《业务Skill学习手册》Day32《业务Skill安全边界与结果沉淀联动》。核心不是再补一层权限，而是把 Skill 的**安全治理**与**结果学习**接成同一条闭环：

```text
调用身份 → 数据权限校验 → 建议输出 → 风险分级 → 人工确认/审批
→ 执行动作 → CRM结果回写 → 经验沉淀或异常纠偏
```

关键要点：
1. 一个可追溯的业务 Skill，必须同时记录结果与责任：谁调用、看了什么、建议了什么、谁确认、执行了什么、结果如何。
2. 沉淀要分层：运行日志保留过程；项目记忆保留已确认的客户规则与异常；组织知识只沉淀人工确认、可跨项目复用的规则和模式。
3. 权限不能只按“是否能打开 Skill”判断，必须按“身份 + 数据范围 + 业务动作 + 风险等级”判定。
4. 对导购沉默会员唤醒，优先跑 L1 建议生成 → L2 导购确认后创建任务/单条触达 → CRM 回写的半自动闭环；批量触达、高面额权益、跨门店触达仍停留在审批边界内。

## 与当前主线的连接
智能导购不是做一个会生成话术的助手，而是把“识别机会—导购确认—触达—结果回写—规则迭代”变成可治理的经营动作。

第一阶段必须守住三条红线：
- 会员数据不进入长期记忆，实时按 SaaS 身份与数据范围判权；
- 先建议、后确认，不以“自动化率”替代经营结果；
- 只有脱敏且经人工确认的有效模式，才进入组织知识与 Skill 规则。

## 今日练习：导购沉默会员唤醒 Skill 安全与沉淀联动表

| 环节 | 当前应明确的设计 |
|---|---|
| 调用身份 | 导购代表本人岗位工作；店长可查看本门店汇总与审核；总部运营只配规则与看汇总 |
| 数据边界 | 导购仅可读取本人客户池的会员、交易、跟进与权益状态；禁止跨导购/跨门店读取明细 |
| 输出等级 | L1：机会排序、推荐商品/权益、话术建议；L2：导购确认后创建跟进任务或发起单条触达 |
| 人工确认 | 每次实际发送、权益选择、客户标签修正均由导购确认；店长对门店规则例外确认 |
| 审批条件 | 批量触达、高面额权益、跨门店触达、批量标签变更必须进入审批 |
| 执行记录 | 留存调用人、代表岗位、数据范围、模型/规则版本、建议、确认人、触达动作与时间 |
| 结果回写 | 是否采纳、是否触达、渠道/话术版本、回复/到店/成交、未采纳原因、异常原因 |
| 沉淀规则 | 客户明细与原始对话只留在运行/项目记录；脱敏且验证有效的话术、权益组合、规则进入组织知识 |
| 纠偏机制 | 支持撤销待发送任务、停用权益规则、版本回退；错误标签必须可人工修正并标注纠偏原因 |

## 今天的一个动作
在智能导购 MVP 的需求/方案评审中，要求补齐上述九项，不接受只写“人工确认、注意权限”的泛化描述；并把一期范围限定为 **L1 建议 + L2 单条确认执行 + CRM 结果回写**。

## 晚间复盘问题
1. 今天是否明确了一个真实角色的“身份—数据—动作—责任”链，而不是只画了功能流程？
2. 结果回写字段是否能支撑判断：建议有没有被采纳、是否完成触达、有没有带来经营结果？
3. 哪一类高风险动作仍没有明确审批、审计或回滚，不能进入一期？

## 一句话总结
> 可进化的业务 Skill，不是把更多结果写进记忆，而是在安全边界内完成动作、回写证据，并只把被验证的经验沉淀为组织资产。
