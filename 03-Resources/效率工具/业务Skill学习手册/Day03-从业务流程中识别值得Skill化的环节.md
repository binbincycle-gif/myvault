# Day03｜从业务流程中识别值得 Skill 化的环节

## 今日主题
很多团队开始做 Skill 时，第一反应是把整条业务流程全部拆开，恨不得每一步都做成 Skill。结果最后 Skill 一大堆，但真正有价值、被高频使用的并不多。原因很简单：**不是流程里的每个环节都值得 Skill 化。**

今天要建立的认知是：Skill 化不是“拆得越细越好”，而是先识别出那些**高频、高价值、可复用、可标准化**的业务动作。

## 一、先从业务流程看问题
大多数业务流程都可以抽象成四段：
1. 识别机会
2. 做判断
3. 执行动作
4. 结果反馈

如果你拿零售 CRM 来看，这四段可能分别是：
- 识别高潜会员
- 判断该推荐什么商品
- 给导购下发跟进动作
- 回收跟进和成交结果

不是每一段都应该优先 Skill 化。

## 二、优先 Skill 化什么
### 1. 高频环节
如果一件事每天都在做、每周都在做，就值得优先考虑 Skill 化。

### 2. 高价值环节
如果这个动作直接影响成交、效率、质量、客户体验，它的 Skill 化优先级就高。

### 3. 可复用环节
如果这个动作不止一个人会做，而是多个角色、多个流程都会用到，它更适合做成 Skill。

### 4. 可标准化环节
如果输入和输出根本说不清，那先别急着 Skill 化。Skill 的前提是它可以被标准描述。

## 三、哪些环节最值得先做
通常来说，最值得先做的不是“页面展示”或“信息搬运”，而是：
- 做判断的环节
- 执行动作的关键环节

例如：
- 高潜客户识别
- 商品推荐
- 重点客户跟进建议
- 标签洞察
- 活动效果分析

这些能力一旦做成 Skill，不只是一个页面用得到，而是多个入口都能调用。

## 四、哪些环节暂时不要急着做
### 1. 纯展示环节
比如排序展示、颜色提示、图标状态，这些更多是 UI 层逻辑。

### 2. 低频边缘环节
如果一年只用几次，先不要着急 Skill 化。

### 3. 需要大量人工判断、还没形成稳定规则的环节
这类能力先用流程沉淀，等稳定后再 Skill 化。

## 五、一个简单判断法
当你看到一个业务动作时，问自己 4 个问题：
1. 这件事是不是经常发生？
2. 这件事是不是直接影响结果？
3. 这件事是不是不止一个人会用？
4. 这件事的输入和输出能不能描述清楚？

如果 4 个问题里至少有 3 个答案是“是”，那这个动作就值得进入 Skill 候选池。

## 六、今天最重要的认知
Skill 化不是把流程拆碎，而是先挑出最值得沉淀的能力节点。

所以真正成熟的做法不是：
- 有流程就拆 Skill

而是：
- 有业务价值、有复用空间、有标准边界，才做 Skill
