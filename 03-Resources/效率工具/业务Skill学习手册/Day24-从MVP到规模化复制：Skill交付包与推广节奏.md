# Day24｜从 MVP 到规模化复制：Skill 交付包与推广节奏

## 今日主题

Day23 解决的是：MVP 试点跑完后，如何判断一个 Skill 值不值得放大。

Day24 往前走一步：**当一个 Skill 被判断为“值得放大”后，如何把它从一个试点能力，变成多个团队、多个客户场景都能复用的组织资产。**

> Skill 放大，不是把使用范围一口气扩大，而是把“能跑通的经验”整理成交付包，再按节奏复制。

---

## 技术原理（技术视角）

### 1. 规模化复制前，先做 Skill 交付包

一个能被复制的 Skill，至少要有 6 个交付件：

| 交付件 | 解决的问题 | 示例 |
|---|---|---|
| 触发说明 | 什么时候该用 | 导购每日会员跟进、运营活动复盘、客户风险识别 |
| 输入要求 | AI 需要什么上下文 | 会员池、交易记录、触达历史、商品偏好、权限身份 |
| 输出标准 | AI 应该给什么结果 | 推荐名单、原因解释、话术、风险提示、下一步动作 |
| 人工确认点 | 哪些地方必须人判断 | 是否触达、是否发券、是否提交审批、是否升级客户 |
| 反馈字段 | 如何知道有没有效果 | 采纳/未采纳、触达结果、成交结果、异常原因 |
| 风险边界 | 哪些动作不能自动做 | 越权查看、自动营销、敏感承诺、大额权益发放 |

没有交付包，放大就会变成“口口相传”；一换团队、一换客户，效果就散掉。

### 2. 放大节奏要分三层

Skill 放大建议按三层推进：

```text
小范围复制：同一团队 / 同类场景，再跑 1-2 周
跨团队复制：换一个团队或角色，验证是否仍然成立
客户化复制：进入真实客户场景，补齐权限、审计、交付与培训
```

这能避免两个常见误区：
- 一个团队跑通，就误以为所有团队都适用。
- 一个客户能用，就误以为已经具备标准产品能力。

### 3. 技术放大要检查三件事

1. **上下文是否稳定**：不同团队、不同客户的数据字段和业务口径是否一致。
2. **权限是否可控**：Skill 是否能识别身份、角色、组织范围和敏感动作。
3. **反馈是否闭环**：使用结果是否能回写，是否能形成后续优化样本。

如果这三件事没检查，规模化推广越快，风险越大。

## 业务翻译（业务视角）

业务上可以这样理解：

> Skill 规模化，不是“让更多人试试”，而是“把一套有效动作变成可复制打法”。

管理者今天要盯住三句话：

1. 先标准化，再扩大范围。
2. 先复制动作链，再复制功能入口。
3. 每扩大一层，都要重新验证使用、动作、结果和风险。

## 典型场景（EZR 业务版）

### 场景：导购会员跟进建议 Skill 放大

**试点已验证**：3-5 名导购连续使用，AI 推荐名单和话术有一定采纳率，并产生真实触达记录。

### 放大前交付包

| 模块 | 内容 |
|---|---|
| 使用对象 | 导购、店长、区域运营 |
| 触发时机 | 每日开店前、活动前一天、会员沉默预警后 |
| 输入数据 | 会员池、最近消费、触达历史、商品偏好、活动信息 |
| 输出结果 | 今日重点跟进会员、推荐理由、建议话术、风险提示 |
| 人工确认 | 导购确认是否触达；店长确认是否升级重点客户 |
| 反馈字段 | 是否采纳、是否触达、客户反馈、是否成交、未成交原因 |
| 风险边界 | 不自动发送消息；不自动发券；不跨门店查看会员 |

### 推广节奏

```text
第 1 步：同门店多导购复制，验证新导购是否也能用。
第 2 步：同品牌不同门店复制，验证门店差异是否影响效果。
第 3 步：不同品牌试点复制，验证行业/客户差异是否需要配置化。
第 4 步：沉淀为标准 Skill 模板，进入产品化或交付包。
```

### 管理判断

如果一个 Skill 只能靠某个强导购、某个产品经理、某个技术同学盯着才有效，它还不是组织资产。

真正值得放大的 Skill，要做到：
- 换人还能用；
- 换店还能跑；
- 换客户能配置；
- 出问题能追责；
- 有结果能复盘。

## 管理者关注点（成本 / 效率 / 风险）

### 1. 成本

不要让每个客户、每个团队都重新试错。MVP 通过后，必须把触发条件、输入输出、风险边界和反馈字段整理成标准包。

### 2. 效率

推广时不要先培训一堆概念，直接给角色一个固定动作：什么时候打开、输入什么、看哪个结果、反馈什么字段。

### 3. 风险

Skill 一旦放大，风险不再是“回答错一句”，而是“错误动作被组织复制”。涉及客户触达、权益、订单、财务、敏感数据的场景，必须保留人工确认、审批和审计。

### 4. 组织沉淀

规模化的最终目标不是让更多人用 AI，而是让组织多一套可复制的业务动作链。

## 本日自检

1. 这个 Skill 是否已经有完整交付包，而不是只有演示稿？
2. 换一个团队或客户后，输入数据和业务口径是否还能成立？
3. 哪些动作必须人工确认，哪些可以自动化？
4. 推广后如何判断效果是变好、变差还是不可解释？
5. 本轮推广结束后，能沉淀成标准产品能力，还是只能停留在项目经验？

---

## 一句话总结

**Skill 放大的关键不是“扩大使用人数”，而是把一个有效试点沉淀成交付包，再按同团队、跨团队、客户化的节奏复制成组织资产。**
