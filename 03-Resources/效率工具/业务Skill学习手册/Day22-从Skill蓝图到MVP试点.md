# Day22｜从 Skill 蓝图到 MVP 试点

## 今日主题

Day21 解决的是：如何从客户场景拆出 Skill 蓝图。

Day22 要继续往前走一步：**如何把蓝图压缩成一个可以在 1-2 周内验证的 MVP 试点。**

> 业务 Skill 不怕小，怕的是一开始就做成“大平台、大闭环、大而全”。MVP 的目标不是证明想象力，而是证明一个真实动作能不能带来可复盘的业务结果。

---

## 技术原理（技术视角）

### 1. Skill MVP 不是功能删减版，而是最小可验证闭环

一个 Skill MVP 至少包含 5 个要素：

| 要素 | 要回答的问题 | 示例 |
|---|---|---|
| 触发场景 | 什么情况下调用 Skill | 导购每天早上查看今日跟进会员 |
| 必要输入 | 没有它就无法判断的数据 | 会员最近消费、偏好、触达记录 |
| 核心判断 | AI 必须做对的一件事 | 判断为什么这个会员值得跟进 |
| 可执行输出 | 使用者能直接拿去做什么 | 推荐理由 + 跟进话术 + 风险提醒 |
| 反馈回流 | 如何知道结果好不好 | 是否触达、会员反应、是否成交 |

如果 MVP 只有生成内容，没有反馈回流，它只是演示；如果有反馈回流，才有机会变成组织能力。

### 2. MVP 要先砍掉三类东西

为了让试点跑起来，必须主动砍范围：

1. **砍角色**：先服务一个角色，不要同时覆盖导购、店长、运营、总部。
2. **砍动作**：先验证一个关键动作，不要一口气做完整经营链路。
3. **砍自动化**：先人审后执行，不要一开始让 AI 自动触达客户或自动发券。

这不是保守，而是为了减少不必要的失败噪音。

### 3. MVP 验收要看“业务动作是否发生”

不要只看模型回答是否流畅，要看三类结果：

| 维度 | 验收问题 |
|---|---|
| 使用 | 目标角色是否愿意真的用？ |
| 动作 | 使用后是否产生了真实业务动作？ |
| 回流 | 动作结果是否被记录，能否复盘？ |

## 业务翻译（业务视角）

业务上可以这样理解：

> Skill MVP，就是把一个看起来完整的 AI 业务想法，压成一条最短、最能证明价值的行动链。

管理者今天要盯住三句话：

1. 先别问“最终平台长什么样”，先问“这周谁会用它做哪一个动作”。
2. 先别追求全自动，先让 AI 给建议、人来确认、系统做留痕。
3. 先别追求指标大而全，先证明使用、动作、反馈三件事成立。

---

## 典型场景（EZR 业务版）

### 场景：导购智能体的第一个 MVP

**业务目标**：让导购每天更快找到值得跟进的会员，并完成一次有理由、有话术、有记录的触达。

### MVP 范围

| 项目 | MVP 选择 |
|---|---|
| 角色 | 导购 |
| 场景 | 每日会员跟进 |
| 触发 | 每天上班后查看今日跟进建议 |
| 输入 | 会员消费记录、偏好、最近互动、活动/权益 |
| 输出 | 3-5 个优先跟进会员 + 推荐理由 + 话术 |
| 人工确认 | 导购决定是否采用话术与是否触达 |
| 反馈 | 是否触达、客户反应、未成交原因 |

### 最小链路

```text
会员机会识别 → 推荐理由 → 导购话术 → 导购确认 → 触达反馈记录
```

### 暂时不做

- 不自动替导购发消息
- 不自动发券
- 不覆盖所有会员运营场景
- 不做复杂组织级经验库
- 不追求画像一次性完美

这些可以后置，先验证“AI 建议是否能推动导购行动”。

### 示例

```text
Skill MVP 名称：导购会员跟进建议 Skill
服务角色：导购
挂靠业务场景：每日会员跟进
本周只验证的一件事：AI 能否帮助导购找到更值得跟进的会员
必要输入：会员最近消费、偏好、互动、权益
核心输出：跟进名单、推荐理由、话术建议
人工确认点：导购确认是否采用与是否触达
反馈字段：是否触达、客户反应、是否成交、未成交原因
成功标准：试点导购连续 5 天使用；触达反馈记录率 ≥70%
风险边界：不自动发消息、不自动发券、不越权查看会员
试点范围：1 个品牌 / 3-5 名导购 / 1 周
复盘时间：每晚看使用与反馈，周末看转化趋势
```

## 管理者关注点（成本 / 效率 / 风险）

### 1. 成本

MVP 要小到 1-2 周能跑完，最好只涉及一个角色、一个动作、一组反馈字段。

### 2. 效率

MVP 的核心产物不是页面，而是可复用的业务 Skill 定义：触发、输入、输出、确认、反馈。

### 3. 风险

越靠近客户触达和权益发放，越要坚持人审、留痕、权限控制。试点阶段不要让 AI 直接做不可回滚动作。

### 4. 组织沉淀

每个 MVP 结束后都要沉淀三件事：

1. 哪个判断有效
2. 哪个动作被使用
3. 哪个反馈字段值得长期保留

## 一句话总结

**从 Skill 蓝图到 MVP，关键不是把能力做完整，而是把一条最短业务行动链跑通：有人用、有动作、有反馈、有边界。**
