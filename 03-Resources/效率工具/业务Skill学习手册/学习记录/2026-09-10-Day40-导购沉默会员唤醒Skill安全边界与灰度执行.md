# 2026-09-10 Day40｜导购沉默会员唤醒 Skill 安全边界与灰度执行

## 今日阅读

复习《业务Skill学习手册》Day29《Skill 安全边界：权限、审批、回滚与人工确认》，并承接 Day39《导购沉默会员唤醒 Skill 上线前检查与灰度准入》。

## 我今天抓到的核心一句话

**灰度准入解决“能不能上线”，安全边界解决“上线后谁能以什么权限做什么，以及出错后怎么止损”。**

## 结合 EZR / OpenClaw / 智能导购的理解

导购沉默会员唤醒 Skill 在首版不应追求自动群发或自动发券，而应保持在：

```text
L0/L1：取数、诊断、客户排序、话术和商品建议
L2：导购逐条确认后创建触达或跟进动作
L3：默认不开；批量触达、高额权益、跨门店客户动作必须走审批、限额和审计
```

OpenClaw/Agent 可以编排“筛选—解释—建议—待执行清单”，但不能成为绕过 CRM 权限、业务状态和责任归属的旁路。CRM 必须继续承担实时判权、动作落库、结果回写和审计事实源角色。

## 今日形成的安全边界表

| 项目 | 首版规则 |
|---|---|
| 调用角色 | 试点门店的指定导购、店长；总部运营仅做规则配置和监控 |
| 可读数据 | 导购仅可读本人/授权门店会员池内的脱敏经营信息；不开放跨店明细 |
| 可生成内容 | 沉默会员优先级、推荐原因、话术、推荐商品/权益建议 |
| 可执行动作 | 创建待触达任务、保存跟进记录；实际发送须导购本人确认 |
| 人工确认点 | 触达渠道、发送文案、具体客户、是否发券，均需确认 |
| 审批条件 | 批量触达、高额权益、跨门店触达、规则变更，需店长/总部按规则审批 |
| 限额与止损 | 首期单人每日触达量、权益额度设上限；异常可一键停止当日待执行队列 |
| 回滚方式 | 未发送任务可取消；错误标签/任务记录需保留修正痕迹；已发权益按原业务规则撤销或补偿 |
| 审计记录 | 调用人、门店、数据范围、建议ID、推荐依据、确认人、执行时间、结果与异常原因 |

## 今日要落到项目上的动作

在智能导购 MVP 的灰度评审里，补一张《动作分级与授权表》：每一个动作标明 L0-L3 级别、调用角色、人工确认点、审批人、限额、审计字段和回滚方式。未填完整的动作一律降级为“只生成建议”。

## 风险边界

- 不把“导购点了确认”当成完整风控；后台仍需校验数据范围、权益资格和动作频控。
- 不以提示词承诺替代系统权限；权限、审批、限额、审计和回滚必须由系统能力兜底。
- 首期不要为追求转化放开自动批量触达，先验证采纳率、异常率和客户体验。

## 今晚复盘要回答的问题

今天是否已把智能导购首版的每个动作分成 L0-L3，并明确了**谁可调用、谁确认、谁审批、如何回滚、在哪里审计**？如果没有，缺的具体字段或系统能力是什么，负责人和补齐时间是什么？
