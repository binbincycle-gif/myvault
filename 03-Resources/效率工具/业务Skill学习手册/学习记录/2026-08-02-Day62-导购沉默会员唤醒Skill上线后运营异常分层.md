## 今日抓到的核心判断

Day61 定义了上线后的运营机制：调用、采纳、触达、响应、回写、复盘。

Day62 要继续补一个关键点：**上线后运营不能只看指标，要把异常分层；否则看板会变成报表，不能变成动作入口。**

Skill 运营看板的价值不是“展示数据”，而是触发动作：

```text
数据异常 → 定位原因 → 决定动作 → 记录结果 → 下次复盘
```

对导购沉默会员唤醒 Skill 来说，异常不能笼统写成“效果不好”。必须拆成 4 层：

1. **调用异常**：导购没打开 / 系统没触发 / 权限不足 / 数据缺失。
2. **采纳异常**：导购看了但不用，说明建议不可信、动作太重、解释不清。
3. **触达异常**：导购采纳了但没完成触达，说明流程卡、任务过载、触达工具不顺。
4. **结果异常**：触达了但客户无响应或无转化，说明人群、权益、话术、时机需要优化。

管理上要避免一个误区：**不要看到唤醒率低就直接否定 Skill。** 先判断问题发生在哪一层。不同异常，对应不同 Owner 和动作。

## 今日可落地动作

如果今天继续推进智能导购 / 导购小龙虾 / CRM AI 能力释放，建议给上线后运营看板补一列：**异常分层 + 责任动作**。

最小版本可以这样落：

```text
能力名称：导购沉默会员唤醒 Skill
今日运营检查：
1. 调用异常 Top3 是什么？
2. 未采纳原因 Top3 是什么？
3. 采纳后未触达原因 Top3 是什么？
4. 触达无响应会员集中在哪类人群？
5. 今日是否出现权限、免打扰、权益冲突、投诉等风险异常？

每个异常必须绑定：原因判断 + Owner + 下一步动作 + 是否进入下周版本优化。
```

## 管理提醒

1. **看板不是报表，是动作入口。** 只展示调用量、触达率、唤醒率不够，必须能指导扩、改、停。
2. **异常要分层，不要一锅端。** 调用低、采纳低、触达低、响应低，是四类完全不同的问题。
3. **失败原因要结构化回写。** 未采纳、未触达、无响应，如果只停留在群反馈，下一版 Skill 就无法变聪明。
4. **风险异常优先级高于效果异常。** 一旦出现越权、投诉、权益冲突，要先控风险，再谈放量。
5. **Owner 要按异常层级拆。** 技术不背业务效果全部责任，业务也不能把权限和稳定性问题甩给导购。

## 晚上复盘问题

1. 今天导购沉默会员唤醒 Skill 的主要问题发生在哪一层：调用、采纳、触达、结果，还是风险？
2. 每类异常是否都有结构化原因，而不是只写“效果不好”？
3. 哪个异常已经明确 Owner 和处理动作？哪个还处于责任悬空？
4. 今日异常里，哪些应该进入下周版本优化？哪些只需要运营推动？
5. 如果明天要扩围，当前最大的阻断点是什么？

## 今日一句话

> 导购沉默会员唤醒 Skill 上线后，不能只问“效果好不好”，要先问“问题卡在哪一层”：调用、采纳、触达、结果、风险，分层清楚，动作才会准。
