## 今日抓到的核心判断

Day39 的重点是把“导购沉默会员唤醒 Skill”从 **安全边界草案**，继续推进到 **上线前可交付检查**。

> Demo 能跑，只能证明能力存在；上线前检查要证明它可以交给真实导购、店长、总部运营长期使用。

对导购 Skill 来说，最容易犯的错是：AI 能生成名单和话术，就以为可以上线。但真实经营里，必须回答：谁用、何时触发、读什么数据、输出什么结构、哪些动作必须确认、结果如何回写、异常谁处理、下个品牌能不能复用。

所以今天不继续扩功能，而是补一张“上线前检查清单”。

## 导购沉默会员唤醒 Skill｜上线前检查清单

| 检查项 | 当前建议 |
|---|---|
| Skill 名称 | 导购沉默会员唤醒 Skill |
| 当前版本 | v0.1 MVP 试点版 |
| 目标角色 | 导购、店长、总部运营 |
| 主 Owner | 产品负责人 + CRM 业务负责人；技术 Owner 负责接口、权限、审计与回写 |
| 触发场景 | 导购每日查看待跟进沉默会员；店长查看本店唤醒任务进度；总部运营查看品牌级唤醒策略效果 |
| 不应触发场景 | 非授权会员、跨门店会员明细、无导购关系会员、权益规则不明确、敏感客诉/赔付场景 |
| 必要输入 | 品牌/门店/导购身份、会员归属、沉默天数、最近消费/互动摘要、偏好标签摘要、可用权益、历史触达结果 |
| 输出结构 | 会员优先级、推荐理由、建议话术、建议权益、下一步动作、数据依据、风险提示 |
| 可执行动作 | v0.1 仅生成名单与建议；导购确认后可触达；结果结构化回写 CRM |
| 权限边界 | Agent 不新增权限，只继承 SaaS 实时判权；导购只看本人权限会员；店长只看本店；总部默认看汇总 |
| 人工确认点 | 发送话术、选择渠道、发券/权益、标记跟进状态、结果回写都需人工确认 |
| 审批点 | 批量触达、高面额权益、跨门店协同、涉及客诉/赔付/价格承诺的动作 |
| 异常降级 | 数据不足时输出“缺少依据”；权限不足直接拒绝；权益冲突要求人工确认；规则缺失不强行推荐 |
| 审计字段 | skill_run_id、调用人、代表身份、数据范围、输入口径、输出版本、确认人、执行动作、触达对象数、回写状态、异常状态 |
| 回写机制 | 触达/未触达、是否回复、是否到店/成交、失败原因、导购反馈、下一次跟进时间 |
| 验收指标 | 导购 3 分钟内完成一次有效跟进；触达完成率、回复率、转化率、失败原因记录率、导购采纳率 |
| 复用条件 | 换品牌/门店时，只需调整会员分层口径、权益规则、话术风格和权限配置，不改核心流程 |

## 上线前必须补齐的 5 个契约

### 1. 触发契约

```text
应该调用：导购每日跟进沉默会员、店长检查门店唤醒进度、总部复盘唤醒策略效果。
不该调用：越权会员、敏感客诉、权益不明确、跨门店未授权场景。
```

### 2. 输入契约

```text
必须有：调用身份、会员归属、沉默天数、最近消费/互动摘要、可用权益、历史触达结果。
缺一不可：身份与权限范围。没有身份，就不能查会员明细。
```

### 3. 输出契约

```text
必须输出：优先级、推荐理由、建议话术、下一步动作、依据、风险提示。
禁止只输出“建议联系客户”这种不可执行结果。
```

### 4. 执行契约

```text
MVP 阶段：AI 只给建议，不自动触达、不自动发券、不自动改会员标签。
执行动作：必须由导购/店长确认后进入业务系统。
```

### 5. 运维契约

```text
每个版本必须有 Owner、版本号、变更说明、异常反馈入口、审计记录和暂停机制。
线上异常优先暂停批量能力，再定位数据、规则、话术或权限问题。
```

1. 今天有没有把导购 Skill 从 Demo 能跑，推进到可交付检查？

5. 这个 Skill 换一个品牌/门店时，能否通过配置复制，而不是重新写一套？
