如果导购沉默会员唤醒 Skill 每天只是生成名单和话术，但不记录导购是否采纳、客户是否回应、是否到店/下单、哪些话术有效、哪些分层误判，那么它仍然只是一次性自动化。

真正有复利的 Skill，要形成这条链路：

```text
Skill 输出 → 导购采纳 → 客户触达 → 业务结果 → 经验回写 → 规则/话术/分层升级 → 下一次推荐更准
```

## 导购沉默会员唤醒 Skill｜结果沉淀设计 v0.1

| 沉淀层级 | 要沉淀什么 | 推荐位置 | 用途 |
|---|---|---|---|
| 临时上下文 | 本次名单、推荐理由、话术、注意事项 | 当前任务日志 / 运行记录 | 支撑本次执行和排查 |
| 项目记忆 | 某品牌/门店的会员分层偏好、活动规则、导购执行习惯 | 客户项目文档 / CRM 配置说明 | 支撑同客户持续优化 |
| 组织知识 | 被验证有效的话术模板、沉默会员分层规则、风险边界、异常处理清单 | 业务 Skill 知识库 / 标准 Skill 文档 | 跨客户复制和产品化 |

## 从结果回写到能力升级

| 回写信号 | 说明 | 应触发的能力升级 |
|---|---|---|
| 名单查看率高、采纳率低 | 导购看了但不用 | 优化推荐理由和话术长度，补未采纳原因 |
| 采纳率高、客户回复低 | 导购执行了但客户无反应 | 优化客户分层、触达时机、利益点表达 |
| 回复率高、成交低 | 客户感兴趣但没转化 | 检查权益、商品推荐、到店承接 |
| 某类话术转化稳定高 | 已有可复用经验 | 沉淀为标准话术模板和适用条件 |
| 某类客户频繁误判 | 分层规则不准 | 调整沉默周期、复购排除、RFM/偏好字段 |
| 出现投诉/权益争议 | 风险边界不足 | 增加高风险词拦截和人工确认 |

## 管理提醒

1. **没有结果回写，就没有经营复利。** Skill 不能只证明“能生成”，还要证明“能改善结果”。
2. **不要把所有执行记录都写进长期知识库。** 长期沉淀只保留被验证有效的规则、模板、风险边界和可复用经验。
3. **CRM 回写优先于文档总结。** 业务结果最好回到业务系统，知识库只沉淀方法和规则。
4. **导购记忆要区分人和岗。** 客户关系记忆应归岗位/门店继承，个人表达风格可跟随自然人。
5. **沉淀要有清理机制。** 过期活动、失效权益、低置信经验不能长期污染推荐。

## 晚上复盘问题

1. 今天导购沉默会员唤醒 Skill 是否拿到了执行结果回写，而不只是生成结果？
2. 哪个字段今天最缺：采纳、触达、回复、成交，还是未采纳原因？
3. 今天有没有沉淀出一条可复用的话术、规则或风险边界？
4. 哪些内容只适合留在客户项目记忆，哪些可以升级为组织知识？
5. 下一版 Skill 是否需要把结果回写字段变成强制项？

## 今日一句话

> Skill 的复利不来自一次生成，而来自每次执行结果都能反哺下一次判断；没有回写，就没有进化。
