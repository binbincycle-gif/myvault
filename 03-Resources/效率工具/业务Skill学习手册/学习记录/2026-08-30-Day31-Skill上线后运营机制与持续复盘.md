## 我今天记住的一句话
- Skill 真正难的不是上线，而是上线后有没有持续使用、持续复盘、持续优化；没有运营机制，Skill 很快会变成一次性交付物。

## 今日学习要点
1. **上线只是运营起点**：发布后必须持续看谁在用、用在什么场景、输出是否被采纳、异常是否重复出现。
2. **运营指标要固定**：使用量、命中率、采纳率、结果率、异常率，不能只看“调用次数”。
3. **复盘重点是闭环顺不顺**：输入上下文、输出结构、人工确认、权限审计、结果回写、跨客户复制条件。

## 结合当前业务的判断
- OpenClaw / AI Coding 不能只统计“多少人用了工具”，要盯是否进入需求、缺陷、测试、发布链路，并沉淀成 Skill / 检查表 / 工作流。
- 导购小龙虾 / 智能导购不能只看“AI 给没给建议”，要看导购是否触达、触达后是否回复/转化、经验是否回流成下一轮策略。
- EZR SaaS 能力层不能只做能力清单，要盯哪些能力已经被 Agent 调用，并形成真实业务闭环；权限、审计、回写不完整的能力暂不能规模化。

## 今天可直接落的一步
- 给“导购沉默会员唤醒 / 会员洞察跟进”补一张上线后运营卡：Owner、目标角色、核心场景、使用量、命中率、采纳率、结果率、异常率、异常入口、下次复盘时间。

## 晚上复盘问题
- 今天盯的 Skill 是否已经从“能跑通”推进到“有人持续用、结果可回收、问题可优化”？
- 如果没有，卡点是在使用频次、业务闭环，还是运营责任人缺失？
