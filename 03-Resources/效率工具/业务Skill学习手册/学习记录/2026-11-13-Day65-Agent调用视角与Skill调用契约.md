# Day65｜Agent 调用视角与 Skill 调用契约

> 对应章节：[[Day26-Agent调用视角：让Skill被正确理解、选择和执行]]

## 今日结论

Skill 不是给人阅读的功能说明，而是 Agent 判断“何时调用、是否具备输入与权限、应如何交付”的行动契约。只有写清触发、输入、步骤、风险、输出，Skill 才能从偶发有效的提示词变成可治理的组织能力。

## Agent 调用的三道判断

```text
意图是否匹配
→ 输入与上下文是否充足
→ 权限与风险是否允许
→ 调用执行 / 追问 / 降级
```

涉及客户数据、外部触达、CRM 写入、批量修改或权益发放时，不能因“意图匹配”就自动执行；仍要根据数据范围、动作等级与审批要求拦截。

## 首个 CRM Skill：导购会员跟进建议

### 调用契约 v0.1

| 要素 | 定义 |
|---|---|
| 触发条件 | 导购需要会员跟进名单、沉默会员唤醒、复购建议或一对一话术时调用 |
| 必填输入 | 品牌/门店范围、会员筛选口径、活动目标、导购身份与可用权益 |
| 缺失处理 | 信息不足时只输出草案与待确认项，不生成可直接执行名单 |
| 可做动作 | L0 权限内查询；L1 生成优先级、理由、话术与推荐动作 |
| 人工确认 | 建任务、实际发送、渠道选择、权益使用、标签修正均需导购确认 |
| 审批拦截 | 批量触达、高面额权益、跨门店客户、规则版本发布必须审批 |
| 输出 | 目标分组、跟进理由、建议话术、推荐动作、CRM 回写字段、复盘指标 |
| 审计 | 调用人、数据范围、输入、规则/模型版本、建议、确认/拒绝、执行结果 |

## 对 EZR 的落地要求

1. Skill `description` 必须先写清可命中的业务场景与产出，避免泛化为“提升效率”。
2. 每个 Skill 都要声明“不适用场景”和缺失信息的降级方式，防止 Agent 在信息不足时硬跑。
3. 权限按“身份 + 数据范围 + 业务动作 + 风险等级”实时判断；记忆和历史策略不得替代 SaaS 实时判权。
4. 输出同时服务三类对象：管理者结论、执行者动作、系统回写字段；以采纳率、触达率、转化率、异常率进行复盘。

## 今日可执行动作

为首批 10 个 CRM 高频任务模板补齐统一 Skill 卡：

> 触发条件｜必填输入｜可选输入｜禁止/需确认动作｜执行步骤｜输出格式｜回写字段｜复盘指标｜版本与 Owner

优先覆盖：会员分层、待跟进清单、沉睡会员唤醒、活动名单、导购日报、异常提醒。

## 一句话收获

**Skill 的本质不是功能说明，而是 Agent 的行动边界：触发明确、输入完整、权限受控、输出可回写，才能稳定进入真实业务流程。**
