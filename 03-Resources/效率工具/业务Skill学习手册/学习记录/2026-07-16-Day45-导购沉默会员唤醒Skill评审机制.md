## 今日抓到的核心判断

Day44 解决的是“Skill 如何进入目录并持续运营”。Day45 要补的是目录之前的一道门：**导购沉默会员唤醒 Skill 不能写出来就上架，必须先经过轻量评审，判断它是否值得做、能否复用、风险是否可控、有没有人负责。**

> Skill 评审不是代码评审，而是能力准入评审。对导购场景来说，重点不是“话术生成得好不好看”，而是“这个能力能不能安全、稳定、可复用地影响真实会员触达结果”。

如果没有评审，导购相关 Skill 很容易变成三类问题：

1. **重复建设**：会员推荐、话术生成、沉默唤醒在不同项目里各写一套，口径不一致。
2. **价值不清**：能生成内容，但导购不采纳、客户无响应、结果不回写。
3. **风险外溢**：越权看会员、错误承诺权益、误触达敏感客户、没人负责解释和下线。

## 导购沉默会员唤醒 Skill｜一页评审材料 v0.1

| 字段 | 内容 |
|---|---|
| Skill 名称 | 导购沉默会员唤醒 Skill |
| 目标用户 | 导购、店长、总部运营 |
| 业务场景 | 对沉默会员进行分层识别，给出唤醒理由、触达优先级和建议话术 |
| 输入参数 | 品牌、门店、导购身份、会员范围、沉默周期、最近消费/互动、可用权益、触达渠道 |
| 输出结果 | 沉默会员分层、推荐唤醒原因、建议话术、跟进优先级、风险提示、结果回写字段 |
| 使用边界 | 不自动发送；不承诺库存/价格/权益；不输出导购权限外会员；敏感客户需提示人工确认 |
| 权限范围 | SaaS 实时判权；导购只看自己会员池；店长看门店；总部运营看汇总和脱敏策略 |
| 成功指标 | 导购采纳率、触达完成率、会员响应率、唤醒成交率、投诉率、误触达率 |
| 负责人 | 产品负责人 + 研发负责人 + 业务试点负责人 |
| 当前状态 | Beta / 小范围灰度前评审 |

## 四道准入门在导购 Skill 上的落法

| 阶段 | 今天要问的问题 | 通过标准 |
|---|---|---|
| 问题评审 | 沉默会员唤醒是不是高频、高价值问题？ | 能明确目标门店、沉默定义、预期改善指标 |
| 设计评审 | 输入输出、权限、异常、结果回写是否清楚？ | 一页评审材料能写完整，且研发/产品/业务口径一致 |
| 灰度评审 | 小范围导购是否真的愿意用？ | 有采纳率、修改率、响应率、异常记录 |
| 上架评审 | 是否值得进入导购 Skill 目录？ | 有负责人、版本号、指标看板、维护/下线规则 |

## 今日可落地动作

给“导购沉默会员唤醒 Skill”补一次轻量评审，不开大会议，只用一页材料过四个问题：

```text
1. 这个 Skill 解决的沉默会员问题是否足够高频 / 高价值？
2. 输入、输出、权限、结果回写是否清楚？
3. 是否允许进入 1 个门店 / 1 组导购灰度？
4. 谁负责解释、维护、复盘和必要时下线？
```

如果这四个问题答不清楚，就先不要进入目录，也不要包装成正式能力。

## 管理提醒

1. **不要把评审做重。** 一页材料即可，目标是统一判断，不是增加流程负担。
2. **不要只评技术实现。** 导购 Skill 的关键在业务价值、权限边界、结果回写和风险可解释。
3. **不要跳过灰度。** 客户可见、导购触达、经营建议类 Skill 必须先小范围验证，再考虑目录上架。
4. **不要无人负责。** 没有负责人、没有版本号、没有下线规则的 Skill，不应进入组织资产库。

## 晚上复盘问题

1. 今天是否产出了一页“导购沉默会员唤醒 Skill 评审材料”？
2. 四道门里，当前最薄弱的是问题价值、设计完整度、灰度数据，还是上架维护责任？
3. 这个 Skill 是否可以进入 1 个门店 / 1 组导购灰度？如果不行，缺哪一项前置条件？
4. 是否明确了谁负责解释输出错误、处理投诉风险、维护版本和决定下线？
5. 它和“今日重点会员推荐”“会员触达话术生成”“导购执行复盘”是否存在重复建设，需要合并成统一导购经营 Skill 体系？

## 一句话沉淀

导购沉默会员唤醒 Skill 要成为组织资产，不能只靠“能跑”，必须先过价值、设计、灰度、上架四道轻量评审门。
