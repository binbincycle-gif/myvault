## 今日抓到的核心判断

Day18 的重点不是“出错后写一份复盘”，而是把异常变成 Skill 成熟度的一部分。

导购沉默会员唤醒 Skill 如果要继续扩围，不能只证明它推荐得准，还要证明三件事：

1. 异常能被及时发现。
2. 异常能被准确归类。
3. 异常能推动 Prompt、Schema、权限、数据口径或话术模板升级。

> 真正可规模化的业务 Skill，不是永远不出错，而是出错后能进入闭环，并且同类错误不会反复出现。

## v0.3 升级重点：从“异常复盘表”升级为“异常分级 + 处置 SLA”

v0.2 已经定义了 6 类异常：输入、数据、逻辑、权限、话术、运营。今天补一层管理动作：不同异常不能用同一种响应速度处理。

### 1. 异常分级

| 等级 | 典型场景 | 处置原则 | 建议 SLA |
|---|---|---|---|
| P0 | 越权看到会员数据、错误承诺权益引发客诉、自动触达失控 | 立即暂停相关能力，人工介入复核 | 2 小时内定位，24 小时内给修正方案 |
| P1 | 推荐名单明显偏差、核心数据口径错误、重复触达风险升高 | 暂停扩围，限制使用范围 | 当日定位，当日形成版本修正项 |
| P2 | 话术可用性差、解释理由弱、导购采纳率低 | 纳入迭代优化 | 3 个工作日内优化模板或规则 |
| P3 | 格式不顺、字段展示不清、操作路径不顺 | 体验优化 | 下个小版本处理 |

### 2. 异常处置责任

| 异常类型 | 第一责任 | 协同角色 | 最终产物 |
|---|---|---|---|
| 输入异常 | 产品 / 运营 | 导购代表 | 输入模板、必填字段、追问规则 |
| 数据异常 | 数据 / 后端 | 产品 | 数据时间戳、口径版本、缺失提示 |
| 逻辑异常 | 产品 / 算法策略 | 业务负责人 | 推荐规则、反例、优先级策略 |
| 权限异常 | 后端 / 安全 | 产品、运维 | SaaS 实时判权、审计日志、拦截策略 |
| 话术异常 | 运营 / 产品 | 品牌业务方 | 敏感词、权益校验、人工确认 |
| 运营异常 | 运营负责人 | 店长 / 导购 | 频控规则、冷却期、冲突检测 |

### 3. 版本升级记录必须固定

每次异常关闭前，必须回答：

```text
这次异常最终改了什么？
- Prompt 是否改？
- Schema 是否改？
- 数据口径是否改？
- 权限校验是否改？
- 话术模板是否改？
- 运营规则是否改？
- 是否需要补一条回归用例？
```

如果以上都没有变化，只是“解释清楚了”，就不能算关闭，只能算临时处理。

## 导购沉默会员唤醒 Skill｜异常复盘 v0.3 表

```text
1. 异常编号
2. 异常时间
3. 品牌 / 门店 / 导购（脱敏）
4. 会员范围或会员类型（脱敏）
5. 触发入口：看板指标 / 人工反馈 / 客诉 / 系统拦截 / 回归测试
6. 异常等级：P0 / P1 / P2 / P3
7. 异常分类：输入 / 数据 / 逻辑 / 权限 / 话术 / 运营
8. 导购输入
9. Skill 输出：推荐名单 / 推荐理由 / 话术片段
10. 影响判断：效率 / 成交 / 客诉 / 越权 / 信任 / 扩围节奏
11. 临时处置：暂停 / 降级 / 人工确认 / 回滚 / 保持观察
12. 根因判断：字段缺失 / 口径错误 / 规则缺失 / 权限缺口 / 模板不稳 / 频控不足
13. 版本变更：Prompt / Schema / 数据口径 / 权限校验 / 频控规则 / 话术模板
14. 回归用例：同类会员 / 同类门店 / 同类活动是否复测
15. 关闭结论：可恢复 / 继续观察 / 不可扩围 / 进入下线评估
```

## 三条红线继续保留

1. **权限异常按 P0 处理。** 会员归属、门店权限、品牌权限不清时，不输出会员详情，必须走 SaaS 实时判权。
2. **权益承诺异常按 P0/P1 处理。** 活动权益字段不完整时，不生成承诺型话术，只能输出“需人工确认”。
3. **触达频控异常必须能暂停扩围。** 连续重复触达、同会员多导购冲突、冷却期失效时，先降级再优化。

## 今日可落地动作

如果今天继续推进智能导购 / 导购小龙虾，建议补一个最小可用的“异常分级规则”：

```text
风险事件出现
  ↓
先判 P0/P1/P2/P3
  ↓
P0 立即暂停相关能力
P1 暂停扩围并当日修正规则
P2/P3 纳入版本迭代
  ↓
关闭前必须留下版本变更或回归用例
```

## 管理提醒

1. 异常复盘不是客服解释，是产品能力升级机制。
2. 会员触达类 Skill 的风险优先级高于效率指标，宁可保守，不要误触达、乱承诺、越权看数。
3. 扩围前必须看三张表：运营看板、异常复盘表、版本变更记录。
4. 没有暂停权的灰度发布是假灰度。
5. 每个 P0/P1 异常都要补回归用例，否则下一轮还会重复踩坑。

## 晚上复盘问题

1. 今天是否把导购沉默会员唤醒 Skill 的异常分级规则补齐？
2. P0/P1 异常出现时，谁有权暂停、谁负责定位、谁拍板恢复？
3. 最近一次异常有没有真正改动 Prompt、Schema、权限、数据口径或话术模板？
4. 当前扩围最大风险是越权、权益承诺，还是重复触达？
5. 下一次评审能不能用“看板 + 异常复盘 + 版本变更 + 回归用例”证明它值得继续放大？
