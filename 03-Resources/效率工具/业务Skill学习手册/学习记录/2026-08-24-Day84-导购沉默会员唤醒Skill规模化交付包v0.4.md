## 今日抓到的核心判断

Day24 的重点是：MVP 试点判断“值得放大”以后，不能直接扩大使用范围，而要先把试点中跑通的动作链整理成标准交付包。

> Skill 规模化，不是“让更多人试试”，而是把一套有效动作变成可复制、可培训、可审计、可复盘的组织资产。

对导购沉默会员唤醒 Skill v0.4 来说，下一步不是简单增加导购人数，而是先把这条链路标准化：

```text
沉默会员识别 → AI 推荐理由 → 导购人工确认 → 触达执行 → 结果回写 → 经验沉淀
```

只有这条链路能在换导购、换门店、换品牌后仍然跑通，才说明它具备规模化复制价值。

## v0.4 规模化交付包

```text
Skill 名称：导购沉默会员唤醒 Skill v0.4
适用角色：导购 / 店长 / 区域运营 / CSM
适用场景：沉默会员唤醒、活动前会员跟进、门店复购提升
试点结论：MVP 复盘通过后，进入小范围复制；未通过则继续小范围迭代或暂停
```

## 1. 触发条件

| 项目 | v0.4 口径 |
|---|---|
| 使用时机 | 每日开店前 / 活动前 1 天 / 会员沉默预警后 |
| 触发方式 | 优先人工触发，暂不自动推送 |
| 触发角色 | 导购本人、店长、区域运营 |
| 最小频率 | 每名导购每日查看 3-5 名推荐会员 |
| 不建议触发 | 会员权益不明、活动规则不清、导购无权限查看该会员时 |

## 2. 输入上下文

| 类型 | 必要字段 | 说明 |
|---|---|---|
| 会员信息 | 会员 ID、所属门店、归属导购、沉默天数 | 必须经过权限校验 |
| 交易信息 | 最近购买时间、购买品类、客单价、复购周期 | 只提供判断所需摘要，不暴露无关明细 |
| 触达历史 | 最近触达时间、触达方式、客户反馈 | 防止重复打扰 |
| 偏好信息 | 商品偏好、尺码、风格、价格带 | 用于生成推荐理由和话术 |
| 活动信息 | 当前可用活动、权益规则、适用范围 | 防止错误承诺 |

## 3. 输出标准

每次输出必须固定包含：

```text
1. 推荐会员：最多 3-5 人
2. 推荐理由：为什么今天值得跟进
3. 建议话术：一句可直接使用的话
4. 风险提示：是否存在权益、重复触达、敏感承诺风险
5. 下一步动作：触达 / 暂缓 / 升级店长 / 标记跳过原因
```

### 输出示例

```text
会员：王女士
推荐理由：已沉默 45 天，历史偏好连衣裙，最近同类新品上新，且上次活动期间有响应记录。
建议话术：王女士，之前您关注过的连衣裙风格这周有新款到店，我帮您挑了两件更适合通勤的款式，要不要发您看看？
风险提示：不要承诺专属折扣，当前未确认该会员可用权益。
下一步动作：导购确认后触达，并回写客户是否有兴趣。
```

## 4. 人工确认点

| 动作 | 是否允许 AI 自动执行 | 处理规则 |
|---|---|---|
| 推荐会员名单 | 可生成 | 必须展示推荐理由 |
| 发送触达消息 | 不允许 | 必须导购人工确认 |
| 发放优惠券 | 不允许 | 需按品牌权益规则审批或确认 |
| 标记会员状态 | 可建议 | 实际写入需人工确认或系统规则校验 |
| 升级重点客户 | 可建议 | 店长 / 区域运营确认 |

## 5. 反馈闭环字段

| 字段 | 用途 |
|---|---|
| 是否采纳 AI 推荐 | 判断推荐有效性 |
| 是否实际触达 | 判断是否产生业务动作 |
| 触达方式 | 分析不同渠道效果 |
| 客户反馈 | 判断话术和推荐理由是否有效 |
| 是否成交 / 产生复购线索 | 判断业务结果 |
| 未采纳 / 跳过原因 | 反哺推荐规则 |
| 异常类型 | 权限、权益、重复触达、话术风险等 |

## 6. 推广节奏

```text
第 1 层：同门店多导购复制
目标：验证新导购是否也能稳定使用
周期：1 周
判断：是否仍有调用、动作、反馈记录

第 2 层：同品牌不同门店复制
目标：验证门店差异是否影响推荐结果
周期：1-2 周
判断：数据口径、导购习惯、客户类型是否需要配置

第 3 层：不同品牌小范围试点
目标：验证行业/品牌差异是否可通过配置解决
周期：2 周
判断：是否需要形成品牌配置模板

第 4 层：沉淀标准 Skill 资产
目标：进入产品化、交付包或 CSM 复制打法
产物：标准说明、培训材料、配置清单、运营看板、风险边界
```

## 7. 风险边界

1. 不自动发送营销消息。
2. 不自动发券或承诺权益。
3. 不跨门店、跨品牌查看会员。
4. 不输出敏感会员明细给无权限角色。
5. 不把一次试点成功直接包装为标准产品能力。
6. 不只看推荐准确率，必须看导购动作和 CRM 回写结果。

## 8. 今日可落地动作

如果今天继续推进智能导购 / 导购小龙虾，建议只做一件事：

```text
把 v0.4 MVP 复盘结果后面补一页“规模化交付包”
  ↓
固定 6 个交付件：触发说明、输入要求、输出标准、人工确认点、反馈字段、风险边界
  ↓
定义 4 层推广节奏：同门店、同品牌跨门店、不同品牌、标准 Skill 资产
  ↓
明确：未形成交付包前，不做大范围扩围
```

## 管理提醒

1. 放大前先标准化，否则就是扩大混乱。
2. 先复制动作链，不要先复制页面入口。
3. 每扩大一层，都要重新验证使用、动作、结果和风险。
4. 如果换一个导购就跑不动，说明还不是组织资产。
5. 如果换一个品牌就失效，要优先补配置化能力，而不是硬推标准化。

## 晚上复盘问题

1. 今天是否已经形成 v0.4 的标准交付包？
2. 交付包里是否明确了触发条件、输入上下文、输出标准、人工确认点、反馈字段和风险边界？
3. 下一步复制应该先选同门店多导购，还是同品牌不同门店？为什么？
4. 当前最不稳定的是数据口径、导购动作、反馈回写，还是权限边界？
5. 这个 Skill 如果换一个品牌，哪些内容可以复用，哪些必须配置？

## 一句话沉淀

导购沉默会员唤醒 Skill v0.4 的规模化，不是扩大试用人数，而是先把“AI 推荐 → 导购确认 → 触达执行 → 结果回写 → 经验沉淀”整理成可复制的交付包。
