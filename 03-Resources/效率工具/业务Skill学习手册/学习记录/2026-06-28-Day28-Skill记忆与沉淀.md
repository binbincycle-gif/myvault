# 2026-06-28｜Day28 学习记录：Skill 记忆与沉淀

## 今日阅读
- 原文：[[Day28-Skill记忆与沉淀：让执行结果反哺能力]]
- 主题：Skill 执行后，如何把结果、证据、异常和复盘判断沉淀回组织资产，让下一次调用更准、更快、更稳。

## 核心理解

Skill 不应该只完成一次任务，而要形成“执行 → 回写 → 复盘 → 复用”的闭环。

如果没有沉淀机制，Skill 只是一次性自动化；如果能持续沉淀已验证口径、有效模板、异常经验和业务结果，它才会变成组织能力。

## 今天最重要的启发

业务 Skill 的设计不能只写输入、输出和执行步骤，还要提前定义“回写字段”：

1. **结果写到哪里**：业务系统、知识库、项目文档，还是仅保留运行日志。
2. **哪些字段必须回写**：采纳情况、执行动作、结果指标、异常原因。
3. **哪些结论需要人工确认后沉淀**：客户经营判断、对外触达话术、风险定级、管理口径。
4. **谁维护、多久清理**：避免知识库从能力资产变成噪音库。

## 对 EZR 的落地联想

以“导购客户跟进 Skill”为例，不能只生成话术。更有价值的是沉淀：

- 导购是否采纳建议；
- 实际发送了哪个话术版本；
- 客户是否回复、领券、到店、下单；
- 哪类客户对哪类话术响应更好；
- 哪些推荐被导购忽略，原因是什么；
- 是否出现客户反感、敏感优惠、权限审批等风险。

这套回写机制，最终会让“智能导购”从内容生成工具，进化成可持续优化的经营经验资产。

## 可复用检查清单

后续设计业务 Skill 时，每个 Skill 都要补一段“沉淀设计”：

```text
Skill 名称：
目标场景：

1. 本次输出是否需要沉淀？
2. 沉淀到哪个资产层？临时上下文 / 项目记忆 / 组织知识
3. 必填回写字段有哪些？
4. 哪些字段必须人工确认？
5. 是否记录数据来源、执行证据和异常？
6. 沉淀内容多久复盘一次？
7. 错误口径如何纠偏或清理？
```

## 今日行动建议

今天可以把这条规则加到下周 AI 试点验收清单里：

> 每个 AI 试点不仅要验收“能不能生成结果”，还要验收“结果有没有被采纳、有没有产生动作、动作结果有没有回写”。

优先落到 4 条线：项目管理助手、CRM 数据报告、智能问数 / UND、导购小龙虾。

## 一句话沉淀

Skill 的价值不只在“帮你做一次”，而在“每做一次，组织就多一份可复用经验”。
