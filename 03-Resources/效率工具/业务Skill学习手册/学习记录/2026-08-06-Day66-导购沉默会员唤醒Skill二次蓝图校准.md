## 今日抓到的核心判断

Day65 关注的是 Skill 生命周期治理：什么时候冻结、废弃、归档，避免能力目录变成“AI 垃圾箱”。

Day66 重新回到源头：**任何业务 Skill 都不能从“想做一个 AI 功能”开始，而要从客户/员工真实场景开始。**

导购沉默会员唤醒 Skill 之前已经走过 MVP、灰度、运营、异常、下线归档等治理动作，但今天要重新校准一个关键问题：

> 这个 Skill 到底服务的是“生成一批沉默会员名单”，还是服务“导购完成一次可复盘的会员经营动作”？

如果只服务名单生成，它只是一个工具；如果能串起“识别机会 → 给出理由 → 生成话术 → 导购触达 → 结果回写 → 下次优化”，它才是智能导购里的一个业务能力单元。

一句话：**Skill 蓝图不是功能清单，而是业务结果的施工图。**

## 从“单点 Skill”升级为“最小业务闭环”

### 原来的单点能力

```text
输入：沉默会员规则 + CRM 数据
输出：沉默会员名单 + 推荐话术
```

这个形态的问题是：

1. 导购只知道“AI 推荐了谁”，不一定知道为什么。
2. 话术生成后没有确认导购是否使用。
3. 触达结果不回流，下一次推荐还是从头开始。
4. 店长/运营无法判断这个 Skill 是否真的创造经营结果。

### 现在要校准成最小闭环

```text
会员机会识别
  ↓
推荐理由解释
  ↓
导购话术生成
  ↓
导购确认触达
  ↓
触达反馈回写
  ↓
效果复盘与下次优化
```

最小闭环不追求一次做完整智能导购，但至少要做到：

- AI 推荐的人有理由。
- 导购执行前有人确认。
- 执行后结果能回写。
- 回写结果能影响后续推荐。

## 可拆分 Skill 单元

| 业务环节 | Skill 单元 | 最小验收问题 |
|---|---|---|
| 识别机会 | 沉默会员机会识别 Skill | 能否说清“这个会员为什么值得今天跟进”？ |
| 判断偏好 | 会员偏好洞察 Skill | 能否提炼可用于话术/商品建议的偏好？ |
| 推荐动作 | 唤醒策略推荐 Skill | 能否给出权益、商品、活动或关系维护建议？ |
| 沟通执行 | 导购话术生成 Skill | 话术是否符合品牌、客户状态和触达渠道？ |
| 结果回流 | 触达反馈记录 Skill | 能否记录采纳、触达、回复、成交、未采纳原因？ |
| 效果复盘 | 唤醒效果归因 Skill | 能否判断本次推荐是否带来回复/复购/负反馈？ |

## 今天可落地动作

如果今天继续推进智能导购 / 导购小龙虾，建议补一页“导购沉默会员唤醒 Skill 蓝图 v0.2”，只画一条最小闭环：

```text
导购每天打开任务
  → AI 给出 10 个优先唤醒会员
  → 每个会员展示推荐理由和风险提醒
  → 导购确认/调整话术后触达
  → 触达结果回写 CRM
  → 第二天推荐时避开已触达/反感/无效会员
```

同时定义 3 个今天就能验收的字段：

```text
推荐理由：为什么推荐这个会员
导购动作：采纳 / 跳过 / 延后 / 改写话术
结果回写：已触达 / 已回复 / 已成交 / 无响应 / 反感 / 未采纳原因
```

## 管理提醒

1. **不要把 SaaS 页面直接翻译成 Skill。** 页面是人用的，Skill 是 Agent 调用的，必须按业务动作重拆。
2. **不要只盯生成质量。** 业务 Skill 的价值不在“话术写得像不像人”，而在是否推动一次经营动作闭环。
3. **蓝图要能让产品、研发、测试、运营一起对齐。** 如果蓝图里没有输入、输出、权限、反馈、风险，后面一定会各做各的。
4. **每个 Skill 单元都要能独立验收。** 不能验收的能力，不要急着放进组合工作流。
5. **反馈回流是智能导购的复利起点。** 没有回写，AI 永远不知道自己推荐得准不准。

## 今日一句话

> 业务 Skill 的起点不是“AI 能生成什么”，而是“它能不能帮一线角色完成一次可追踪、可复盘、可优化的业务动作”。
