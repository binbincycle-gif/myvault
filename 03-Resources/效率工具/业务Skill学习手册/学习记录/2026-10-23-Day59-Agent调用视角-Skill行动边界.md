# Day59｜Agent 调用视角：让 Skill 被正确理解、选择和执行

> 对应学习章节：[[Day26-Agent调用视角：让Skill被正确理解、选择和执行]]
> 衔接上篇：[[2026-10-22-Day58-从标准Skill到产品能力-配置化权限与商业化]]

## 今日主题

一个 Skill 写得再好，如果 Agent 不知道**何时该用、缺什么不能硬跑、哪些动作不能越权**，它就无法稳定进入真实工作流。

核心判断：**Skill 不是给人看的功能说明，而是 Agent 的行动边界。**

## Agent 调用前的三次判断

1. **意图匹配**：用户的问题是否属于这个 Skill 的处理范围？
2. **输入足够**：必要参数、权限、上下文是否齐全？
3. **风险可控**：是否涉及外发、数据写入、审批、删除、公开发布等动作？

因此，Skill 不只要写“能做什么”，还必须明确：什么时候用、什么时候不用、缺什么先问、哪些动作必须确认、输出怎样解释与复盘。

## 可稳定调用的 Skill：五要素

| 要素 | 要解决的问题 |
|---|---|
| 触发条件 | Agent 知道何时命中 |
| 输入要求 | 信息不足时不硬跑 |
| 执行步骤 | 减少自由发挥与绕路 |
| 风险边界 | 知道哪些动作必须先确认 |
| 输出格式 | 结果可读、可回写、可复盘 |

## description 是第一道分流器

好的 description 至少回答：

```text
解决什么问题？
什么触发词/业务场景该用？
哪些相似情况不该用？
最终产出是什么？
```

只写“提升效率”或只有技术能力描述，Agent 无法稳定命中；没有产出物定义，调用后也不会形成可交付结果。

## 导购会员跟进建议 Skill：从模糊到可调用

**不要只写：**“根据会员数据生成跟进建议。”

**应写成：**

```text
当用户需要为导购生成会员跟进名单、唤醒话术、复购建议或沉睡会员激活方案时使用。
输入至少包括：品牌/门店范围、会员筛选口径、活动目标、可用权益、导购权限范围。
涉及自动发券、自动群发或对外发送消息，必须先确认。
输出：目标会员分组、跟进理由、建议话术、推荐动作、回写字段与复盘指标。
```

这让 Agent 能正确判断：接不接、缺什么、何时必须停下来确认、最终交付什么。

## 今日可执行动作

1. 从现有业务 Skill 中选 3 个，逐个审查 description 是否回答“何时用 / 不何时用 / 产出什么”。
2. 对涉及 CRM 数据、会员权益、外部触达、批量写入的 Skill，补上人工确认点与审计要求。
3. 为每个 Skill 补“输入不全时的降级策略”：先给草案、追问补齐，或拒绝执行；禁止硬生成后直接外发。

## 晚间自检

1. description 能否让 Agent 一眼判断何时调用？
2. 必填输入缺失时，Agent 是追问还是硬跑？
3. 外部动作、数据写入和批量修改是否明确人工确认？
4. 输出是否同时给结论、执行动作、回写字段与复盘指标？

## 一句话结论

**写清触发、输入、步骤、风险与输出，Skill 才能从偶尔有用的提示词，变成可治理的组织能力。**
