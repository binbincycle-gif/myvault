## 今日抓到的核心判断

Day19 的重点不是“上线前找几个人试用”，而是把 Skill 发布变成一套受控扩围机制。

导购沉默会员唤醒 Skill 如果要从 MVP 走向更多门店或品牌，不能只看“试用反馈不错”，必须同时控制四件事：

1. 谁能用。
2. 用在哪个业务场景。
3. 能读取什么数据。
4. 能做到建议、确认，还是自动执行。

> 灰度发布不是降低速度，而是用最小真实战场验证价值、边界和风险，避免不成熟能力大范围扩散。

## v0.3 升级重点：从“可试用”升级为“可受控扩围”

Day78 已补了异常分级和处置 SLA。今天继续补灰度发布层：每次扩围前，必须有明确准入、观察、暂停和扩大标准。

### 1. 灰度变量控制

| 灰度变量 | 导购沉默会员唤醒 Skill v0.3 控制方式 | 目的 |
|---|---|---|
| 使用人群 | 先开放给 1-2 个品牌、少数门店、稳定导购 / 店长 | 避免问题快速扩散 |
| 使用场景 | 只开放“沉默会员唤醒建议”，不泛化到所有会员运营 | 防止被用于设计外场景 |
| 数据范围 | 限定品牌、门店、会员归属、沉默周期、活动权益字段 | 控权限和口径风险 |
| 动作权限 | 只生成推荐名单、理由和话术；不自动发送消息 | 先建议，后执行 |
| 回写范围 | 只回写导购采纳、触达、客户反馈、成交/未成交结果 | 建立反馈闭环 |

### 2. 灰度通过标准

| 指标 | 判断问题 | 建议口径 |
|---|---|---|
| 使用率 | 导购是否真的愿意用 | 目标导购使用占比、连续使用天数 |
| 采纳率 | 推荐名单是否被认可 | 推荐客户被触达比例、跳过原因 |
| 修正率 | 输出是否需要大量人工改 | 话术修改比例、推荐理由修改比例 |
| 异常率 | 是否出现口径、权限、权益、重复触达问题 | P0/P1/P2/P3 异常数 |
| 业务影响 | 是否带来实际经营价值 | 触达转化、复购、成交、沉默会员响应 |

灰度扩大不能只凭主观反馈，至少要有“使用 + 采纳 + 异常 + 结果”四类证据。

### 3. 灰度决策规则

```text
试点周期结束
  ↓
看 4 张表：运营看板 / 异常复盘表 / 版本变更记录 / 回归用例
  ↓
评审决策：扩大 / 保持 / 降级 / 回滚 / 停用
  ↓
扩大前明确下一批品牌、门店、导购、数据范围和暂停权
```

## 导购沉默会员唤醒 Skill｜灰度扩围 v0.3 检查表

```text
1. 灰度批次：v0.3 / 第几批
2. 灰度品牌 / 门店 / 导购范围（脱敏）
3. 使用场景：沉默会员唤醒 / 活动前召回 / 新品推荐 / 其他
4. 数据范围：会员归属、沉默周期、消费记录、权益字段、活动字段
5. 输出范围：推荐名单 / 推荐理由 / 建议话术 / 触达优先级
6. 动作权限：仅建议 / 人工确认后执行 / 自动执行（默认不开放）
7. 回写字段：是否采纳、是否触达、客户反馈、成交结果、异常反馈
8. 观察指标：使用率、采纳率、修正率、异常率、业务影响
9. 暂停条件：P0、连续 P1、重复触达、权益承诺异常、口径争议
10. 回滚方案：停用 / 降级为建议 / 回退上版模板 / 缩小数据范围
11. 扩围条件：指标达标、异常闭环、回归通过、责任人确认
12. 评审结论：扩大 / 保持观察 / 降级 / 回滚 / 停用
```

## 三条扩围红线

1. **没有暂停权，不允许扩围。** P0/P1 出现后必须能立即停用或降级。
2. **没有回写闭环，不允许扩围。** 只生成推荐、不知道导购是否执行，就无法证明价值。
3. **没有异常复盘和回归用例，不允许扩围。** 同类错误不能靠口头提醒解决。

## 管理提醒

1. 灰度不是试用名单，而是受控扩围机制。
2. 会员触达类 Skill 的灰度范围要同时管住人、场景、数据和动作权限。
3. 扩围评审必须看真实数据，不只听“导购觉得不错”。
4. 灰度通过标准要提前定，不能试完后再找理由。
5. Skill 的信任来自稳定闭环，不来自一次漂亮 Demo。
