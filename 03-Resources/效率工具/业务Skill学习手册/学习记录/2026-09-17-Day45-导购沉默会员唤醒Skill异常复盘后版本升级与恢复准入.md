# Day45｜导购沉默会员唤醒 Skill：异常复盘后版本升级与恢复准入

> 对应学习章节：[[Day18-Skill异常复盘：从问题暴露到能力升级]]

## 今天学什么

Day44 已经明确：当 Skill 的核心指标或风险信号触线，应进入异常复盘与冻结机制。

今天继续推进一个关键问题：**冻结后不是凭感觉恢复上线，而是要完成规则修正、回归验证和恢复准入。**

Skill 的成熟，不是“出了问题能停”，而是“停下来以后能证明已经修好，再安全地恢复”。

---

## 当前业务场景

### Skill
导购沉默会员唤醒 Skill。

### 假设异常
某品牌在灰度中发现：部分推荐名单使用了延迟同步的消费数据，导致导购把已经复购的会员仍当作“沉默待唤醒”客户触达；少量会员同时命中权益活动，但推荐话术未带活动适用限制。

### 风险判断
- **经营风险：** 导购无效触达，降低客户体验和导购对系统信任。
- **数据风险：** 数据时效不足时仍输出经营建议。
- **权益风险：** 不完整活动规则可能形成过度承诺。

结论：暂停异常品牌/门店的自动下发；保留“仅生成待人工确认名单”的低风险模式。

## 异常证据最小集

| 证据项 | 本次要求 |
|---|---|
| 发生时间与版本 | 记录具体日期、Skill版本、规则版本、数据批次 |
| 触发场景 | 品牌、门店、导购角色、唤醒任务类型 |
| 输入与数据 | 脱敏保存筛选条件、消费数据时间戳、活动规则版本 |
| 输出结果 | 脱敏保存推荐名单、触达建议、话术关键片段 |
| 实际结果 | 是否已复购、是否误触达、是否产生投诉或权益误解 |
| 影响等级 | P0 权益/隐私；P1 错误经营动作；P2 效率或体验问题 |
| 处置动作 | 冻结范围、人工兜底、修复负责人、预计恢复时间 |

---

## 根因分类与版本修正

| 异常类型 | 本次根因假设 | 必须修正的能力项 |
|---|---|---|
| 数据异常 | 消费数据同步延迟未被识别 | 输出前校验数据时间戳；超阈值只提示数据异常，不生成名单 |
| 逻辑异常 | 已复购排除规则不完整 | 固化“最近消费/订单状态/退款状态”排除条件，并提供规则版本号 |
| 输入异常 | 活动适用范围没有结构化输入 | 强制带门店、人群、时间、权益条件；字段缺失则追问或禁止生成承诺话术 |
| 权限/体验异常 | 导购拿到任务后直接执行，缺少风险提示 | 高风险权益话术进入人工确认；结果页展示数据时间、置信度和待确认项 |

**版本改动必须可追溯：** 规则、Prompt、Schema、数据口径、审批策略任一变更，都要登记版本号、责任人、变更原因与回滚方案。

---

## 恢复准入：四道门

Skill 只有同时通过以下四道门，才允许从“冻结”恢复为“小范围灰度”。

1. **数据门：** 目标门店关键数据在阈值内更新；数据异常样本能被拦截。
2. **规则门：** 已复购、退款/取消、活动不适用等反例全部进入回归样本；同类误判不再出现。
3. **权限门：** 数据范围遵循 SaaS 实时判权；高风险话术不能绕过人工确认；全链路保留审计日志。
4. **价值门：** 灰度名单的有效触达率、导购采纳率、复购/到店转化至少不低于人工基线，并能解释差异。

任何一门不通过：不得恢复自动下发，只能保持人工确认模式或继续冻结。

---

## 验证样本与灰度步骤

### 回归样本包
- 已复购但数据延迟的会员；
- 退款、取消订单、跨渠道订单会员；
- 活动仅部分门店/会员等级可用的会员；
- 无历史消费、画像不完整的会员；
- 无权限查看的跨门店会员。

### 灰度步骤

```text
修复版本提交
  ↓
离线回归：覆盖历史异常与反例
  ↓
单品牌 / 单门店 / 少量导购人工确认灰度
  ↓
观察有效触达、投诉、人工拦截与数据异常率
  ↓
评审是否扩大；不通过则回滚或继续冻结
```

建议首轮灰度只运行 3–5 个工作日，且不允许自动承诺活动权益。

## 今日可执行动作

1. 为该 Skill 建立一张《异常—版本—回归—恢复》台账，字段按“证据最小集”固化。
2. 选 10 条历史触达样本，人工核验消费时效、已复购排除和活动适用性，形成首批回归样本。
3. 明确恢复灰度的拍板人：业务负责人确认价值与客户体验，产品确认规则口径，技术确认数据/权限/审计，交付确认客户现场可执行。

## 晚间复盘

1. 今天找到的异常，是否已经归到输入、数据、逻辑、权限或体验之一，而不是笼统归因“AI 不准”？
2. 修复动作是否真的改变了 Skill 的规则、数据校验、权限或输出结构？
3. 恢复灰度前，四道门里哪一道还没有证据？谁负责补齐？
4. 这次异常沉淀后，是否能减少下一次同类客户/门店的重复踩坑？

## 一句话结论

**Skill 冻结是止血，版本修正与恢复准入才是能力升级；没有回归证据的“恢复上线”，本质还是把风险重新推回客户现场。**
