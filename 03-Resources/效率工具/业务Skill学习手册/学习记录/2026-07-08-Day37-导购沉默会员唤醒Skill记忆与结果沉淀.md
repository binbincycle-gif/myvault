## 今日抓到的核心判断

Day37 的重点是把“导购沉默会员唤醒 Skill”从 **Agent 能正确调用**，继续推进到 **执行结果能反哺组织能力**。

> 没有结果沉淀的导购 Skill，只是一次话术生成；能把采纳、触达、回复、到店、成交、未采纳原因持续回写，才会变成会进化的导购经营能力。

当前最容易犯的错误是：只重视“生成名单和话术”，但没有设计清楚执行后写回什么、写到哪里、谁来复盘、哪些结果能沉淀为组织经验。

对 EZR 来说，这一步决定了智能导购到底是“AI 内容工具”，还是“CRM + 导购关系 + 交易闭环”的真正护城河。

## 导购沉默会员唤醒 Skill｜结果沉淀设计草案

### 1. 本次 Skill 输出什么

给导购：
- 今日优先唤醒会员名单；
- 每个会员的唤醒理由；
- 建议话术；
- 推荐权益 / 活动；
- 下一步跟进节奏。

给店长 / 管理者：
- 可唤醒会员规模；
- 分层占比；
- 导购任务分布；
- 预估机会；
- 风险提醒。

给系统：
- 本次策略版本；
- 输出时间；
- 使用的数据口径；
- 人工确认状态；
- 后续回写字段。

### 2. 结果写回哪里

建议分三层沉淀：

#### A. 写回 CRM / 业务系统
用于业务闭环，必须结构化：
- 是否采纳建议；
- 是否触达会员；
- 触达渠道；
- 触达时间；
- 客户是否回复；
- 是否到店 / 预约 / 加购 / 下单；
- 成交金额 / 件数 / 客单价；
- 未采纳原因；
- 异常或投诉标记。

#### B. 写入项目记忆 / 客户场景沉淀
用于品牌、门店、导购策略复盘：
- 哪类会员更容易被唤醒；
- 哪类权益更有效；
- 哪类话术导购更愿意用；
- 哪些门店执行率高；
- 哪些策略容易被忽略。

#### C. 写入组织知识 / Skill 资产
只沉淀可复用经验：
- 已验证有效的话术结构；
- 会员分层与动作建议模板；
- 常见异常处理方式；
- 权限与人工确认边界；
- 上线前检查清单和复盘模板。

### 3. 回写字段建议

必填字段：
```text
skill_run_id
brand_id / brand_name
store_id / store_name
guide_id / guide_name
member_id（按权限脱敏展示）
silence_rule（30/60/90天等口径）
recommendation_reason
action_suggestion
script_version
adopted_status
touched_status
result_status
created_at
```

人工确认字段：
```text
send_message_confirmed
coupon_confirmed
batch_touch_confirmed
cross_store_access_confirmed
sensitive_offer_confirmed
```

复盘字段：
```text
member_reply_status
visit_status
order_status
order_amount
not_adopted_reason
negative_feedback
next_followup_date
strategy_effect_score
```

### 4. 不应该沉淀什么

以下内容不要直接进入长期组织知识：
- 未经确认的会员敏感画像；
- 单个导购个人风格的主观评价；
- 没有数据验证的“最佳话术”；
- 过期活动权益；
- 一次性异常个案；
- 越权获取的数据结论。

原则：
> 会员数据留在 CRM 实时判权，组织知识只沉淀脱敏后的策略模式和复盘结论。

## 今日可以推进的一个动作

给“导购沉默会员唤醒 Skill”补一张 **结果回写字段表 v0.1**，先不追求完整系统设计，只确认 5 个问题：

```text
1. 导购是否采纳，写在哪里？
2. 是否触达会员，写在哪里？
3. 客户是否回复 / 到店 / 下单，如何回收？
4. 未采纳原因怎么分类？
5. 哪些经验可以脱敏沉淀成组织级话术 / 策略模板？
```

## 对产品和技术的提醒

### 产品侧
- PRD 里不能只写“生成推荐”，必须写“推荐后如何采纳、触达、回写、复盘”。
- 智能导购的价值证明不是生成多少话术，而是导购是否采纳、客户是否响应、经营结果是否改善。
- 需要给店长 / 总部一个复盘视角，避免结果只停留在导购个人动作里。

### 技术侧
- 每次 Skill 调用应有 `skill_run_id`，便于追踪策略版本和结果回流。
- 回写字段要区分系统自动生成、导购手动确认、CRM 交易结果自动回收。
- 涉及会员数据的沉淀必须遵守实时权限，不把敏感会员明细写入通用知识库。

### 管理侧
- 评审智能导购时，不只看 Demo 生成效果，要看有没有形成“输出 → 采纳 → 触达 → 结果 → 复盘 → 策略优化”的闭环。
- 如果没有回写和复盘，这个 Skill 只能算内容辅助，不能算经营能力。

1. 今天是否明确了导购沉默会员唤醒 Skill 的关键回写字段？

## 一句话总结

Day37 的重点是结果沉淀：**导购 Skill 不是生成一次名单和话术就结束，而是要把采纳、触达、响应、成交和未采纳原因回写成可复盘资产；每执行一次，CRM 和组织都应该更懂导购经营。**
