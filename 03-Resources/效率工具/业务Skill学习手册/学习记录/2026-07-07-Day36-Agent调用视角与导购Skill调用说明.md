## 今日抓到的核心判断

Day36 的重点不是继续扩展功能，而是从 Agent 调用视角重新检查：

> 一个 Skill 能不能稳定进入真实业务流程，关键不只是它会做什么，而是 Agent 能不能正确判断“什么时候该用、缺什么不能硬跑、哪些动作必须确认、结果如何回写和复盘”。

对“导购沉默会员唤醒 Skill”来说，当前最容易出问题的不是话术质量，而是调用说明不够清楚导致的三类风险：

1. **误用**：普通会员分析、活动复盘、导购绩效分析都被误判成沉默会员唤醒。
2. **硬跑**：缺品牌、门店、会员筛选口径、活动权益、导购权限时仍然生成建议。
3. **越权**：把“生成建议”滑向自动发券、自动群发、跨门店查看会员。

因此，下一步要补的不是更多提示词，而是一份可被 Agent 稳定理解和执行的 **Skill 调用说明**。

## 导购沉默会员唤醒 Skill｜Agent 调用说明草案

### 1. 触发条件

当用户提出以下需求时，应该调用本 Skill：

- 给导购生成沉默会员唤醒名单；
- 为沉睡/流失风险会员生成跟进建议；
- 按门店/导购筛选需要唤醒的会员；
- 生成复购提醒、关怀话术、权益推荐；
- 需要把会员唤醒动作回写 CRM 并做效果复盘。

不应调用的相似场景：

- 单纯查看会员画像，不需要唤醒动作；
- 活动整体复盘，不涉及导购逐个跟进；
- 导购绩效考核，不直接生成会员跟进建议；
- 自动群发、自动发券、自动外呼等执行动作未授权场景。

### 2. 输入要求

必填信息：

- 品牌 / 客户范围；
- 门店 / 导购权限范围；
- 沉默会员定义，例如 30/60/90 天未消费或未互动；
- 当前可用活动或权益；
- 输出目标：名单、话术、动作建议、复盘看板中的哪一种。

缺失时处理：

- 缺品牌/门店/权限范围：必须追问，不能生成具体会员建议；
- 缺沉默会员定义：可给默认口径建议，但必须标注“待确认”；
- 缺活动权益：只能生成非权益型关怀话术，不能虚构优惠；
- 缺回写字段：可先给草案，但不能宣称可直接闭环。

### 3. 权限与边界

必须继承 CRM 现有权限体系：

- 导购：仅能处理自己权限内会员；
- 店长：可看本门店导购过程与汇总；
- 区域：可看区域汇总，不直接替导购触达；
- 总部：可配置策略、看全局效果，不默认下钻到敏感个人数据。

必须人工确认的动作：

- 自动发消息；
- 自动发券；
- 批量触达；
- 修改会员标签；
- 调整权益；
- 跨门店/跨导购分配会员。

### 4. 执行步骤

1. 判断是否属于“沉默会员唤醒”场景；
2. 检查品牌、门店、导购、会员筛选口径和权限范围；
3. 读取允许范围内的会员行为、交易、互动和活动上下文；
4. 生成会员分组、唤醒理由、建议动作、话术草案；
5. 标注每条建议的风险、适用权益和人工确认点；
6. 输出回写字段和复盘指标；
7. 对缺失信息或越权动作给出降级方案。

### 5. 输出结果

给管理者看的结论：

- 本次可唤醒会员规模；
- 优先唤醒分层；
- 预计动作价值；
- 主要风险点。

给导购用的动作：

- 会员名单；
- 跟进理由；
- 建议话术；
- 推荐权益；
- 下一步跟进节奏。

给系统回写的字段：

- 是否采纳；
- 是否触达；
- 客户是否回复；
- 是否到店/预约/成交/加购；
- 未采纳原因；
- 风险备注；
- 使用的策略版本。

复盘指标：

- 导购采纳率；
- 触达率；
- 回复率；
- 唤醒率；
- 成交/复购线索贡献；
- 未采纳原因 TOP；
- 异常话术/权益拦截次数。

## 今日可以推进的一个动作

给“导购沉默会员唤醒 Skill”补一版正式的 `description + 输入要求 + 风险边界 + 输出格式`，先不要急着扩展更多能力。

建议今天只确认 3 件事：

```text
1. 哪些用户表达应该触发这个 Skill？
2. 缺哪些信息时必须追问，不能硬跑？
3. 哪些动作必须人工确认，不能自动执行？
```

## 对产品和技术的提醒

### 产品侧
- Skill 文档不是产品介绍，而是 Agent 的调用说明。
- 产品 PRD 里要增加“Agent 何时调用 / 何时不调用 / 缺什么追问 / 风险如何降级”。
- 不要只定义页面功能，要定义 Agent 输出后如何进入导购动作和 CRM 回写。

### 技术侧
- description 要写清业务场景和触发词，避免 Agent 命中错误。
- 输入 Schema 要区分必填、可选、可默认、必须追问。
- 涉及外部触达、权益、批量操作时，必须在工具层做二次确认和审计，不只依赖提示词约束。

### 管理侧
- 评审 Skill 时，不只看它生成内容好不好，还要看 Agent 是否能稳定判断调用边界。
- 后续 Skill 资产评审建议增加一项：是否具备可治理的调用说明。

## 晚上复盘问题

1. 今天是否明确了导购沉默会员唤醒 Skill 的触发条件和非适用场景？
2. 是否列清楚了必填输入、可选输入和必须追问的信息？
3. 是否把自动发券、自动群发、跨门店查看等高风险动作写入人工确认边界？
4. 输出结果是否同时覆盖管理者结论、导购动作、系统回写和复盘指标？
5. 这个 Skill 是否已经从“提示词能力”推进到“Agent 可稳定调用的业务能力”？

## 一句话总结

Day36 的重点是把“导购沉默会员唤醒 Skill”从产品化检查继续推进到 Agent 调用治理：**Skill 不是给人看的功能说明，而是 Agent 的行动边界；触发、输入、步骤、风险、输出写清楚，才可能被稳定调用、持续复盘、规模化复制。**
