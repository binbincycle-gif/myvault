## 今日抓到的核心判断

Day38 的重点是把“导购沉默会员唤醒 Skill”从 **能沉淀结果**，继续推进到 **能安全进入真实经营流程**。

> 导购 Skill 越接近真实动作，越不能只靠提示词约束；必须把身份、数据、动作、审批、回滚和审计写进产品机制。

这类 Skill 的风险不在“AI 说错一句话”这么简单，而在它可能影响会员隐私、客户触达、权益发放、门店边界和品牌经营结果。

所以今天的落点不是继续扩功能，而是先把安全边界画清楚：哪些只读、哪些只建议、哪些必须人工确认、哪些暂时不能自动执行。

## 导购沉默会员唤醒 Skill｜安全边界草案

### 1. 身份边界：Agent 代表谁工作

必须先明确当前调用身份：

```text
总部运营：可看品牌级汇总、策略效果、门店执行情况。
店长：可看本店会员唤醒任务、导购执行率、门店转化结果。
导购：只可看自己权限范围内的会员建议与话术。
客服/运营支持：可协助生成建议，但不能越权查看会员明细或代替导购触达。
```

底线：
- 导购不能查看非本人会员池的明细；
- 店长不能跨门店查看会员隐私明细，除非品牌规则授权；
- 总部可以看汇总趋势，但敏感会员明细需按现有 CRM 权限走；
- Agent 不新增权限，只继承并执行 SaaS 实时判权。

### 2. 数据边界：能读什么，不能沉淀什么

允许读取：
- 会员沉默天数；
- 最近消费 / 互动 / 触达摘要；
- 偏好标签摘要；
- 导购关系；
- 当前活动 / 权益规则；
- 历史触达结果。

不应进入长期组织知识：
- 明文会员手机号、地址等敏感信息；
- 未脱敏的单个会员完整交易轨迹；
- 导购个人主观评价；
- 未经验证的“最佳话术”；
- 客户隐私细节。

建议做法：
- CRM 业务系统存结构化执行结果；
- Skill 资产只沉淀脱敏后的策略模式、话术结构、异常处理经验；
- 所有会员级数据实时判权，不复制到长期记忆。

### 3. 动作分级：从建议到执行分四层

```text
L0 只读查询：查看沉默会员规模、分层、趋势、历史触达摘要。
L1 建议生成：生成唤醒名单、推荐理由、建议话术、权益建议。
L2 半自动执行：导购确认后发送话术、标记跟进、领取任务。
L3 自动执行：批量发送、批量发券、跨门店触达、修改会员标签/权益。
```

当前 MVP 建议：
- 开放 L0 / L1；
- L2 只允许“人确认后执行”；
- L3 默认不开放，除非具备明确审批、限额、审计和回滚机制。

### 4. 人工确认点：这些动作不能自动做

必须人工确认：
- 是否发送给会员；
- 选择触达渠道；
- 是否使用 AI 推荐话术；
- 是否发放优惠券 / 权益；
- 是否跨门店协同；
- 是否修改会员跟进状态；
- 是否将结果写回 CRM。

高风险场景必须审批：
- 批量触达；
- 高面额权益；
- 跨门店 / 跨导购客户触达；
- 涉及敏感客诉或承诺赔付的话术；
- 可能影响会员等级、权益、价格的动作。

### 5. 审计与回滚：出错后能查、能停、能修

每次 Skill 执行至少记录：

```text
skill_run_id
调用人 / 代表身份
品牌 / 门店 / 导购
数据权限范围
输入数据口径
输出建议版本
人工确认人
实际执行动作
执行时间
触达对象数量
权益/券配置
结果回写状态
异常与回滚状态
```

回滚机制建议：
- 话术发送错误：记录异常，标记客户反馈，进入人工补救；
- 权益发放错误：按券状态判断撤回、冻结或补偿；
- 标签写入错误：保留原值，支持恢复；
- 批量任务异常：一键暂停后续任务，保留已执行清单。

## 晚上复盘问题

1. 今天有没有把导购 Skill 的动作分级说清楚，避免一上来就做自动触达？
2. 哪些会员数据必须实时判权，不允许进入长期 Skill 记忆？
3. 如果 AI 推荐错话术、错权益、错客户，系统能不能追溯责任并暂停后续动作？
4. 当前 MVP 最安全的边界是否应该定为：AI 生成名单和话术，导购确认后执行，结果结构化回写？

## 一句话沉淀

导购沉默会员唤醒 Skill 的 MVP 不要追求“自动化到底”，而要先做到 **权限不越界、动作有人确认、结果可审计、异常可回滚**。这一步做好，智能导购才有资格从建议工具进入真实经营流程。
