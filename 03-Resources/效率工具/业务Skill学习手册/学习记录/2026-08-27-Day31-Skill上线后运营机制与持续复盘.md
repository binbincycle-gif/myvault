# 2026-08-27 Day31｜Skill上线后运营机制与持续复盘

## 今日承接
- 昨日学习：Day30《Skill上线前检查清单：从可用到可交付》
- 今日推进：从“能上线”继续推进到“上线后能稳定跑、持续优化、能形成组织资产”

## 一句话结论
Skill 真正难的不是上线，而是上线后有没有被持续使用、持续复盘、持续优化；没有运营机制，Skill 很快就会变成一次性交付物。

## 今日学习要点
### 1. 上线不是终点，而是运营起点
业务 Skill 一旦进入真实团队使用，就会立刻暴露四类问题：
- 调用频率和预期不一致
- 场景命中率不稳定
- 输出有用但不好执行
- 规则变化后版本老化

所以 Skill 上线后，必须有人持续盯：
- 谁在用
- 用在哪些场景
- 哪些结果被采纳
- 哪些异常在重复出现
- 是否还值得继续投入

### 2. Skill 运营至少看 5 个指标
- 使用量：被调用多少次，哪些角色在用
- 命中率：是否在正确场景被触发
- 采纳率：输出建议被执行/确认的比例
- 结果率：是否带来业务结果改善
- 异常率：权限不足、数据缺失、误触发、低质量输出占比

### 3. 复盘重点不是“模型聪不聪明”，而是“闭环有没有更顺”
对业务 Skill，最值得持续优化的不是文案润色，而是：
- 输入上下文够不够
- 输出结构能不能直接行动
- 审批/确认链路是否过长
- 结果是否完成回写
- 是否已具备跨团队/跨客户复制条件

## 结合当前主线的落点
### 1. OpenClaw / AI Coding
不能只统计“多少人用了”，要盯：
- 是否真的进入需求、缺陷、测试、发布链路
- 是否沉淀出可复用 Skill / 检查表 / 工作流
- 是否减少了负责人亲自盯的协调成本

### 2. 导购小龙虾 / 智能导购
不能只看“AI给没给建议”，要盯：
- 导购是否按建议完成触达
- 触达后是否有回复/转化
- 哪类客群/商品/话术更有效
- 经验是否回流成下一轮策略优化依据

### 3. EZR SaaS能力层
不能只做能力清单，要盯：
- 哪些能力已被真实 Agent 调用
- 哪些调用结果形成业务闭环
- 哪些能力因为权限/审计/回写不完整而无法规模化

## 今日可执行动作
1. 给每个在推的业务 Skill 补一张“上线后运营卡”：Owner、目标角色、核心场景、5个指标、异常入口、下次复盘时间。
2. 选 1 个正在推进的真实场景（建议：导购沉默会员唤醒 / AI Coding任务协同），补齐“调用→执行→回写→复盘”链路。
3. 晚上复盘时，不问“今天做了多少功能”，只问“哪个 Skill 更接近可持续经营”。

## 今晚复盘问题
- 今天盯的 Skill，是否已经从“能跑通”推进到“有人持续用、结果可回收、问题可优化”？
- 如果没有，卡点是在使用频次、业务闭环、还是运营责任人缺失？
- 哪一个 Skill 最值得进入下一轮样板放大？
