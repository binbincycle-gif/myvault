# Day66｜Skill 结果回写与组织沉淀

> 对应章节：[[Day28-Skill记忆与沉淀：让执行结果反哺能力]]
> 日期：2026-11-18

## 今日结论

Skill 的价值不止在完成一次任务，而在于每次执行都把结果、证据、异常与复盘回写到正确的资产层，让下一次调用更准、更快、更稳。没有回写机制，Skill 只是一次性自动化；沉淀错误口径则会把风险规模化。

## EZR 首个闭环：导购跟进建议 Skill

```text
会员分层 / 当前活动 / 导购权限
→ 生成优先级、推荐动作与话术
→ 导购确认后执行
→ CRM 回写触达与反馈
→ 回流到店 / 下单 / 核销结果
→ 周度复盘规则、话术和客群口径
```

## 回写字段 v0.1

| 层级 | 必填回写 | 用途 |
|---|---|---|
| 执行 | 调用人、数据范围、规则/模型版本、建议、采纳/拒绝、实际动作与时间 | 审计与追溯 |
| 结果 | 回复、领券、到店、下单、成交金额、异常/投诉 | 衡量业务价值 |
| 经验 | 有效客群/话术、未采纳原因、规则缺陷、数据缺失 | 优化下一次调用 |
| 治理 | 来源、人工确认人、纠偏记录、有效期、维护 Owner | 避免错误知识扩散 |

## 三层沉淀规则

1. **临时上下文**：当天任务与报告草稿，任务结束后不进入长期记忆。
2. **项目记忆**：客户/项目专属的规则、范围、已确认风险与决策，随项目维护。
3. **组织知识**：可跨客户复用的指标定义、Skill 卡、准入清单、异常复盘和最佳实践；必须带来源、Owner 与更新时间。

## 管理要求

- 读可自动；写入 CRM、发消息、发券、批量修改必须人工确认。
- 业务结果与经验结论须区分：原始记录可以自动留痕，进入规则库的结论应经人工确认。
- 每周复盘采纳率、触达率、转化率、异常率和人工接管率；低收益或高风险规则及时停用。
- 每条沉淀需有来源、版本、维护 Owner 和过期清理方式，避免知识库成为噪音库。

## 今日可执行动作

为“沉睡会员唤醒”建立一张结果回写卡：

> 客群规则｜导购建议｜人工确认｜实际触达｜客户反馈｜到店/成交/核销｜未采纳原因｜异常｜规则版本｜复盘结论

先以 20 个脱敏历史样本完成回放，验证字段完整度、人工接管点与可量化结果，再进入客户侧试点。

## 一句话收获

**Skill 不是做完即结束；只有把执行结果、异常和验证过的经验持续回写，才会从一次性自动化变成组织能力。**
