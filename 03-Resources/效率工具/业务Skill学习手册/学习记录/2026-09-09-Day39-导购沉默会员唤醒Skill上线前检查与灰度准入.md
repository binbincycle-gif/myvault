# 2026-09-09 Day39｜导购沉默会员唤醒 Skill 上线前检查与灰度准入

## 今日阅读

复习《业务Skill学习手册》Day30《Skill上线前检查清单：从可用到可交付》，并联动昨日 Day38《业务Skill安全边界与结果沉淀联动》。

## 我今天抓到的核心一句话

**Skill 上线不是“能跑一次”，而是同时通过价值、权限、流程、数据和运营五道准入；未通过就只能留在试验环境。**

## 结合 EZR / OpenClaw / 智能导购的理解

导购沉默会员唤醒 Skill 的首个灰度版本，不应以“话术生成效果”作为上线标准，而应验证完整闭环：

1. 导购身份、门店和会员范围判权；
2. 以统一口径筛出沉默会员，并能解释推荐原因；
3. 给出客户级建议、话术与推荐商品；
4. 导购确认后才创建触达或跟进动作；
5. 回写采纳、触达、回复、到店、成交、拒绝/异常原因；
6. 能按人、时间、输入、输出和动作进行审计；
7. 通过一小组门店灰度数据判断是否扩围。

OpenClaw/Agent 负责把“取数—分析—建议—执行编排”串起来，但 CRM 仍是权限判定、业务状态和结果沉淀的事实源。

## 今日形成的上线前准入表

| 准入项 | 首版必须达到的标准 | 不通过的处理 |
|---|---|---|
| 业务价值 | 明确目标：提升沉默会员触达率、回复率或回店转化；有基线口径 | 不扩围，只保留样例验证 |
| 数据口径 | 沉默定义、可触达条件、推荐依据可解释 | 先修口径，不允许直接下发名单 |
| 权限边界 | 导购仅见本人会员；跨门店/高价值权益有审批 | 降级为只读建议 |
| 执行流程 | 触达必须人工确认；异常可撤回/停止 | 禁止自动批量执行 |
| 结果回写 | 至少回写采纳、触达、回复、到店、成交、异常原因 | 不计入效果，不能沉淀经验 |
| 审计与运营 | 可定位调用人、输入、输出、确认及执行时间；有异常负责人 | 不进入客户灰度 |

## 建议的灰度节奏

- **阶段 1：内部回放。** 选 3 个历史会员样例，验证数据、推荐理由、权限和回写字段。
- **阶段 2：单店小范围。** 1 家门店、2—3 名导购、限定会员池；只开放 L1 建议和 L2 人工确认。
- **阶段 3：扩围决策。** 连续观察一周，不只看成交，也看建议采纳率、触达率、异常率与导购反馈；达到门槛才扩店。

## 对当前项目的下一步

1. 智能导购 MVP 评审中补一张《灰度准入表》，把“可演示”与“可试点”分开。
2. 给 CRM 回写增加固定字段：建议ID、采纳状态、触达渠道、结果、异常原因、确认人和时间。
3. 指定门店试点负责人及异常升级路径；没有负责人、不开放灰度。

## 风险边界

- 不能用单次成交证明 Skill 有价值，必须与基线和人工组对照。
- 不让 Agent 绕过 CRM 的实时权限和业务状态校验。
- 试点产生的会员明细、未确认模型推测不能进入组织长期知识库；只沉淀脱敏且经确认的策略模式。
