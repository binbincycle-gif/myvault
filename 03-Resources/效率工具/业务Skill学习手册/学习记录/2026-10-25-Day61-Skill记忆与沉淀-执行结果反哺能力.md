# Day61｜Skill 记忆与沉淀：让执行结果反哺能力

> 对应学习章节：[[Day28-Skill记忆与沉淀：让执行结果反哺能力]]
> 衔接上篇：[[2026-10-24-Day60-Skill上下文工程-正确业务资料]]

## 今日主题

Skill 的价值不只在“这一次帮你完成任务”，还在于每次执行后能否把有效结果、异常和口径沉淀下来，让下一次更准、更快、更稳。

核心判断：**没有沉淀机制的 Skill 只是一次性自动化；能持续回写执行结果与复盘判断的 Skill，才会成为会进化的业务能力。**

## 一次执行应沉淀的四类信息

| 类别 | 应沉淀什么 |
|---|---|
| 结果数据 | 结论、动作、清单、报告 |
| 过程证据 | 数据源、知识库引用、指标口径 |
| 异常经验 | 数据缺失、权限不足、口径冲突、需人工确认点 |
| 复盘判断 | 是否采纳、业务是否有效、下次如何优化 |

不回写，下一次 Agent 仍从零开始；组织不会积累经验。

## 沉淀必须分层

```text
临时上下文：当前任务/当前报告草稿
项目记忆：客户、项目、专题内持续有效的规则与口径
组织知识：跨项目可复用的字段定义、模板、最佳实践、风险清单
```

不是所有日志都应进入长期记忆。优先沉淀：重复问题、已验证做法、确认口径、关键风险边界、可复用模板；一次性结果和噪音留在任务日志。

## 导购客户跟进 Skill：回写设计

```text
执行回写：是否采纳、实际话术版本、发送时间、触达渠道
结果回写：回复、点击/领券/到店/下单、成交金额、客单、连带
经验沉淀：什么客户对什么话术响应好；什么推荐常被忽略；什么权益带来转化
风险记录：客户反感、敏感优惠、权限/审批异常
```

这才让“生成一段话术”升级为“导购 Agent 的经验资产”。

## 今日可执行动作

1. 为 CRM Agent 首个闭环确定回写最小集：**是否采纳、动作类型、动作时间、结果、异常原因**；没有回写字段，不进入灰度。
2. 建立三层归档规则：任务日志 / 项目知识 / 组织模板，防止把原始执行记录直接塞进长期知识库。
3. 每两周复盘一次已沉淀规则：确认有效、纠正错误、清理过期内容；经营结论和客户数据必须保留来源与人工确认标记。

## 晚间自检

1. 结果写回业务系统、项目文档、知识库还是只留日志？
2. 哪些内容是一次性结果，哪些值得跨项目复用？
3. 发生错误时，沉淀内容能否追溯、纠偏、清理？
4. 谁维护、多久复盘、何时过期？

## 一句话结论

**Skill 的价值不只在“帮你做一次”，而在“每做一次，组织就多一份可复用经验”。**
