# Day52｜导购沉默会员唤醒 Skill：灰度发布与通过标准

> 对应学习章节：[[Day19-Skill灰度发布：先小范围验证再规模化推广]]
> 衔接上篇：[[2026-09-21-Day48-导购沉默会员唤醒Skill异常复盘与版本回归]]

## 今天学什么

Day48 解决“出错后如何不复发”；Day52 要把“不出错”前置——不是等 Skill 写完美再全员开放，而是**先在小范围真实场景里验证价值、边界和风险，再决定是否扩大**。

核心原则：**灰度不是上线慢一点，而是把人、场景、数据、动作权限四个变量同时圈住，用通过标准决定扩还是收。**

## 当前业务场景

### Skill
导购沉默会员唤醒 Skill。

### 当前运行边界
- 只生成“优先级排序 + 推荐理由 + 建议话术”，不自动触达；
- 已保留门店、导购、数据批次、规则版本、采纳/修改/拒绝及后续结果；
- 已有运营看板与异常复盘机制，具备扩围后的观测基础。

## 灰度要控制的四个变量

| 变量 | 当前场景里的控制方式 | 目的 |
|---|---|---|
| 使用人群 | 先选 1–2 个品牌、少数门店、表现稳定的导购 | 防止问题快速扩散 |
| 使用场景 | 只做“今日优先跟进会员 + 理由 + 话术”，不做自动发券/自动触达 | 防止被用到设计外场景 |
| 数据范围 | 限定品牌、门店、会员池与数据批次时间范围 | 降低越权和口径风险 |
| 能力权限 | 停留在 L1 建议生成，人工确认后才进入下一步 | 控制生产风险 |

## 通过标准（不是“大家觉得不错”）

| 指标 | 判断问题 | 当前场景的验收口径 |
|---|---|---|
| 使用率 | 目标导购是否真的愿意用？ | 灰度门店日均打开率达标 |
| 成功率 | 是否稳定完成“出名单+给理由”任务？ | 无批量报错、无空名单 |
| 修正率 | 导购是否大量改/跳过建议？ | 采纳率与修改率在可接受区间 |
| 异常率 | 是否出现口径/权限/事实/体验问题？ | 无越权查看、无权益误导、无重复打扰 |
| 业务影响 | 是否真的省时间或推动转化？ | 跟进记录回写率 + 触达后转化对比 |

## 回滚机制（三种，缺一不可）

```text
停用：出现权限风险或权益误导 → 立即关闭入口
降级：从“建议+自动排序”降为“纯人工名单”
回退：切回上一个稳定规则版本 / 模板
```

## 今日可执行动作

1. 为当前导购沉默会员唤醒 Skill 写一张**灰度卡**：灰度人群、灰度场景、数据范围、能力等级（L1）、起止时间、责任人。
2. 把上表的 5 类指标落成看板字段，并给出“扩大 / 维持 / 降级 / 停用”的阈值。
3. 明确一条硬规则：**未同时具备“停用 + 降级 + 回退”三种预案，不允许从灰度扩大到全量。**

## 晚间复盘

1. 当前要推广的 Skill，是否已明确灰度人群和灰度场景，而不是凭感觉铺开？
2. 它现在是 L1“给建议”，还是已经碰到 L2/L3“自动执行”？边界写清楚了吗？
3. 如果今天出问题，能否立即停用、降级或回退到稳定版本？

## 一句话结论

**Skill 发布不能靠感觉铺开；先灰度验证价值和边界，用通过标准拍板扩大，才是组织级 AI 能力的正确打法。**
