# Day53｜导购沉默会员唤醒 Skill：下线与归档机制

## 今天学什么

Day52 解决“怎么受控扩大”；Day53 要解决“什么时候该停、该并、该归档”。

核心原则：**Skill 不是上线后就永远存在。能上架、能运营、能下线、能归档，才是真正可治理的组织级 AI 能力。**

## 当前业务场景

### Skill
导购沉默会员唤醒 Skill。

### 当前状态
- 已走过：蓝图 → MVP → 交付包 → 灰度 → 运营看板 → 异常复盘 → 版本回归 → 灰度通过标准；
- 属正式运营态，已形成依赖，此时最怕“旧口径继续被用、多个相似 Skill 并存、无人维护仍被调用”三类问题。

## 生命周期六态（当前 Skill 的落位）

| 状态 | 含义 | 本场景 |
|---|---|---|
| 草稿 | 设计中，不开放真实使用 | — |
| 灰度 | 小范围试点，限定人群/场景/数据/权限 | Day52 已完成 |
| 正式 | 通过验证，进入目录与运营机制 | ← 当前位置 |
| 冻结 | 暂停扩大，等待修复或评审 | 出现权限/权益误导时进入 |
| 废弃 | 不建议继续用，标记替代方案 | 口径整体过期时进入 |
| 归档 | 退出生产使用，保留历史 | 被新工作流替代时进入 |

## 下线判断的 5 类信号

| 信号 | 在本场景中的表现 |
|---|---|
| 业务规则变化 | 会员分层、沉默定义、复购潜力口径升级，旧逻辑过期 |
| 数据口径变化 | 数据批次、指标定义、门店/导购归属范围变化 |
| 使用量下降 | 导购已转向更新的工作流入口 |
| 异常率升高 | 频繁出现越权查看、口径错误、重复打扰 |
| 替代能力出现 | 新版“推荐→理由→话术→触达→复盘”工作流已覆盖同一场景 |

**判断口径**：低使用 + 高异常 + 无人维护 → 进入废弃/归档，而不是继续挂在目录里。

## 下线不是删除，而是受控迁移

```text
标记：明确 已废弃 / 待下线 / 已归档
迁移：说明推荐使用哪个新版 Skill 或人工流程
留痕：保留版本、负责人、下线原因、影响范围
```

## 今日可执行动作

1. 为当前 Skill 在目录里补一列**生命周期状态**（草稿/灰度/正式/冻结/废弃/归档），并指定**唯一负责人 + 维护周期**。
2. 选一个最可能被新版工作流覆盖的点（如“只出名单”被“名单+理由+话术+反馈”覆盖），写一条**迁移说明**：旧入口如何提示、新入口是谁、历史报告口径如何标注。
3. 定一条下架标准：**连续两周无人维护，或异常率超阈值 → 先冻结、再废弃归档**；下架前必须提供替代方案与影响范围。

## 晚间复盘

1. 当前 Skill 目录里，是否已有功能相似但没人合并的入口？
2. 这个 Skill 的规则、数据口径、权限边界，是否有部分已经过期？
3. 如果今天就要下线它，能否说明替代方案和影响范围？

## 一句话结论

**Skill 资产不是越多越好；能上架、能运营、能下线、能归档，才是真正可治理的组织级 AI 能力。**
