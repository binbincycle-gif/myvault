## 我今天抓到的核心一句话
Skill 不是给人看的功能说明，而是给 Agent 做判断、选能力、控风险、交付结果的能力说明书。

## 结合当前业务主线的理解
放到 EZR / OpenClaw / 智能导购主线里，导购沉默会员唤醒 Skill 如果要从“人手动调用”走向“Agent 稳定调用”，关键不只是把提示词写好，而是把 5 件事写死：

1. 什么场景必须调用；
2. 缺哪些输入不能硬跑；
3. 哪些动作必须人工确认；
4. 调用后要输出什么交付物；
5. 哪些结果必须回写 CRM 形成复盘闭环。

否则 Agent 很容易出现三类问题：该用不用、误用越权、输出结果无法进入后续流程。

## 导购沉默会员唤醒 Skill 的 Agent 调用说明再校准

### 1. 触发条件
当用户提出以下诉求时，Agent 应优先考虑调用本 Skill：
- 帮导购找一批需要唤醒的沉默会员；
- 生成会员唤醒名单、触达理由、话术建议；
- 针对门店 / 品牌做沉默会员激活方案；
- 复盘导购会员唤醒效果；
- 根据活动、权益、商品库存，安排导购做会员跟进。

相似但不应直接调用的场景：
- 纯会员数据查询，不需要生成动作建议；
- 大规模自动群发或自动发券；
- 客诉、敏感会员、重大权益承诺等高风险场景；
- 没有品牌 / 门店 / 导购权限范围的泛化运营建议。

### 2. 输入要求

#### 必填输入
- 品牌或客户范围；
- 门店 / 导购 / 区域范围；
- 沉默会员定义口径（如 30 / 60 / 90 天未消费）；
- 当前活动目标（唤醒、复购、清库存、节日触达等）；
- 可用权益或禁止使用权益说明；
- 操作人身份与权限范围。

#### 可选输入
- 重点商品 / 库存压力；
- 历史活动表现；
- 会员分层规则；
- 导购执行能力差异；
- 品牌话术风格要求。

#### 缺失处理
- 缺少品牌 / 门店 / 权限范围：必须追问，不能直接生成名单；
- 缺少活动目标：可先给 2-3 个目标选项让用户确认；
- 缺少权益规则：默认只生成建议，不承诺发券 / 折扣；
- 缺少沉默口径：默认给草案，但必须标注“口径待确认”。

### 3. 权限与风险边界

#### 允许动作
- 生成候选会员分组建议；
- 生成导购跟进理由；
- 生成可编辑话术；
- 生成复盘指标；
- 生成 CRM 回写字段建议。

#### 必须人工确认的动作
- 自动发送消息；
- 自动发券 / 锁券 / 批量分配权益；
- 修改会员标签；
- 批量下发导购任务；
- 跨门店 / 跨区域查看会员明细；
- 对投诉、敏感、重点客户生成直接触达动作。

#### 风险红线
- AI 继承 CRM 现有权限，不扩展数据可见范围；
- 总部可看策略效果，不默认代替导购触达；
- 店长看门店汇总，不越权看其他门店会员明细；
- 导购只看自己服务关系内会员；
- 所有自动执行类动作必须留审批、审计、回滚路径。

### 4. 执行步骤

1. **识别场景**：判断是否属于沉默会员唤醒 / 复购激活 / 导购跟进。
2. **检查输入**：品牌、门店、导购、口径、目标、权益、权限是否齐全。
3. **生成分组**：按会员价值、沉默时长、历史偏好、最近触达状态分组。
4. **生成动作**：每组输出跟进理由、推荐商品 / 权益建议、话术草案。
5. **风险拦截**：识别敏感客户、高风险权益、越权数据和自动发送动作。
6. **输出结果**：给管理者看结论，给导购看动作，给系统留回写字段。
7. **复盘回写**：采纳、触达、回复、到店、成交、未采纳原因必须结构化沉淀。

### 5. 输出格式

#### 给管理者看的结论
- 本次建议唤醒会员总量；
- 重点分组与优先级；
- 预计影响指标；
- 风险与人工确认点。

#### 给导购用的动作
- 会员分组；
- 跟进理由；
- 推荐话术；
- 推荐商品 / 权益；
- 今日优先跟进顺序。

#### 给系统回写的字段
- 是否采纳建议；
- 是否触达；
- 客户是否回复；
- 是否预约 / 到店 / 成交；
- 未采纳原因；
- 异常原因；
- 人工拦截原因。

#### 复盘指标
- 建议采纳率；
- 触达完成率；
- 客户回复率；
- 到店 / 预约率；
- 成交 / 复购线索率；
- 未采纳原因 TopN；
- 高风险动作拦截次数。

## 对今天业务 Skill 编写的提醒
后续写业务 Skill，不能只写“使用步骤”，必须补齐 Agent 调用视角：

1. description 要写清触发词、适用场景、产出物；
2. 输入不足时要定义追问规则；
3. 涉及客户数据、权益、外部触达时要定义人工确认；
4. 输出必须能接到 CRM 回写和复盘指标；
5. 每个 Skill 都要说明“不该用”的边界，避免 Agent 误用。
