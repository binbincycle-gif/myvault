# Day62｜Skill 安全边界：权限、审批、回滚与人工确认

> 对应学习章节：[[Day29-Skill安全边界：权限、审批、回滚与人工确认]]
> 衔接上篇：[[2026-10-25-Day61-Skill记忆与沉淀-执行结果反哺能力]]

## 今日主题

业务 Skill 一旦从“生成建议”走向“调用系统能力”，安全边界必须前置设计。

核心判断：**没有边界的自动化不是能力，是风险。** Agent 越能影响客户、数据、订单、权益和经营决策，越需要明确谁能用、能看什么、能做到哪一步、出错怎么撤回、如何审计。

## 权限判断：身份 + 场景 + 动作

| 判断维度 | 要回答的问题 | 导购跟进示例 |
|---|---|---|
| 身份 | 当前调用者是谁？ | 导购、店长、总部运营、管理员 |
| 场景 | 正在做什么？ | 看数据、生成建议、提交审批、执行动作 |
| 动作 | 准备读、改或发什么？ | 读取会员、生成话术、发券、触达客户 |

只按账号分权限不够。导购可以看本人会员池的建议，但不应读取全品牌会员明细；运营可生成活动策略，但高额权益不应自动执行。

## 动作分级与控制

```text
L0 只读查询：查看数据、读知识库、生成摘要
L1 建议生成：方案、话术、清单、诊断结论
L2 半自动执行：先生成待执行动作，由人工确认提交
L3 自动执行：直接发送、改价、发券、建单、改配置
```

- **L0/L1**：相对开放，但记录数据来源与口径。
- **L2**：必须人工确认，可追溯。
- **L3**：默认不开；只有权限、额度、审计、回滚齐全，才可在高确定、低风险动作中灰度放开。

## 高风险动作的最小控制链

```text
权限校验 → 风险分级 → 人工确认 → 审批流 → 执行记录 → 异常回滚 → 复盘沉淀
```

重点覆盖：批量客户触达、发券/权益、会员标签或等级修改、价格/库存/商品状态调整、对外承诺、敏感数据批量导出。

## 导购客户跟进 Skill：安全边界示例

| 类别 | 允许范围 |
|---|---|
| 可读 | 导购本人会员池及授权范围内的交易/触达信息 |
| 可生成 | 重点客户排序、一对一话术、商品/权益建议 |
| 必须人工确认 | 实际发送、触达渠道、是否发券 |
| 需要审批 | 批量发券、高面额权益、跨门店触达、可能引发客诉的营销动作 |
| 默认禁止 | 未确认自动群发、越权查看其他导购客户、自动改会员等级/核心标签 |

## 今日可执行动作

1. 为 CRM Agent 首批场景建立一张安全边界表：调用角色、可读数据、可生成内容、可执行动作、人工确认、审批条件、回滚与审计记录。
2. 将首批能力全部限定在 **L1/L2**：先建议、后确认、小范围半自动；不把外发、发券、标签修改设为默认自动。
3. 把人工确认设计成产品流程字段，而不是口头要求：确认人、确认时间、动作内容、结果、撤回记录必须可追溯。

## 晚间自检

1. 这个 Skill 读取哪些数据、会不会改变业务状态？
2. 哪些动作需要人工确认或上级审批？
3. 出错后是否能撤回、修正并查到责任人、时间、输入与输出？
4. 是否把安全边界做成系统流程而非使用说明？

## 一句话结论

**业务 Skill 要进入真实经营流程，必须从第一天就设计权限、审批、回滚与审计；这是客户信任与商业化的前提。**
