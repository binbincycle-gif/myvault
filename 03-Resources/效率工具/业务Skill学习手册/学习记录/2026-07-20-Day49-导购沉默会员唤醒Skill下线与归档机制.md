## 今日抓到的核心判断

Day48 解决的是“Skill 如何灰度发布”。Day49 要继续补上生命周期后半段：**导购沉默会员唤醒 Skill 不能上线后永久存在，必须有冻结、废弃、替换和归档机制。**

> Skill 下线与归档不是把旧能力删掉，而是保证导购和运营团队调用到的始终是当前可信、可维护、可追溯的经营能力。

导购沉默会员唤醒 Skill 尤其需要下线机制，因为它直接影响会员触达、导购动作、权益表达和品牌信任。一旦旧版本继续被调用，风险会被“AI 建议”的形式放大：

1. **会员沉默口径变了，旧 Skill 还按旧规则推荐。**
2. **权益策略变了，旧话术仍可能给出过期承诺。**
3. **品牌/门店权限调整后，旧 Skill 可能引用不该看的数据范围。**
4. **新版导购工作流已覆盖闭环，旧单点 Skill 继续存在会拆散反馈数据。**
5. **没人维护的 Skill 仍在目录里，会降低组织对 AI 能力的信任。**

所以导购 Skill 不是“做一个入口”，而是要做一套从上线、运营、升级到退出的能力治理机制。

## 导购沉默会员唤醒 Skill｜生命周期状态 v0.1

| 状态 | 适用情况 | 管理动作 |
|---|---|---|
| 草稿 | 还在设计沉默会员口径、输入输出、话术边界 | 不开放真实业务使用 |
| 灰度 | 已在少数品牌/门店/导购试点 | 限定人群、场景、数据、动作权限 |
| 正式 | 使用率、采纳率、异常率、业务影响达标 | 进入 Skill 目录、看板和周复盘 |
| 冻结 | 口径变化、异常升高、反馈不足 | 暂停扩大，保留现有试点或只读建议 |
| 废弃 | 已有新版工作流替代，或规则过期且不再维护 | 标记废弃，提示替代入口 |
| 归档 | 已退出生产使用 | 保留版本、负责人、下线原因、影响范围 |

关键点：**目录里不要只有“可用 / 不可用”，而要让使用者知道这个 Skill 当前处于什么生命周期状态。**

## 触发下线或冻结的 5 类信号

| 信号 | 导购沉默会员唤醒 Skill 的具体表现 | 建议动作 |
|---|---|---|
| 业务规则变化 | 沉默会员定义、复购周期、生命周期分层调整 | 冻结旧版本，评估升级 |
| 数据口径变化 | CRM 字段、门店归属、导购维护关系、触达记录口径变化 | 暂停扩大，补口径说明 |
| 使用量下降 | 导购不再使用，或转向新版导购工作流 | 判断是否合并或废弃 |
| 异常率升高 | 推荐名单被质疑、权益误导、重复触达、权限拦截增加 | 立即降级或停用 |
| 替代能力出现 | 新版智能导购闭环已覆盖“名单→理由→话术→回写→复盘” | 下线旧单点 Skill，归档历史 |

判断标准不要只看“有没有人用”。有些 Skill 使用量还在，但如果口径已过期、异常率升高、无人维护，就不应该继续放在正式目录。

## 下线不是删除，而是受控迁移

导购沉默会员唤醒 Skill 下线至少要做三件事：

```text
1. 标记：说明旧 Skill 已冻结 / 废弃 / 归档，避免继续误用
2. 迁移：提示使用新版智能导购工作流或人工流程
3. 留痕：保留版本、口径、负责人、下线原因、影响范围和历史输出说明
```

不要直接删除。直接删除会让历史报告、导购反馈、复盘依据断链。正确方式是：**生产入口下线，历史资产归档。**

## 导购沉默会员唤醒 Skill｜归档记录模板

```text
Skill 名称：导购沉默会员唤醒 Skill
版本号：vX.X
生命周期状态：冻结 / 废弃 / 归档
原负责人：
适用品牌 / 门店 / 导购范围：
原使用场景：沉默会员推荐、推荐理由、建议话术、触达回写
下线原因：口径变化 / 异常升高 / 新版替代 / 无人维护 / 低使用
替代方案：新版智能导购工作流 / 指定人工流程 / 新 Skill 链接
影响范围：正在使用的团队、历史输出、相关报表或看板
处理动作：入口关闭、目录标记、历史输出加口径说明
复查时间：
```

这张模板的价值不是文档化，而是让组织知道：旧能力为什么退出，新能力接在哪里，历史结论如何解释。

## 今日可落地动作

给“导购沉默会员唤醒 Skill”补一条生命周期管理规则：

```text
每周看 4 个信号：
1. 使用率是否持续下降
2. 推荐采纳率是否低于阈值
3. 异常率是否上升
4. 是否已有新版导购工作流覆盖同一能力

满足任一高风险条件，进入冻结评审；
满足替代能力成熟条件，旧 Skill 标记废弃并归档。
```

建议把这条规则放进 Skill 运营看板，而不是只写在文档里。

## 管理提醒

1. **旧 Skill 不清理，能力目录会变成 AI 工具垃圾箱。**
2. **下线不是否定过去，而是保护当前使用质量。**
3. **越接近客户触达、权益、交易和会员数据的 Skill，越要有归档留痕。**
4. **新版工作流成熟后，旧单点 Skill 应该合并或下线，不能长期并存。**
5. **没人维护的 Skill，不能长期处于正式状态。**
