## 今日抓到的核心判断

业务 Skill 的 MVP 复盘要看四层证据：

```text
调用证据 → 动作证据 → 结果证据 → 沉淀证据
```

对“导购沉默会员唤醒 Skill”来说，最关键的不是“AI 推荐了多少会员”，而是：

```text
导购是否真的用了 → 是否真的触达 → 客户是否有反馈 → 经验是否能沉淀成规则/话术/字段。
```

如果只有调用，没有触达，这个 Skill 只是“看起来有用”。
如果有触达，但没有反馈字段，后续就无法形成复利。
如果有结果，但没有沉淀规则，它仍然是个人试用，不是组织资产。

## 导购沉默会员唤醒 Skill｜MVP 复盘口径

| 复盘项 | 要回答的问题 | 建议判断标准 |
|---|---|---|
| 调用证据 | 试点导购有没有连续使用 | 3-5 名导购连续 5 天使用；每天至少调用 1 次 |
| 采纳证据 | 推荐名单/话术是否被采用 | 推荐名单或话术采纳率 ≥50% |
| 动作证据 | 是否产生真实客户触达 | 触达反馈记录率 ≥70% |
| 结果证据 | 是否带来客户响应或转化趋势 | 客户回复率、到店线索、成交/加购/预约有正向趋势 |
| 风险证据 | 是否出现越权、误导或过度触达 | 不自动发消息、不自动发券、不跨门店查看会员、无高风险话术 |
| 沉淀证据 | 是否形成可复用经验 | 至少沉淀 3 类有效推荐理由、3 条可复用话术、1 组反馈字段 |

## 三种决策口径

### A. 值得放大
满足以下条件时，可以进入小范围灰度：
- 导购连续使用稳定；
- 触达动作真实发生；
- 客户回复或转化有趋势；
- 权限和人工确认无明显风险；
- 已沉淀有效推荐规则和话术模板。

下一步：从 1 个门店扩大到 3-5 个门店，仍保持人工确认和每日复盘。

### B. 继续小范围迭代
满足以下情况时，不急着放大：
- 导购愿意用，但推荐理由不够准；
- 话术需要大量人工修改；
- 反馈字段不完整；
- 样本量太小，结果趋势还不稳定。

下一步：继续优化输入字段、推荐逻辑、话术结构和反馈记录。

### C. 暂停 / 回到蓝图阶段
出现以下情况时，不继续投入扩大：
- 导购不用，或者只看不执行；
- AI 推荐无法推动真实触达；
- 权限、数据、客户体验风险不可控；
- 没有可证明的结果变化，也没有可复用沉淀。

下一步：重新定义场景，判断是否换成更高频、更刚需的导购任务。

## 今日可以推进的一个动作

给“导购沉默会员唤醒 Skill”补一张 MVP 复盘表，试点前就约定字段，不要等试点结束后再凭感觉复盘。

建议字段：

```text
日期
导购
会员ID/昵称
AI推荐理由
导购采纳状态：采纳 / 修改后采纳 / 未采纳
未采纳原因
是否触达
客户是否回复
客户反馈关键词
是否到店/成交/预约/加购
异常或风险备注
可沉淀规则
```

这张表的价值不是统计好看，而是让团队每天能回答：

```text
AI 推荐 → 导购动作 → 客户反馈 → 规则沉淀
```

这条链有没有跑起来。

## 对产品和技术的提醒

### 产品侧
- 不要把复盘做成功能验收表。
- 重点看导购是否产生真实动作，以及哪些推荐理由最容易被采纳。
- 产品下一版需求要从复盘数据里长出来，而不是从会议想象里长出来。

### 技术侧
- 调用日志、采纳状态、反馈结果要尽早埋点。
- 权限判断、人工确认、异常记录要进入放大前检查项。
- 如果未来要做自动化触达，必须先有审批、审计、回滚机制；当前阶段不建议直接自动发消息或发券。

### 组织侧
- 试点 Owner 不只负责“上线”，还要负责“复盘结论”。
- 每晚复盘只看三件事：用了没有、动了没有、沉淀了没有。
- 复盘后必须给出放大 / 迭代 / 暂停三选一，不要用“继续观察”糊住决策。

## 晚上复盘问题

1. 今天是否已经补齐 MVP 复盘字段，而不是只看导购主观反馈？
2. 导购对 AI 推荐名单和话术的采纳率大概是多少？未采纳的主要原因是什么？
3. 是否已经出现真实触达和客户回复？如果没有，卡点在推荐、话术、导购动作，还是客户场景不成立？
4. 今天至少沉淀了哪 1 条有效推荐规则或话术模板？
5. 当前更适合放大、继续迭代，还是暂停重定义场景？

## 一句话总结

Day33 的重点是给“导购沉默会员唤醒 Skill”补上 MVP 复盘机制：**不看演示，看真实使用；不看生成内容，看业务动作；不看单次亮点，看是否能沉淀成组织可复制的能力。**
