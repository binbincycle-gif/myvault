## 今日抓到的核心判断

Day43 解决的是“上线后怎么证明有价值”。Day44 要补的是另一个组织化问题：**当导购相关 Skill 越来越多之后，不能靠口口相传使用，必须进入目录、发布、灰度、评估、下线的运营机制。**

> 导购沉默会员唤醒 Skill 不能只是某个产品或研发手里的能力样例，而要变成一项可发现、可申请、可灰度、可评估、可维护的经营能力资产。

如果没有目录，业务不知道能用什么；如果没有发布规则，试点容易直接变生产风险；如果没有生命周期，低价值 Skill 会越积越多，形成 AI 工具债。

## 导购沉默会员唤醒 Skill｜目录卡片 v0.1

| 字段 | 内容 |
|---|---|
| Skill 名称 | 导购沉默会员唤醒 Skill |
| 适用场景 | 导购每日经营、沉默会员唤醒、门店复购提升 |
| 使用角色 | 导购、店长、总部运营 |
| 输入要求 | 品牌 / 门店 / 导购身份、会员范围、沉默周期、可用权益、触达渠道 |
| 核心输出 | 沉默会员分层、唤醒理由、建议话术、跟进优先级、结果回写字段 |
| 权限范围 | 导购只看自己会员池；店长看门店；总部运营看汇总与脱敏策略 |
| 当前状态 | Beta：小范围门店灰度 |
| 负责人 | 产品负责人 + 研发负责人 + 业务试点负责人 |
| 效果指标 | 采纳率、触达完成率、会员响应率、唤醒成交率、投诉率、误触达率 |
| 风险控制 | SaaS 实时判权；敏感会员数据不沉淀进 Skill；触达前保留人工确认 |

## 发布阶段设计

| 阶段 | 目标 | 通过标准 |
|---|---|---|
| Draft 草稿 | 验证问题是否值得做 | 能说清楚目标用户、输入输出、业务承诺、权限边界 |
| Beta 内测 | 验证能力是否跑得通 | 话术可用率、异常处理、人工修改反馈达标 |
| 灰度试点 | 验证真实导购是否采纳 | 有门店导购使用，触达完成率与会员响应有记录 |
| GA 正式 | 判断是否值得规模化 | 过程指标改善，风险指标可控，有结果回写闭环 |
| Maintain 维护 | 持续优化策略与版本 | 每周复盘过程，每月复盘结果，保留版本兼容 |
| Deprecated 下线 | 停止低价值或高风险能力 | 有替代方案、下线时间、历史记录归档 |

## 管理提醒

1. **不要把“能生成话术”当成“已发布 Skill”。** 能跑只是技术起点，可发布必须有目标用户、权限、灰度、指标和负责人。
2. **不要让导购 Skill 变成孤立功能。** 它应该进入统一的导购经营 Skill 目录，未来和会员推荐、权益推荐、执行复盘形成组合工作流。
3. **不要只新增不下线。** 连续两周没人用、没有过程改善、风险偏高的 Skill，要么改，要么停，要么降级回内部试验。
