## 今日抓到的核心判断

Day75 解决的是：Skill 进入目录后，如何发布、运营、扩围和下线。

Day76 要解决的是：**Skill 进入目录之前，必须先评审。**

一句话：**Skill 不是写出来就能上架，而是要先证明它有业务价值、输入输出清楚、权限风险可控、有人负责、可被组织复用。**

对于“导购沉默会员唤醒 Skill”，评审不是看它能不能生成话术，而是看它是否真正能安全、稳定地影响导购动作和会员经营结果。

## 导购沉默会员唤醒 Skill｜评审机制 v0.1

### 1. 四道准入门

```text
问题评审 → 设计评审 → 灰度评审 → 上架评审
```

| 阶段 | 要判断的问题 | 必须产出 |
|---|---|---|
| 问题评审 | 沉默会员唤醒是否高频、高价值、值得 Skill 化 | 业务问题卡 / ROI 假设 |
| 设计评审 | 输入、输出、权限、异常、回写是否说清楚 | Skill 设计说明 |
| 灰度评审 | 单品牌/单门店是否有人用、有效果、无明显风险 | 灰度数据 + 一线反馈 |
| 上架评审 | 是否能进入智能导购 Skill 目录并承诺维护 | 目录登记 + 负责人 + 版本号 |

管理上要坚持：**内部提效 Skill 可以快；客户可见、导购触达、经营建议类 Skill 必须稳。**

### 2. 一页评审材料

| 字段 | 导购沉默会员唤醒 Skill 评审口径 |
|---|---|
| Skill 名称 | 导购沉默会员唤醒建议 Skill |
| 目标用户 | 导购、店长、区域运营、总部运营、智能导购 Agent |
| 业务场景 | 沉默会员识别、唤醒名单生成、触达话术建议、执行复盘 |
| 输入参数 | 品牌/门店/导购范围、沉默周期、会员权限、购买记录、偏好标签、当前活动/权益 |
| 输出结果 | 唤醒名单、分组理由、跟进优先级、推荐话术、风险提示、CRM 回写建议 |
| 使用边界 | 不自动触达、不自动发券、不绕过导购确认、不承诺库存/价格/权益 |
| 权限范围 | 导购只看自己会员池；店长看本店；运营看授权区域；总部看授权品牌范围 |
| 成功指标 | 名单查看率、建议采纳率、触达完成率、客户回复率、唤醒成功率、投诉/反感率 |
| 负责人 | 产品负责人 + 技术负责人 + 运营/客户成功负责人 |
| 当前状态 | Draft / Beta / GA / Maintain / Deprecated |

### 3. 评审时必须追问的 5 个问题

1. **场景价值：** 这个 Skill 解决的是导购真实高频问题，还是只是“看起来智能”？
2. **输入输出：** 没有完整会员数据、活动数据、权限范围时，是否能降级输出？
3. **复用性：** 是否能跨品牌、跨门店复用，还是只适合一个客户临时场景？
4. **风险边界：** 是否会越权看会员、误导导购、误发权益、引发客户反感？
5. **责任归属：** 出现误推荐、低采纳、高投诉时，谁负责修正、暂停、下线？

## 今天可落地动作

今天建议补一份《导购沉默会员唤醒 Skill 一页评审卡》，作为下周智能导购 / 导购小龙虾评审材料的模板。

评审卡只做 v0.1，不追求完美，重点把 4 件事写硬：

1. **业务问题是否值得做**：沉默会员唤醒是否对应明确经营目标；
2. **输入输出是否可验收**：名单、理由、话术、回写字段是否清楚；
3. **权限审计是否可控**：谁能看、谁能触达、谁能回写、谁审批；
4. **灰度指标是否可复盘**：采纳、触达、回复、唤醒、投诉是否能看。

## 管理提醒

1. **不要让 Skill 评审变成代码评审。** 代码只是实现，真正要评的是业务价值、复用边界和治理责任。
2. **不要让能跑通等于能上架。** 客户可见能力必须先过权限、审计、灰度和回滚。
3. **不要让个人 Prompt 直接变组织资产。** 进入目录前必须统一输入输出和版本口径。
4. **不要只看正向效果。** 沉默会员唤醒必须同时看投诉/反感率，否则容易把触达做成骚扰。
5. **不要无人负责。** 没有产品、技术、运营三方责任人的 Skill，不允许进入正式目录。
