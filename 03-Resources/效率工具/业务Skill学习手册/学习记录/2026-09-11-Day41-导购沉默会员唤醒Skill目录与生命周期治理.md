## 今日阅读

阅读《业务Skill学习手册》Day15《Skill目录、发布与生命周期运营》，并承接 Day40《导购沉默会员唤醒 Skill 安全边界与灰度执行》。

## 我今天抓到的核心一句话

**灰度只是一次上线动作；目录、版本状态、责任人与下线机制，才让 Skill 成为公司可治理、可复用的能力资产。**

## 结合 EZR / OpenClaw / 智能导购的理解

导购沉默会员唤醒 Skill 不能以“某个项目里能跑”为终点。它要进入 EZR 的 AI 能力目录，明确：谁能发现和调用、当前处于什么发布状态、对哪些门店和会员池有效、由谁维护、用什么结果证明价值。

OpenClaw/Agent 负责按编排调用 Skill；CRM 仍是数据权限、动作落库、结果回写和审计事实源。目录中不只登记“能做什么”，还必须登记“能对谁做、能做到哪一步”。

## 今日形成的目录卡（v0.1）

| 字段 | 当前定义 |
|---|---|
| Skill 名称 | 导购沉默会员唤醒 Skill |
| 解决问题 | 帮导购识别本人/授权门店会员池中的沉默会员，并生成优先级、推荐依据与跟进建议 |
| 适用角色 | 试点门店指定导购、店长；总部运营做规则配置和效果监控 |
| 输入 | 导购/门店身份、授权会员范围、沉默周期、近期消费与触达记录、活动/商品可用性 |
| 输出 | 会员优先级名单、推荐原因、建议话术/商品/权益、待执行跟进清单 |
| 动作边界 | L0/L1 只读与生成建议；L2 由导购逐条确认后创建触达任务；L3 批量触达、高额权益、跨店动作默认关闭并走审批 |
| 当前状态 | Beta（仅试点门店灰度） |
| 负责人 | 产品负责人负责场景与指标；研发负责人负责权限、回写、审计与稳定性；门店店长负责试点运营和异常升级 |
| 价值指标 | 建议采纳率、有效触达率、沉默会员唤醒/转化、单次经营动作节省时长、异常率/投诉率 |
| 升级门槛 | 权限/审计/回滚闭环；连续灰度周期内稳定；业务指标有改善；店长与导购有正向反馈 |
| 下线/降级条件 | 连续两个周期低采纳或无价值提升；异常/投诉超阈值；数据口径、权限或依赖能力失效；出现更优替代 Skill |
| 下线要求 | 明确替代方案、停止新调用、保留审计记录、通知试点用户并完成历史任务收口 |

## 今日要落到项目上的动作

在智能导购 MVP 评审中新增一页《AI 能力目录卡》：把“沉默会员唤醒”登记为 Beta，不允许用“已上线”模糊表达；同时确定试点负责人、灰度门店范围、指标看板和下一次升级/降级评审日期。

## 风险边界

- 没有目录和状态，不同团队会把试点误认为通用能力，导致超范围使用。
- 没有负责人和下线机制，Skill 会变成无人维护的 AI 工具债。
- 不能因为“可调用”就升为正式能力；必须以真实用户采纳、业务收益和风险指标共同判断。
