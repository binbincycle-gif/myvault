## 今日抓到的核心判断

Day66 做的是二次蓝图校准：把导购沉默会员唤醒从“名单生成”拉回到“会员经营动作闭环”。

Day67 要继续往前压缩：**蓝图不能直接进入大开发，必须切成一个 1-2 周能验证的 MVP 试点。**

这个 MVP 的目标不是证明智能导购的全部想象力，而是证明一条最短链路成立：

```text
AI 推荐会员 → 导购理解理由 → 导购确认触达 → 触达结果回写 → 晚上能复盘
```

一句话：**MVP 不是功能删减版，而是最小可验证业务闭环。**

MVP 阶段不要试图把智能导购一次做完整，先验证“AI 推荐是否能推动导购完成一次有记录的会员触达”。

## 导购沉默会员唤醒 Skill｜MVP 试点定义 v0.1

```text
Skill MVP 名称：导购沉默会员唤醒建议 Skill
服务角色：一线导购
挂靠业务场景：每日会员跟进 / 活动前老客唤醒
本周只验证的一件事：AI 能否帮导购找到更值得今天唤醒的沉默会员，并推动一次有记录的触达
必要输入：会员基础资料、最近消费、沉默天数、最近互动、导购归属、当前活动/权益
核心输出：3-5 个优先唤醒会员、推荐理由、风险提醒、话术建议
人工确认点：导购确认是否采纳、是否改写话术、是否触达
反馈字段：采纳/跳过/延后、已触达/已回复/无响应/反感/已成交、未采纳原因
成功标准：试点导购连续 5 天使用；触达反馈记录率 ≥70%；至少沉淀 10 条有效推荐理由样本
风险边界：不自动发消息、不自动发券、不越权查看会员、不重复打扰、不绕过品牌话术规则
试点范围：1 个品牌 / 1 个门店或小范围导购 / 3-5 名导购 / 1 周
复盘时间：每天晚上看使用与反馈；周末看回复、复购和负反馈趋势
```

## MVP 必须砍掉的范围

### 1. 先砍角色

只服务一线导购，不同时覆盖店长、运营、总部。

店长和运营可以看结果，但不要在 MVP 阶段让多个角色共同定义流程，否则试点很容易变成管理看板项目。

### 2. 先砍动作

只验证“沉默会员唤醒触达”一个动作，不扩展到完整会员运营、商品推荐、活动邀约、券包发放。

### 3. 先砍自动化

不自动发消息、不自动发券、不自动创建复杂任务流。

MVP 阶段坚持：**AI 给建议，人确认，系统留痕。**

## 今天可落地动作

如果今天推进智能导购 / 导购小龙虾，建议只补一页《导购沉默会员唤醒 Skill MVP 试点卡》：

| 项目 | 内容 |
|---|---|
| 试点角色 | 导购 |
| 试点动作 | 每天唤醒 3-5 个沉默会员 |
| AI 负责 | 推荐会员、说明理由、给话术和风险提醒 |
| 人负责 | 判断是否采纳、是否触达、是否改写话术 |

| 不做事项 | 不自动发消息、不自动发券、不做复杂归因、不覆盖所有会员运营场景 |
| 每日复盘 | 使用人数、推荐人数、采纳率、触达率、反馈记录率、负反馈 |

```text

```

```text

客户是否反感
未采纳原因
备注
```

## 管理提醒

1. **MVP 不要追求完整智能导购。** 先跑通一条最短业务行动链。
2. **不要只验收生成质量。** 要验收导购是否真的用、是否真的触达、是否真的回写。
3. **反馈字段不能后补。** 没有回流，MVP 就只能做 Demo，不能形成组织能力。
4. **风险边界要写进试点卡。** 尤其是会员权限、重复触达、权益过期、客户反感。
5. **试点范围要小。** 一个品牌、一个门店、3-5 名导购、连续 5 天，比大范围浅用更有价值。
