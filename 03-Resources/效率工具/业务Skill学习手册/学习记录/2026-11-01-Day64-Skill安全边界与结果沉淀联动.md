# Day64｜业务 Skill 安全边界与结果沉淀联动

> 对应章节：[[Day32-业务Skill安全边界与结果沉淀联动]]
> 关联：[[Day28-Skill记忆与沉淀：让执行结果反哺能力]]、[[Day29-Skill安全边界：权限、审批、回滚与人工确认]]

## 今日结论

业务 Skill 不能只“产生建议”，也不能只“有权限控制”。真正可规模化的能力，是在安全边界内执行，把**调用—确认—动作—结果**完整记录并回写，再将经过验证的经验沉淀为可复用资产。

> 没有权限治理的结果沉淀，会把错误与越权经验固化；没有结果回写的安全机制，只能形成一次性建议。

## 最小可追溯链路

```text
调用者身份
→ 数据权限校验
→ Skill 建议
→ 风险分级
→ 人工确认 / 审批
→ 执行动作
→ CRM 结果回写
→ 有效经验沉淀 / 异常纠偏
```

每次调用至少能回答：谁调用、读取了什么范围、给出什么建议、谁确认、执行了什么、结果如何、哪些内容允许进入长期知识。

## EZR 导购会员跟进 Skill：建议分级

| 等级 | 示例 | 控制要求 |
|---|---|---|
| L0 | 查询本人沉默会员池 | 按导购/门店数据范围只读 |
| L1 | 输出会员优先级、理由与话术建议 | 不直接触达，不写入业务结果 |
| L2 | 创建跟进任务、发送单条消息 | 导购人工确认，留执行记录 |
| L3 | 批量触达、发高面额权益、跨门店触达 | 审批后执行，默认禁止自动化 |

## 结果回写与沉淀

### CRM 至少回写
- 是否采纳建议；
- 是否实际触达、渠道和话术版本；
- 回复、到店、下单等结果；
- 未采纳/失败/异常原因；
- 是否允许脱敏进入经验库。

### 知识分层
- **运行日志**：调用、权限判断、原始输入输出、错误；
- **项目记忆**：已确认的客户规则、项目异常与门店经验；
- **组织知识**：人工验证后可跨项目复用的口径、模板、风险清单与有效模式。

模型猜测、未确认建议和敏感会员明细不得直接进入组织知识。

## 今日可落地动作

为首个“导购会员跟进”MVP 补齐一张安全与沉淀联动表：

1. 调用身份：导购、店长、总部运营分别可读哪些会员与数据；
2. 行动分级：先只上线 L1 建议，L2 写回/触达必须人工确认；
3. 回写字段：建议采纳、触达时间、渠道、客户反馈、成交/未成交原因；
4. 审计与纠偏：记录调用和确认人；错误建议可撤回任务、修正标签、清除不可信经验；
5. 验收指标：采纳率、触达完成率、转化率、异常率、有效经验复用率。

## 一句话收获

**可进化的 Skill：在最小权限下执行，在人工确认中承担责任，在结果回写里学习，只沉淀被验证的组织经验。**
