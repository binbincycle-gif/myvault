## 今日抓到的核心判断

业务 Skill 上线不是“文件发布”或“Prompt 能跑”，而是发布一套可被 Agent、业务角色和运维机制共同遵守的调用契约。

最关键的不是回答质量，而是：

```text
角色知道什么时候用 → Agent 知道怎么调用 → 结果能落到业务动作 → 异常能被处理 → 经验能继续沉淀
```

## 对 EZR 当前主线的映射

### 1. 智能导购 / 导购小龙虾
当前最适合拿来做 Day30 检查清单的样板。

上线前必须回答：
- 谁用：导购、店长、总部运营分别看到什么？
- 何时触发：沉默会员唤醒、生日关怀、复购提醒、搭配推荐？
- 输入依赖：会员归属、消费记录、互动记录、偏好标签、可用权益。
- 输出结构：客户优先级、推荐理由、建议话术、推荐权益、下一步动作。
- 人工确认：发券、批量触达、自动发送话术必须人工确认。
- 回写机制：是否触达、是否回复、是否转化、失败原因要回 CRM。

### 2. 会员画像 / 会员经营诊断 Skill
不能只停在“画像描述”。要检查输出是否能转成经营动作：
- 该会员/人群现在应该被运营吗？
- 推荐什么动作？
- 动作优先级是什么？
- 结果如何反馈给 Skill 下一次判断？

### 3. AI Coding / 研发 Skill
研发类 Skill 也要按上线检查清单管理：
- 触发场景：需求分析、技术方案、测试用例、Bug 根因定位。
- 输出契约：必须包含影响范围、风险点、验证建议。
- Owner：不能无主漂移。
- 验收：是否减少返工、降低遗漏、沉淀可复用方案。

## 今日可执行动作

拿“导购沉默会员唤醒 Skill”补一张上线前检查表，作为智能导购 MVP 的交付口径：

| 检查项 | 今日建议口径 |
|---|---|
| Skill 名称 | 导购沉默会员唤醒 Skill |
| 目标角色 | 导购日常使用，店长查看跟进质量，总部运营看策略汇总 |
| 触发场景 | 会员超过 N 天未互动/未消费，且属于当前导购或门店 |
| 必要输入 | 会员归属、最近消费、互动记录、偏好标签、可用权益、门店/导购权限 |
| 输出结构 | 优先级、推荐理由、建议话术、推荐权益、下一步动作、风险提示 |
| 可执行动作 | 复制话术、发起企微沟通、申请权益、记录跟进结果 |
| 权限边界 | 只读取授权会员；不可跨门店查看明细；不可自动发券 |
| 人工确认点 | 发送消息、发券、批量触达必须确认 |
| 异常降级 | 数据不足时只给“建议补充信息/保守跟进”，不强推商品 |
| 回写机制 | 触达状态、客户反馈、转化结果、失败原因回 CRM |
| Owner | 产品 Owner + 数据/Skill Owner + 业务试点负责人 |
| 验收指标 | 导购 3 分钟内完成一次有效跟进；触达率、回复率、转化率可追踪 |

## 晚上复盘问题

1. 今天有没有选出一个真实 Skill，按上线检查表补齐契约？
2. 这个 Skill 是否已经从“能生成建议”推进到“能执行并回写”？
3. 哪个风险边界还不清楚：权限、人工确认、异常降级，还是 Owner？

## 一句话总结

Day30 的关键不是多做 Skill，而是让第一批 Skill 具备可交付标准：**输入稳定、输出可行动、权限可控、异常可处理、结果可复盘。**
