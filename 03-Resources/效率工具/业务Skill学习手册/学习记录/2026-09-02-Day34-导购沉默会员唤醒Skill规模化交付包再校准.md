## 我今天抓到的核心一句话
Skill 放大不是“让更多人试试”，而是先把跑通的经验整理成交付包，再按同团队、跨团队、客户化三层节奏复制。

## 结合当前业务的理解
放到 EZR / OpenClaw / 智能导购主线上，“导购沉默会员唤醒 Skill”如果要从 MVP 走向可复制，就不能只保留 prompt、话术和演示效果，而要沉淀成一套能交付、能培训、能审计、能复盘的业务能力包。

今天最关键的判断是：
1. 同一个门店内换导购后，是否还能按同样输入输出跑通；
2. 换到同品牌不同门店后，会员沉默口径、权益口径、触达动作是否仍然成立；
3. 换到不同品牌后，哪些字段必须配置化，哪些能力可以标准化；
4. 风险边界是否足够清楚，避免把错误动作规模化复制。

## 对导购沉默会员唤醒Skill的规模化交付包再校准

### 1. 触发说明
- 每日开店前，导购查看今日优先唤醒会员。
- 活动前一天，店长/运营筛选沉默会员唤醒名单。
- 会员沉默预警后，系统建议导购跟进。

### 2. 输入要求
- 品牌、门店、导购身份与权限范围。
- 会员沉默定义口径，例如 30/60/90 天未消费。
- 会员最近消费、触达历史、偏好标签、可用权益。
- 当前活动目标：唤醒、复购、清库存、节日节点。

### 3. 输出标准
- 今日优先跟进会员名单。
- 每个会员的推荐原因。
- 建议话术与下一步动作。
- 风险提示：不适合触达、权益敏感、跨门店不可见等。
- 建议回写字段：是否采纳、是否触达、客户反馈、是否成交、未成交原因。

### 4. 人工确认点
- 是否触达必须由导购确认。
- 是否发券、发权益、升级重点客户必须由店长/运营确认。
- 不允许自动群发、不允许自动发券、不允许跨门店查看会员明细。

### 5. 反馈闭环
- 使用反馈：采纳 / 未采纳 / 修改后采纳。
- 触达反馈：已触达 / 未触达 / 客户无响应 / 客户拒绝。
- 业务结果：到店、复购、成交金额、权益核销。
- 异常原因：数据不准、会员不适合、话术不匹配、权限不足。

### 6. 推广节奏
- 第一步：同门店多导购复制，验证新导购是否也能用。
- 第二步：同品牌不同门店复制，验证门店差异是否影响效果。
- 第三步：不同品牌小范围试点，验证配置化与行业差异。
- 第四步：沉淀标准 Skill 模板，进入智能导购产品化能力池。

### 7. 风险边界
- 禁止动作：自动发券、自动群发、跨权限查看会员、对客户做敏感承诺。
- 敏感数据：会员手机号、交易明细、权益信息、跨门店客户资产。
- 回滚方案：异常名单下架、暂停自动推荐、保留人工导出链路。
- 审计要求：记录调用人、调用时间、输入范围、输出结果、采纳动作、回写结果。

## 今天这篇内容对当前业务Skill编写的提醒
Skill 规模化前必须先回答：这个能力到底是“某个强人盯出来的试点效果”，还是“换人、换店、换客户后仍然能运行的组织资产”。

后续业务 Skill 不要只写功能说明，要同步补齐：
1. 交付包；
2. 培训动作；
3. 权限边界；
4. 反馈字段；
5. 灰度节奏；
6. 复盘指标。
