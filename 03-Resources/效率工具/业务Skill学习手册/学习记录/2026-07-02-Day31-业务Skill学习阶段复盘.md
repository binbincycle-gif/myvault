## 今日抓到的核心判断

30 天学习后，业务 Skill 的核心标准可以收敛成一句话：

```text
不是让 AI 会回答，而是让 Agent 能在正确场景调用正确能力，并把结果推进到业务动作和反馈闭环。
```

所以接下来不应继续只“学概念”，而要进入三个落地动作：

1. 选 1 个真实业务场景。
2. 写 1 张 Skill 契约表。
3. 跑 1 次最小闭环验证。

## 对 EZR 当前主线的映射

### 1. 智能导购 / 导购小龙虾
最适合做第一批业务 Skill 样板。

建议聚焦“导购沉默会员唤醒 Skill”，不要一开始做大而全的智能导购。

最小闭环：

```text
识别沉默会员 → 给出推荐理由和话术 → 导购确认执行 → 回写触达/回复/转化/失败原因
```

这条链路能验证四件事：
- AI 是否理解会员上下文；
- 输出是否能让导购直接行动；
- 权限和人工确认是否可控；
- 结果是否能回写形成复利。

### 2. EZR SaaS / Skills
SaaS Skill 化不能从页面清单开始，要从“高频经营动作”开始。

优先 Skill 候选：
- 导购沉默会员唤醒；
- 会员经营诊断；
- 活动复盘建议；
- AI 取数与指标解释。

判断标准：

```text
是否高频、是否高价值、是否可标准化、是否有数据闭环、是否能被 Agent 编排。
```

### 3. AI Coding / 研发 Skill
研发 Skill 也要用业务 Skill 的上线标准管理。

不能只看“能生成代码”，要看：
- 需求理解是否完整；
- 改动点是否可追踪；
- 测试建议是否覆盖风险；
- 是否沉淀成 CodeWiki / Skill / MCP 可复用能力；
- 是否有 Owner 和版本记录。

## 今日可执行动作

今天建议只做一件事：

**把“导购沉默会员唤醒 Skill”整理成第一版 Skill 契约表，作为智能导购 MVP 的交付检查口径。**

| 检查项 | 今日建议口径 |
|---|---|
| Skill 名称 | 导购沉默会员唤醒 Skill |
| 目标角色 | 导购日常使用；店长查看跟进质量；总部运营看策略汇总 |
| 触发场景 | 会员超过 N 天未互动/未消费，且属于当前导购或门店 |
| 必要输入 | 会员归属、最近消费、互动记录、偏好标签、可用权益、门店/导购权限 |
| 输出结构 | 优先级、推荐理由、建议话术、推荐权益、下一步动作、风险提示 |
| 可执行动作 | 复制话术、发起企微沟通、申请权益、记录跟进结果 |
| 权限边界 | 只读取授权会员；不可跨门店查看明细；不可自动发券 |
| 人工确认点 | 发送消息、发券、批量触达必须确认 |
| 异常降级 | 数据不足时只给保守建议，不强推商品/权益 |
| 回写机制 | 触达状态、客户反馈、转化结果、失败原因回 CRM |
| Owner | 产品 Owner + 数据/Skill Owner + 业务试点负责人 |
| 验收指标 | 导购 3 分钟内完成一次有效跟进；触达率、回复率、转化率可追踪 |

## 晚上复盘问题

3. 是否能选一个品牌/门店/导购场景，在本周跑一次 10 人会员池的最小验证？

## 一句话总结

Day31 的重点是从学习转入落地：**业务 Skill 的第一阶段成果，不是多写几个 Skill，而是拿一个真实场景跑通“可调用、可执行、可回写、可复盘”的闭环。**
