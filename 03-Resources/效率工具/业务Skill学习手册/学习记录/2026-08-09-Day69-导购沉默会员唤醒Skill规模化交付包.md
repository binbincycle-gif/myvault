## 导购沉默会员唤醒 Skill｜规模化交付包 v0.1

```text
Skill 名称：导购沉默会员唤醒建议 Skill
适用角色：导购 / 店长 / 区域运营
适用场景：沉默会员唤醒、活动前会员预热、老客复购提醒
试点结论：仅在满足 Day68 复盘标准后进入放大

1. 触发条件
- 每日开店前，导购查看今日建议唤醒会员
- 活动前 1-2 天，系统生成重点可唤醒会员名单
- 会员沉默达到指定周期后，进入候选池
- 默认人工触发或半自动生成，不直接自动触达客户

2. 输入上下文
- 必要数据：会员基础信息、消费记录、最近触达记录、沉默天数、所属导购/门店
- 可选数据：商品偏好、活动信息、权益信息、历史话术反馈
- 数据口径：沉默会员定义、消费周期、触达周期必须统一
- 权限范围：导购只能看自己/本门店授权会员，不跨门店、跨品牌查看

3. 输出标准
- 今日建议唤醒会员名单
- 每个会员的推荐理由
- 建议触达话术
- 触达风险提示
- 下一步动作建议：触达 / 暂缓 / 升级店长 / 需要补充信息

4. 人工确认点
- 是否触达，必须由导购确认
- 是否发券/承诺权益，必须按现有权限审批
- 高价值或敏感客户，必要时升级店长确认
- 客户明确反感或投诉时，必须暂停再次触达

5. 反馈闭环
- 使用反馈：是否查看、是否采纳、未采纳原因
- 业务反馈：是否触达、客户是否回复、是否到店/加购/成交
- 异常反馈：重复打扰、权益错误、话术不合适、客户反感
- 沉淀依据：有效推荐理由、有效话术、未采纳原因、风险案例

6. 推广计划
- 第一阶段：同门店多导购复制，验证换人是否还能用
- 第二阶段：同品牌不同门店复制，验证门店差异
- 第三阶段：不同品牌小范围复制，验证配置化需求
- 第四阶段：沉淀为标准 Skill 模板，进入产品化/交付包

7. 风险边界
- 禁止自动发送客户消息
- 禁止自动发券或承诺权益
- 禁止越权查看会员数据
- 禁止跨门店/跨品牌复用敏感会员上下文
- 必须保留触达记录、结果回写、异常追踪和人工回滚机制
```

## 推广节奏建议

| 阶段 | 范围 | 验证重点 | 是否可扩围 |
|---|---|---|---|
| 小范围复制 | 同门店 3-5 名导购 | 换人后是否还能采纳和触达 | 连续 1 周稳定后再扩 |
| 跨门店复制 | 同品牌 2-3 家门店 | 门店客群和导购习惯差异 | 口径稳定后再扩 |
| 跨品牌复制 | 1-2 个不同品牌 | 行业/客户差异与配置项 | 明确配置化后再扩 |
| 产品化收口 | 标准模板 + 配置项 | 是否能交付、培训、审计 | 进入产品路线图 |

## 今天可落地动作

今天如果继续推进智能导购 / 导购小龙虾，不建议只讨论“下一批扩到多少人”。建议先补一页《导购沉默会员唤醒 Skill 交付包 v0.1》，重点补齐：

1. **触发条件**：什么时候出现建议，谁来触发。
2. **输入上下文**：哪些 CRM 数据必须有，哪些是可选增强。
3. **输出标准**：名单、理由、话术、风险、下一步动作是否固定。
4. **人工确认点**：哪些动作必须导购/店长确认。
5. **反馈字段**：采纳、触达、回复、成交、反感、未采纳原因。
6. **风险边界**：不自动触达、不自动发券、不越权查看。

管理上只问一句：**如果明天换一个门店试点，这套 Skill 能不能不靠产品/技术盯场也跑起来？**

## 管理提醒

1. **不要从 MVP 直接跳到大范围推广。** 没有交付包，扩围就是放大不确定性。
2. **不要只复制功能入口。** 真正要复制的是“AI 建议—导购确认—客户反馈—CRM 回写—经验沉淀”的动作链。
3. **不要忽略权限与审计。** 导购场景涉及会员数据和触达动作，越放大越要保守。
4. **不要把客户化差异都做成定制。** 先识别哪些是配置项，哪些是标准能力。
5. **不要让 Skill 只靠强人运行。** 换导购、换门店、换客户还能跑，才叫组织资产。

## 晚上复盘问题

1. 今天是否补出《导购沉默会员唤醒 Skill 交付包 v0.1》？
2. 交付包是否覆盖触发、输入、输出、人工确认、反馈闭环、风险边界？
3. 如果换一个门店或导购，哪些字段/口径最可能失效？
4. 哪些客户差异应该做成配置项，而不是定制开发？
5. 当前 Skill 更适合继续小范围复制、跨门店复制，还是先回到 MVP 迭代？

## 今日一句话

> 导购沉默会员唤醒 Skill 的规模化，不是把 AI 推荐名单推给更多人，而是把一条被验证过的会员经营动作链，包装成可交付、可审计、可复盘、可复制的组织资产。
