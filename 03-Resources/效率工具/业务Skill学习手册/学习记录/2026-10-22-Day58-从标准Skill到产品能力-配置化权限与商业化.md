# Day58｜从标准 Skill 到产品能力：配置化、权限与商业化

## 今日主题

Day57 解决的是：跑通的 Skill 如何通过交付包分层复制。

今天继续回答：**什么情况下，一个可复制的 Skill 才值得进入产品路线图？**

核心判断：**产品化不是把内部工具放进菜单，而是让稳定的业务能力可配置、可授权、可审计、可运营、可证明价值。**

## 三个阶段，不能跳级

```text
内部 Skill → 交付型 Skill 模板 → 产品化 AI 能力
```

| 阶段 | 判断标准 |
|---|---|
| 内部 Skill | 团队自己能跑通，验证能力与流程 |
| 交付型 Skill 模板 | 可以为指定客户交付，但仍依赖实施配置 |
| 产品化 AI 能力 | 客户可配置、可授权、可持续运营，并能进入定价/续费价值 |

如果每次落地都需要研发重新改逻辑，它仍是交付工具；只有客户能通过配置适配自身口径，才开始接近产品能力。

## 产品化前必须补齐的 5 件事

1. **配置化**：品牌差异、活动策略、会员规则不能写死在代码里。
2. **权限化**：角色、组织、数据范围、敏感动作必须分层控制。
3. **可观测**：调用次数、采纳率、成功率、异常率必须可看。
4. **可回滚**：错误建议、触达和配置必须能停、能查、能恢复。
5. **可定价**：要能说明为客户节省什么、提升什么，支撑续费或增购。

## 用导购会员跟进建议 Skill 做产品化检查

| 必补能力 | 产品化要求 |
|---|---|
| 品牌策略配置 | 会员分层、活动目标、权益策略可后台配置 |
| 门店/导购权限 | 导购仅看本人范围；店长看门店；区域看区域 |
| 话术模板管理 | 品牌语气、活动政策、禁用词可管理 |
| 触达审批边界 | 发券、承诺折扣、敏感关怀不能自动执行 |
| 结果回写 | 采纳、触达、成交、反馈回流 CRM |
| 效果看板 | 采纳率、成交率、复购率、沉睡唤醒率可追踪 |

## 今日可执行动作

1. 对当前任一 AI 场景先标注阶段：内部 Skill / 交付模板 / 产品能力；不要用“Demo 成功”替代阶段判断。
2. 按五件套做缺口表：配置、权限、观测、回滚、定价。未补齐前，不进入产品路线图承诺。
3. 产品评审补一条商业化验证：客户愿意为哪个可感知经营结果付费？若答不清，先继续试点和沉淀。

## 晚间自检

1. 客户差异能否通过配置解决，而非研发改代码？
2. 角色、数据、敏感动作的权限边界是否清楚？
3. 结果能否结构化回写并形成运营指标？
4. 出错后能否停止、审计、回滚？
5. 客户能否感知明确经营价值，支撑续费或增购？

## 一句话结论

**Skill 产品化不是“做出来”，而是换客户、换角色、换场景后，仍能安全地产生可证明、可运营、可收费的经营结果。**
