## 今日抓到的核心判断

Day25 解决的是：一个 Skill 能不能从交付包走向产品能力，关键看配置化、权限化、可观测、可回滚、可定价。

Day26 往 Agent 调用视角推进：**Skill 不是给人看的功能说明，而是给 Agent 做决策时使用的能力说明书。**

对导购沉默会员唤醒 Skill v0.4 来说，下一步不能只补业务流程，还要补清楚 Agent 什么时候该调用、缺什么信息不能调用、哪些动作必须人工确认、输出结果要如何进入 CRM 回写和复盘。

> Agent 调用说明写不清，Skill 就会从“组织能力”退化成“偶尔能用的提示词”。

## v0.4 Agent 调用定义

```text
Skill 名称：导购沉默会员唤醒 Skill v0.4
调用对象：OpenClaw / 导购小龙虾 / 智能导购 Agent / 运营辅助 Agent
目标：基于 CRM 会员数据、门店权限、活动权益和历史触达记录，为导购生成沉默会员唤醒名单、跟进理由、建议话术、推荐动作和复盘字段。
调用原则：不越权、不自动外发、不自动发券、不绕过 CRM 判权与审计。
```

## 1. 触发条件

### 应该调用

当用户提出以下需求时，Agent 可以调用该 Skill：

- “帮导购找一批该跟进的沉默会员”
- “给门店生成老客唤醒名单”
- “最近复购下降，帮我找可唤醒会员”
- “为导购生成今天要联系的客户和话术”
- “结合活动权益给导购一批跟进建议”
- “分析沉默会员为什么没复购，并给下一步动作”

### 不应该调用

以下情况不应直接调用，或只能给方法建议：

- 用户没有品牌、门店、导购或会员范围；
- 用户要求跨品牌、跨门店查看无授权会员明细；
- 用户要求自动群发、自动发券、自动触达客户；
- 用户要求导出会员手机号、微信、地址等敏感信息；
- 用户只问通用营销方法，不涉及 CRM 会员数据和导购执行。

## 2. 输入要求

| 输入项 | 是否必填 | 说明 |
|---|---|---|
| 品牌范围 | 必填 | 决定数据边界和策略配置 |
| 门店 / 区域范围 | 必填 | 决定导购和店长可见范围 |
| 导购身份 / 岗位权限 | 必填 | 决定会员可见范围和动作权限 |
| 沉默会员口径 | 必填 | 如 30/45/60/90 天未消费或未互动 |
| 活动 / 权益信息 | 可选但建议有 | 没有则不能承诺优惠，只能给通用话术 |
| 历史触达记录 | 必填或系统自动取 | 防止重复打扰 |
| 推荐人数 | 可选 | 默认按导购工作量给 3-5 人 |
| 输出用途 | 必填 | 给导购执行 / 店长查看 / 运营复盘，输出颗粒度不同 |

### 缺失信息处理

```text
缺品牌/门店/导购权限：必须追问，不能硬跑。
缺活动权益：可以输出无权益承诺版话术。
缺历史触达：必须提示重复打扰风险，建议先补数据。
缺沉默口径：可给默认口径草案，但必须标注待确认。
```

## 3. 权限与边界

### 读取边界

- 导购：只能读取本人或授权范围内会员建议，不看跨导购、跨门店无关明细。
- 店长：可看门店聚合效果和本店导购执行情况，不默认看跨门店会员明细。
- 区域运营：优先看区域聚合，不默认展开无关会员个人信息。
- 品牌管理员：可配置策略、查看审计和汇总结果。
- Agent：所有数据读取必须按 SaaS 实时判权，不在 Skill 内沉淀会员明细。

### 动作边界

以下动作必须人工确认：

1. 对外发送消息。
2. 自动发券或承诺权益。
3. 批量导出会员名单。
4. 修改会员标签、等级、归属或营销状态。
5. 对门店 / 导购策略进行全量启用或停用。

## 4. 执行步骤

```text
第一步：识别意图
- 判断是否属于沉默会员唤醒 / 老客复购 / 导购跟进建议场景。

第二步：检查输入
- 核对品牌、门店、导购权限、沉默口径、活动权益、历史触达。

第三步：拉取 CRM 上下文
- 按授权范围读取会员生命周期、消费记录、互动记录、导购关系、权益适用范围。

第四步：生成建议名单
- 输出会员分组、唤醒理由、推荐动作、话术草案、风险提示。

第五步：等待人工采纳
- 导购选择采纳 / 跳过 / 延后 / 不适合，并记录原因。

第六步：CRM 回写
- 回写建议生成、导购采纳、实际触达、客户反馈、成交结果、跳过原因。

第七步：复盘沉淀
- 汇总采纳率、触达率、回复率、唤醒率、复购率、异常原因，进入 Skill 运营看板。
```

## 5. 输出格式

### 给导购

```text
今日建议跟进会员：3-5 人
每位会员输出：
- 推荐理由
- 最近一次消费 / 互动摘要
- 当前适合推荐的商品或权益方向
- 建议话术
- 注意事项
- 是否建议今天联系
```

### 给店长

```text
门店今日建议概览：
- 涉及导购数
- 建议会员数
- 高价值会员数
- 重复打扰风险数
- 需店长审批动作
- 昨日跟进结果
```

### 给运营 / 管理者

```text
Skill 运行复盘：
- 调用次数
- 建议名单查看率
- 导购采纳率
- 实际触达率
- 客户回复率
- 沉默唤醒率
- 复购成交金额
- 跳过原因 TOP3
- 异常 / 投诉 / 权益错误
```

## 6. Agent 调用 description 草案

```yaml
description: >
  当用户需要为导购、门店或品牌运营生成沉默会员唤醒名单、老客复购跟进建议、会员触达话术、导购每日客户跟进任务时使用。
  适用于智能导购、导购小龙虾、CRM 经营闭环、会员唤醒、复购提升场景。
  调用前必须具备品牌/门店/导购权限范围、沉默会员口径、历史触达记录；如涉及活动权益，还需明确权益适用规则。
  不适用于无授权跨品牌/跨门店查询、会员敏感信息导出、自动群发、自动发券或未经确认的外部触达。
  输出包括建议会员分组、推荐理由、导购话术、下一步动作、CRM 回写字段和复盘指标。
```

## 今天可落地动作

今天如果继续推进智能导购 / 导购小龙虾，建议补一页《导购沉默会员唤醒 Skill v0.4 Agent 调用说明》，重点只做 4 件事：

1. 写清楚触发条件：哪些用户问题会调用该 Skill。
2. 写清楚必填输入：品牌、门店、导购权限、沉默口径、历史触达。
3. 写清楚禁止动作：不自动外发、不自动发券、不导出敏感信息、不绕过 SaaS 判权。
4. 写清楚输出结果：导购动作、店长看板、运营复盘、CRM 回写字段。

## 管理提醒

1. Skill 文档不是说明书，是 Agent 的决策依据。
2. description 要写业务场景、触发词、边界和产出，不要只写“提升效率”。
3. 会员数据类 Skill 必须把权限、审批、审计写在调用规则里。
4. Agent 不能只生成建议，要推动采纳、触达、回写、复盘闭环。
5. 调用说明越清楚，后续越容易从单个 Skill 扩展成 EZR SaaS 的能力目录。

## 晚上复盘问题

1. 今天是否完成 v0.4 Agent 调用说明页？
2. description 是否足够让 OpenClaw / Agent 自动判断“该不该用”？
3. 缺少品牌、门店、导购权限、沉默口径时，Agent 是否会追问而不是硬跑？
4. 自动外发、自动发券、会员导出等高风险动作是否已明确必须人工确认？
5. 输出是否已经覆盖导购执行、店长查看、运营复盘和 CRM 回写？

## 今日一句话

> 导购沉默会员唤醒 Skill 要被 Agent 稳定调用，关键不是写更多业务说明，而是把触发条件、输入要求、权限边界、执行步骤和输出格式写到 Agent 不会误用。
