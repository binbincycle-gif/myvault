# Day63｜Skill 上线前检查清单：从可用到可交付

> 对应学习章节：[[Day30-Skill上线前检查清单：从可用到可交付]]
> 衔接上篇：[[2026-10-28-Day62-Skill安全边界-权限审批回滚与人工确认]]

## 今日主题

Demo 能跑，只证明“能不能做”；上线检查才证明“能不能交给真实团队长期使用”。

核心判断：**Skill 上线不是发布一份文件，而是发布一套可调用、可行动、可维护、可回滚的业务契约。**

## 上线前的五个契约

| 契约 | 必须明确的内容 |
|---|---|
| 触发契约 | 什么场景该调用，什么场景不该调用 |
| 输入契约 | 参数、上下文、数据口径与权限要求 |
| 输出契约 | 输出结构、必填字段与可行动结果 |
| 执行契约 | 只建议还是触发业务动作；人工确认点 |
| 运维契约 | Owner、版本、审计、异常处理与回滚 |

## 三类必测路径

1. **正常路径**：标准输入能否产出预期结果。
2. **边界路径**：数据缺失、权限不足、客户场景不匹配时能否正确拒绝或降级。
3. **业务验收路径**：一线角色拿到结果后，能否直接完成下一步动作。

## 导购沉默会员唤醒 Skill 的上线标准

```text
触发：导购每日查看待跟进沉默会员
输入：会员归属、最近消费、互动记录、偏好、可用权益
输出：客户优先级、推荐理由、建议话术、推荐权益、下一步动作
边界：只能读取当前导购/门店授权会员
确认：发送、发券、批量触达必须人工确认
降级：数据不足时提示“缺少依据”，不强行推荐
回写：触达、回复、转化、失败原因
验收：导购能否在 3 分钟内完成一次有效跟进
```

如果只会生成话术，仍是工具；跑通“识别对象 → 给出动作 → 确认执行 → 结果回写”才是可交付业务能力。

## 今日可执行动作

1. 首批只选 1–3 个样板 Skill，不追数量：导购客户跟进、会员经营诊断、活动复盘建议优先。
2. 对每个试点补齐上线卡：角色、触发、输入、输出、动作、权限、确认、降级、回写、Owner、验收指标。
3. 建立最小运营机制：**Owner + 使用说明 + 常见问题 + 版本记录 + 异常反馈入口 + 周期复盘指标**。

## 晚间自检

1. 这是“Demo 能跑”还是“真实业务能用”？
2. Agent 何时应调用、何时应拒绝？
3. 一线拿到输出后是否知道下一步动作？
4. 出错时是否知道找谁、看什么记录、怎么回滚？
5. 能否复制到第二个客户或团队？

## 一句话结论

**Skill 从功能可演示走向能力可交付，必须做到：触发清楚、输入稳定、输出可行动、权限可控、异常可处理、结果可复盘。**
