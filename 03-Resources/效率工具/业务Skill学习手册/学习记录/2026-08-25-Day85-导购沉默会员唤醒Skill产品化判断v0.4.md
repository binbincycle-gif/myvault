## 今日抓到的核心判断

Day24 解决的是：MVP 试点通过后，先把有效动作整理成可复制、可培训、可审计、可复盘的交付包。

Day25 往前推进一步：**交付包能复制，不等于产品能力已经成立。** 产品化必须补齐 5 件事：配置化、权限化、可观测、可回滚、可定价。

对导购沉默会员唤醒 Skill v0.4 来说，产品化的核心不是“AI 推荐几个人”，而是让这套能力能在不同品牌、不同门店、不同导购之间稳定运行，并且权限可控、过程可查、结果可证、价值可讲。

> 产品化判断标准：如果第二个品牌上线时还需要研发重新改逻辑，它仍是交付型 Skill；如果通过配置、授权、运营模板就能跑起来，才开始接近产品能力。

## v0.4 产品化判断

```text
Skill 名称：导购沉默会员唤醒 Skill v0.4
当前阶段：规模化交付包 → 产品化 AI 能力候选
产品化前提：完成跨导购 / 跨门店小范围复制，并能稳定产生调用、采纳、触达、回写和复盘数据
```

## 1. 配置化判断

| 配置项 | v0.4 要求 | 产品化判断 |
|---|---|---|
| 沉默会员定义 | 支持按品牌配置 30/45/60/90 天等口径 | 不能写死在代码里 |
| 会员分层规则 | 支持按等级、消费频次、客单价、生命周期配置 | 不同品牌可用不同规则 |
| 活动策略 | 支持配置当前活动、权益适用范围、推荐重点 | 防止 AI 错误承诺权益 |
| 话术模板 | 支持品牌语气、导购风格、禁用词配置 | 不同品牌不能共用一套话术 |
| 触达频率 | 支持按触达历史、客户反馈、渠道限制配置 | 防止重复打扰 |
| 推荐人数 | 支持按导购工作量配置 3-5 人或更多 | 避免建议过载 |

**判断：** 如果以上差异仍依赖研发改代码，v0.4 只能作为交付模板继续打磨，暂不进入标准产品能力。

## 2. 权限与安全判断

| 角色 | 可见范围 | 可执行动作 | 边界 |
|---|---|---|---|
| 导购 | 本人/授权会员 | 查看建议、采纳、触达、回写反馈 | 不自动发送，不自动发券 |
| 店长 | 门店范围 | 查看门店效果、审批重点客户动作 | 不默认跨门店查看会员明细 |
| 区域运营 | 区域聚合数据 | 调整策略、查看效果 | 默认看聚合，不看无关会员明细 |
| 品牌管理员 | 品牌配置与审计 | 配置规则、模板、权益边界 | 敏感策略需留痕 |
| 系统/Agent | 按授权调用数据 | 生成建议、解释理由、记录过程 | 所有写入动作需校验与审计 |

**判断：** 导购场景涉及会员数据、营销触达、权益承诺。权限、审批、审计没清楚前，不能扩客户。

## 3. 可观测判断

必须进入看板的指标：

```text
使用指标：日活导购数、建议名单查看率、建议调用次数
过程指标：推荐采纳率、实际触达率、客户回复率、跳过原因分布
结果指标：沉默唤醒率、复购率、成交金额、客单变化、到店率
风险指标：重复打扰率、客户反感率、权益错误率、投诉/异常率
运营指标：门店差异、导购差异、品牌差异、模板效果差异
```

**判断：** 没有可观测数据，就无法证明客户价值，也无法支撑续费、增购或商业化包装。

## 4. 可回滚判断

产品化前必须支持：

1. 暂停某品牌 / 门店 / 导购使用该 Skill。
2. 禁用某条推荐策略、话术模板或权益建议。
3. 追溯错误建议来源：数据、规则、模型、配置、人工操作。
4. 回退到上一个稳定版本。
5. 对异常客户进入冷却期、黑名单或人工复核。

**判断：** 不能停、不能查、不能恢复的 AI 能力，不适合进入客户生产场景。

## 5. 可定价判断

客户愿意付费的不是“AI 推荐”，而是这些可感知结果：

- 导购少花时间筛会员；
- 老客复购提升；
- 沉默会员被重新激活；
- 店长/运营能看见导购跟进过程；
- CRM 从记录系统变成经营动作建议系统；
- CSM / 交付可通过模板降低复制成本。

**判断：** 如果只能证明“AI 建议看起来合理”，还不能产品化；必须证明“导购采纳后带来动作和结果”。

## 今天可落地动作

今天如果继续推进智能导购 / 导购小龙虾，建议补一页《导购沉默会员唤醒 Skill 产品化判断 v0.4》，只回答 5 个问题：

1. 第二个品牌上线时，哪些规则只靠配置解决？
2. 导购、店长、区域运营、品牌管理员分别能看什么、做什么？
3. 查看、采纳、触达、回复、成交是否已结构化回写 CRM？
4. 错误建议、重复打扰、权益错误能不能暂停、追溯、回滚？
5. 这个能力未来支撑续费、增购，还是只能作为交付提效工具？

## 管理提醒

1. 不要把“可复制交付包”误认为“产品化能力”。
2. 不要让客户差异进入代码，能配置就配置。
3. 不要先卖再补权限，会员数据和触达动作必须前置治理。
4. 不要只证明 AI 推荐准确，更要证明导购采纳后有业务结果。
5. 不要把 AI 做成黑盒，客户要能知道为什么推荐、谁采纳、结果如何、出了问题怎么停。

## 晚上复盘问题

1. 今天是否完成 v0.4 产品化判断页？
2. 哪些客户差异已经明确可配置，哪些还依赖研发？
3. 权限边界是否覆盖导购、店长、区域运营、品牌管理员？
4. 看板是否能证明沉默唤醒、复购、成交或导购提效？
5. 当前 Skill 更适合继续做交付模板，还是可以进入产品路线图？

## 今日一句话

> 导购沉默会员唤醒 Skill 产品化的标志，不是 AI 会推荐名单，而是换品牌、换门店、换导购后，仍能在权限可控、过程可查、结果可证的前提下，稳定推动老客复购和沉默唤醒。
