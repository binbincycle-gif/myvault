## 今日抓到的核心判断

Day20 的重点不是“把旧 Skill 删掉”，而是给组织级 AI 能力建立退出机制。

导购沉默会员唤醒 Skill 一旦进入门店试点或灰度扩围，就会被导购、店长、运营和产品团队形成使用依赖。如果旧版本不标记、不迁移、不归档，最容易出现三个风险：

1. 旧口径继续生成建议，和当前会员分层、权益、活动规则不一致。
2. 新旧 Skill / 工作流并存，导购不知道该用哪个入口。
3. Skill 已经无人维护，但仍被调用，异常发生后找不到责任人和版本依据。

> Skill 下线不是否定旧版本，而是保证能力目录始终可信、可用、可治理。

## v0.3 升级重点：从“灰度扩围”补上“退出机制”

Day79 已经补了灰度扩围机制：范围受控、指标可看、异常可停、结果可回写。今天要补的是：如果 v0.3 后续不达标，或被新版工作流替代，应该如何冻结、废弃、迁移和归档。

### 1. 生命周期状态

| 状态 | 导购沉默会员唤醒 Skill v0.3 管理动作 | 进入条件 |
|---|---|---|
| 草稿 | 只在内部设计，不开放真实门店使用 | 蓝图未评审、数据字段未确认 |
| 灰度 | 限定品牌、门店、导购、场景和数据范围 | 通过 MVP 检查，具备暂停和回写机制 |
| 正式 | 进入能力目录和运营看板 | 使用、采纳、异常、业务影响达标 |
| 冻结 | 暂停扩围，仅保留现有试点 | 口径争议、异常升高、权限变化、数据链路不稳 |
| 废弃 | 不建议继续新调用，提示替代入口 | 新版工作流覆盖、业务规则变化、长期低使用高异常 |
| 归档 | 退出生产入口，只保留历史记录 | 替代方案上线、影响范围确认、历史留痕完整 |

### 2. 下线判断信号

| 信号 | 导购沉默会员唤醒 Skill 要看的问题 | 处理倾向 |
|---|---|---|
| 业务规则变化 | 沉默周期、会员分层、权益规则是否变了 | 先冻结，评审是否升级 |
| 数据口径变化 | 会员归属、门店关系、消费记录、触达记录是否变化 | 冻结或重建数据口径 |
| 使用量下降 | 导购是否转向新版智能导购工作流 | 合并升级或废弃 |
| 异常率升高 | 是否出现重复触达、权益承诺错误、权限越界 | 立即冻结，必要时回滚 |
| 替代能力出现 | 新版导购工作流是否已覆盖名单、理由、话术、触达、回写 | 废弃旧入口，归档旧版本 |

### 3. 受控迁移动作

```text
旧 Skill 准备下线
  ↓
标记状态：冻结 / 废弃 / 待归档
  ↓
说明替代入口：新版导购唤醒工作流 / 人工流程 / 店长审核流程
  ↓
确认影响范围：品牌、门店、导购、客户群、历史报告
  ↓
保留留痕：版本、负责人、下线原因、数据口径、异常记录、迁移时间
  ↓
生产入口下线，历史资产归档
```

```text
3. 触发下线原因：规则变化 / 数据变化 / 使用下降 / 异常升高 / 替代能力出现

```

## 三条下线红线

1. **没有替代说明，不要直接下线。** 导购不知道下一步去哪，会造成业务中断。
2. **没有历史留痕，不要直接删除。** 后续追溯推荐依据、权益承诺、异常原因时必须能查到旧版本。
3. **没有权限复核，不要切到新版。** 新版工作流如果数据范围更大、动作权限更强，必须重新做 SaaS 实时判权和审计。

## 管理提醒

1. Skill 目录不是越多越好，可信、当前、可治理才有价值。
2. 导购触达类 Skill 过期后继续使用，风险比普通文档过期更高。
3. 下线不是删除资产，而是让旧能力退出生产入口、保留历史证据。
4. 新旧 Skill 并存超过一个周期，必须明确合并、替代或归档决策。
5. 没有负责人维护的正式 Skill，不能长期挂在目录里。
