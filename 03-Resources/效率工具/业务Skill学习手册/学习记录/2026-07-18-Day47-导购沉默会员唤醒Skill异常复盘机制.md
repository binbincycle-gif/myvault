## 今日抓到的核心判断

Day46 解决的是“Skill 上架后怎么看价值”。Day47 要继续补上另一半：**当导购沉默会员唤醒 Skill 出错时，不能靠人临时解释，必须把异常转成规则、权限、数据和话术的升级。**

> 导购沉默会员唤醒 Skill 的成熟度，不是保证永不出错，而是每次异常都能被记录、分类、修正，并减少同类问题复发。

这个 Skill 一旦进入真实导购动作，最容易出问题的不是“模型不会写话术”，而是：

1. **会员判断错**：把不该唤醒的人推给导购，比如近期已投诉、已退货、已明确拒收营销的会员。
2. **推荐理由弱**：只说“长期未消费”，没有结合偏好、最近互动、权益、门店场景。
3. **权益承诺过满**：话术里出现“必送、免费、无门槛、一定可用”等高风险表达。
4. **触达频次失控**：同一会员被不同导购或不同活动反复触达。
5. **结果没回写**：导购否定、客户无响应、投诉、成交这些反馈没有进入下一轮策略。

所以异常复盘不是售后动作，而是 Skill 运营的一部分。

## 导购沉默会员唤醒 Skill｜异常分类 v0.1

| 异常类型 | 典型表现 | 复盘重点 | 修正方向 |
|---|---|---|---|
| 输入异常 | 导购只输入“帮我唤醒沉默会员”，缺少门店、活动、会员范围 | 是否需要追问；是否有默认安全范围 | 增加输入模板和必要字段校验 |
| 数据异常 | 会员沉默天数、消费记录、权益状态不准 | 数据更新时间、字段来源、口径版本 | 增加数据时间戳和缺失提示 |
| 逻辑异常 | 推荐了低价值或高风险会员 | 分层规则、排除规则、优先级 | 补沉默会员筛选规则和反例 |
| 权限异常 | 导购看到不属于自己门店/客户的数据 | 身份、门店、会员归属、品牌权限 | SaaS 实时判权 + 拦截日志 |
| 话术异常 | 承诺权益过满、语气骚扰、暗示过度 | 敏感词、权益适用条件、人工确认 | 高风险话术拦截和降级 |
| 运营异常 | 多导购重复触达、频次过高 | 触达记录、导购关系、冷却期 | 增加频控和触达冲突检测 |

## 最小异常记录模板

导购沉默会员唤醒 Skill 每次异常至少记录 8 个字段：

```text
1. 异常时间
2. 品牌 / 门店 / 导购（必要时脱敏）
3. 会员范围或会员类型（脱敏）
4. 导购输入
5. Skill 输出：推荐名单 / 推荐理由 / 话术片段
6. 异常分类：输入 / 数据 / 逻辑 / 权限 / 话术 / 运营
7. 影响判断：效率 / 成交 / 客诉 / 越权 / 信任
8. 处理动作：修规则 / 补数据 / 加拦截 / 降级 / 暂停
```

这张表不追求复杂，但必须能支撑两个问题：

- 这次问题到底是模型问题、数据问题、规则问题、权限问题，还是运营机制问题？
- 这次处理后，Skill 的哪个部分变强了？

## 三类高风险异常要优先设红线

### 1. 权益承诺异常

**风险表现**：话术承诺“免费领取”“一定有券”“到店必送”，但会员实际不满足条件。

**处理原则**：
- 活动权益字段不完整时，不能输出承诺型话术。
- 权益类表达必须带适用条件或人工确认提示。
- 高风险词进入拦截：必送、一定、免费、无门槛、保证、专属保留等。

### 2. 权限越界异常

**风险表现**：导购看到非本门店、非本人维护、非授权范围内的会员信息。

**处理原则**：
- 会员数据不沉淀在 Skill 内，必须通过 SaaS 实时判权。
- 输出前做导购身份、门店、会员归属校验。
- 每次越权拦截都要进入审计日志。

### 3. 频次骚扰异常

**风险表现**：同一会员短期内被多个导购、多次活动反复触达，引发反感或投诉。

**处理原则**：
- 增加触达冷却期。
- 同一会员存在近 N 天触达记录时，优先提示“暂不建议触达”。
- 多导购关系冲突时，优先归属主维护导购或门店负责人确认。

## 异常到版本升级的闭环

```text
异常发生
  ↓
记录证据：输入 / 输出 / 数据 / 权限 / 场景 / 影响
  ↓
分类定位：输入 / 数据 / 逻辑 / 权限 / 话术 / 运营
  ↓
确定动作：补字段 / 补规则 / 加拦截 / 降级 / 暂停
  ↓
版本升级：Prompt / Schema / 权限校验 / 频控规则 / 话术模板
  ↓
复测验证：同类会员、同类门店、同类活动是否不再复发
```

复盘不是写一份说明，而是要让 Skill 的版本发生变化。

## 今日可落地动作

给“导购沉默会员唤醒 Skill”补一张异常复盘表，并先固定三条红线：

```text
1. 权益字段不完整，不输出承诺型话术。
2. 会员归属或门店权限不清，不输出会员详情。
3. 近 N 天已有触达记录，默认降级为“暂不建议触达 / 需人工确认”。
```

这三条红线先不求完美，但要先把高风险区域框住。

## 管理提醒

1. **不要把异常都甩给模型。** 导购 Skill 的问题很多来自数据口径、权限边界、活动规则和运营频控。
2. **异常必须和运营看板打通。** 投诉率、误触达率、越权拦截次数不能只在日志里，要进入每周运营判断。
3. **越接近客户沟通，越要保守。** 会员触达类 Skill 先给建议，不直接自动发送。
4. **每次异常必须推动版本变更。** 没有补规则、补字段、补权限、补话术模板，就不算真正复盘。
