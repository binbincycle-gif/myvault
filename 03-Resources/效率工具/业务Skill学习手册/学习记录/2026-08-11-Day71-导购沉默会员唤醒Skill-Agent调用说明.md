## 导购沉默会员唤醒 Skill｜Agent 调用说明 v0.1

```text
Skill 名称：导购沉默会员唤醒建议 Skill
目标业务场景：帮助品牌/门店/导购从 CRM 会员数据中识别沉默会员，生成唤醒名单、跟进理由、建议话术和复盘指标。
当前阶段：产品化 AI 能力候选 → 补齐 Agent 可调用说明

1. 触发条件
- 用户提出：沉默会员唤醒、老客复购、导购跟进名单、会员激活、客户流失预警、导购话术、会员经营建议时，应考虑调用。
- 典型表达：
  - “帮我找一批最近没来的会员”
  - “给导购生成沉默会员跟进名单”
  - “哪些老客适合今天唤醒”
  - “给门店做一版会员唤醒方案”
  - “根据 CRM 数据给导购推荐跟进动作”
- 不应调用的情况：
  - 用户只是要泛泛的营销文案，不需要会员数据；
  - 用户要做全量群发，不关注导购一对一跟进；
  - 用户要求绕过权限查看其他门店/品牌会员；
  - 用户要求直接自动发券、自动外呼、自动群发且未确认审批。

2. 输入要求
- 必填信息：
  - 品牌 / 客户范围
  - 门店 / 导购 / 区域范围
  - 沉默会员定义，如 30/60/90 天未消费
  - 会员数据权限范围
  - 当前活动或可用权益
  - 输出用途：导购跟进、店长管理、运营复盘、客户汇报
- 可选信息：
  - 会员等级
  - 最近购买品类
  - 客单价区间
  - 最近触达记录
  - 导购话术风格
  - 禁用词 / 合规要求
- 信息缺失处理：
  - 缺品牌/门店/权限范围：必须追问，不能硬跑；
  - 缺活动权益：可先生成“无权益版唤醒建议”；
  - 缺触达记录：必须提示重复打扰风险；
  - 缺沉默周期：默认给 30/60/90 天三档建议，并请用户确认。

3. 权限与边界
- 可读取：授权范围内的会员基础画像、消费记录、最近触达记录、导购归属、门店归属。
- 不可默认读取：跨品牌会员明细、未授权门店会员、敏感联系方式、非必要个人隐私字段。
- 可生成：唤醒名单、分组理由、建议话术、推荐权益、导购动作、复盘指标。
- 不可擅自执行：自动发券、自动群发、自动外呼、自动修改会员标签、批量写入 CRM、对外发送消息。
- 必须人工确认：
  - 任何对外触达动作；
  - 任何权益承诺或优惠券发放；
  - 任何批量写入 / 修改 CRM 数据；
  - 任何跨门店 / 跨品牌数据使用；
  - 任何高价值会员或投诉风险会员触达。

4. 执行步骤
- 第一步：确认业务目标和授权范围。
- 第二步：按沉默周期、会员价值、最近互动、导购归属做候选分组。
- 第三步：为每组生成跟进理由、建议动作和话术。
- 第四步：标注风险，如重复打扰、权益不匹配、客户投诉风险、导购权限不足。
- 第五步：输出可执行清单，并明确 CRM 回写字段和复盘指标。
- 异常降级：
  - 数据不足：输出口径说明 + 待补数据清单；
  - 权限不足：只输出方法和字段清单，不展示会员明细；
  - 活动信息不足：输出非权益型话术和运营建议；
  - 风险较高：建议先做小范围试点，不做批量触达。

5. 输出结果
- 给管理者看的结论：本次可唤醒人群规模、预估价值、关键风险、是否适合试点/扩围。
- 给导购用的动作：会员名单、跟进优先级、推荐话术、建议触达时间、注意事项。
- 给店长/运营看的管理项：导购执行进度、采纳率、触达率、回复率、复购率、异常反馈。
- 给系统回写的字段：是否采纳、触达时间、触达方式、客户反馈、成交结果、未采纳原因。
- 晚上/周会复盘指标：名单查看率、建议采纳率、触达完成率、客户回复率、复购率、投诉/反感率。
```

## description 草案｜供 Skill 文件使用

```text
用于导购沉默会员唤醒、老客复购、会员激活、导购跟进名单和会员经营建议场景。当用户需要基于 CRM 会员数据生成唤醒名单、分组理由、导购话术、推荐动作、CRM 回写字段和复盘指标时使用。输入至少需要品牌/门店/导购范围、沉默会员定义、数据权限范围、当前活动或可用权益。若涉及自动发券、自动群发、自动外呼、批量写入 CRM、跨门店/跨品牌数据使用，必须先人工确认。不适用于无会员数据支撑的泛营销文案生成，也不允许绕过权限查看未授权会员明细。
```

## Agent 调用设计检查清单｜导购沉默会员唤醒版

| 检查项 | 必须回答 | 当前建议 |
|---|---|---|
| 触发条件 | 用户说什么时应调用？ | 沉默会员、老客复购、导购跟进、会员激活、客户流失预警 |
| 不适用场景 | 哪些相似需求不能调用？ | 泛营销文案、全量群发、绕权限查数、自动触达未确认 |
| 输入要求 | 缺哪些信息不能硬跑？ | 品牌/门店/导购范围、沉默周期、权限范围必须确认 |
| 权限边界 | 哪些动作必须确认？ | 发券、群发、外呼、批量写入、跨范围数据使用 |
| 输出结果 | 给谁用、怎么接后续？ | 管理者看结论，导购看动作，系统回写字段，周会看指标 |
| 异常降级 | 数据不足怎么办？ | 输出方法与待补数据，不伪造会员明细 |

## 今天可落地动作

如果今天继续推进智能导购 / 导购小龙虾，建议把 Day70 的“产品化判断”补成一个真正能被 Agent 调用的 Skill 说明：

1. **补 description**：让 Agent 能识别“沉默会员唤醒 / 老客复购 / 导购跟进”场景。
2. **补输入门槛**：品牌、门店、导购、沉默周期、权限范围必须明确。
3. **补人工确认边界**：发券、群发、外呼、批量写入、跨范围数据使用必须确认。
4. **补输出结构**：管理结论、导购动作、系统回写、复盘指标四层分开。
5. **补异常降级**：数据缺失、权限不足、活动不明时不能硬生成会员明细。

管理上只问一句：**如果把这个 Skill 交给 Agent 自动选择，它会不会误用、漏用、越权用？**

## 管理提醒

1. **不要只写给人看。** Skill 文档首先要让 Agent 能判断调用条件、输入要求和风险边界。
2. **不要让 Agent 在信息不足时硬跑。** CRM 场景尤其要防止编造会员结论。
3. **不要把“生成建议”和“执行触达”混在一起。** 建议可以自动生成，触达必须人工确认。
4. **不要忽略 description。** 它是 Skill 自动命中的第一道分流器。
5. **不要只输出话术。** 真正的经营闭环必须包含回写字段和复盘指标。
