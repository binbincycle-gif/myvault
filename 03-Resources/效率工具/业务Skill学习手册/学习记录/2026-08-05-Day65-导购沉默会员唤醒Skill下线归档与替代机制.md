## 今日抓到的核心判断

Day64 讲的是 Skill 正常执行后的结果沉淀：没有采纳、触达、回复、成交、未采纳原因等回写，就没有能力复利。

Day65 要补的是另一侧：**当一个 Skill 已经过期、低效、高异常，或者被新版工作流替代时，必须能受控下线和归档。**

导购沉默会员唤醒 Skill 不能只考虑“怎么上线”和“怎么扩围”，还要提前设计“什么时候冻结、什么时候废弃、什么时候合并进更大的导购工作流”。否则后面最容易出现三个问题：

1. 旧规则继续推荐错误会员，导购还以为是 AI 智能判断。
2. 新旧 Skill 并存，导购不知道该用哪个入口。
3. 出现异常后找不到负责人、版本和当时口径，无法复盘。

一句话：**Skill 能力资产不是越多越好，而是要始终保持可信、当前、可追溯。**

## 导购沉默会员唤醒 Skill｜生命周期状态 v0.1

| 状态 | 适用条件 | 管理动作 | 对导购入口的影响 |
|---|---|---|---|
| 草稿 | 规则、字段、话术仍在设计 | 不开放真实业务使用 | 不出现在导购入口 |
| 灰度 | 小范围门店 / 导购验证 | 限定品牌、门店、人群、批次 | 标记“灰度能力” |
| 正式 | 已验证采纳率、触达率、异常率可接受 | 进入目录和运营看板 | 默认可用 |
| 冻结 | 业务口径变化、异常率升高、数据不稳定 | 暂停扩围，只保留现有试点 | 提示“暂停扩大使用” |
| 废弃 | 已有新版替代，或长期无人维护 | 限制新调用，提示替代方案 | 不建议使用 |
| 归档 | 已退出生产使用 | 保留版本、口径、负责人、下线原因 | 入口下线，仅保留历史记录 |

## 下线判断信号

### 1. 业务规则变化

例如：沉默会员定义从“90 天未购”调整为“60 天未购 + 近 30 天有互动但未转化”。旧 Skill 如果不更新，推荐名单会失真。

**动作**：进入冻结，补充新规则评审；若新版工作流已覆盖，旧版废弃。

### 2. 数据口径变化

例如：CRM 新增生命周期、复购潜力、导购归属、企微互动字段，旧 Skill 仍只按消费间隔和金额判断。

**动作**：标记旧版口径，禁止继续生成正式经营建议。

### 3. 异常率升高

例如：导购持续反馈“推荐客户不准”“权益已过期”“客户已被其他导购触达”。

**动作**：冻结扩围，要求异常复盘；连续两周未修复则废弃。

### 4. 新版工作流替代

例如：新版导购工作流已经覆盖“名单 → 理由 → 话术 → 触达 → 反馈 → 转化复盘”。旧的单点唤醒 Skill 应合并，不应继续独立作为入口。

**动作**：原 Skill 改为废弃，并在目录提示“请使用新版导购经营工作流”。

### 5. 负责人缺失

如果正式 Skill 没有产品、业务或技术负责人维护，不能长期留在生产目录。

**动作**：先冻结；两周内无人接手则归档。

## 与 Day64 的衔接：结果沉淀也要参与下线判断

Day64 设计的结果回写字段，不只是为了优化下一版，也可以成为下线判断依据。

| 运营指标 | 健康信号 | 下线/冻结信号 |
|---|---|---|
| 导购查看率 | 导购愿意打开 | 长期低于阈值，说明入口或价值不清 |
| 导购采纳率 | 推荐理由可信 | 查看高但采纳低，说明名单/话术不准 |
| 客户回复率 | 触达内容有效 | 采纳高但回复低，说明分层或时机不准 |
| 成交转化率 | 经营结果有效 | 持续无转化，需重新验证场景价值 |
| 未采纳原因 | 可定位问题 | TOP 原因长期不变但未修复，说明无人维护 |
| 投诉/反感记录 | 风险可控 | 出现高风险投诉，必须立即冻结 |

## 管理提醒

1. **上线标准和下线标准要一起设计。** 只会新增能力，不会治理能力，目录很快会变成 AI 垃圾箱。
2. **旧 Skill 不要直接删除。** 生产入口可以下线，但历史口径、版本、负责人、影响范围要保留，方便审计和复盘。
3. **新旧能力并存要有明确引导。** 如果新版导购工作流已经替代旧 Skill，入口必须提示推荐使用新版，而不是让导购自己猜。
4. **无人维护的正式 Skill 是风险资产。** 涉及客户、权益、交易、会员分层的 Skill，必须有维护责任人。
5. **结果数据要反向驱动生命周期。** 使用率、采纳率、异常率、转化率都要参与“继续运营 / 冻结 / 废弃 / 归档”的判断。

## 晚上复盘问题

1. 导购沉默会员唤醒 Skill 现在处于哪个生命周期状态：灰度、正式，还是仍应视为草稿？
2. 如果新版导购工作流上线，旧的单点唤醒 Skill 是否要合并、废弃或归档？
3. 当前是否有明确负责人维护规则、话术、权限和异常复盘？
4. 今天有没有定义清楚冻结条件：什么异常一出现就暂停扩围？
5. 如果明天要下线旧版本，是否能说清楚替代入口、影响范围和历史数据处理方式？

## 今日一句话

> Skill 治理不是只管上线；能灰度、能运营、能冻结、能废弃、能归档，才是真正可被组织长期信任的 AI 能力资产。
