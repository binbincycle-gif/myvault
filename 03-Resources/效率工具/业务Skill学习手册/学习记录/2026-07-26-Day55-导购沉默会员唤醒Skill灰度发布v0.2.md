## 今日抓到的核心判断

Day54 已经把“运营看板 → 异常复盘 → 版本升级”的风险闭环补上。Day55 要把灰度发布机制再往前推一层：**灰度不是一次性试用，而是一套可控扩围机制。**

> 导购沉默会员唤醒 Skill 的灰度发布 v0.2，核心不是“先给少数门店用”，而是把扩围条件、暂停条件、降级条件、复测条件提前写清楚。

如果灰度只有“选几个导购试试”，团队很快会掉回主观判断：谁觉得好、谁觉得不好、谁想扩、谁担心风险。真正可管理的灰度，必须回答四个问题：

1. **什么时候可以扩大？** 看哪些指标达标。
2. **什么时候必须暂停？** 哪些风险一票否决。
3. **什么时候只降级不停止？** 哪些问题可以先退回建议模式。
4. **修完后怎么恢复？** 是否经过同类会员、同类门店、同类活动复测。

## 导购沉默会员唤醒 Skill｜灰度发布 v0.2

### 1. 灰度分三档推进

| 阶段 | 范围 | 能力权限 | 目标 |
|---|---|---|---|
| G1 小范围验证 | 1 个品牌 / 1-2 家门店 / 少数成熟导购 | 只输出推荐名单、推荐理由、建议话术 | 验证推荐可信、话术可用、权限安全 |
| G2 受控扩围 | 同品牌更多门店 / 更多导购 | 增加批量推荐、看板统计、异常记录 | 验证跨门店稳定性和运营可复制 |
| G3 稳定运营 | 多品牌可配置试点 | 接入目录、看板、异常复盘、版本管理 | 进入组织级 Skill 运营 |

### 2. G1 → G2 扩围标准

```text
1. 灰度导购使用率 ≥ 60%
2. 推荐会员采纳率 ≥ 50%
3. 触达结果回写率 ≥ 80%
4. 高风险异常 = 0
5. 权益承诺、会员归属、触达频控三类规则均已通过检查
6. 至少沉淀 3 条有效互动或成交样例
```

这里的重点不是数值绝对正确，而是让团队从“感觉能用”转到“有证据扩围”。

### 3. G2 → G3 稳定运营标准

```text
1. 跨门店使用后，采纳率没有明显下降
2. 不同导购的结果回写字段一致，能形成看板
3. 异常复盘表至少跑通过 1 次闭环：发现 → 分类 → 修正 → 版本记录 → 复测
4. 新门店接入不依赖人工反复讲解，有标准使用说明和禁用边界
5. 店长 / 运营负责人能看懂看板，并能判断是否扩、停、降级
```

如果 G2 阶段无法跨门店稳定复制，就不能急着包装成正式产品能力。

## 暂停 / 降级 / 回退规则

### 1. 立即暂停

出现以下任一问题，直接暂停当前灰度入口：

```text
- 会员数据越权展示
- 出现明确客诉或权益误导
- 同一会员被重复触达并产生负反馈
- 输出内容违反品牌沟通规范
- 风险事件连续上升且无法定位原因
```

### 2. 降级为只读建议

出现以下问题，先不扩大，降级为“只输出分析和建议，不给具体会员详情或触达话术”：

```text
- 推荐名单采纳率持续偏低
- 数据口径被频繁质疑
- 导购大量修改话术
- 结果回写率不足，无法判断业务价值
- 触达频控或会员归属规则还未完全打通
```

### 3. 回退到上一版稳定规则

如果新版本 Prompt、Schema、会员分层、话术模板或频控规则上线后异常升高，先回退上一版稳定规则，再做复盘，不要在生产灰度里连续试错。

## 灰度发布 v0.2 清单

```text
1. 灰度阶段：G1 / G2 / G3
2. 灰度品牌、门店、导购名单
3. 可使用会员范围：会员归属、沉默天数、消费时间、触达历史
4. 允许输出内容：名单 / 理由 / 建议话术 / 权益提醒 / 风险提示
5. 禁止动作：自动发送、跨门店推荐、无条件权益承诺、绕过人工确认
6. 必填回写字段：是否触达、客户反馈、是否成交、异常备注
7. 扩围标准：使用率、采纳率、回写率、异常率、业务样例
8. 暂停条件：越权、客诉、权益误导、重复触达、风险升高
9. 降级条件：采纳低、口径疑、回写弱、话术大量修改
10. 恢复条件：规则修正、版本记录、同类场景复测通过
```

## 和 Day54 的衔接

Day54 解决“出了问题怎么复盘”；Day55 解决“什么时候可以继续扩大”。

两者要连成一条管理链路：

```text
灰度发布
  ↓
运营看板
  ↓
风险事件
  ↓
异常复盘
  ↓
版本升级 / 降级 / 暂停
  ↓
同类场景复测
  ↓
决定是否扩围
```

没有异常复盘的灰度，是冒险；没有扩围标准的复盘，是原地打转。

如果今天继续推进智能导购 / 导购小龙虾，可以让产品或项目负责人补一张“灰度发布 v0.2 决策表”：

```text
当前处于 G1 / G2 / G3 哪一档？
已达标指标有哪些？
未达标指标有哪些？
当前最大风险是什么？
下一步是扩大、观察、降级、暂停，还是回退？
```

这张表可以直接用于产品评审或项目周会，避免讨论停留在“感觉不错”。

## 管理提醒

1. **灰度不是试用，是受控经营实验。** 要有边界、指标、暂停权。
2. **越靠近会员触达，越要先建议后执行。** 自动发送必须放到后期。
3. **扩围前先看风险，再看效率。** 会员权益、权限、频控不能靠事后解释。
4. **没有结果回写，不允许判断成功。** 只听导购反馈不够。
5. **暂停权要提前给清楚。** 风险事件连续上升时，运营负责人必须能冻结扩围。

## 晚上复盘问题

1. 今天是否明确导购沉默会员唤醒 Skill 当前处于 G1 / G2 / G3 哪一档？
2. 是否定义了进入下一档的硬指标，而不是只靠主观反馈？
3. 是否把暂停、降级、回退规则写进灰度清单？
4. 是否完成至少一次“异常修正后复测”的闭环？
5. 下一次评审能否用“指标 + 风险 + 版本记录”决定是否扩围？

## 一句话沉淀

导购沉默会员唤醒 Skill 的灰度发布，不是小范围用一下，而是用 G1/G2/G3 的受控扩围机制，证明它能安全、稳定、可复盘地从单店样板走向多店复制。
