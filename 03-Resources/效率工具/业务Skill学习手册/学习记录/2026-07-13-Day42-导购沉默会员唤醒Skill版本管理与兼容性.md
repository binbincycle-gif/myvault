## 今日抓到的核心判断

Day41 解决的是“出错后如何复盘与止损”。Day42 要补的是生产级 Skill 的另一条纪律：**每次升级都必须有版本边界，不能让新能力打断老流程。**

> Skill 版本管理不是技术洁癖，而是 ToB AI 能力进入真实导购流程后的交付纪律：新能力要能长出来，老流程不能被打断。

对“导购沉默会员唤醒 Skill”来说，版本变化会直接影响导购怎么触达会员、店长怎么监管、品牌怎么解释权益。如果没有版本管理，一次字段调整、话术策略变化、权限扩大或自动执行能力升级，都可能造成一线执行混乱。

## 导购沉默会员唤醒 Skill｜版本节奏 v0.1

| 版本 | 能力范围 | 关键边界 | 适用阶段 |
|---|---|---|---|
| v0.1 | 人工输入会员场景，生成唤醒话术草稿 | 不接真实会员详情；不自动发送；仅内部验证话术质量 | 内部 PoC |
| v0.2 | 接入脱敏会员标签、沉默天数区间、最近消费概况 | 数据脱敏；仅输出建议；必须人工确认 | 小范围试点 |
| v1.0 | 面向导购生成可执行唤醒建议与话术 | SaaS 实时判权；导购确认后使用；结果人工回写 | 门店灰度 |
| v1.1 | 增加品牌语气、活动权益校验、话术 A/B 版本 | 权益不完整不生成承诺型话术；保留旧模板 | 品牌试点优化 |
| v2.0 | 生成导购每日沉默会员唤醒任务清单 | 店长可查看；批量触达需审批；保留 v1 单会员模式 | 规模化推广 |
| v3.0 | 联动优惠券 / 营销策略 / 自动任务分发 | 涉及权益、群发、自动执行必须审批、审计、可回滚 | 成熟生产能力 |

## 哪些改动必须标记为破坏性变更

导购沉默会员唤醒 Skill 中，以下变化不能静默上线：

1. **输入字段变化**：如从“沉默天数区间”改成“RFM 分层”，会影响下游判断。
2. **输出结构变化**：如从纯话术文本改为“任务 + 话术 + 权益建议”结构，会影响前端展示和导购理解。
3. **权限范围扩大**：如从导购个人会员扩展到门店或区域会员，必须重新校验权限。
4. **执行动作升级**：如从“生成建议”变成“自动建任务 / 自动触达”，必须加审批和审计。
5. **权益策略变化**：如新增券、折扣、活动推荐逻辑，必须同步活动规则和前线解释口径。
6. **结果回写字段变化**：如新增“客户反馈 / 是否成交 / 下次提醒”，要保证旧数据兼容。

## 最小版本治理规则

```text
1. v1 稳定前，不做自动执行，只做建议 + 人工确认。
2. 新增字段必须有默认值，旧调用至少保留一个灰度周期。
3. 输出结构大改时，v1 / v2 并行，不直接覆盖旧版本。
4. 权限范围扩大、权益触达、批量任务、自动执行，全部算高风险升级。
5. 每次版本升级必须记录：版本号、变更点、影响范围、灰度对象、回滚方式、复测结果。
```

## 版本发布记录字段

每次升级至少记录：

```text
1. version
2. release_date
3. 变更类型：新增 / 优化 / 修复 / 破坏性变更
4. 影响范围：内部 / 单品牌 / 单门店 / 全量
5. 涉及能力：输入 / 输出 / 权限 / 权益 / 任务 / 回写 / 审计
6. 灰度对象
7. 回滚版本
8. 负责人
9. 前线说明口径
10. 复测结果
```
