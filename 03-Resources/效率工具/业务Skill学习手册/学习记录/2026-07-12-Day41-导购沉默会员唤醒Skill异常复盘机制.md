## 今日抓到的核心判断

Day40 解决的是“上线后怎么看运营数据”，Day41 要补上另一条底线：**一旦 Skill 出错，不能靠群里解释、人工兜底或临时改 prompt，而要把异常变成可定位、可复盘、可升级的机制。**

> Skill 的成熟度，不是不出错，而是出错后能不能留下证据、定位原因、改进规则，并验证同类问题不再复发。

对“导购沉默会员唤醒 Skill”来说，异常不是小问题。它靠近会员数据、导购触达、活动权益、客户体验和品牌经营结果。如果话术承诺过度、会员分层不准、触达建议不合适，轻则导购不信，重则客户投诉、品牌质疑。

所以今天要给这个 Skill 补一套最小异常复盘机制。

## 导购沉默会员唤醒 Skill｜异常分类 v0.1

| 异常类型 | 典型表现 | 处理重点 |
|---|---|---|
| 输入异常 | 导购没有说明门店、会员场景、活动背景，AI 直接生成泛话术 | 增加必填字段、缺失时先追问 |
| 数据异常 | 会员沉默天数、最近消费、权益状态、互动记录不完整或过期 | 增加数据时间戳、缺失降级提示 |
| 逻辑异常 | 推荐理由跳跃，给高价值会员推低价值权益，或忽略历史偏好 | 补规则、补反例、补优先级判断 |
| 权益/承诺异常 | 话术出现“一定、免费、无门槛、必送”等过度承诺 | 敏感词拦截、权益字段校验、人工确认 |
| 权限异常 | 导购看到不属于自己门店/客户范围的会员信息 | SaaS 实时判权、审计日志、越权拦截 |
| 体验异常 | 话术不像导购会说的话，太长、太硬、不可直接发 | 输出风格模板、品牌语气、人工编辑反馈 |
| 结果异常 | 触达后会员负反馈、投诉、退订、到店权益不一致 | 结果回写、冻结批量能力、复盘规则 |

## 最小异常记录字段

每次异常至少记录这些字段，不追求复杂，但要能复盘：

```text
1. abnormal_id
2. skill_run_id
3. 异常时间
4. 品牌 / 门店 / 导购身份
5. 会员分层 / 沉默天数区间（脱敏）
6. 用户输入 / 调用参数（脱敏）
7. AI 输出关键片段
8. 异常类型
9. 影响判断：效率 / 质量 / 客户体验 / 权限 / 经营结果
10. 当前处理动作：回滚 / 修正 / 补规则 / 加审批 / 冻结 / 观察
11. 责任人
12. 是否完成复测
13. 对应版本号
```

没有这些字段，异常最后只会变成“感觉讨论”，无法沉淀为能力升级。

## 异常处理动作

| 动作 | 触发条件 | 处理方式 |
|---|---|---|
| 补输入 | 关键信息缺失导致输出偏差 | 增加必填项；缺失时不直接生成，先追问 |
| 补数据 | 推荐理由薄弱或数据不可信 | 增加数据时间戳、字段完整性检查、缺失降级 |
| 补规则 | 推荐逻辑不符合业务优先级 | 增加规则、反例、主链路优先级 |
| 补权限 | 出现越权或数据范围不清 | 接入 SaaS 实时判权、审计、拦截 |
| 补审批 | 涉及权益承诺、批量触达、高风险会员 | 转人工确认或店长/品牌审批 |
| 补体验 | 导购采纳率低、人工修改率高 | 调整话术风格、品牌语气、输出长度 |
| 冻结/回滚 | 客诉、误导、越权、高风险连续出现 | 冻结批量能力，保留单人试用或下线版本 |

## 高风险场景优先拦截

导购沉默会员唤醒 Skill 早期必须重点盯 4 类风险：

1. **权益承诺风险**：不得在活动规则不完整时生成确定性承诺。
2. **越权触达风险**：导购只能看和触达自己权限范围内会员。
3. **客户体验风险**：不要对高敏感会员频繁、强推式触达。
4. **经营误判风险**：数据延迟或缺失时不能输出强建议，只能输出“需人工确认”。

## 今日可落地动作

给“导购沉默会员唤醒 Skill”补一个独立章节：

```text
异常复盘机制
- 异常分类
- 异常记录字段
- 高风险拦截规则
- 处理动作：补输入 / 补数据 / 补规则 / 补权限 / 补审批 / 冻结
- 版本复测要求
```

并先内置三条硬规则：

```text
1. 活动权益字段不完整 → 不生成承诺型话术，只提示人工确认。
2. 未通过 SaaS 权限校验 → 不展示会员信息，不生成触达建议。
3. 数据更新时间超阈值 → 不输出经营建议，只输出数据异常提醒。
```
