## 导购沉默会员唤醒 Skill｜权限审批审计 v0.1

### 1. 权限矩阵

| 角色 | 可查看数据 | 可执行动作 | 禁止动作 |
|---|---|---|---|
| 导购 | 自己会员池、会员基础画像、最近消费/互动摘要、推荐理由 | 查看唤醒名单、生成/修改话术、记录触达反馈、提交跟进结果 | 查看其他导购/门店会员明细、自动群发、自动发券、批量改标签 |
| 店长 | 本店会员池、本店导购执行进度、本店沉默会员分层汇总 | 审核批量触达名单、查看导购采纳率/完成率、调整本店唤醒节奏 | 查看其他门店明细、绕过运营审批发券、导出非授权会员明细 |
| 区域/运营 | 授权区域/品牌范围内的汇总数据、门店执行对比、活动权益配置 | 配置沉默周期、权益策略、灰度门店、复盘指标 | 未审批直接全量触达、跨品牌使用会员明细、绕过审计下发动作 |

## 与 Day71 调用说明的衔接

Day71 的 Agent 调用说明需要补充一个强制前置判断：

```text
Agent 在调用导购沉默会员唤醒 Skill 前，必须先确认：
1. 当前操作者角色；
2. 品牌/门店/导购数据范围；
3. 输出用途；
4. 是否涉及对外触达、权益发放、批量写入或跨范围数据使用；
5. 若涉及高风险动作，必须进入人工确认/审批，不允许直接执行。
```

如果这些信息缺失，Agent 只能输出“待确认清单 + 方法建议”，不能输出具体会员明细或执行动作。

## 今天可落地动作

如果今天继续推进智能导购 / 导购小龙虾，建议把导购沉默会员唤醒 Skill 的文档补三个模块：

1. **权限矩阵**：导购、店长、运营、总部、Agent 分别能看什么、能做什么、不能做什么。
2. **审批规则**：把触达、发券、批量写入、跨范围数据使用列为高风险动作。
3. **审计字段**：至少记录调用人、角色、数据范围、动作类型、审批状态、输出摘要、结果回写和风险标记。

管理上只问一句：**这个 Skill 出了问题后，能不能还原是谁、在什么权限下、基于哪些数据、做了什么动作？**

## 管理提醒

1. **不要把“可生成”误认为“可执行”。** 话术可以生成，触达和发券必须确认。
2. **不要让 Agent 拿全量会员明细。** 默认最小权限，只给完成任务必需字段。
3. **不要只做功能日志。** 审计要能支撑复盘、合规和效果优化。
4. **不要让权限只停留在前端。** 后端 Skill 调用也必须校验角色、数据范围和动作权限。
5. **不要忽略回滚。** 批量写入、标签修改、权益发放必须有可回滚或补救机制。

## 晚上复盘问题

1. 今天是否补齐导购沉默会员唤醒 Skill 的权限矩阵？
2. 哪些动作已经明确列为必须人工确认或审批？

4. Agent 在权限不足或输入缺失时，是否会自动降级而不是硬跑？
