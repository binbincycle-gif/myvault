## 今日抓到的核心判断

业务 Skill MVP 不是完整产品的缩水版，而是一条最短业务行动链：

```text
有人用 → 有动作 → 有反馈 → 有边界 → 可复盘
```

对“导购沉默会员唤醒 Skill”来说，MVP 不应一开始追求完整智能导购平台，而是先证明：

```text
AI 能否帮导购更快找到值得跟进的沉默会员，并推动一次有理由、有话术、有记录的真实触达。
```

## MVP 试点设计

| 项目 | 今日建议口径 |
|---|---|
| Skill MVP 名称 | 导购沉默会员唤醒 Skill |
| 服务角色 | 一线导购 |
| 挂靠业务场景 | 每日会员跟进 / 沉默会员唤醒 |
| 本周只验证的一件事 | AI 推荐的会员名单和话术，是否能推动导购完成真实触达 |
| 必要输入 | 会员归属、最近消费、最近互动、偏好标签、沉默天数、可用权益、导购/门店权限 |
| 核心输出 | 3-5 个优先跟进会员、推荐理由、建议话术、推荐权益、风险提示 |
| 人工确认点 | 导购确认是否触达；发消息、发券、批量触达必须人工确认 |
| 反馈字段 | 是否触达、客户是否回复、客户反馈关键词、是否到店/成交、未成交原因 |
| 成功标准 | 试点导购连续 5 天使用；触达反馈记录率 ≥70%；至少沉淀 3 类有效推荐理由 |
| 风险边界 | 不自动发消息、不自动发券、不跨门店查看会员、不在数据不足时强推权益 |
| 试点范围 | 1 个品牌 / 1 个门店或小区域 / 3-5 名导购 / 1 周 |
| 复盘时间 | 每晚看使用和反馈；周末看触达率、回复率、转化趋势 |

## 今天可以推进的一个动作

把试点范围收小到“10-20 个沉默会员样本池”。  
不要先做大页面，先让产品/业务拿一批真实会员样本，按以下格式手工或半自动跑一版：

```text
会员ID/昵称 → 沉默原因判断 → 推荐理由 → 建议话术 → 导购是否采用 → 触达结果 → 失败原因
```

这一步的目标不是追求模型完美，而是验证两个问题：

1. AI 给出的推荐理由，导购是否觉得“像真实客户”；
2. 导购是否愿意按这个建议完成一次触达并回填结果。

## 对产品和技术的提醒

### 产品侧
- 不要把 MVP 做成“智能导购首页”。
- 先做一个可执行任务：今天该跟进谁、为什么、怎么说、结果怎么记。
- 产品验收口径要从“页面是否完整”改成“导购是否完成真实动作”。

### 技术侧
- 权限判断必须前置：只读取当前导购/门店授权会员。
- 触达和发券必须人审，不做自动执行。
- 回写字段要尽早设计，否则后续无法形成复利。

### 组织侧
- 需要指定 3 个 Owner：产品 Owner、数据/Skill Owner、试点业务 Owner。
- 每晚只复盘三项：用了没有、动了没有、回写了没有。

## 晚上复盘问题

1. 今天是否已经确定 1 个试点品牌/门店/导购范围？
2. 是否拿到了 10-20 个沉默会员样本，并跑出第一版推荐理由和话术？
3. 导购看完建议后，是愿意执行，还是觉得“不像真实客户”？原因是什么？
4. 触达结果有没有回写字段，还是仍停留在口头反馈？

## 一句话总结

Day32 的重点是把“导购沉默会员唤醒 Skill”从契约表压成 MVP：**先不做完整平台，先跑通一条最短行动链，让导购真的用、真的触达、真的回写。**
