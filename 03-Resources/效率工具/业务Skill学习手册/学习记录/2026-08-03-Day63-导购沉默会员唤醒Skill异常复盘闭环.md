Skill 的成熟度不取决于“永远不出错”，而取决于：

```text
异常发生 → 证据留存 → 分类定位 → 改进动作 → 版本升级 → 复测验证 → 运营看板继续观察
```

如果一次异常没有改变任何输入模板、规则、权限、数据口径或输出结构，本质上就没有完成复盘。

## 导购沉默会员唤醒 Skill｜异常复盘闭环 v0.1

| 复盘环节 | 必须记录什么 | 对应动作 | 产出物 |
|---|---|---|---|
| 1. 异常记录 | 时间、门店/导购、会员分层、触发入口、原始输入、Skill 输出、执行结果 | 脱敏留证，避免只靠群反馈 | 异常记录表 |
| 2. 异常分类 | 输入 / 数据 / 逻辑 / 权限 / 体验 / 运营执行 | 先分类，再分 Owner | 异常类型标签 |
| 3. 影响判断 | 影响效率、客户体验、转化、合规、品牌信任中的哪一类 | 判断是否冻结、灰度收缩或进入版本优化 | 影响等级 |
| 4. 改进动作 | 补输入、补规则、补数据、补权限、补体验、补运营动作 | 明确 Owner + 截止时间 | 改进任务 |
| 5. 版本升级 | Prompt、Schema、接口字段、权限策略、话术模板、看板字段是否变更 | 形成版本号和更新说明 | v0.x 更新记录 |

## 典型异常复盘样板

### 异常 1：AI 推荐了不适合唤醒的会员

- **表现**：导购反馈名单里有近期已复购会员，推荐不准。
- **可能原因**：会员最近消费数据延迟 / 沉默周期口径没有排除已复购 / 数据时间戳未展示。
- **异常类型**：数据异常 + 逻辑异常。
- **改进动作**：
  1. 推荐结果必须展示数据更新时间。
  2. 增加“最近 N 天已复购排除规则”。
  3. 数据延迟超过阈值时，只输出“数据异常提醒”，不生成唤醒建议。
- **版本升级**：v0.2 补充数据完整性校验。
- **复测问题**：同一批会员回放后，是否还能被错误推荐？

### 异常 2：导购采纳了话术，但客户投诉权益承诺过满

- **表现**：话术中出现“免费、一定、必送”等承诺，实际活动不适用。
- **可能原因**：活动权益规则未结构化接入 / 高风险词未拦截 / 不确定时没有人工确认。
- **异常类型**：权限异常 + 逻辑异常 + 风险异常。
- **改进动作**：
  1. 权益类话术必须引用活动规则字段。
  2. 字段缺失时输出“需人工确认”，不能直接承诺。
  3. 高风险承诺词进入拦截或二次确认。
- **版本升级**：v0.2 增加权益风险拦截规则。
- **复测问题**：无活动规则输入时，Skill 是否会停止承诺型输出？

### 异常 3：导购觉得建议太长，实际不用

- **表现**：名单查看率高，采纳率低，导购反馈“看不懂、太长、要再改”。
- **可能原因**：输出结构偏管理视角，不适合一线导购执行。
- **异常类型**：体验异常。
- **改进动作**：
  1. 输出改为“一句话推荐理由 + 1 条可直接发送话术 + 1 个注意事项”。
  2. 长分析隐藏到“查看原因”。
  3. 增加导购未采纳原因快捷回写。
- **版本升级**：v0.2 调整一线导购输出模板。
- **复测问题**：新模板是否提升采纳率和触达完成率？

## 管理提醒

1. **异常复盘不是追责表，是能力升级表。** 目标是让同类问题下次少发生。
2. **不要把所有问题都归因给模型。** 很多问题本质是数据口径、权限边界、输入模板和业务规则没设计清楚。
3. **证据要脱敏保留。** 没有原始输入和输出，就只能凭感觉讨论。
4. **风险异常优先冻结，效果异常优先优化。** 越权、投诉、权益冲突不能等下周复盘。
5. **复盘必须连到版本号。** 没有版本升级记录，异常就不会变成组织资产。
