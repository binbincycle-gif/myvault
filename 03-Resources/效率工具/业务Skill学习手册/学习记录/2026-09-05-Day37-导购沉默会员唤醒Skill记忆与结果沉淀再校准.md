## 我今天抓到的核心一句话
没有结果沉淀的 Skill，只是一次性自动化；能把采纳、执行、业务结果、异常原因持续回写的 Skill，才会变成可进化的组织能力。

## 结合当前业务主线的理解
放到 EZR / OpenClaw / 智能导购主线里，导购沉默会员唤醒 Skill 的价值不能停在“帮导购生成名单和话术”。真正要形成复利，必须把每次唤醒动作后的结果写回资产层：

1. 导购是否采纳建议；
2. 是否实际触达客户；
3. 客户是否回复、到店、下单；
4. 哪类话术、权益、商品组合有效；
5. 哪些建议被导购忽略，以及忽略原因；
6. 哪些动作因为权限、权益、客诉风险被拦截。

否则 Agent 每次都在重新“猜”，组织不会因为用了 AI 而越来越懂客户。

## 导购沉默会员唤醒 Skill 的结果沉淀再校准

### 1. 本次 Skill 输出结果

#### 给管理者
- 本次建议唤醒会员数量；
- 按价值 / 沉默时长 / 最近触达状态分组后的优先级；
- 预计影响指标：回复、到店、复购线索；
- 风险动作数量：越权、敏感权益、客诉风险、需人工确认。

#### 给导购
- 今日优先跟进会员清单；
- 每个会员的跟进理由；
- 建议话术；
- 推荐商品 / 权益；
- 不建议触达或需人工确认的原因。

#### 给系统
- 一组结构化回写字段，用于后续复盘、看板和经验沉淀。

### 2. 回写位置分层

#### 写回 CRM / 业务系统
用于沉淀真实业务动作和结果：
- 建议是否采纳；
- 是否下发导购任务；
- 是否完成触达；
- 触达渠道；
- 客户是否回复；
- 是否预约 / 到店 / 成交；
- 成交金额 / 件数 / 客单价；
- 未采纳原因；
- 异常原因。

#### 写入项目知识库
用于沉淀客户 / 门店 / 项目级经验：
- 某品牌有效的话术风格；
- 某类活动有效权益组合；
- 某类门店执行卡点；
- 特定客户场景下的权限和审批边界。

#### 写入组织知识
用于跨项目复用：
- 沉默会员唤醒字段口径；
- 导购任务回写标准；
- 权益使用风险清单；
- 会员唤醒 Skill 复盘模板；
- 经验资产沉淀规则。

#### 仅保留运行日志
不进入长期知识库的内容：
- 单次临时查询过程；
- 未确认的模型推测；
- 低价值重复执行记录；
- 涉及敏感会员明细但无复用价值的数据。

### 3. 必填回写字段草案

```text
任务ID：
品牌 / 客户：
门店 / 导购：
沉默口径：
活动目标：
会员分组：
推荐动作：
推荐话术版本：
是否采纳：是 / 否 / 部分采纳
未采纳原因：无库存 / 权益不合适 / 客户敏感 / 导购判断不适合 / 其他
是否触达：是 / 否
触达渠道：企微 / 短信 / 电话 / 到店沟通 / 其他
客户反馈：已回复 / 未回复 / 拒绝 / 投诉风险 / 已预约 / 已到店 / 已成交
成交结果：金额 / 件数 / 客单价 / 连带率
异常原因：权限不足 / 数据缺失 / 权益冲突 / 客户敏感 / 系统失败
人工确认人：
回写时间：
```

### 4. 复盘指标

#### 执行侧指标
- 建议采纳率；
- 导购触达完成率；
- 任务超时率；
- 未采纳原因 TopN。

#### 客户侧指标
- 客户回复率；
- 预约 / 到店率；
- 复购线索率；
- 成交转化率；
- 客诉 / 反感反馈次数。

#### 组织资产指标
- 有效话术沉淀数量；
- 被复用的权益组合数量；
- 异常场景进入检查清单数量；
- 下次 Agent 推荐命中率是否提升。

### 5. 治理规则

1. **人工确认后再沉淀**：未被业务负责人确认的结论，只能放项目记录，不进入组织知识。
2. **会员明细不沉淀到长期知识库**：长期沉淀只保留脱敏经验、口径和模式。
3. **每周复盘一次有效样本**：看哪些建议真正带来回复、到店、成交。
4. **错误沉淀要有纠偏机制**：错误话术、错误口径、越权建议必须进入异常复盘。
5. **沉淀内容要能反哺下一次调用**：不是为了记录而记录，而是为了让 Agent 下次更准。

## 对今天业务 Skill 编写的提醒
业务 Skill 的设计不能只问“这次输出什么”，还要问“这次跑完后，组织多知道了什么”。

后续写 Skill 时，必须在文档里补齐 5 个问题：

1. 哪些结果要写回业务系统；
2. 哪些经验要写入项目知识库；
3. 哪些口径要升级为组织知识；
4. 哪些敏感数据只能留日志或不留；
5. 谁负责定期清理和纠偏。

## 下一步动作
1. 把“回写字段草案”整理成导购沉默会员唤醒 Skill 的标准输出段落。
2. 给智能导购 MVP 增加“采纳 → 触达 → 回复 → 到店 / 成交”的最小闭环埋点要求。
3. 将“结果沉淀规则”加入业务 Skill 上线前检查清单，避免只做一次性自动化。
