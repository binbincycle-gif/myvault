## 今日抓到的核心判断

Day47 解决的是“出错后怎么复盘和升级”。Day48 要进一步补上上线节奏：**导购沉默会员唤醒 Skill 不能一写完就全员开放，必须先在小范围真实门店灰度，验证价值、边界和风险。**

> 导购沉默会员唤醒 Skill 的灰度发布，不是慢一点上线，而是用最小真实战场验证它是否真的能帮助导购提升复购，同时不制造权益、权限、骚扰和信任风险。

这个 Skill 越接近真实会员触达，越不能直接规模化。原因很简单：

1. **推荐对象错了，会影响客户体验。** 把不该唤醒的人推给导购，可能引发反感或投诉。
2. **话术承诺过满，会带来权益风险。** 尤其涉及券、积分、赠品、专属权益时。
3. **权限边界不清，会触碰数据合规。** 导购只能看到自己授权范围内的会员。
4. **没有结果回写，灰度就无法判断价值。** 只看导购“觉得好不好用”不够，必须看是否带来触达、成交、复购或有效互动。

所以灰度阶段要控制四件事：谁能用、在哪用、用什么数据、能做到哪一步。

## 导购沉默会员唤醒 Skill｜灰度范围 v0.1

| 灰度变量 | 建议范围 | 控制目的 |
|---|---|---|
| 使用人群 | 先选 1-2 个品牌、3-5 家门店、表现稳定的导购 | 避免低成熟度使用导致误判 |
| 使用场景 | 只做沉默会员唤醒，不扩展到全部会员经营 | 保持试点目标清晰 |
| 数据范围 | 限定品牌、门店、导购维护会员、近 6-12 个月消费/触达数据 | 降低越权和口径风险 |
| 能力权限 | 只生成推荐名单、推荐理由和建议话术，不自动发送 | 保留人工确认 |
| 反馈要求 | 导购必须回写：已触达/未触达/客户反馈/是否成交 | 支撑复盘和版本升级 |

灰度不是“给几个人试试看”，而是把使用边界提前框住。

## 灰度阶段的通过标准

导购沉默会员唤醒 Skill 是否可以扩大，不看主观感觉，先看 5 类指标：

| 指标 | 建议观察口径 | 判断问题 |
|---|---|---|
| 使用率 | 灰度导购中实际使用人数 / 可使用人数 | 导购是否愿意用 |
| 采纳率 | 被导购采纳的推荐会员 / 推荐会员总数 | 推荐名单是否可信 |
| 修正率 | 导购修改话术或理由的比例 | 输出是否贴近一线沟通 |
| 异常率 | 权益误导、越权拦截、重复触达、投诉等异常次数 | 是否安全可控 |
| 业务影响 | 有效触达数、互动数、成交数、复购金额 | 是否真的带来经营价值 |

最小通过标准可以先设为：

```text
1. 灰度导购使用率 ≥ 60%
2. 推荐会员采纳率 ≥ 50%
3. 高风险异常 = 0
4. 每次触达结果回写率 ≥ 80%
5. 至少出现可解释的有效互动或成交样例
```

这些数值不是最终标准，但可以让团队从“感觉不错”进入“数据判断”。

## 灰度回滚与降级规则

灰度必须提前约定回滚，不要等出问题再讨论。

### 1. 立即停用
出现以下情况，直接停用该灰度入口：

```text
- 发生会员数据越权展示
- 出现明确客诉或权益误导
- 同一会员被多次重复触达并引发负反馈
- 输出内容明显违反品牌沟通规范
```

### 2. 降级为只读建议
出现以下情况，先不扩大，降级为“仅生成建议，不推荐具体会员详情”：

```text
- 数据口径被频繁质疑
- 推荐名单采纳率持续偏低
- 导购大量修改话术
- 结果回写率不足，无法评估价值
```

### 3. 回退到稳定模板
如果新版本 Prompt / 规则调整后异常升高，先回退上一版稳定模板，同时记录变更原因。

## 灰度试点流程

```text
选择灰度品牌 / 门店 / 导购
  ↓
定义灰度边界：会员范围、触达场景、话术权限、回写字段
  ↓
上线建议模式：推荐名单 + 推荐理由 + 建议话术，人工确认后触达
  ↓
收集数据：使用率、采纳率、修正率、异常率、业务影响
  ↓
每周评审：扩大 / 降级 / 回滚 / 停用
  ↓
沉淀为正式 Skill：进入目录、看板、异常复盘和版本管理
```

## 今日可落地动作

给“导购沉默会员唤醒 Skill”补一份灰度发布清单，先固定 6 个字段：

```text
1. 灰度品牌 / 门店 / 导购名单
2. 可使用会员范围
3. 允许输出内容：名单 / 理由 / 话术 / 权益提醒
4. 禁止动作：自动发送、跨门店推荐、无条件权益承诺
5. 必填回写字段：是否触达、客户反馈、是否成交、异常备注
6. 灰度评审节奏：每日看异常，每周看价值
```

这张清单是导购 Skill 从 Demo 走向真实门店的第一道闸。

## 管理提醒

1. **不要用全员开放证明价值。** 全员开放只会放大不成熟能力的问题。
2. **灰度阶段先建议，后执行。** 越接近客户沟通，越要保留人工确认。
3. **没有结果回写，就不算灰度。** 没有数据，就只能听主观反馈。
4. **灰度不是产品发布会，是经营试验。** 目标是验证是否能带来更高质量的会员触达和复购机会。
5. **扩大前必须过一次风险评审。** 权益、权限、频控、话术、数据口径都要确认。
