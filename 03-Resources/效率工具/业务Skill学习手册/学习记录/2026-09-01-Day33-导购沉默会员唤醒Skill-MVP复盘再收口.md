## 我今天抓到的核心一句话
Skill 不是给人看的功能说明，而是给 Agent 做决策时使用的能力说明书。

## 结合当前业务的理解
放到 EZR / OpenClaw / 智能导购这条主线上，今天最该收口的不是“这个 Skill 能不能生成一段话术”，而是：

1. Agent 什么时候该调用这个 Skill；
2. 调用前最少需要哪些业务上下文；
3. 哪些动作只能给建议，哪些动作可以进入系统；
4. 调用后结果是否能回写，形成下一轮优化。

如果这些没写清楚，所谓“导购沉默会员唤醒 Skill”就只是一个 prompt，不是一个可治理、可复制、可接入组织流程的业务能力。

## 对导购沉默会员唤醒Skill的再收口
### 1. 触发条件
当门店/导购需要处理沉默会员唤醒、复购提醒、活动触达优先级排序时调用。

### 2. 最小输入
- 品牌 / 门店范围
- 会员沉默定义口径
- 活动目标（唤醒 / 复购 / 清库存 / 节日节点）
- 可用权益
- 导购或店长权限范围

### 3. 边界
- 可生成名单、分层理由、建议话术、建议动作
- 不可默认自动发券、自动群发、自动外呼
- 涉及客户触达和权益发放，必须人工确认

### 4. 输出结果
- 会员分组
- 唤醒理由
- 建议动作与话术
- 建议回写字段
- 复盘指标（触达率、打开率、回复率、到店率、复购率）

## 今天这篇内容对当前业务Skill编写的提醒
后面再写业务 Skill，必须固定补这 5 个字段：
1. 触发条件
2. 输入要求
3. 权限与边界
4. 执行步骤
5. 输出结果

没有这 5 个字段，就不要急着说“已经 Skill 化”。
