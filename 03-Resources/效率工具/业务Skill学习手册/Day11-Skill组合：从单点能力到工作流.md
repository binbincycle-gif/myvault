# Day11｜Skill组合：从单点能力到工作流

## 今日主题

从今天开始进入第三阶段：**学会产品化与规模化。**

前 10 天解决的是“一个 Skill 怎么写对”。Day11 要解决的是下一层问题：

> 单个 Skill 只能解决一个能力点，真正产生组织效率和客户价值的是 Skill 组合成工作流。

业务 Skill 不是越多越好。如果每个 Skill 都孤立存在，最后会变成一堆“会做小事的工具”。真正有价值的是：把多个稳定能力按业务流程串起来，让 Agent 能从识别问题、查询数据、生成判断、推动动作，到复盘结果形成闭环。

---

## 技术原理（技术视角）

### 1. Skill 组合的本质是流程编排

单点 Skill 关注：

```text
输入 → 处理 → 输出
```

组合工作流关注：

```text
触发条件 → 多个 Skill 调用 → 中间状态判断 → 人工确认 → 外部动作 → 结果复盘
```

所以工作流不是简单“连续调用几个工具”，而是要设计清楚：

- 哪个 Skill 先执行；
- 上一个输出如何成为下一个输入；
- 哪些步骤必须人工确认；
- 哪些失败可以降级；
- 最终业务结果如何回写。

### 2. 工作流必须有状态

单个 Skill 可以只关注本次请求，但工作流一定要关注状态：

- 当前执行到哪一步；
- 哪些信息已经拿到；
- 哪些信息还缺；
- 是否等待用户/负责人确认；
- 是否已完成、失败、超时或取消。

没有状态，组合 Skill 就会变成“长 Prompt”；有状态，才有可能变成可治理的业务流程。

### 3. 组合 Skill 要保留人工控制点

业务工作流里最危险的不是“AI 不会做”，而是“AI 做过头”。

建议默认把工作流拆成三类节点：

| 节点类型 | 说明 | 是否可自动执行 |
|---|---|---|
| 查询/整理 | 拉数据、归类、生成摘要 | 可以自动 |
| 判断/建议 | 给风险判断、优先级、方案 | 可以自动，但要标置信度 |
| 外部动作 | 发邮件、改数据、通知客户、提交审批 | 默认需要人工确认 |

一句话：**AI 可以自动准备，关键动作要可确认、可审计、可回滚。**

## 业务翻译（业务视角）

业务上不要问“我们要做多少个 Skill”，而要问：

1. 哪些业务流程每天都在重复消耗人？
2. 这些流程是不是由多个固定动作组成？
3. 哪些动作可以自动化，哪些动作必须人工确认？
4. 每一步的输出能不能被下一步直接使用？
5. 最终是否能推动一个明确结果：成交、续费、降本、提效、控风险？

如果一个场景只解决“查询一下”“写一段话”，那它是单点 Skill。  
如果它能推动“发现问题 → 判断优先级 → 给动作 → 跟进结果”，它才是工作流。

## 典型场景（EZR 业务版）

### 场景 1：每日线上问题治理工作流

不要只做“Bug 日报 Skill”，而要升级成线上问题治理工作流。

建议组合：

```text
Bug 数据查询 Skill
→ 严重级别与模块归类 Skill
→ 高风险问题识别 Skill
→ 责任人与截止时间整理 Skill
→ 管理层日报生成 Skill
→ 次日闭环追踪 Skill
```

关键控制点：

- 高风险判断要标明依据，不能只给结论；
- 对外发送前必须人工确认；
- 次日要追踪昨日未闭环问题，避免日报变成“信息展示”。

业务价值：

- 从“每天看列表”变成“每天抓闭环”；
- 从“谁有空谁跟”变成“责任人、截止点、升级规则清楚”；
- 管理层看到的是风险与动作，不是流水账。

---

### 场景 2：导购小龙虾客户运营工作流

不要只做“生成导购话术”。话术只是末端动作，前面必须有会员洞察和商品推荐。

建议组合：

```text
会员画像 Skill
→ 最近行为分析 Skill
→ 商品偏好/试穿记录分析 Skill
→ 推荐商品 Skill
→ 导购跟进话术 Skill
→ 跟进结果回收 Skill
```

关键控制点：

- 推荐理由必须可解释，不能只说“猜你喜欢”；
- 输出要服务导购动作：找谁、推什么、怎么说、注意什么；
- 结果要回写：是否触达、是否成交、是否拉黑/反感。

业务价值：

- 不是帮导购“写一句话”，而是帮品牌提升导购触达质量；
- CRM 数据、交易闭环、导购关系能真正变成 EZR 的 AI 护城河；
- 后续可以按“召回任务次数”“推荐采纳率”“成交贡献”设计商业计量。

---

### 场景 3：资源预警与排期治理工作流

资源预警不应该只输出“谁忙谁闲”，而要进入排期治理。

建议组合：

```text
任务列表查询 Skill
→ 人员工时归一 Skill
→ 负载分层 Skill
→ 可释放人员识别 Skill
→ 调配建议 Skill
→ 预警日报/周报 Skill
```

关键控制点：

- 不能只看小时数，还要看角色、项目紧急度、跨组约束；
- 创新组、武汉研发、底层能力等组织边界要进入规则；
- 外发前要确认收件范围，避免误发管理敏感信息。

业务价值：

- 从“人肉问排期”变成“数据驱动调配”；
- 从“忙闲感知”变成“释放窗口与调配建议”；
- 为技术中心资源会议提供直接材料。

## 设计方法：三层拆解法

### 第一层：业务主流程

先画出完整业务链路，不要先写 Skill。

例如导购运营：

```text
选人 → 看人 → 选货 → 生成建议 → 导购触达 → 结果回收 → 策略优化
```

### 第二层：能力节点

把每一步拆成可复用能力：

- 选人：高潜会员识别；
- 看人：会员画像分析；
- 选货：商品推荐；
- 建议：话术生成；
- 回收：结果归因。

### 第三层：治理节点

再补上权限、确认、审计、异常处理：

- 谁能看会员数据；
- 哪些建议可以自动生成；
- 哪些触达必须导购确认；
- 输出错误怎么纠正；
- 结果如何回写。

## 今日小结

Day11 的核心不是“把 Skill 串起来”，而是：

> 用业务工作流承接 Skill，让 AI 从单点提效进入流程提效。

判断一个组合是否成立，看四件事：

1. 是否围绕真实业务结果；
2. 每个 Skill 是否有稳定输入输出；
3. 中间是否有必要的人工确认和风险边界；
4. 最终结果是否能被追踪、复盘、优化。

单点 Skill 是能力单元，组合工作流才是组织提效资产。
