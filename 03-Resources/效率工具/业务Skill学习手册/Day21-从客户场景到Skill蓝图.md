# Day21｜从客户场景到 Skill 蓝图

## 今日主题

前 20 天已经把 Skill 的认知、编写、发布、运营、评审、下线都走了一遍。

Day21 开始进入真实业务演练：**如何从一个客户场景，反推出一组可落地的业务 Skill 蓝图。**

> 业务 Skill 不是从“我想做一个 AI 功能”开始，而是从“客户/员工在一个真实场景里要完成什么结果”开始。

如果没有客户场景，Skill 很容易写成泛泛的 prompt；如果没有蓝图，多个 Skill 又会变成零散工具，无法组成真正的业务闭环。

今天要学的是：把一个业务场景拆成“角色、目标、输入、判断、动作、反馈、风险”，再决定哪些环节应该 Skill 化。

---

## 技术原理（技术视角）

### 1. Skill 蓝图不是功能清单，而是能力链路

一个完整业务 Skill 蓝图至少包含 7 个元素：

| 元素 | 要回答的问题 | 示例 |
|---|---|---|
| 角色 | 谁在使用 / 谁受影响 | 导购、店长、运营、客户成功 |
| 目标 | 要完成什么业务结果 | 提升会员跟进转化 |
| 输入 | AI 需要哪些上下文 | 会员画像、消费记录、偏好、最近互动 |
| 判断 | AI 要做什么分析 | 是否值得跟进、适合什么商品、风险点是什么 |
| 动作 | AI 输出什么可执行建议 | 推荐名单、推荐理由、沟通话术、下一步任务 |
| 反馈 | 结果如何回流 | 是否触达、是否成交、是否复购 |
| 风险 | 哪些地方必须受控 | 权限、口径、误推荐、客户敏感信息 |

如果一个 Skill 只有“输入 + 输出”，但没有角色、目标和反馈，它通常只能算工具，不算业务能力。

### 2. 蓝图拆解要遵循“三层结构”

业务 Skill 可以按三层拆：

```text
业务闭环层：这件事最终要改善什么业务结果
  ↓
能力动作层：中间需要哪些可复用动作
  ↓
Skill 单元层：哪些动作可以被 Agent 稳定调用
```

以智能导购为例：

```text
业务闭环：提升导购会员跟进与成交转化
  ↓
能力动作：识别机会 → 生成推荐 → 生成话术 → 记录反馈 → 复盘效果
  ↓
Skill 单元：会员洞察 Skill / 商品推荐 Skill / 话术生成 Skill / 反馈归因 Skill
```

这也是 SaaS 能力 Agent 化的关键：不是把页面搬给 AI，而是把页面背后的业务动作拆成 AI 可调用能力。

### 3. 每个 Skill 单元都要能独立验收

蓝图里的每个 Skill 都要有最小验收口径：

| Skill 单元 | 最小验收问题 |
|---|---|
| 会员洞察 Skill | 能否说清“这个会员为什么值得跟进”？ |
| 商品推荐 Skill | 能否给出“推荐什么 + 为什么推荐 + 风险提醒”？ |
| 话术生成 Skill | 话术是否符合品牌、场景和客户状态？ |
| 反馈归因 Skill | 能否把导购动作和转化结果关联起来？ |

如果一个 Skill 无法独立验收，就不要急着进入组合工作流。

## 业务翻译（业务视角）

业务上可以这样理解：

> Skill 蓝图，就是把一个业务场景拆成一张“AI 能力施工图”。

过去我们做 SaaS 功能，容易从页面、按钮、字段开始；现在做业务 Skill，要从结果、动作、判断、反馈开始。

管理者要盯住三句话：

1. 不从功能页出发，要从业务结果出发。
2. 不先追求大而全，要先拆出能独立验收的能力单元。
3. 不只看 AI 是否能生成内容，要看结果是否能回流到 CRM。

## 典型场景（EZR 业务版）

### 场景：导购智能体调用 CRM Skill 完成会员跟进闭环

**业务目标**：帮助导购每天优先跟进最值得行动的会员，并提高成交/复购机会。

### 1. 角色与目标

- 使用者：导购
- 管理者：店长 / 运营
- 受益对象：品牌会员
- 目标：让导购从“凭经验找人”升级为“基于 CRM 数据识别机会并执行动作”

### 2. 输入上下文

- 会员基础信息
- 最近消费记录
- 偏好品类 / 尺码 / 风格
- 最近互动记录
- 优惠券 / 活动 / 商品库存
- 品牌会员运营规则

### 3. Skill 蓝图

| 环节 | 可沉淀 Skill | 输出结果 |
|---|---|---|
| 识别机会 | 会员机会识别 Skill | 今日值得跟进的会员名单与原因 |
| 判断偏好 | 会员偏好洞察 Skill | 偏好、风险、历史购买特征 |
| 推荐动作 | 商品/权益推荐 Skill | 推荐商品、优惠、搭配建议 |
| 沟通执行 | 导购话术生成 Skill | 微信/企微跟进话术 |
| 结果回流 | 触达反馈记录 Skill | 是否触达、会员反应、下一步 |
| 效果复盘 | 转化归因 Skill | 本次推荐是否带来成交/复购 |

### 4. 最小闭环

今天不需要一次做完全部能力，最小闭环可以先定为：

```text
会员机会识别 → 推荐理由 → 导购话术 → 触达反馈
```

只要这条链能跑通，就已经不是单点 AI 功能，而是一个可以继续扩展的导购智能体雏形。

## 管理者关注点（成本 / 效率 / 风险）

### 1. 成本

不要一开始就做完整智能体。先拆出 1 条最小闭环，验证是否值得继续投入。

### 2. 效率

Skill 蓝图能减少反复解释需求的成本：产品、研发、测试、业务可以围绕同一张能力链路对齐。

### 3. 风险

越接近客户沟通、权益推荐、交易判断，越要保留人工确认、权限控制和输出留痕。

### 4. 组织沉淀

一个好 Skill 蓝图，最后应该变成组织资产：以后做会员经营、导购推荐、客户成功、运营分析，都能复用同一套拆解方法。

## 本日自检

1. 我今天能否选出一个真实客户/员工场景，而不是泛泛说“做 AI 能力”？
2. 这个场景是否已经拆成“识别、判断、推荐、执行、反馈”几个动作？
3. 哪一个动作最适合作为第一个可验收 Skill？
4. 这个 Skill 的结果能否回流 CRM，形成后续复盘？

---

## 一句话总结

**业务 Skill 蓝图的价值，不是把功能拆小，而是把一个真实业务结果拆成 Agent 可调用、可验证、可复盘的能力链路。**
