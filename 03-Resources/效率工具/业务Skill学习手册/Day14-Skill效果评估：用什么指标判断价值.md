# Day14｜Skill效果评估：用什么指标判断价值

## 今日主题

今天继续第三阶段：**学会产品化与规模化。**

Day13 讲版本管理，解决的是“Skill 如何稳定迭代、不破坏老流程”。Day14 要解决的是另一个管理问题：

> 一个 Skill 到底有没有价值，不能只看“能不能跑”，而要看它是否真的让业务结果变好、流程更稳、风险更可控。

业务 Skill 不是 demo，也不是 prompt 收藏夹。它进入真实业务后，必须能被评估、被复盘、被取舍。

---

## 技术原理（技术视角）

### 1. Skill 评估要分三层

一个 Skill 的效果，建议从三层看：

| 层级 | 关注点 | 示例指标 |
|---|---|---|
| 调用层 | 有没有被用起来 | 调用次数、活跃用户数、成功率、平均耗时 |
| 过程层 | 有没有改善流程 | 人工处理时长、返工次数、升级次数、审批通过率 |
| 结果层 | 有没有改变业务结果 | 转化率、复购率、客单价、工单关闭率、续费风险下降 |

只看调用量很危险。调用量高，可能只是入口醒目；结果没变化，说明 Skill 没真正创造价值。

### 2. 不同类型 Skill 指标不同

| Skill 类型 | 核心评估指标 | 不建议只看 |
|---|---|---|
| 信息查询类 | 命中率、答案准确率、节省查询时间 | 调用次数 |
| 诊断分析类 | 异常识别准确率、建议采纳率、复盘命中率 | 输出字数 |
| 生成建议类 | 建议采纳率、人工修改率、后续转化效果 | 生成速度 |
| 自动执行类 | 成功率、异常率、回滚率、审计完整率 | 自动化比例 |
| 工作流编排类 | 端到端完成时长、断点数量、跨团队协作成本 | 单节点效率 |

评估指标必须跟 Skill 的业务承诺一致。承诺“降低客服压力”，就看工单处理效率；承诺“提升导购转化”，就看触达后的转化和反馈。

### 3. 必须区分“AI 指标”和“业务指标”

AI 指标回答：模型或工具表现怎么样。

```text
准确率、召回率、响应时间、失败率、置信度、幻觉率
```

业务指标回答：这件事有没有帮公司赚钱、省钱、控风险。

```text
转化率、续费率、客单价、处理时长、人工成本、客户满意度、风险事件数
```

生产级 Skill 的评估不能停在 AI 指标。AI 指标是底线，业务指标才决定值不值得继续投。

## 业务翻译（业务视角）

业务上可以这样理解：

> Skill 效果评估，就是用数据回答：这个 AI 能力是“好玩”，还是“有用”；是“有人试”，还是“值得规模化”。

管理者要重点问四个问题：

1. 谁在用？高频用户是不是目标用户？
2. 用完之后，原来的流程有没有变短、变准、变稳？
3. 业务结果有没有改善？如果没有，是数据周期不够，还是方向不对？
4. 继续投入，应该扩范围、改产品，还是停掉？

## 典型场景（EZR 业务版）

### 场景 1：导购智能助手 Skill

如果 Skill 承诺是“帮导购提升会员经营效率”，指标不要只看导购打开次数。

建议指标：

| 维度 | 指标 |
|---|---|
| 使用 | 日活导购数、任务查看率、话术生成次数 |
| 过程 | 导购触达率、话术人工修改率、会员跟进完成率 |
| 结果 | 触达后成交率、复购率、沉默会员唤醒率、客单价变化 |
| 风险 | 投诉率、误触达率、优惠券误用率 |

关键不是“AI 生成了多少话术”，而是“导购是否更容易做出正确动作”。

### 场景 2：指标库 / 经营诊断 Skill

如果 Skill 承诺是“帮业务快速理解经营异常”，可以这样评估：

```text
v1：指标解释准确率、查询节省时间、重复咨询下降
v2：异常识别命中率、建议采纳率、复盘验证命中率
v3：经营动作执行率、指标改善幅度、管理会议决策效率
```

不要一上来就要求 Skill 直接拉动销售额。先证明它能缩短判断时间，再证明它能提高决策质量，最后再看业务结果。

### 场景 3：AI Coding / 测试辅助 Skill

如果 Skill 承诺是“提升研发交付效率”，指标要从端到端看：

| 阶段 | 指标 |
|---|---|
| 需求理解 | 需求澄清次数、遗漏点数量 |
| 开发 | 开发耗时、AI 生成代码采纳率、CR 问题数 |
| 测试 | 用例覆盖率、缺陷发现提前量、回归耗时 |
| 交付 | 按期率、线上 Bug 数、返工次数 |

重点是不要只看“代码写得快”，而要看“上线后问题是否更少、整体交付是否更稳”。

## 管理者关注点（成本 / 效率 / 风险）

### 1. 成本

没有指标，Skill 会越做越多，但不知道哪些值得维护。评估体系的价值，是把资源从“看起来很 AI”的东西，转向“真的改善经营”的能力。

### 2. 效率

好的评估指标能让团队少争论。不是问“这个 Skill 酷不酷”，而是问“是否缩短流程、减少返工、提升结果”。

### 3. 风险

自动执行类 Skill 不能只追求自动化率。自动化越高，越要看异常率、回滚率、审计完整率。尤其涉及会员、优惠券、客服承诺、导购触达时，宁可慢一点，也不能失控。

## 本日自检

1. 我们现在做的每个 AI Skill，有没有写清楚它承诺改善哪个业务指标？
2. 这个指标是调用层、过程层，还是结果层？有没有只停留在调用量？
3. 如果一个 Skill 连续两周没有改善过程或结果，应该扩、改、停，还是重新定义？

---

## 一句话总结

Skill 的价值不靠演示证明，而靠评估闭环证明：有人用只是开始，流程变好才有意义，业务结果改善才值得规模化。
