# OpenClaw Day2｜从"分层"到"可交付"

理解了OpenClaw第二天，我想明白了一件事：AI助手能不能稳定干活，取决于"分层"设计。

分享一下Day2的核心认知：

## 1. 为什么要分层？

- **不分层**：AI直接干，错了就崩，回不去了
- **分层**：交互→决策→执行→治理，失败能"退回"重试
- **差别在于**：后者有"容错兜底"，像工厂流水线一样，每层独立又联动

> 举例子：就像装修房子，不分层就是找一个师傅全包，分层就是设计→施工→监理→验收各司其职

## 2. 四层架构详解

### 第一层：交互层（Channel / Session）
- **职责**：接收消息，维护上下文，承载回执
- **像什么**：公司的前台+秘书
- **作用**：记住你是谁、之前聊过啥

### 第二层：决策层（Agent Loop）
- **职责**：判断是直接回答，还是进入工具调用链路
- **像什么**：公司的老板/指挥官
- **作用**：分析任务、规划步骤、选择路径

### 第三层：执行层（Tools）
- **职责**：read / write / exec / web / browser / cron / message 等可执行能力
- **像什么**：公司的执行员工
- **作用**：真正动手干活的那双手

### 第四层：治理层（Audit / Guardrails）
- **职责**：日志记录、权限控制、失败重试、合规边界
- **像什么**：公司的财务+合规部门
- **作用**：记录轨迹、控制风险、出了问题能回溯

> 这四层不是简单串行，而是"可回退"的闭环：执行失败时会回到决策层进行补救策略（重试、降级、人工确认）

## 3. 消息变动作的完整链路

一个自然语言请求通常经历6步：

1. **解析目标**：识别用户真正想要的输出与约束
2. **拆分步骤**：将目标拆成可执行子任务
3. **选择工具**：为每个子任务匹配最低风险工具
4. **执行与观察**：执行后读取结果，判断是否满足目标
5. **汇总与回传**：形成可直接使用的结果并反馈
6. **留痕与审计**：记录动作轨迹，便于复盘与治理

## 4. 关键机制与常见误区

### 三个关键机制

- **工具选择最小化**：够用即可，避免过度调用
- **失败可恢复**：超时、权限不足、结构变化时可走备用路径
- **上下文约束**：沿用当前会话目标，避免"跑题执行"

### 常见误区

- ❌ 把 Agent 当"万能脚本"，忽略权限与审批边界
- ❌ 只看最终答案，不看执行轨迹，导致问题无法复盘
- ❌ 把一次成功当稳定能力，缺少异常场景验证

## 5. 对工作的启发

- **复杂任务拆成步骤**，让AI一步步来，别一口气吃个胖子
- **重要操作要"审计"**，出了问题能定位到哪一步
- **先从高频、标准化任务切入**，不要一开始覆盖全部流程
