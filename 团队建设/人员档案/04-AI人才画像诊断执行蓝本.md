## 一、四层可信度（证据分层）
诊断时按层标注材料是否齐全；缺层不得编造。

| 层 | 含义 | 本轮可用本地材料 | 本轮明确缺失 |
|---|---|---|---|
| 第1层 | 客观系统事实（任务/排期快照） | OpenClaw `daily-commitment-check-20261105/06.json`、`resource-daily` 11-05/06 | 更长窗口、实际填报工时、状态码正式口径 |
| 第2层 | 结构化历史评估 | 用户 2026-11-08 上传评估表五维；档案职级字段 | 人事正式职级核验 |
| 第3层 | 过程角色与质量证据 | （无） | **玄武迭代分级/角色**、**bug SLA** 与线上问题闭环证据 |
| 第4层 | 工作方式与自我/协作举证 | （无完整正文） | **Skill**、**周报正文**、Get笔记述职/1on1 原文、协作方深访 |

原则：第1层与第2层冲突时，**标矛盾**，并以可核对客观事实为优先讨论基础；第2层单独出现时只能作「参考暂判」，证据强度弱。

## 二、四维度 · 五档（摘要）
与评估表字段、人才盘点计划一致。AI/助手**不定最终 T 级**，只给维度档位 + 证据 + 存疑。

1. **结果闭环**：完成任务 → 跑通目标 → 真正解决问题 → 放大团队结果 → 牵引组织结果  
2. **问题复杂度**：明确问题 → 中等复杂(中等负责)问题 → 跨模块复杂问题 → 团队级卡点 → 方向级/系统级  
3. **影响范围**：自己 → 模块/项目 → 跨职能/团队 → 跨团队/领域 → 公司/组织生态  
4. **AI工作方式深度**：辅助学习 → 个人提效 → 业务问题解决/可复用工作流 → 放大团队效率 → （更高档：重塑工作方式/组织级，以蓝本原文为准）

边界：项目分配 ≠ 绩效；排期小时 ≠ 实际投入；历史评估表须与客观数据交叉。

## 三、报告格式（试跑输出结构）
1. 概述（材料覆盖层、不作出最终 T 结论声明）  
2. 四维度分述（暂判档位 / 证据 / 存疑）  
3. 汇总表  
4. 矛盾点（评估表 vs 客观）  
5. 成长建议（建议项，非双方承诺、非绩效结论）  
6. 贺斌批注区（留空）

档位表述：证据足写「暂判第X档」；不足写「暂判第X档（证据弱）」或「材料不足暂不判」。

## 四、试跑步骤
1. 按四层列材料清单，缺失显式写出。  
2. 只基于第1–2层（本轮）起草四维度暂判。  
3. 交叉评估表与闭环/排期；冲突单列。  
4. 写入个人档案「画像重评」诊断报告 + 对比摘要。  
5. **贺斌决定**是否采纳、是否改档、是否进入新要求正式评估。
