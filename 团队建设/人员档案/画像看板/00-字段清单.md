## 总览页计划列

建议新建 `画像看板/00-团队总览.md`（本次不做），用 Dataview 读取本目录下各成员页 frontmatter，可排序、可筛选。计划列：

| 列 | 对应键 | 排序 / 筛选用途 |
|---|---|---|
| 姓名 | person | 链接到个人看板 |
| 组 | group | 筛选 |
| 岗位 | role | 筛选 |
| 历史职级 | level_hist | 仅展示，附注历史参考 |
| 进行中迭代 | projects_in_progress | 排序 |
| 有上线记录迭代 | projects_online_recorded | 排序；需同时展示数据窗口 |
| 最近排期 h | load_hours_latest | 排序 |
| 排期快照日 | load_snapshot_date | 判断是否过期 |
| 未来 2 周上线/截止 | upcoming_2w（可另做文本或条数键 upcoming_2w_count） | 筛选临期 |
| 协作 Top1 | collab_top | 展示 |
| 后端唯一迭代数（指定窗） | single_point_backend_augoct 或更新后的窗口键 | 排序；窗口变化要改键名或加 window 字段 |
| 线上 Bug | bug_ytd | 在全年数据完成前固定显示「待补」 |
| 更新日 | updated | 排序 |

Frontmatter 里的数字字段尽量用数字（空值不要写成 0）。待补用文本 `待补`，避免 Dataview 把空当成 0。

示例查询（确认后放入总览页）：

```dataview
TABLE
  group AS 组,
  role AS 岗位,
  level_hist AS 历史职级,
  projects_in_progress AS 进行中,
  projects_online_recorded AS 有上线记录,
  load_hours_latest AS 最近排期h,
  load_snapshot_date AS 排期快照日,
  bug_ytd AS 线上Bug,
  updated AS 更新日
FROM "团队建设/人员档案/画像看板"
WHERE type = "成员画像看板"
SORT group ASC, projects_in_progress DESC
```

若某次打开 Dataview 未实际渲染，再退回普通 Markdown 表，并在总览页注明。当前插件已安装且在启用列表中，优先按 Dataview 设计。

## 已发现的口径问题（批量前要先定规则）

1. **「项目」≠「迭代」≠「公司级项目」**。成员日常交付主要在迭代上；公司级项目周报覆盖面很小。建议总览主数字用迭代，公司级项目另列。
2. **同一天、同一迭代，任务总数对不上。** 例（均为 2026-11-11）：4298 在非终止清单为 22 项、在迭代快照为 70 项；4431 为 12/12 vs 19/24；2064 为 519 vs 947；4107 为 51 vs 62。很可能是任务过滤窗口或「计入哪些任务」不同。批量时需并列或先统一取数脚本，不能混用后直接相减得出「完成率」。
3. **清单的 start/end 不是上线日。** 4107 的 end=11-12，计划上线=11-25。
4. **8–10 月目录名含 10-31，文件生成于 10-12**，窗口末期迭代（如 4107、4561、4456）可能没收全。
5. **7 月没有同等任务级清单**，H1 止于约 6-29，全年去重和协作次数都会偏少。
6. **任务 Status 0/1/2 官方口径未书面确认**；完成工时有时被写成与预估工时相同（Q2 人员汇总即如此），不能当实际投入。
7. **资源日报花名册与在职档案不完全同一口径**（27 vs 29 等），且会出现「既不在有排期也不在无排期」的人（马超 11-11）。
8. **Handler / PIC / owner / 下一处理人** 不是同一角色；Bug 角色映射已发现冲突，未核验前不用于归责。
9. **长期支持池、暂停遗留、已上线但状态未归档** 若都算「进行中」，人数会被放大。
10. **承诺检查的逾期是候选**，已上线迭代仍可能留着旧任务状态。

## 批量时预计的难点

- 最缺的是一份可重复的「全年或至少近 90 天、含全部负责人的任务导出」，以及带 HandlerIdsDesc 或任务详情的当前迭代快照。没有它，进行中人数、协作 Top、单点依赖、未来 2 周任务截止都只能做部分。
- 其他人的个人月度复盘原文覆盖不齐，Skill/成长目标/亮点自述会大量待补；不要用部门月度总结「未点名」去填空。
- 线上 Bug 在全年导出和角色核验完成前，全员都应保持待补。
- 戴鹏等离职人员、王宇锋/朱建云等后补建档、资源日报 27 人与档案 29 人的差集，要先定在职范围。
- 不要把 Q2 分数、分层、严格全栈判断、诊断报告暂判写进看板；那些仍放在各人诊断/档案页，由贺斌做判断。
