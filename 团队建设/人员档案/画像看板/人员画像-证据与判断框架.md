# 人员画像 · 证据与判断框架

依据：[AI 人才画像诊断·执行蓝本](https://yhdn05cxqe.feishu.cn/wiki/Ph8jwrOPSimHJTklwnzcruPbnYg)。本页补充落地字段、缺失处理和更新方式，保留蓝本的四条主线，不替换原有人工评估。

画像应回答：这个人负责过什么、能解决什么问题、做到什么程度、与谁共同完成、留下什么可复用成果，以及每个判断来自哪里。数据既用于支持判断，也用于暴露暂时不能判断的部分。

## 四条判断主线

| 主线 | 要回答的问题 | 必要证据 |
|---|---|---|
| 结果闭环 | 是否完成验收、恢复业务并预防同类问题？ | 目标、本人动作、验收结果、生产观察与预防动作；不能止于任务关闭 |
| 问题复杂度 | 面对多大不确定性、跨多少边界，本人做出什么关键决策？ | 已核验项目等级、本人角色与贡献、方案取舍、风险、依赖及实际解决过程 |
| 影响范围 | 成果帮助了谁，能否持续被别人使用？ | 受益团队/用户、对方反馈、复用与采用记录、关键依赖及交接情况 |
| AI 工作方式深度 | 是否形成可重复执行、可验证、被团队采用的工作方式？ | 工作流、权限与校验、真实使用、人工接管、质量与耗时对照 |

不从预设职级或升降级结论倒推事实。能力结论、证据充分度与数据覆盖率分别呈现；缺失不记零分，也不自动等同于能力弱。

## 八类证据，映射到四条主线

| 证据轨道 | 推荐采集与计算 | 可以支撑的判断 | 常见误判 |
|---|---|---|---|
| 数据工程与数据判断 | 指标口径与边界、建模/查询、同步一致性、对账差异、数据量、P95 耗时与超时率 | 能否定义正确问题，兼顾正确性、容量、权限及可运维性 | 写过统计 SQL 或方案，就认为有规模化生产效果 |
| 线上问题处理 | 发现、首次响应、实际接手、止损、业务恢复、永久修复、验证与复发观察 | 响应、定位、恢复与根因闭环能力 | 处理人等于修复人/引入人；转交等于实质处理；关闭等于恢复 |
| 迭代实效与时效 | 初始承诺、变更、实际完成/验收、个人投入、外部阻塞、上线效果 | 承诺可靠性、推进能力与价值交付 | 用最后一次计划算准时率；用任务数代替效率 |
| 交付质量与返工 | 引入归因、严重度、提测冒烟、回归、重开、返工投入与缺陷原因 | 预防能力、设计质量与质量改进 | 修复数等于引入数；迭代全量缺陷归给 PIC |
| 人员协作 | 共挂任务、同迭代角色、实际联调、澄清记录、等待与返工、协作者反馈 | 边界澄清、跨角色推进、问题升级与帮助他人 | 共挂同一任务就等于合作顺畅；次数越多评价越高 |
| 业务结果与影响 | 需求目标、验收人、结果指标、观察窗口、受益范围与外部反馈 | 是否理解业务并产生可归因结果 | 上线即收益；项目金额或业务涨幅全部归给个人 |
| AI 工作方式与采用 | 非作者去重用户、调用成功/人工接管、复用频次、可比任务耗时与质量 | 从个人尝试到团队可用工作流的成熟度 | 上传 Skill 就算使用；个人自述提效直接当团队收益 |
| 复盘转化与知识复用 | 问题、根因、动作、负责人、截止日、验收、后续复发、SOP/Skill 被他人采用 | 学习、预防与组织资产沉淀 | 写了复盘就算闭环；有文档就等于团队采用 |

建议再增加两个可从上述轨道汇总的视图：**关键依赖与备份图**（哪些能力只有一人掌握，谁能接手）；**近三个月变化**（同类问题是否减少，承诺、协作与采用是否改善）。这两项同样需要交接或前后对照证据，不能凭项目多寡猜测。

## 指标计算的前置条件

- **准时交付率**：先确定承诺口径和到期队列。保留最初承诺与经确认的变更承诺，按固定粒度对照实际验收；分列未完成、范围变更和外部阻塞。不能只统计已完成项，也不能用当前计划覆盖初始承诺。个人任务与迭代分别计算。
- **响应/恢复时长与 SLA**：明确起算事件、等级、服务时段及 SLA 标准；有完整时间戳后，再计算首次响应和业务恢复间隔，按等级看中位数/P90。修复人与转交人分列；缺少恢复时间时不以关闭时间替代。MTTR 的 R 含义先统一，本系统优先明确写“业务恢复耗时”。
- **质量与返工**：先核验引入归因、严重度和提测范围，再按可比变更规模或同类迭代比较。没有可靠分母时只呈现事实与案例，不计算个人缺陷率；不以“修复数/任务数”替代。
- **协作评价**：任务关系用于找协作者，联调/评审用于描述实际行为，再由产品、前端、测试等 3—5 位协作者补充事实反馈。反馈记录项目、时间、具体行为、结果与建议；不以频次或人气打分。
- **数据能力**：同时看设计与实际验证。关键口径有业务验收；同步有乱序/重复/回补与对账；性能有数据量和前后测量；访问与导出有权限边界。不同数据规模不能直接比较耗时。
- **AI 提效与影响**：区分作者自用与他人采用，记录观察窗口、用户去重规则、成功/接管、可比任务和质量结果；没有基线和对照时不填提效百分比。

## 线上 Bug 的专门验收口径

线上问题与迭代缺陷分库统计；Normal 与 DevCreated 保留类型并分别展示。线上问题需要看 **响应接手 → 止损 → 业务恢复 → 根因定位 → 永久修复 → 生产验证 → 复盘预防**；处理可并行，不能将阶段图当作实际完成比例。

- ⏱ **时效**：保存实际发现/报障、首次有效响应、接手、止损、恢复、修复上线、生产验证时间。按严重度显示中位数/P90和可评估分母；未完成项同时展示，不能只看已关单样本。记录账龄独立呈现，不当作个人处理耗时。
- 🛡 **闭环**：根因有证据、修复有回归、生产有验收、预防项有负责人/截止日/验收、复发有观察窗口。`verified`、灰度中、已关单均不能独立证明完整生产闭环；需要止损与否也应有记录。
- ⚑ **归属与口径**：处理人、转交人、实际修复人、引入人与补丁负责人分别保存。个人接手前等待、外部阻塞与服务时段单列；SLA 标准不自行设定。
- 🔎 **冲突与缺失**：问题单和补丁计划同时保留，冲突待核验；LastModifiedDate 不替代首次响应，EndTime 在语义核验前不作为 SLA 截止，缺失时间不填 0。

### 非紧急线上 Bug 制度对照（2026-11-13 录入）

已保存用户提供的制度截图及结构化规则 `data/wang-shaojia/enrichment/online-bug-sla-policy.json`。按群内接单、定位、开发、测试 / 灰度、线上数据验证、总时长、升级七阶段展示规则、责任角色、事件线索与缺口。运维 10 分钟接单不能用作开发 SLA；中低优先级 24 小时要求是给方案，不是完成修复。根因字段与方案字段存在不等于在期限内完成。

制度仅适用指定非紧急群，Normal 不是所属群证据；制度版本、生效时间、提单起点、工作日与调休时历、时段累计口径及总处理完成节点核验前，不对全年问题自动计算正式达标率。条件性提示必须写明假设，不作为已确认逾期或个人责任结论；缺失值不转成 0%。已有方案不需升级，需核验当时的方案时间，不能用当前字段倒推。

页面先呈现图标、时效卡片、类型条形图和阶段链路；点击指标查看计算规则，点击阶段/问题查看时间线、角色、根因、方案、补丁与证据。知识库保留相同结构化数据，避免只把结论留在 HTML 中。

## 每个判断都保存的证据卡

```json
{
  "dimension": "线上问题处理",
  "period": "明确的观察区间",
  "coverage": "来源范围、查询过滤和完整性",
  "facts": [],
  "personal_role": "引入/修复/处理/转交/协作分别标注",
  "judgment": "基于哪些事实，能判断到什么程度",
  "evidence_readiness": "已有证据 / 部分可判 / 待核验",
  "sources": [{"url": null, "source_id": null, "fetched_at": null}],
  "metric": null,
  "missing": [],
  "next_verification": "明确材料、负责人和验收方式",
  "reviewed_at": null
}
```

`metric: null` 表示无法计算，不等于 0。证据充分度不是能力等级，不转成 1—5 分。量化指标应同时展示分子、分母、时间窗口、角色、过滤条件和缺失量。

## 来源可信度与时间对齐

沿用蓝本的客观记录、需标注材料、自述材料和人工反馈四层来源。系统字段也可能缺失或被更新：应检查字段语义、原始承诺、身份映射和查询覆盖后，再决定能支撑什么。

技术方案证明设计内容；测试报告证明相应环境与用例；上线记录证明系统登记状态；生产指标证明实际效果。它们不能互相替代。本人复盘中完成的动作需另取验收或运行证据；协作者反馈也需对应具体事件。

对照材料时保留文档覆盖日期、系统状态变更日期和取数日期。较早复盘写“未上线”、较晚系统写“已上线”，通常只是时间推进，不直接判定相互矛盾。不同来源存在真实冲突时，保留双方证据，等待核实。

## 落库与更新

1. Codex 从玄武和飞书读取材料，先保存原始来源、查询范围、取数时间与失败项。先完成身份、字段与数量校验，再生成指标。
2. 生成八类证据卡，保留事实与分析边界。人工评估、成长目标与 1on1 不由自动汇总覆盖。
3. 结构化 `latest.json`、地图和分析页同版本导出；各来源保持独立截止日，旧批次不因新材料入库变成最新。
4. 取数失败时保留最后成功版本；部分补查时明确哪些来源更新、哪些未更新。历史快照仅供追溯，不与最新版本累加。
5. Codex / OpenClaw 回答人员问题时，先读原档案、当前地图和分析页，写明各来源截止日；没有证据的百分比、职级和效果不自动补全。
