# EZR Skill建设：销售日报汇总

## 背景

该 Skill 面向门店、品牌经营分析场景，基于销售日报数据，对指定时间范围内的销售表现进行汇总，帮助快速查看：

- 整体销售情况
- 会员贡献
- 重点门店表现
- 销售排行
- 门店销售排名
- 销售额对比
- 阶段性经营复盘

## 要解决的问题

### 1. 统一入口

将多个业务能力统一到同一调用入口下，对外只暴露标准化 Skill 调用方式，降低接入复杂度。

### 2. 统一鉴权与身份隔离

通过数字员工和 Skill 绑定机制，统一处理：

- 账号身份
- 品牌范围
- 门店范围
- Skill 权限

避免外部直接接触底层系统权限细节。

### 3. 统一 Skill 封装

把底层原子接口能力封装成更贴近业务问法的 Skill，例如：

- 会员画像
- 会员 RFM
- 销售日报汇总
- 销售趋势

提升业务可用性。

### 4. 统一返回结构

将不同系统的原始返回统一整理成适合 AI 和业务人员理解的结构，减少调用方二次适配成本。

### 5. 降低系统耦合

外部调用方不需要了解底层是 CRM、reportsite 还是其他服务，由 Gateway 负责路由和聚合，降低系统间耦合。

### 6. 支持持续扩展

新增业务能力时，只需要新增 Skill 和对应封装，不需要让每个调用方重复对接底层接口，提高能力复制效率。

## 使用流程

1. 登录 EZR 后台，生成对应数字员工的调用凭证。
2. 安装 EZR Skills 技能包。
3. 配置对应凭证后开始使用。

> 安全说明：原资料中包含测试安装地址和 api_key 示例，本文档已脱敏，不写入可检索正文。

## 当前能力方向

从资料可见，当前优先能力是面向经营分析的销售日报汇总。建议把它作为 Skill Gateway 的第一批样例之一，与 `member_summary` 共同验证：

- 业务问法到参数转换
- 权限 scope 控制
- 多服务聚合
- 结构化返回
- 审计日志
- 错误降级

## 建议补充字段

后续补完整 Skill 定义时，建议补齐：

| 字段 | 说明 |
|---|---|
| skill_id | 如 `sales_daily_summary` |
| description | 用一句话说明业务用途 |
| input_schema | 开始日期、结束日期、门店范围、品牌范围、排序方式等 |
| output_schema | 销售额、订单数、会员贡献、门店排行、同比/环比等 |
| scope_required | 需要的品牌 / 门店 / 指标权限 |
| upstream_services | CRM、订单、会员、指标、reportsite 等 |
| error_policy | 无权限、无数据、服务超时、字段缺失时如何返回 |
| examples | 典型业务问法与返回样例 |

## 管理判断

销售日报汇总是很适合首批建设的 Skill：

- 高频；
- 业务价值清楚；
- 数据边界明确；
- 容易验证权限和返回结构；
- 可扩展到经营日报、门店排行、会员贡献、趋势分析等后续 Skill。
