## 二、数据结构

### 案例表字段定义

| 字段 | 类型 | 说明 |
|------|------|------|
| 案例ID | 唯一字符串 | 格式：CASE-年份-序号 |
| 客户名称 | 文本 | 脱敏处理，可标注"XX品牌" |

## 三、存储方案

### 方案对比

| 方案 | 工具 | 适用场景 | 优点 | 缺点 |
|------|------|----------|------|------|
| 轻量 | Obsidian + Dataview | 个人/团队查阅 | 免费、快速搭建 | 协作弱 |
| 中等 | 飞书多维表格 | 团队协作 | 协作方便、可视化 | 需手动同步 |
| 生产 | CRM案例对象 | 销售系统内嵌 | 与业务深度绑定 | 开发成本 |
| AI增强 | 向量库 (Milvus/PgVector) | Agent语义检索 | 语义匹配、智能推荐 | 需要向量服务 |

### 推荐：渐进式路径

```
Phase 1 (Week 1): 飞书多维表格启动
    ↓
Phase 2 (Week 2-3): 填充50条历史案例
    ↓
Phase 3 (Month 2): CRM集成 + 自动化采集
    ↓
Phase 4 (Month 3): 向量检索 + Agent集成
```

## 四、采集流程

```
1. 交付完成
      ↓
2. 交付负责人填写案例模板（72小时内）
      ↓
3. 客户成功审核（效果数据真实性）
      ↓
4. 打标签（行业/类型/质量）
      ↓
5. 入库（按存储方案选择）
      ↓
6. 定期复盘（月度提取高价值案例）
```

## 五、检索方案

### 分层检索架构

```
用户 Query: "我们是做母婴用品的，想提升复购率"
      ↓
┌─────────────────────────────────────┐
│  第一层：标签过滤                     │
│  行业 = 母婴 AND 痛点包含 复购       │
│  → 精确匹配，返回 5-10 条            │
└─────────────────────────────────────┘
      ↓ （若无结果）
┌─────────────────────────────────────┐
│  第二层：向量语义检索                 │
│  使用 text-embedding-3-small        │
│  → 语义相似度排序                    │
└─────────────────────────────────────┘
```

### 是否需要训练？

**结论：不需要训练**

- 开箱即用的向量模型（text-embedding-3-small / 阿里embedding）足够
- 案例库量级（几百-几千条）远达不到训练门槛
- 优先标签保证准确，向量做排序补充

### 成本估算

| 量级 | 向量API成本/月 |
|------|----------------|
| 500条 | ~¥30 |
| 2000条 | ~¥120 |
| 1万条 | ~¥600 |

## 六、与智能导购Agent集成

```
用户 Query: "我们是做母婴用品的，想提升复购率"
      ↓
Agent 调用案例检索API
      ↓
返回: 
  - 3个相似案例（摘要）
  - 关键数据（转化率提升xx%）
  - 推荐话术
      ↓
销售根据案例跟进客户
```
