## 会议结论

### 1. 营销目标拆解逻辑
- **业绩拆解**：总业绩 = 新会员业绩 + 老会员业绩 → 拆解为多个细分过程指标
- **定位问题**：定位同比下降幅度最高的3个指标 → 作为本次营销提升目标
- **输入**：营销目标 + 品牌信息 → 传入三库匹配

---

### 2. 三库结构设计

#### 产品功能库
| 字段 | 说明 |
|------|------|
| 功能名称 | |
| 功能摘要 | |
| 营销目标标签 | 一个功能可对应多个营销目标 |
| 适用渠道 | 抖音/微信/小红书等 |
| 功能状态 | 可使用 / 下架 / 白名单可用 |

**示例**：
- 大转盘 → 营销活动页面 → 通用
- AI外呼 → 老客转化 + 新客复购 → 微信

#### 行业案例库

**存储**：结构化数据库（SQL），不需要向量切片

#### 品牌标签库
- **核心作用**：为当前品牌推荐同主营行业案例
- **主营行业判定**：
  - 品牌自行维护
  - 或基于商品分类占比自动判定
- **多行业**：一个品牌可同时运营多个行业

---

### 3. 匹配输出流程

```
输入：营销目标 + 品牌信息
    ↓
匹配：三库检索（产品功能 + 行业案例 + 品牌标签）
    ↓
输出：匹配的产品功能 + 参考案例
    ↓
生成：传入应用端 → 预设提示词 → 最终营销话术
```

**组件化**：设计为独立搜索组件，可嵌入各业务智能体

---

### 4. 检索匹配方案

**兜底方案**：
- 精准筛选 + 向量近似匹配结合
- 精准匹配无结果 → 向量近似匹配兜底

**排序优化**：
- 标签匹配度排序
- 客户体量维度
- 优先返回满足多个指标的案例

---

### 5. 案例标签自动清洗

- **方案**：大模型自动提取标签（产品功能/营销目标/营销场景/适用渠道）
- **人工**：仅复核，降低清洗成本
- **重洗**：调整规则后可新建任务批量重洗

---

### 6. 词库与指标关联

- 标签词库需和现有指标库关联
- 例：工具拉新 → 非私域非小程序渠道拉新人数
- 优先复用现有指标，缺少的再补充
