# 导购小龙虾

## 项目定位

导购小龙虾不是单纯的试衣记录工具，而是围绕导购工作场景，持续沉淀高价值业务数据、经验和动作，并逐步演进为导购数字员工体系中的关键角色。

一期聚焦：

> 线下试衣场景的数据补录、结构化沉淀、未购原因识别和高销导购经验复用。

## 一期目标

验证一套 **轻量化、可执行、可持续的数据采集与沉淀机制** 是否成立。

核心不是做大而全产品，而是先抓住“试衣但未购”这个高价值数据空白。

## 核心问题

1. 线下试衣场景中，上身效果、导购判断、会员偏好、不合适原因、未购原因等高价值数据沉淀不足。
2. 一线导购掌握大量一手信息，但缺少低成本、可持续的记录机制。
3. 缺少结构化试衣数据，后续销售线索识别、导购跟进、高销经验沉淀和智能分析缺少可靠基础。

## 目标用户与受益角色

- 直接使用者：门店一线高销导购。
- 样本对象：高销导购。
- 受益角色：店长、运营、CRM / 会员运营团队。
- 试点对象：优先选择对试衣数据沉淀、导购跟进、会员运营有明确诉求的品牌门店，例如 UND、江南布衣。

## 一期边界

- 不做完整会员管理。
- 不做完整导购督导。
- 不走重硬件路线。
- 不把全程录音分析作为主方案。
- 当前优先以飞书等聊天工具验证轻量入口，但不固化为唯一长期形态。

## 当前方案

聊天输入不直接等于正式记录，而是走：

> 图片 / 语音 / 文本输入 → 草稿态 → 商品或试衣轮次归并 → 结构化确认 / 卡片补录 → 正式写入

这样降低上下文污染和串单风险。

## 核心指标

| 指标类别 | 重点指标 |
|---|---|
| 试点覆盖 | 试点品牌数、试点门店数、高销导购样本数、实际参与导购数 |
| 过程执行 | 试衣记录数、关键字段完整率 |
| 数据沉淀 | 结构化字段覆盖率、高质量试衣数据沉淀量 |
| 业务产出 | 试衣数据结构化分析、试衣未购原因分析、可跟进线索产出数 |
| 使用效率 | 单次补录耗时、导购使用频次、试点期连续使用天数 |
| 试点反馈 | 导购接受度、门店反馈、业务方对后续价值的认可度 |

## 当前状态

**正常，但要盯数据链路和真实反馈。**

项目已从早期 demo 进入内部试用阶段。当前最关键的变化是：

- 已完成试衣 Skill 包与飞书 demo。
- 已在 UND / Five Plus 试衣场景跑通过单个数字员工链路。
- 多 OpenClaw 共写同一飞书表稳定性差，已调整为每个数字员工单独写一张表。
- 已开放试衣机器人权限给运营中心。
- PPT 介绍资料已完成。

## 风险与阻塞

1. **上下文污染 / 串单风险**：纯聊天输入直接写入会导致商品、轮次、反馈串扰。
2. **字段稳定性风险**：guide_name / customer_id 语义混写、source_sender_id 丢失曾出现。
3. **写表稳定性风险**：多 OpenClaw 共写同一飞书表不稳定，已调整为单员工单表。
4. **身份识别风险**：首次和机器人对话配对、guide_name 不强询问，会影响导购身份稳定识别。
5. **落地载体风险**：当前主要是飞书入口，但已有客户表达企微使用诉求，因此需要数据入库和多入口承载能力。
